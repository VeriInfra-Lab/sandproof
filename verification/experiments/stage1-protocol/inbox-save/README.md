# Inbox 保存调用与状态

[组件入口](../README.md) · [V3 范围](../../../../docs/formal/03-protocol-inbox.md) ·
[依赖合同](../../../../docs/formal/dependencies.md) · [证明工作流](../../../../docs/proof-workflow.md)

本包固定 a9c 的 `codec::save`，复用完整 Inbox 值校验候选，检查保存的调用顺序。
生产只读。原整根在固定工具的嵌套循环、Serde 和 rusqlite 动态参数处存在抽取障碍；
隔离候选保留原守卫、SQL 和返回值，将三个具体库调用放入有显式可变状态的窄接口。
`production-candidate.patch` 只供工程审查，原候选一般等价与生产采用仍未闭合。

`InboxSave.FullSaveContract` 是所有正反视图共用的完整合同。`save_refines` 对任意
表示范围内已解码 Inbox、完整校验的编码参数和保存效果字典，连接实际生成入口与
`saveView`。顺序为完整校验、编码整个同一 Inbox、检查返回字节长度、对同一字节
调用 digest、以原 SQL 和同一字节及返回摘要调用 UPDATE，最后只接受行数等于 1。
长度比较保留实际 usize→u64 转换，未引入更强的预算、配置或事务条件。

三个效果调用传递前一调用返回的完整状态。正常错误保留已经发生的效果：预算拒绝
保留编码状态，更新错误或行数错误保留更新后的状态。外层失败与发散原样传播，不能
从没有可观察的后态推出回滚。校验错误则在调用编码、digest 和 UPDATE 之前返回。

合法空 Inbox、完整 Create、预算等于上限和超限、零行更新及完整参数轨迹用于检查
合同可实现性与遗漏。它们不替代任意输入定理。四个实际 Rust 错误版分别丢弃校验
错误、删除预算守卫、接受零行更新、对空字节调用 digest；正反版使用同一完整合同，
错误视图不导入正确保存函数的对应证明。

## 开发与验收入口

`native.py --output ...` 在独立源码和 Cargo target 中检查原版、候选、四个错误版及
恢复版。原版与恢复版运行 11 个共同断言；有窄接口的版本另运行 7 个完整参数／状态
断言。错误版必须实际编译并到达精确断言，随后仍须通过格式和严格 Clippy。协议库
与服务测试的源码、manifest、fresh 状态和实际二进制均需核对。

`formal.py --variant correct --development-native .../result.json --output ...` 是本地
开发入口；错误版选择对应 variant。每个正式视图独立重抽取 save／完整 Inbox 根和
graphic／Result 原语根，检查两条透明单调用转发及全部生成函数和外部符号。所有
真实文件经过内核、工作流规定的同服务完整诊断及依赖审计，拒绝 stale/partial。
执行者须持有共享重锁，各视图使用独立 `.lake/build`，保留缓存与失败证据。

`library_binding.py` 逐字复用既有值模型和同版字面量适配。SQL 字面量的长度证明
使用已有的内核归约方式，保持原文本、字节和长度条件；不使用默认 native 决定，
不手改生成体，不放宽公理审计。`inventory.json` 记录精确生产输入、证明提供者和
每个视图闭包；清单本身不代表检查完成，结果以实际执行记录为准。

`--require-native` 要求 ning 的完整功能和本组件封口。公共原生／形式登记及覆盖记录
只在 `coordinator-candidate.patch` 提供候选增量，采纳和共享整套验收由主控执行。
局部开发通过不代表 ning、完整 `verify-controller.sh`、E2E 或完整 V3 通过。

## 后续义务与提供者

有状态效果字典不是具体 Serde、SHA 或 SQLite 正确性的假设。任意编码回调甚至可以
返回空字节；正常保存返回值不证明 JSON 合法。32 字节摘要值也不证明实际计算了哈希
或材料完整。标准提供者的实际字节／错误／参数连接、原候选一般等价、同一事务中的
接受、未知提交和重启恢复继续开放，不能把整个收件事务设为可信。

共同原生用例还保留 `record→validate→save` 的边界：合法 resolved-Unload 前态与
形状合法的新意图，在重复 capture 时可以 record 成功但随后完整校验拒绝；实际 save
拒绝且原 SQLite 行不变，新 capture 对照可以保存。这是实际用例结果，尚不是任意
转换保持定理，也不是非法持久接受的结论。

V0 提供逐符号库合同及具体编码、哈希和 SQL 参数连接；V7 提供独立认证来源和受保护
配置；V1/V2 提供当前规范意图与耐久发送；V4/V5 提供实际本地接受、结果、收据和事务
事实；V6 提供文件、VM 与清理事实。完整 JSON/TLS/handler、网络外壳、持久收件和
系统结论均须另行闭合。
