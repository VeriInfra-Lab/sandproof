# 公共采用候选

本包只含 integration `9c50da7c` 之后的未发布读取增量，不重带 #751 的12个 Create 包。
生产仍为原数组表达式；最小候选由 source-candidate.json 逐字节准备，没有改 SHA 或
其它业务算法。库接口和该源候选均未采用。下面三份补丁交主控单写，不自动应用。

- dependencies-candidate.patch：五个固定读库符号、正常行条件及提供者，待 V0/主控协调。
- coverage-candidate.patch：精确条件与开放范围，不声称普通或正式共享入口通过。
- public-registration-candidate.patch：在原 full 清单追加本组件；固定 create-delivery
  的12包、42视图和全部原任务保持原范围。补丁是接线候选，主控取得 ning 收据后，
  同批完成累计审计、冻结/输入、Lake/根及原公共入口验收，不能只运行旧根。

registration.py 校验同一完整结果的三个实际视图、所有文件/审计和生成比较、反例标记；
原 registered.py 的实际物理文件、日志和同服务读回继续执行，不能以该结构校验替代。
本包21份模板有77个唯一审计名（其中两份 Model 无审计）；正确视图137文件/500审计，
两错各20/27，三视图并集513名含原支持、见证与反例，不是513个独立业务性质。
累计审计候选为增加19份含审计模板、77项声明；最终须按全部当前源重新核对。

普通入口需要原共享协调锁或其已持有的同一 FD；由主控传入 --lock/--lock-fd，
不能在父进程持锁时重新打开同一路径等待。native.py 的数组表示、实际 Unit、两错、
恢复五视图共享九条真实 SQLite 断言，严格 Clippy 无豁免；尚未在 ning 运行。
主控把结果接入 proof_native_suite 时须保留完整源/规则/合同、所有原日志、实际新编译
protocol/service 的源/manifest/链接及精确失败集合检查，不能仅凭退出码封口。

本包不向全局登记新的完整 handler、数据库、认证或 JSON/SHA 业务假设。
未闭合项继续分别由 V0/固定库符合性、V5/A4 活对象与事务历史、V7 认证来源、
V1/V2 当前意图/耐久发送、V4/V5 本地结果和 V6 实际材料提供；其余 IO、原编码、
正常摘要 agrees 以及 Graphic/字符串表示条件在原 Load 定理中显式保留。
