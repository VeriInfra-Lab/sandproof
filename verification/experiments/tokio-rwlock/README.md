# Tokio RwLock：原锁上的读守卫与映射

[证明入口](../../../docs/proof-workflow.md) · [依赖合同](../../../docs/formal/dependencies.md) · [V0](../../../docs/formal/00-foundations.md)

本目录是 T6 的一个公共接口批次。模型、实际 Rust 回归、原工具抽取预检和整套验收分别报告；不能把组件通过写成 V0 完成。生产仍使用真实 Tokio，本批不修改生产代码或工具。

## 能复用什么

固定 Tokio 1.49.0 的 `RwLock::new/read/read_owned/write`、原守卫的正常释放，以及 `OwnedRwLockReadGuard::try_map` 的 `Option::as_ref` 接法。多个读者可以同时持有，写者独占；映射成功仍持有原锁，映射失败把仍持锁的原守卫放在 Err 中。接收错误和丢弃其中的守卫是两个不同事件。

`Core` 提供读写排斥、原身份、释放/遗忘的区别及调用者写关系下的不变量保持。`Mapping` 提供原许可的线性转交和固定共享投影；`Examples` 给出多个读者的合法历史，以及复制字段后提前解锁不再满足同一个 `ProtectedRead` 合同的反例。

调用者先提供原锁、原守卫和实际 A6/B2 操作对应，证明 `Safe` 初态及自己的每次写入。若能证明调用期间保留同一读守卫的 `ReadHistory`，即可引用 `retained_reader_keeps_payload` 或 `retained_mapped_snapshot`，不用再证明其它合法写者无法同时改写这些字段。这里保留的是受保护内联字段和句柄，不冻结内部可变对象、外部进程、时钟或整个堆。

逻辑 ticket 标识一次领取，不是地址、线程 ID、永不复用的运行时编号或 FIFO 位置。`try_map` 消耗原 Rust 守卫；模型里相同 lease 的值相等不允许复制出两个独立拥有的守卫。任意有状态回调、内部可变访问和可观察回调析构不在这个投影接口范围。

## 取消、释放与最后一个 Arc

模型只描述已经取得的读写权。等待中的内部排队和部分预留没有变成可读守卫；取消可以撤销这些预留并唤醒别人，不能说整个运行时没有变化。其它任务的取得与写入仍可交错发生。没有 FIFO、最大读者数、最终调度或硬返回时限定理；没有写者也不等于下一次读必定立即成功。

`forget` 不解锁；panic 不回滚已经写入的数据。没有正常完成事件时不补造析构、释放或恢复。

**载荷保持结论只适用于原锁继续存活的观察域。** owned 守卫也持有原 Arc；如果它是最后一个强引用，完整 Drop 会先释放读许可，再析构 Arc，可能接着销毁原锁和载荷。不能用“守卫释放不改写仍存活的锁内值”推出“最后一个 Arc 析构后载荷仍存在”。本地夹具分别观察保留外部原 Arc 和仅剩 owned 守卫两种情况；最终对象销毁、秘密清零及其它资源析构由 T5/实际业务继续连接。

## 实际来源和业务责任

`Session.shared.current` 是本轮代码检索发现的生产 RwLock。`authorize` 和文件授权取得原 owned 读守卫并映射 `Option::as_ref`，`AuthPermit` 保留它；`apply` 先读取旧身份，结束该次借用后等待写锁，再执行原默认值处理和完整替换。

A6 只提供固定库操作；B2 只连接原 Arc/锁、守卫、实际参数/结果与操作顺序。令牌/签名是否合法、旧快照可否用于后续决定、元数据绑定、默认值预算、何时结束授权许可及替换后的析构仍归 V8/V9。检查与初始化整个函数不列可信，不因有读锁就获得授权定理。

原 `Session::authorize` 在固定 Charon 的 aeneas preset 下被 coroutine 和 MetadataSource 的 GAT 限制拒绝。保留失败原文和带错误的 LLBC，不移除类型、升级工具或把失败当语义反例。因此本批是条件模型及有限接线证据，尚无完整 async Rust 机器精化。
