状态：公共底座的交付要求；已完成的局部定理和剩余项以覆盖记录为准。适用代码定位基线与实际证明状态分别见总览和[覆盖记录](../proof-coverage.md)，不因本页完成而新增已证明结论。

V0 是 #333 统一跟踪的证明底座，包含原 #515 的 T0–T8 和原 #510 的任务/取消接口。把身份、数值、拒绝、证据和实际实现对应的含义固定下来，供各模块直接导入。它不掌管运行中的实例，也不另造一套业务算法；单独拆分可避免各负责人对同一编号、未知结果或“成功”使用不同定义。

## 2 共有对象与合同形式

统一定义 `Binding`、`OperationIdentity`、`ExactAttempt`、`ApprovedPlan`、`Evidence`、`ResourceVector`、`ErrorClass`。它们是证明侧公共词汇，按字段映射实际类型，不要求生产代码改名。地址/路径/PID/摘要不单独充当永久身份。

每个合同为 `(Pre, Input, Event, Post, Frame, Fault, Budget)`：输入前提、可观察事件、后果、修改范围、失败/崩溃可能性和预算。区分纯检查拒绝、服务拒绝但已提交到期事实、明确外部失败、效果未知；不定义一个统包一切的 `Result<bool>`。外部依赖 A、获批薄适配 B、业务定理和调用绑定证据的明细只在[依赖登记](dependencies.md#逐符号可信适配登记)维护；公共定义不另复制一套依赖保证。

统一 `ModelInit`、`ModelStep`、`ModelReject`、`R_i` 和不改变抽象业务状态的内部步。模块模型拥有状态，公共定义只提供类型和约束；具体 `Init_i` 可实现性由所属模块及 V9 证明。事件历史是证明用对象，不要求运行时永久存储。

`Evidence` 是带绑定、类别和观察版本的历史断言，不是物理事实的证明。V0 证明结果/类别不会被错误转换；V6 提供原对象、观察点、覆盖范围及保护条件的真实证据，V4/V5/V9 再连接发布。字段相等亦不等于合法编码：完整 JSON 往返、未知字段/非法字符串/越界值拒绝、自有编号无别名以及构造/恢复时的合法域建立，须逐入口连接，未完成项只在覆盖记录登记。

## 3 待证接口

| 拟定定理 | 精确义务 | 前提提供方 |
|---|---|---|
| `identity_roundtrip` | 对构造域内完整身份 `b`，实际编码后成功解码等于 `b`；字段完整、非法字符串/不可表示值拒绝，不缩窄或混用字段。可表示但不支持的协议版本及零位置可先解码，随后按版本→节点→位置的原序拒绝，不能改为解析阶段拒绝 | 协议解析库最小合同；调用范围由 V3/V7 |
| `checked_counter_refines` | 未耗尽时下一个编号恰为原值加一；耗尽拒绝、无回绕；退休不降低高水位 | 各模块 `R_i` 与实际有界整数定义 |
| `resource_arithmetic_refines` | 已接受的各分量加减及单位换算等于数学结果且落在表示域；不足/溢出不进入成功分支 | V1/V4 的准入条件 |
| `evidence_kind_separated` | Accepted、Ready、Stopped、Cleaned、Released、Unknown 不互推；任何持久记录不自动产生物理证据 | V6 证据构造及 V5/V2 提交连接 |
| `refinement_contract_compose` | 核心及合同事件可投影到抽象事件，内部步保持 `R_i`；有限多步组合保持可观察历史与修改范围 | 各模块核心对应、显式 A/B 合同与实际调用绑定；V9 接口相容 |
| `goal_dependency_audit` | 业务前提有提供定理，外部/获批薄适配前提有 A/B 编号及实际使用点，调用绑定的证据类别明确，初始化非空；这是审计交付，不用新公理实现 | 各负责人＋V9 |

共有接口使用显式参数携带 A/B 合同，不导入“整个 adapter 正确”。获批 B 只覆盖登记的机械接线，不担保业务决定。条件定理仍需 V9 实例化业务前提、固定 A/B 与真实调用绑定才能成为相应条件下的系统结论。

## 4 首批与后续任务

首批：身份/有界算术/结果分类 → 一个 V1 纯决定的实际抽取 → V2 Lua 与 V3 编解码可行性检查 → 固定 `R_i` 和事件接口。先用最大值、参数冲突、未知提交各一个样例检查定义；既有样例能覆盖时不加重复测试。

后续：容器写入、删除与修改范围、序列化界限、窗口/代次比较、查询投影和流历史公共引理。查询接口使用独立的首次匹配语义，泛型键的相等合同由实际键类型的对应定理提供；不能把任意自有比较函数列为外部假设。下方 I2 的判定接口分别由 V7（normalize/page）、V5（lifetime）、V4（identity/publication/capacity）、V6（observation/release）、V8（transfer end）提供，V0 不复制其实现。

### 公共循环复用接口

[FiniteCopy](../../SandboxModel/Foundations/FiniteCopy.lean)提供原顺序复制、前置一元素及有限终止的参数化合同；[FiniteInsert](../../SandboxModel/Foundations/FiniteInsert.lean)提供首次匹配短路、缺失时前置复制，以及独立的成员、顺序、长度、唯一性和投影性质。它们不导入完整业务状态或历史生成命名空间。

调用模块须证明真实抽取的循环体及包装与公共算法对应，再使用 `vectorCopyLoop_transport` / `vectorInsert_transport`；连接条件是自有证明义务，不是库合同或环境假设。复制需要自有类型的 `CloneExact`，比较需要 `ValueEqExact`。已有元素分支既不需要追加余量，也不需要克隆合同；缺失时需原长度小于 `Usize.max`。这只约束纯模型的可表示长度，不保证实际分配永不失败，也不承诺自定义析构效果或外部状态的失败回滚。实际调用者的额度、表示关系和状态不变量由所属模块证明。

### 范围和模块验收

V0–V9 是证明责任模块，不是顺序版本。V0 完成条件只包含本模块公共定义、实际公共实现的对应、依赖登记和公共组合接口；不能把历史控制器全部业务证明迁移加入其前置条件。

| V0 自有义务 | 邻接模块仍需落实的义务 |
|---|---|
| 完整共享身份/字段的表示、相等、合法编解码往返与规范编号解析 | V3/V7 的认证、调用绑定和真实收发；V2 的存储编码使用 |
| 受检查的加减、单位转换、编号/窗口/代次比较及不回绕 | V1/V4 的分配与准入；V2/V3/V4/V5 的退休推进、持久高水位和复用许可 |
| 通用有限表查询、写入、删除、唯一性与修改范围 | 调用模块的自有键/谓词对应、可达不变量和追加额度；V4 的完整 World 与业务状态更新 |
| 有限事件/流历史、拒绝/未知分类和参数化组合接口 | V8 的业务读写/撤销/结束核心、A/B 使用点与调用绑定；V9 的具体初态、故障、邻接与系统组合 |
| 固定依赖合同、抽取/审计接线、失效影响和最小桥接可行性 | V2 的实际 Lua/CAS/耐久协调，V3 的真实协议路径；不得将它们假定已正确 |

完整 `verify-controller.sh` 每批仍执行并如实报告，不删根或绕过失败。另用 `verify-foundations.sh` 验收列明的 V0 集合。V0 自有缺口未闭合时不能宣称模块完成。旧整控制器抽取链已退役，当前完整入口验收保留集合；V4 当前业务实现义务继续归 #337，不加入 V0 的前置。保留集合通过不等于 V0 全部义务或全系统证明完成。

### 公共查询投影接口

[TableQueryContracts](../../SandboxModel/Foundations/TableQueryContracts.lean)连接首次匹配查询、值投影与实际 `get_copy`/u64 调用根。键投影必须单射，值可抽象，顺序与重复键不能悄悄改成无序映射；调用模块提供自有比较及表示关系。它不授权维护或建立完整 World 不变量。不能以几项通用定理代替全部调用入口清单。

[共享查询接入](../../SandboxModel/Foundations/LoopCallbacks.lean)另外连接原 get/contains_key 的安全共享值观察及四个透明委托；保留首次匹配/重复键、比较和投影条件，不代表所有业务调用者或有状态回调已完成。

有状态回调另由 [CallbackState](../../SandboxModel/Foundations/CallbackState.lean)提供真实 helper 对应及逐次外部状态组合。正常遍历与机械状态传递分别依 A6/B4；完整自有谓词/比较和业务提供方仍须实例化。原 Child 的退出观察及未知 pair 交接见 [ChildObservation](../../SandboxModel/Boundaries/ChildObservation.lean)与依赖登记；它是隔离同步候选，不代替生产一般等价或完整宿主生命周期。T7/T8 的[有限使用目录](../../verification/experiments/os-boundary-catalogue/README.md)帮助逐点审查，不能当作语义覆盖证明。

### 可观察组合合同

[Composition](../../SandboxModel/Foundations/Composition.lean)保留参数化的一般有限精化接口；全系统安全结论还须使用[Observations](../../SandboxModel/Foundations/Observations.lean)的加强合同，或提供相同强度的义务：

1. 逐事件保持完整可观察内容，再连接有限历史；不能只保持事件数量或标签。
2. 声明关键事件的具体观察非空，因此投影不能将其擦除；多层组合保持同一观察词汇和顺序。
3. 给出真实合法初态及对应模型初态，不能以空初态完成证明。正常请求可接受的见证和完备性仍由各真实处理函数提供，事件框架不代替请求检查。

事件分类、具体/模型观察和投影都由自有模块/V9 实例化并审计，不是可任意选择的环境前提。实际启动、副作用、授权/撤销、耐久提交、用户响应、流结束及异常/未知的公开含义按所属合同连接，不能把它们伪装成纯内部步。只有确实不改变所声明观察的计算步才可为空；瞬时、历史和已提交事实不混用。

这些接口只覆盖有限前缀，不排除无限内部空转，也不自动推出请求最终完成。后者须由所属模块/V9 另证工作启用、预算/出队、良基度量和无环等待，再使用明确的外部最终可用与公平条件；不把自有推进义务藏进公平假设。

### 有限字节流公共合同

[StreamHistory](../../SandboxModel/Foundations/StreamHistory.lean)定义单方向的源、已读、已写、待写及结束类别；源和历史是证明侧记录，不要求运行时保存全部字节。读追加原源的下段，确认短写只消费待写前缀，保持 `Read = Written ++ pending` 和源序列的内容/次序。驻留上限约束待写队列，可选累计预算单独约束历史；无限累计输出不能被错误替换为无限驻留。

完成要求真实提供方认可的源结束证据、全部源已读及待写为空；HTTP 状态、EOF、时间到期不自行充当结束证据。失败、取消和未知不构造完成，终态不继续产生该方向步骤。V0 的一步/有限历史性质及可实现完成轨迹不等于公平调度进展；V8 须连接实际 I/O、所有缓冲、协议结束、原绑定和机器计数，V9 再提供组合及条件推进。

### T0–T8 公共底座验收点

T0–T8 原由 #515/#510 分别跟踪，现统一归 [V0 #333](https://github.com/VeriInfra-Lab/sandproof/issues/333)。T 是验收分类，V 是业务证明归属；T9 浮点/来宾兼容算法继续排除。公共底座负责让本轮实际用到的接口有模型、有明确条件、有真实接入方法和检查入口，不负责提前证明全部 V1–V9，也不承诺支持所有 Rust 语法。

各项均以**本轮列明的真实使用点清单**验收：每个点要么已连接可复用接口，要么列为带负责人/归属的未完成项，不能靠删掉清单中的点通过。库条件、获批薄适配条件和自有定理分别标注。正例必须可实现；错误版须先成功编译/抽取，再被正确版同一性质拒绝；测试失败和形式反例分别记录。当前进度和证据只在 #333 与覆盖记录维护，以下不预勾完成。

#### T0 真实来源、覆盖和验收入口

- 列齐根函数、实际调用者、可达自有函数、外部接口、类型和会影响结果的析构；新入口须进入对应抽取/审计清单。[原编译器使用清单](../../verification/use-inventory/config.json)保留所有已编译自有函数，不按猜测的可达性剪枝；其用途和仍待绑定的动态/取消路径见[依赖登记](dependencies.md#真实使用点的来源清单)。
- 固定源码、平台/features/cfg、工具、依赖配置和模型摘要。缺函数体、错误节点、未登记外部调用/析构、旧产物冒充新产物必须被拒绝。
- 每次真实重新生成，并核对完整 LLBC 与生成 Lean；只允许现有审计器明确允许的无序表规范化，不手改生成语义。
- 单模块入口和完整入口均执行实际编译、依赖审计和占位检查；明确“模型通过、真实核心通过、适配工程核对、当前保留集合通过”的差别。退役旧生成链不删当前模块的失败检查。

#### T1 身份、数值、字符和基本类型

- 完整字段、不同编号类型、非零域、机器整数上下界、秒/毫秒/字节单位和规范编号文本有公共表示及对应定理。
- 字符串明确按字节还是字符计数；UTF-8、ASCII 允许字符、空串、最大长度、前导符号/零及错误文本按真实入口处理，不做隐藏规范化或截断。
- 成功保留原值，非法值按原顺序拒绝，编号不回绕；合法可表示输入有接受结论，不能只证明拒绝安全。
- 公共 String/Option/Vec/整数模型按精确接口复用。调用模块负责自己的身份选择、授权和持久高水位，不能从字符串相等推出已获授权。

#### T2 JSON、标准派生和自有校验

- 按实际类型登记字段名、可选/默认、重复/缺失/未知字段、枚举及数字范围；说明哪些由固定引擎/标准派生提供，哪些是自有 visitor/TryFrom/校验。
- 实际自有字段转换、合法性和首个拒绝保持透明抽取；完整字段与原输入/解析状态/错误字典绑定，不能把整个自有解码器或“已经合法”当作外部结果。
- 非零计数器和八类编号叶子接线复用已有定理；完整字节入口、复合 schema、编码与往返另逐项验收。失败可消费输入/输出前缀，不假定两次有状态编码等价。
- 代表性完整协议输入须接通真实入口、大小限额、合法接受与异常/尾随输入的顺序。第三方扫描/转义算法不要求重证；其符合性条件必须显式登记。

#### T3 有限循环、容器和借用

- 有限表查询、首次替换/缺失插入、筛选、顺序/重复项、唯一性保持和其它字段不变有公共合同；终止和追加范围条件不能遗漏。
- 各实际循环体连接公共定理；自有比较/克隆/谓词由实际实例证明，不因 trait 名称相同就假定正确。
- 工具不支持的嵌套循环/借用可作保持行为的小重构；核对短路、首错、回调状态、回写和析构时机，重抽取真正被调用的新函数。
- 原版/重构版的对照只是有限证据；若只依赖审查/测试连接，结论必须注明该条件，不称一般性等价已证。

#### T4 动态接口、闭包和回调

- 列出实际 trait 实例/回调及完整输入输出；固定函数指向、次数、顺序、捕获状态和错误传播，禁止用无关的纯函数替代真实回调。
- 机械调用可登记 B4，授权/提交/恢复/释放等回调业务仍抽取证明；不把整个回调体放入可信层。
- 以具体值和实际实例预检签名；有状态 FnMut、None 不调用与捕获值仍可能析构等情况单列。两遍编码/调用不能直接假定结果相同。
- 至少接通一个真实后台回调和一个不同调用场景，说明复用条件与新增业务义务；隔离副本成果必须标明尚未进入生产路径。

#### T5 资源移动、共享状态与 Drop

- 定义原资源身份、谁持有、何时转交/克隆/归还、修改范围和计费；区分纯值内存析构与有业务效果的析构。
- 固定纯后端可以擦除的 Drop/DropGlue 按类型和位置准入；许可、FD、锁、子进程、未知标志等可观察效果不能被擦除后仍宣称已覆盖。
- Arc/Atomic 的多个读数不假定原子快照；复用 DataDrain 读体时，调用者提供原对象、禁止新增 pin、unknown 保持及释放依据。
- 正常 Drop、取消等待、panic/unwind、abort/崩溃分开；后台或外部资源可能继续存活。实际移动/析构接线按获批 B 条件核对，业务释放决定仍证明。

#### T6 后台任务、许可与取消

- 公共合同覆盖未领取、等待、已获额未 poll、已提交/运行、调用方取消、回调结果/JoinError、逐个许可归还；模型有合法执行，允许交错而非只证一条顺序轨迹。
- 普通单池及健康查询双池使用原池；所有执行中/已提交和已分配许可的责任计入额度，容量定理由初态和每步保持推出，不把容量正确写进假设。
- 真实 `HostLifecycle` 与 `status_admission` 按 B1 逐函数核对；提前释放、错误池等实际错误版本由同一资源性质拒绝。模型定理和真实适配的工程证据分别交付。
- 撤销接口说明已撤销/权限方关闭、等待期间撤销、成功与撤销同时就绪的顺序；取消 future 不等于 relay 退出，已发生效果不回滚。
- 下游直接复用任务/池/撤销合同，提供自己的回调定理、原输入/池/信号绑定和业务不变量。调度公平另列条件；自有启用、预算、出队和无环等待仍须证明。不以前置开发通用 async/Pin/Drop 翻译器验收本项。

#### T7 SQL、Lua、提交与未知

- 统一成功提交、观察到值、明确未开始、可能已提交但结果未知四类结果；冻结引擎版本/持久化配置和故障范围。
- 固定 Redis 脚本和 SQLite 事务选择一个代表性真实路径，接通实际文本、参数位置、列/返回码和 Rust 结果解释；不能假定“数据库可靠，所以自有事务正确”。
- 公共接口保留部分效果、未知、重放与恢复所需证据。Redis 脚本原子不等于报错回滚；SQLite 事务不包含 VM/网络副作用。
- V0 交付可复用结果/接口和最小连接方法；V2/V5 提供全部实际 SQL/Lua、缓存/outbox/提交确认/恢复定理。未完成代表路径或签名适配时仍是本项阻断，不能用计划表代替可行性。

本轮 SQLite 代表接法见[固定五参数 UPDATE](../../SandboxModel/Boundaries/SqliteStatements/Model.lean)及[接口限制](dependencies.md#a4a6b4-sqlite-条件-update-的固定五参数接口)。完整生成体和反例采用独立审计视图；公共根复用纯行模型，保留真实绑定失败、部分效果和完整事务/恢复的下游责任。

#### T8 宿主、TLS 和流式输入输出

- 对实际使用的 OS/Firecracker/TLS/I/O 接口登记原对象、前提、成功/错误/未知、部分效果和配置依据；稳定句柄不替代首次身份选择。
- 公共流合同覆盖原字节顺序、短写续传、待写/在途缓冲、半关闭和完整/失败/取消/未知；累计输出与驻留上限分开，EOF/HTTP 200 不自动表示业务完成。
- 代表性真实动作与流路径接入具体值/句柄边界并预检：机械传递按 B，策略/授权、对象选择、撤销/退出/清理判断由真实核心证明。
- 启动接受、就绪观察、终止接受、真实停止、清理、排空、释放分别提供证据；测试命令退出或信号发送成功不能互相替代这些事实。
- V6/V8 完成业务规则和全路径覆盖；V0 提供公共合同与接入方式，V9 组合共同不变量。底座验收不先要求全部物理隔离或全系统完成性已证。

### 底座完成后，下游还要做什么

下游复用已有类型、库模型、任务/流合同和验收脚本，补自己的状态表示、实际调用绑定、业务守卫、错误/未知及状态更新证明。依赖版本或用法超出已登记范围才回到对应 T 项扩展。每个未解条件都能找到提供方；“由系统保证”“稍后接线”不算底座交付完成。

## 精确条款

以下条款为本模块的规范定义；跨模块条款通过前提提供方连接，不将下游自有义务假定为已证。

### B2 身份和数值域

| 类型 | 含义与必要限制 |
|---|---|
| 租户、沙箱、工作区、虚拟机、网络资源编号 | 不同类型不混用；在同一持久部署命名空间内按各自规则分配 |
| 操作键 | 沙箱与操作编号的组合；同键绑定相同操作种类和完整参数 |
| 代次 `generation` | 区分同一沙箱的运行代；不是虚拟机编号的替代品 |
| 控制轮次 `epoch` | 撤销旧工作权限；与代次分开，销毁可以改变轮次而不产生新运行代 |
| 逻辑工作键 | 完整工作命令；包括命令种类和其全部身份、策略参数 |
| 尝试键 | 逻辑工作键与尝试编号的组合；不同尝试不能共用回执 |
| 宿主位置编号 | 节点命名空间内的可复用位置；复用不复用原实例身份 |
| 部署/节点身份与节点代际 | 持久身份；地址不是身份，节点重装不能认领旧资源 |
| 全局沙箱/操作与本地映射 | 中心持久分配，节点持久映射原本地实例/操作；计数器不混用 |
| 中心修订/意图版本/节点观察版本 | 分别约束提交、实例意图与事实次序，不代替本地 epoch/generation/attempt |
| 毫秒、秒、字节、资源数量 | 模型中用非负整数或明确的有符号整数；实现转换时另证范围和单位 |

令 `U64 = {n ∈ ℕ | n < 2^64}`。模型中的加一不能自动代替 Rust 的有界加一：必须证明未到上界，或明确拒绝分配。不得回绕。记录退休后保留必要高水位，不能把老请求当成第一次出现的新请求。

公共 `makeCounter` 是从任意自然数到合法机器计数器的构造器，成功恰当且仅当 `0 < n ≤ 2^64 - 1`，零和越界均拒绝；在实际 U64 输入域与原 Rust 构造含义一致。`nextCounter` 同时用于允许初始前沿为零的后继查询，不是编号字符串或协议解析器。它们都不能代替实际编码/解码及各构造/恢复入口对合法域的建立。

### H2 Rust 与 Lean 模型的对应

真实同步 Rust 核心经固定原 Charon 提取、Aeneas 翻译得到 Lean 中的实现语义；手写 Lean 模型描述允许的行为。二者不是因为都用 Lean 就自动相同。依赖机制与已登记机械适配使用 A/B 合同；证明对象、可信范围与真实调用绑定须分别标明，不宣称完整异步 Rust 已自动翻译。

定义表示关系 `R(r,m)`，其中 `r` 是翻译后的实现状态，`m` 是规约状态。它逐字段说明：有限整数怎样表示自然数、容器怎样表示逻辑映射、缺失值和错误怎样对应、完整尝试键怎样相等、哪些具体缓存由哪个提交派生。

最少需要以下定理：

```text
初始化：RealInit(r) ⇒ 存在 m，ModelInit(m) ∧ R(r,m)

成功：R(r,m) ∧ RunRust(r,input)=Success(out,r')
    ⇒ 存在 m'，ModelStep(m,input,out,m') ∧ R(r',m')

拒绝：R(r,m) ∧ RunRust(r,input)=Reject(e)
    ⇒ ModelReject(m,input,e)，并满足该入口的无副作用条件

完备：R(r,m) ∧ ModelAccepts(m,input)
    ⇒ 实现不会额外拒绝、溢出或在自己的有限处理逻辑中不终止
```

对纯核心可逐处理函数证明一步对应；对持久服务、网关和宿主执行，需要带事件的多步对应。锁获取、缓存查找等内部步可以在抽象模型中不改变业务状态，但不能允许实现永远只走这些步而仍宣称最终完成。

核心定理覆盖实际抽取函数，不覆盖被排除的异步外壳。锁/任务/许可移动、poll/drop 和 I/O 驱动的机械接线可按登记 B 信任；输入/结果、池/锁/句柄和具体回调与核心的绑定必须记录源码与证据。若绑定仅经审查和差分/故障测试，组合结论显式依赖其符合合同；不得把这些测试描述为适配的一般性精化证明。业务启用、出队、峰值预算与无环等待仍须证明，调度公平或外部最终返回不能替代它们。

崩溃也属于对应关系：删除易失内存后，由持久状态和真实宿主状态重建的结果仍符合规约。仅证明正常返回路径不够。

外部调用、异步任务和不支持的 Rust 结构需要受审计的窄接口模型或局部重构；模型可描述已批准 A/B，但不能手工重写一份更简单的 Lean 业务函数后跳过真实核心对应。翻译工具链版本固定，A/B 合同作为显式参数；不通过新增自定义公理、占位证明或关闭检查来取得通过。拒绝的无副作用结论须有对应分支证据；对外 Busy、JoinError、取消或超时不自动满足这一条件。

### H2.1 抽取能力与可信链

固定工具链主要支持安全、顺序 Rust 子集，抽取成功不自动覆盖 async/Tokio、锁、数据库/系统调用或终止。当前路线把可抽取业务决定与 A/B 机制接口分开，固定真实锁/事务/回调调用绑定，不以先开发通用 Future/Pin/Drop 翻译器为条件。不以手写简化 Lean 业务程序代替实际核心对应，也不把 SQL/Lua、提交恢复和撤销判断整体放进适配。

编译器前端、Charon/Aeneas 实际翻译器、Lean 内核、外部库模型分别登记信任角色，不称任意 Rust 全语言无条件无损。手写可计算标准库定义无公理，不等于已证明与真实库一致，需对应论证或显式模型前提。证明绑定源提交、目标平台、features/cfg、生产/抽取编译器、依赖、工具、生成入口和外部模型指纹；生成文件不手改，测试/指纹不替代翻译器正确性证明。

### H2.2 翻译障碍与工具变更责任

固定工具不支持某种程序结构时，先区分业务核心、外部依赖和已批准薄适配；对业务结构优先通过保持行为的小范围生产代码重构继续实际实现证明，不扩大业务拒绝范围，也不维护只供验证的替代业务实现。对 A/B 边界可提供验证接口模型，生产仍调用真实依赖；不支持类型仍穿过接口时改用具体值/句柄/结果再预检。新核心仍须满足原规约，对照测试不等于旧新程序已建立一般性等价证明。分类、共享修复、重构审查及验收按[证明工作流](../proof-workflow.md#翻译障碍的识别与处理)执行，具体诊断和进度放关联 issue。

修改提取或翻译工具时，必须单独说明新增规则的输入范围、状态/调用/错误与终止行为保持，以及实际工具实现如何对应规则。机器可检查保证应连接真实输入输出：可以证明实际转换实现，或用已证明正确的检查器验证每次转换；仅证明手写小模型、运行测试或编译生成物不能替代该连接。检查器的输入导入及证据对应也需审查，范围外结构应拒绝。该局部保证不自动覆盖 Rust 前端、其他转换步骤、库模型或最终编译器；仍需登记余下信任条件、冻结版本并重查受影响证明。

### I2 必须独立命名的判定函数

为确保规约能够落实到实际代码，至少建立以下可执行定义及相应的判定正确性定理：

| 定义 | 主要输入 | 输出 |
|---|---|---|
| `normalizeRequest` | 方法、认证上下文、原始字段 | 完整请求或精确拒绝 |
| `checkIdentityAndPlan` | 状态、原尝试、计划 | 身份与资源匹配结果 |
| `checkPublication` | 状态、回执、宿主证据、期限 | 运行或终止是否可发布 |
| `checkObservation` | 原登记、实际观察、保护条件 | 已存在、不存在、未知 |
| `checkRelease` | 原绑定、工作、连接、资源、引用 | 是否可安全释放 |
