## 2 调用模型

`ApiCall=(auth context, method, raw input, normalized input, call interval, authority view/operation identity, observed result)`；易失响应不成为新的权威状态。

鉴权→完整归一化→取得合法权威视图/原操作→耐久接受/节点确认→投影响应。读调用需要 `view` 属于本次 begin/end 间的合法提交；写调用按原操作提交与结果语义分层。不以收到HTTP头代表流成功，数据路径归 V8。

没有公开幂等键的重复 create 可是两个合法创建；内部 operation_id 的去重不能声称保护外部重试。命令/写文件故障后不自动重发有副作用请求。

## 3 拟定定理

| 定理 | 义务 |
|---|---|
| `normalize_preserves_meaning` | tenant只来自鉴权；实际方法的字段/默认/空值/单位/网络/环境/元数据完整保留；固定拒绝顺序 |
| `public_call_authorized` | 每次管理/数据路由资格对应原租户与实例；其他租户与未知的可观察错误满足合同 |
| `visible_page_refines` | 同一视图 Filter→Sort→After→Take；metadata全匹配，排序/反序/游标/limit边界、统计不泄漏 |
| `query_observation_order` | 成功query对应调用期间提交视图；已成功确认续期之后的查询不能返回更旧期限；不承诺跨页快照 |
| `lifecycle_reply_refines` | 公开创建/续期/销毁成功具有各自原耐久事实；错误/未知不伪装业务完成 |
| `public_route_exact_binding` | 令牌/固定登记路由属于原实例，中心不将客户端URL/PID/宿主路径当目标，不向下游泄漏API key |
| `api_acceptance_complete` | 满足全部固定合同前提的输入被实际入口接受，所有返回字段/错误映射对应模型 |

主要 S2/S9/S10/S12、F1/F2、DS5/DS6/DS8。鉴权单轨迹不能替代双执行保密；本模块提供可见投影引理给 V9 的保密定理。

## 4 分批与依赖

首批仅证明真实创建/销毁解析、鉴权、原结果与最小数据资格撤销，供跨层闭环。随后分别补：（1）get/list完整字段、排序/分页与视图；（2）connect/set_timeout与已确认续期顺序；（3）数据令牌/错误/私密日志可见投影。

复用现有HTTP/固定SDK样例，包括零/负期限、跨租户、空/极限页面、续期后查询；不把 E2B 整个平台或 SDK 实现纳入证明。解析引擎与标准 serde 派生按[依赖登记](dependencies.md#a6-json-与标准派生的最小合同)的 A6 合同使用，实际类型、属性和完整字段搬运以冻结版本、源码审查及差分样例绑定；未机器证明的符合性显式保留。自定义 visitor、`TryFrom`/`is_valid`、字段使用、大小/预算、归一化和授权仍是自有证明义务，不能只手写 normalize 或假设解码结果已合法授权。

依赖 V0、V1、V2 的权威提交/新鲜读取、V3/V5 的节点确认与时间、V8 的正文语义；A7/A9/A10。相邻结果条件由 V9 连接，不假定所有副本同时相等。开工/完成沿用 [V0](00-foundations.md#5-开工与完成条件)。

## 精确条款

以下条款为本模块的规范定义；跨模块条款通过前提提供方连接，不将下游自有义务假定为已证。

### C2 每个接口的输入合同

对方法 `m` 定义：

```text
Normalize_m(认证上下文, 原始请求)
    : 拒绝(错误类别) 或 完整语义请求
```

每个字段都必须在接口合同中指定：数据类型、缺失值、显式空值、零和负数、最大值、重复字段、非法编码、未知字段、单位与跨字段限制。不是一律严格拒绝，也不是一律忽略：应实现固定兼容合同规定的行为。

归一化正确性分三项：

1. 认证租户仅来自认证上下文；原始正文不能覆盖它。
2. 两个请求若归一化成同一值，必须在合同定义的意义下等价；不能把不同的命令、环境变量或网络规则压成同一请求。
3. 对字节载荷，除明确规定的协议编码外不裁剪、不补零、不转码；对数值，默认、拒绝和截顶分别证明，不能混为一种“规范化”。

例如，创建寿命超过上限时应拒绝，不得静默缩短；设置寿命则有约定的截顶语义。这些不是同一个算术函数。

从完整请求到外部参数还需要第二个对应关系。例如命令请求包括原实例、用户、工作目录、环境变量、命令内容、后台选项与期限；虚拟机启动描述包括原绑定、内核、私有磁盘、处理器、内存、网络和初始化参数。对允许的描述 `p`，应在登记的标准编解码及机械转发合同下证明 `DecodeExternal(EncodeExternal(p)) = p`，再证明调用目标属于 `p` 的原绑定。标准派生的字段搬运可由 A6 提供；自有字段选择、单位转换和调用对象不由它代证。只证明 JSON 格式合法，不足以排除内存单位错一千倍、工作目录遗漏、参数转义改变命令含义等错误。

### D2 列表不是另一份数据库

定义 `Visible(u,t,K,J)` 为调用者拥有、按合同可见且未到期的实例集合。每一页结果定义为：

```text
Page = Take(page_size,
         AfterCursor(cursor,
           Sort(order,
             Filter(query, Visible(u,t,K,J)))))
```

过滤先于排序和分页；默认按启动时间降序、同时间按外部编号升序，升序反转两个键。元数据各项同时精确匹配，时间边界按合同精度比较。运行总数在游标和页大小之前计算，不能泄漏其他租户数量。

游标是排序位置，不是授权凭据。它绑定方向和排序键；游标目标后来删除，不妨碍按键继续翻页。每次翻页重新检查当前归属和可见性，不承诺并发修改期间得到数据库快照。非法游标、越界页大小和不支持的筛选值按固定合同明确处理。

### D5 两端授权、全局查询和跨机时间

中心从认证上下文产生 tenant_id，依据权威绑定/意图/期限授予新资格，路由只来自受保护登记。节点实际派发再次核对本地映射、VM、许可、围栏和寿命。两端分别证明，不用中心曾经通过代替节点当前资格，也不每块数据运行全局控制转换。

全局 get/list 先在同一中心权威视图筛选，再排序/分页，不能拼各节点第一页。节点事实带身份和观察版本；需要当前确认而无法获得时返回约定未知/不可用，不把心跳/旧 Ready 当当前健康证明。

运行起点来自节点首次持久发布就绪，中心晚收不重算。续期意图与参数固定，节点持久应用后才公开确认成功；重放不反复从新的 now 增加时长。本机到期独立执行，失联不延长期限。

中心终止提交后不授予新的中心资格；节点收到并持久落实后撤销本地资格，围栏与排空另有事件。分区期间不承诺中心提交瞬间所有来宾停止。各机时钟误差/裕量为冻结部署前提，单位、溢出、重启和续期/到期竞争属自有义务，不假设时钟相同。

### D5.1 查询的可观察顺序

本条细化 S10/S12、F1/F2 与 G3 的查询合同，不新增公开 SDK 字段。

- 成功的管理查询须对应本次调用开始与结束之间某个合法的、已提交的中心权威视图；不能任意返回调用前的历史缓存。单次 list 从同一视图筛选/排序/分页，跨页仍不承诺快照。
- 若成功续期回复已经返回，之后才发起的查询不得返回该次续期之前的旧期限；允许更晚合法续期、到期或终止改变结果。并发调用按其合法提交/观察顺序解释，不能仅比较网络回复到达先后。
- 中心提交的意图版本与节点事实的身份/观察版本分别记录。旧事实不得覆盖较新的期限/终止决定；最近一次节点观察不是当前物理健康的证明。必须实时确认却无法确认时按固定错误合同返回未知/不可用。
- 证明自己维护的视图、缓存失效及结果投影与权威提交对应，不直接假定“所有副本一致”；仍不承诺分区下全球实时健康、跨机同一时钟或完整跨页快照。

最小正常轨迹：续期耐久落实并确认 → 发起详情查询 → 返回该续期或后续合法决定的期限。禁止轨迹：已经确认续期，随后另一入口从旧缓存返回原期限。工程冻结输入/错误及观察点；形式化证明所有允许交错，不只证明这一例。[E2B runtime #2217](https://github.com/e2b-dev/runtime/issues/2217) 提供多入口期限不一致的用户报告，不能据此认定其具体根因已证实。
