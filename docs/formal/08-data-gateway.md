# V8 生命周期访问、撤销与恢复授权

[文档目录](../README.md) · [验证总览](../formal-verification-design.md) · [模块合同](../module-contracts.md) · [依赖登记](dependencies.md) · [证明覆盖](../proof-coverage.md)

任务：[#640](https://github.com/VeriInfra-Lab/sandproof/issues/640)。状态：第一阶段实施与证明计划；代码定位基线 `56b14d64`。本页的性质是验收义务，已有结果按覆盖记录复用，不自动成为新生命周期的已证结论。

## 1. 收缩范围

对应 center/host 两端网关、[sandbox-data-transport](../../sandbox-data-transport/src/lib.rs) 和必要 guest 连接。保留已有后台持额、完整请求绑定、授权重查/撤销、锁和排空试点；只完成本阶段状态交接所需真实连接，不把全部 PTY/压缩/文件内容协议加入前置。

端点模型维护当前 `(owner,session,incarnation,permission,deadline,credential)`、开放/关闭门、已登记连接/工作及撤销代次。物理用户流、宿主 relay、guest 进程是不同对象；关闭 HTTP/vsock 不自动证明命令退出，也不应误杀应保留进程。

## 2. 三组合同

| 合同 | 提供的保证 | 仍需注意 |
|---|---|---|
| 当前访问 | 中心和宿主各自按当前身份/权限/寿命/阶段核对；重新派发必重查，不能缓存旧 permit 再用 | 上游已接受不代表下游此刻有权；旧历史结果不授予当前权限 |
| 暂停/终止撤销 | 关闭新准入、登记在途效果、撤销并排空影响捕获的工作后才准许 V6 截面 | 网络丢失允许撤销传播窗口；不假设中心决定与宿主门同时变化 |
| 恢复重授权 | 新运行代先保持数据门关闭、完成当前凭据/必要 guest hook，再开放；旧快照中的凭据无权访问新代 | 不承诺 TCP/vsock 连续；加载 RAM 可能恢复旧内存，需要实际双方接线而非只更新中心表 |

保持状态的见证至少包含一个明确 detached 的 guest 进程；断开输出订阅不能杀它。必须沿当前所选 envd 和 relay 的真实取消/持有路径核对，若现有语义不满足须在本模块实现/验证所需小改动，不能假设所有 Guest 代码正确。

## 3. 证明与验收

复用 V0 A/B 的机械任务/锁/传输合同，证明实际授权回调、原请求全文、permit 所有权、撤销后重派发、工作结束证据与阶段门。取消等待不释放 worker/FD/进程责任；panic/abort/manager crash 不等于正常 Drop。

关键判据：访问在门关闭前已进入可以仍有需排空责任；门有效关闭后新访问不可成功；恢复后仅新运行代凭据可用；freeze 前捕获相关写者全部结束。V4/V5 提供有效阶段，V6 提供真实 freeze/load/stop，V7 提供 owner 与完整输入。

测试和证明涵盖并发撤销/登记、旧凭据重放、dispatch 前授权变化、断线但后台进程存活、恢复后的新连接、写文件与 pause 竞争。正确版与绕过撤销/提前归还错误版使用同一性质。V8 负责 LC-I9、LC-P4/8/9 的数据面部分；不将全量来宾应用正确性或完整网络非干扰列作结论。
