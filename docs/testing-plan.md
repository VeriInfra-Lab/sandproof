# V1 验收清单

[文档目录](README.md) · [开发与测试规则](../CONTRIBUTING.md) · [产品范围](project-blueprint.md)

本文只定义验收场景，不重复分支规则、合并门槛或 CI 操作流程。S01–S13 在建立清单时均待实现，当前执行状态和证据随对应 issue/PR 维护；不能因清单存在就计为通过。

## 1. 模块测试重点

- A：所有者、阶段、同键改参、旧代数/尝试、重复回执、容量边界；寿命续期与到期竞争；事务提交前后进程退出。
- B：精确资源选择、路径越界、恶意输入、大输出、部分失败、重复停止与清理；真实宿主资源和隔离。
- C：固定客户端字段、默认值、错误映射、身份不可伪造、命令/文件网关权限及未支持功能拒绝；固定 `base` 的任务初始化与 Harbor 薄适配。

## 2. 系统场景

以下 ID 用于 issue/PR 的验收引用。

| ID | 场景 | 通过依据 | 主责 |
|---|---|---|---|
| S01 | 原客户端创建、连接、查询、销毁 | 同一实例；真实停止后才返回销毁完成 | C+A+B |
| S02 | 多次命令、后台进程、输出及非零退出 | PID/句柄、输出和退出码正确，后台任务不会被误重复派发 | B+C |
| S03 | 上传下载、修改系统文件、安装依赖 | 私有系统可写、共享基础镜像不变、宿主文件不被越界修改 | B+C |
| S04 | 两用户、两沙箱交叉访问 | 未授权管理、命令、文件和网络请求拒绝，资源不混绑 | A+C+B |
| S05 | connect、set_timeout 与到期 | 延长/缩短语义正确；旧定时任务不会销毁已续期实例 | A+C |
| S06 | create 与 kill、并发重复 kill | 不发布虚假成功；最终无运行残留，无误杀 | A+B |
| S07 | VM 启动后回执丢失、重复派发 | 恢复认出同一资源，不再启动第二台 VM | A+B |
| S08 | controller/worker 在关键窗口重启 | 提交前无外部动作；提交后能重放/对账；未知结果不丢失 | A+B |
| S09 | 旧资源清理迟到、标识被系统复用 | 只处理绑定身份，不影响其他或新资源 | B+A |
| S10 | 禁网、公网/静态规则与资源限制 | 实际探测不能绕过策略，不能访问宿主管理或其他沙箱 | B |
| S11 | 磁盘/配额不足、恶意大输出或文件 | 新请求合理拒绝，收尾仍有空间，宿主与其他沙箱不受污染 | A+B |
| S12 | 客户端超时及命令通道断开 | 状态未知可观察，不自动重复执行有副作用命令 | B+C+A |
| S13 | 固定 `base` 创建、逐任务初始化、执行、评分与清理 | 预检后使用新沙箱，初始化不泄露答案或扩大权限；失败不留下可执行残留；报告为 Harbor 经适配运行 | B+C |

部分失败测试包括：磁盘已创建但 VM 未启动、网络部分配置、VM 已启动但回执未落盘、停止已生效但记录未提交。程序退出后还要从宿主检查进程/cgroup、TAP/网络空间、磁盘目录和端口，不只读服务自己的“成功”字段。

S10 还须让来宾 root 改写解析配置，探测未授权的 UDP/TCP 53、IPv6 与其他 DNS 出站路径。若将来启用受控解析器，须用随机子域名、TXT/NS、委托链和携带数据的查询证明不会经解析器访问未授权外部服务；只固定解析器 IP 不算通过。

`controller-service/tests/v1_workflow.rs` 已用确定性回执测试无部分副作用的明确失败：可重试时分配下一尝试；不可重试时撤销、停止、发布失败；补偿停止回执丢失时重启后先观察再完成。真实节点尚不能把任意 I/O 错误证明为无部分副作用，所以这些测试不覆盖部分网络创建、启动进程中断或恶意来宾流量。

销毁完成不等于任意存储介质的物理擦除。测试判断资源不可执行、不可被未授权访问，并按约定回收；不声称证明安全擦盘。


## 3. 兼容与 Terminal-Bench 验收

固定版本的 SDK 调用清单位于[兼容合同](../tests/compat/contract.json)。`bash scripts/check-compat.sh` 使用 E2B Python SDK 2.51.0 和本机回环合成响应；[实机系统测试](../tests/system/sdk_server_smoke.py)则使用同版原 SDK，经真实控制器和网关驱动 Firecracker，覆盖显式禁网的创建、连接、查询、列表、续期、销毁，以及基本命令、文件、超时、终止、断线重连、1 MiB 输出、跨租户与旧令牌、非法文件路径、重复令牌、超限上传拒绝和到期清理。隔离 Linux/KVM 测试已通过，但只覆盖 S01–S05、S11–S12 的部分路径。

网关超限与断流回归按以下证据边界记录，不能合并算作实机通过：

- [网关组件测试](../sandbox-server/src/gateway/tests.rs)：在 Linux 上执行 `cargo test -p sandproof-server --locked`。通过实际网关的请求处理、响应限流及 HTTP 编码，覆盖 8 MiB 文件请求、1 MiB 命令输入、32 MiB 响应边界；区分已知长度、分块传输和上游 HTTP/1.0 未声明长度，检查中途 EOF、逐块传输、不重发及失败后的新请求，以及非 HTTP/1.1 请求在读取 body 前被拒绝。使用内存传输替换 envd，不覆盖鉴权、进程执行或 VM 隔离。响应上限计算 HTTP body 字节，包含 Connect 编码，不能直接等同于原始 stdout 大小。
- SDK 合同测试：`bash scripts/check-compat.sh` 另覆盖 Connect 帧被截断和文件长度不足。已取得命令 PID 后，缺少完整结束事件仍报错，不自动重发 Start；文件下载不返回成功的部分内容。测试使用固定 SDK、现有 `retries=0` 配置与合成服务。
- SDK/网关组合测试：同一脚本在 Linux 上还启用 `sdk-contract-tests`，让[原 SDK 调用集](../tests/compat/gateway_sdk.py)经过[实际 Rust 网关的请求分类、请求体处理和 HTTP 转发代码](../sandbox-server/src/gateway/sdk_tests.rs)。除了复用 SDK 的命令、后台句柄、退出码、文件和目录用例，还验证上传 8 MiB 和下载 32 MiB 的前一字节/恰好/多一字节边界、大命令输出、管理 API key 不被转发、失败后继续使用。上游是合成 envd，下游是真实 SDK；不覆盖 `handle` 的鉴权、命名空间 relay 或 VM。夹具只编入测试二进制，正式服务没有旁路启动模式。非 Linux 会明确报告组合测试未运行，不能用 SDK 单层通过代替。
- 显式流式配置另运行同一 SDK 调用集：使用仅供测试的 64 MiB 上传、96 MiB 下载预算，分别覆盖已知/未知长度的空文件、少一字节/恰好/多一字节；验证 415 压缩拒绝、identity 协商、并发 429 后仍可 health、输入 408 和下载中途空闲失败、失败后正常请求。使用明确的事件屏障保持在途请求，不靠随机 sleep。组件测试另用暂停时钟验证写阻塞超时与安静命令的区别，并以生产者等待上游收到第一块的屏障证明上传不整包缓冲。组合测试记录 Rust 网关进程 RSS 高水位（不包含 Python 合成 envd）；这是观测证据，不是整个部署的内存上界或实机磁盘证据。上传/响应体与上游连接均结束后才释放并发名额，夹具退出时等待连接任务收尾。
- 固定 SDK 的同步路径会把部分 Connect 流的 HTTP EOF 包装成 `TimeoutException`。组合测试与实机脚本共用错误分类，同步路径只有底层 `ConnectError(UNAVAILABLE)` 的原因确为传输读错误时才将它视为断流；普通期限超时、鉴权失败和测试异常不能算作限流通过。异步后台等待可能丢失原因链，检查仅接受实测的两条精确 EOF 文本（分块长度行处或未达到声明长度），并拒绝附带普通期限原因的异常。这个 SDK 错误映射差异不表示沙箱已到期，失败后仍须另行验证可用性。流式配置的已知长度超限另以只发送请求头的 HTTP 调用核验 413；原 SDK 大体写入与服务端提前关闭竞争时也可能先观察到具体的 EPIPE 写错误，仍须核对 envd 未收到请求、无完整成功且后续调用可用。
- [独立实机脚本](../tests/system/gateway_stream_limits.py)：在原系统测试相同的隔离服务环境，沿用 `retries=0` 配置，使用 `SANDPROOF_TEST_API_KEY` 和显式 `--api-url`、`--sandbox-url` 运行。它创建自己的禁网沙箱，检查 32 MiB 前一字节/恰好/多一字节的文件下载、超大命令输出和主动断线后同 PID 重连；用 FIFO 同步断线时机，用来宾标记核对副作用只观察到一次，每次失败后验证沙箱仍可执行命令，最后销毁本轮沙箱。启动需允许 300 秒寿命，来宾须有现有探针使用的 shell/coreutils。该脚本已在固定新 base 上执行选定 KVM 场景；证据绑定见[版本基线](../references/v1-baseline.json)，不代替完整 S11/S12。

实机脚本运行示例（在已配置服务的测试机上执行，API key 由环境提供）：

```sh
uv run --locked --project tests/compat python tests/system/gateway_stream_limits.py \
  --api-url http://127.0.0.1:3000 --sandbox-url http://127.0.0.1:3000
```

验收显式 `data_transfer` 配置时，在同一命令追加 `--file-upload-bytes`、`--file-download-bytes`、`--command-output-bytes`，值须与待测服务配置一致；不能把测试夹具值当作已测定的部署值。新增上传场景通过原 SDK 发送可定位文件和不可定位流，覆盖零/上限前/上限/超限；成功后核对来宾文件信息和 SHA-256，下载同样校验内容。已知长度拒绝不得创建文件，分块拒绝允许部分写入且不重传。脚本按本轮路径删除测试文件并销毁自己的沙箱；仍需宿主侧独立观察进程、网络空间、cgroup、磁盘残留，以及磁盘满、断线、到期和 kill 竞争。扩展脚本已在真实 KVM 使用 64 MiB 上传、96 MiB 下载测试预算通过上述边界和内容检查；宿主独立观察确认本轮精确进程停止，网络空间、cgroup 和私有 jail 无残留，基础盘指纹不变。服务进程本轮 RSS 高水位约 15.4 MiB；这不包含所有 relay/来宾资源，也不是总内存上界或最终部署预算。

[异步流式实机脚本](../tests/system/gateway_async_stream_limits.py)使用原 `AsyncSandbox` 完成 create/kill，以显式参数匹配部署的上传、下载和命令输出预算。上传分别用可定位文件与不可定位流覆盖零/上限前/上限/超限，下载逐块核验字节与 SHA-256；每次拒绝后用同一 VM 验证后续调用。固定异步 SDK 对两种 IO 源都发送分块请求，因此超限都允许留下部分文件，不能沿用同步已知长度拒绝的“文件未创建”断言。命令输出先用较小输出核对完整成功，再通过回调计数检查截流。固定 SDK 的异步后台任务会丢失异常链，只对此版本实测的完整 chunk EOF 文本接受 `TimeoutException`；普通超时、相似文本、鉴权错误或带期限原因的异常仍拒绝，组合测试复现这条路径并验证没有重发 Start。FIFO 和输出事件共同确定断线时刻，重连仍使用原 PID 并检查副作用标记只有一次。

```sh
uv run --locked --project tests/compat python tests/system/gateway_async_stream_limits.py \
  --api-url http://127.0.0.1:3000 --sandbox-url http://127.0.0.1:3000 \
  --file-upload-bytes 67108864 --file-download-bytes 100663296 \
  --command-output-bytes 33554432
```

这组参数沿用 64/96/32 MiB 测试配置，不是最终部署值。该异步脚本已在真实 KVM 完成上述边界、较小输出成功对照、截流与重连，独立宿主审计确认精确进程、cgroup、网络空间和私有盘回收，基础盘指纹不变；提交与证据见[版本基线](../references/v1-baseline.json)。不能据此推断并发、慢流、到期或授权撤销竞争全部通过。

同步与异步的数据调用合同复用同一合成 envd 和真实 Rust 网关：检查 cwd、含空格/Unicode 的命令 envs、user 的鉴权头、stdout/stderr、非零退出；后台连接和终止只发送已有 PID，不重发 Start；Stat、递归 ListDir 请求和批量上传保留路径及字节。批量收到合成 507 时抛出 `NotEnoughSpaceException`，已发起的上传不重发；同步 octet-stream 逐项发送，第二项失败后不发送第三项，而异步 SDK 并发发送，其他项可能仍在写入。用屏障确保并发请求均已到达再返回故障，不承诺批量回滚。这组组合测试验证错误传播；真实 ENOSPC 由下面的独立来宾磁盘探针验收。异步 SDK 的文件流使用分块传输，另经流式配置覆盖大文件边界和失败恢复；不能只以同步 SDK 的已知长度结果推断异步行为。

[来宾磁盘满探针](../tests/system/sdk_disk_full.py)在原 SDK 创建的独占沙箱内，用有容量上界的 `posix_fallocate` 实际触发根盘 ENOSPC；不填宿主文件系统。同步与异步调用分别检查文本 multipart、可定位文件和不可定位流都收到 `NotEnoughSpaceException`，同时让第二台 VM 持续核验命令与读写。释放本轮填充文件后，同一 VM 必须能恢复写入；再次触发 ENOSPC 后直接销毁，并创建新 VM 验证初始目录干净、写入正常。脚本保留内核 errno、实际分配与剩余块数，不把文件系统保留块当成可写容量；失败也按已知沙箱 ID 清理。宿主空间耗尽、日志/数据库收尾预留和 inode 耗尽另行测试，不能用来宾块 ENOSPC 代替。

```sh
uv run --locked --project tests/compat python tests/system/sdk_disk_full.py \
  --api-url http://127.0.0.1:3000 --sandbox-url http://127.0.0.1:3000
```

服务须允许同租户同时创建两台 VM、300 秒寿命；来宾需有 Python 3、`posix_fallocate` 和现有 shell 工具。`--max-guest-disk-bytes` 默认 2 GiB 是探针拒绝意外大盘的上界，不是部署磁盘配额；测试仍使用已预检的固定私有 base。该脚本已在启用宿主 cgroup 限制的真实 KVM 服务通过，六台 VM 的精确进程/cgroup/网络空间/私有盘回收与基础盘指纹另经宿主审计；提交和配置见[版本基线](../references/v1-baseline.json)。

[命令输入探针](../tests/system/sdk_command_input.py)使用原同步/异步 SDK，分别以 root 和 ubuntu 验证省略 stdin、显式 false、启用后空输入关闭，以及文本/二进制输入后断线并按同一 PID 重连。启用路径检查 EOF 后的完整长度和 SHA-256、单次启动标记及后续可用性；不把重连当成重新执行命令。运行方式与其他实机脚本相同，显式提供 `--api-url`、`--sandbox-url` 及环境中的测试凭据；该探针已在固定 base 的真实控制器/网关/VM 链完成十六个场景，精确提交与残留检查见[版本基线](../references/v1-baseline.json)；命令输入预算与完整超时参数矩阵另行验收。

[并发与慢流探针](../tests/system/gateway_pressure.py)使用两个租户的真实 VM，原同步/异步 SDK 以已输出就绪标记、等待 stdin 的命令固定在途请求，分别检查每实例与全局 429，以及 health、SendInput、CloseStdin、SendSignal 的预留名额；失败调用不能留下文件或重复启动。原始 HTTP 客户端精确控制上传进度，另验停顿 408 与持续慢上传的完整内容；下载由原 SDK 暂停读取后观察反压断流和名额释放，必须收到实际的传输异常；另以无写入方的来宾 FIFO 阻塞文件响应头，验证 504 及安静命令仍存活，最后唤醒并移除本次 FIFO。普通超时不能算通过。该脚本要求独立服务配置全局/每实例/控制预留为 `4/3/1`，请求/文件/写入空闲为 `3/5/3` 秒，文件上传/下载预算为 `64/96 MiB`，并提供两个租户的测试凭据。这些是探针配置，最终部署预算仍依赖固定任务。该脚本已在固定 base 上完成同步/异步的上述场景；四台 VM 的宿主身份、实际 cgroup 限制和服务退出前的精确回收另经核验，基础盘未变，提交与指纹见[版本基线](../references/v1-baseline.json)。仍不能据此认定所有并发交错、SDK 超时参数和宿主盘耗尽路径通过。

[传输中断探针](../tests/system/transfer_interruption.py)分别对同步/异步 SDK 的上传、下载执行 kill 与到期场景。上传用有界生产者屏障暂停在前缀之后，并通过来宾文件信息确认实际写入；下载先收到有效内容再触发中断。另一个持续命令连接用于观察在途访问撤销；物理 VM 停止和清理由宿主另外核验，不能只根据查询列表消失或中继断开就认定到期销毁完成。旧令牌的 health、文件读写与 Start 新请求须被拒绝，独立控制 VM 始终能执行和读写。SDK 或传输的普通超时不能代替中断成功，最后仍需宿主精确残留审计。该脚本已在固定 base 上通过八个真实场景；同一提交也通过旧配置的生命周期和同步/异步数据调用回归。宿主在服务退出前核对精确进程、盘、cgroup 和网络空间持有者，基础盘未变；精确版本见[版本基线](../references/v1-baseline.json)。完整超时参数、并发慢流与重启竞争仍未由此覆盖。

```sh
uv run --locked --project tests/compat python tests/system/transfer_interruption.py \
  --api-url http://127.0.0.1:3000 --sandbox-url http://127.0.0.1:3000
```

该探针要求显式流式配置至少支持 2 MiB 上传和 64 MiB 下载；请求、文件与写入空闲预算均至少 30 秒，避免与 2 秒到期场景混淆。每租户同时保留两台 VM；来宾需有现有 shell/coreutils。测试使用屏障和有界状态轮询，失败只销毁本轮已知实例，不把手动 kill 的结果写成自动到期通过。

[完整服务数据脚本](../tests/system/sdk_data_contract.py)通过原 SDK 的 create/connect/kill 创建自己的沙箱，分别以 root 和固定 base 的普通用户运行同步/异步调用。它上传包含文本、二进制和空文件的多层目录，检查返回路径、文件信息、递归列表、普通/流式下载及 SHA-256；用 FIFO 和异步输出回调同步断线时机，确认重连同一 PID、只写一次标记，并验证终止、后续调用和销毁后的旧令牌拒绝。它没有绕过管理链直接构造来宾客户端；已用 root/ubuntu 在真实 KVM 的默认与显式流式配置执行，并覆盖省略 cwd 使用所选用户 home、显式 cwd 优先。时间参数的省略/零/负值/超限、销毁期间的授权竞争和宿主残留仍需独立用例。

```sh
uv run --locked --project tests/compat python tests/system/sdk_data_contract.py \
  --api-url http://127.0.0.1:3000 --sandbox-url http://127.0.0.1:3000 \
  --unprivileged-user ubuntu
```

[宿主故障测试](../sandbox-node/tests/host_smoke.rs)覆盖 VM 启动或停止后回执丢失，以及独立工作进程恰在真实启停成功、回执提交前退出或被 SIGKILL 杀死。新增测试覆盖首个槽位未写入、网络空间已创建但 inode 记录未提交，以及真实 VM 已停止、私有资源已清理但清理回执尚未提交。重开数据库后只对精确身份做观察或幂等清理，不重复启停；错误 owner 被拒绝，结果未明时 create×kill 被拒绝，迟到的同一回执不改变运行或销毁终局。运行中 VM 的启动盘点核对网络空间 inode 与完整禁网规则；实机测试添加额外限制规则后盘点拒绝，原子恢复规则后仍可正常销毁。[运行层故障注入](../sandbox-runtime/src/linux.rs)验证了未放行门控不能启动子进程、网络空间已创建但 inode 记录未提交、准备回执不确定而精确进程已停止、编号不可复用，以及禁网规则被篡改时不能取得成功观察。[来宾探针](../tests/system/guest_smoke.py)让 root 改写解析器，测试 UDP/TCP DNS、853 和 443 端口及 IPv6 出站被拒绝，同时管理通道可用。 独立运行命令见[运行层 B01 验收入口](../sandbox-runtime/README.md#独立复现-b01-节点验收)。双 VM 重复停止/清理用例在每次重复动作及重建 worker 后，核对另一台的精确进程与资源 inode、真实 envd 鉴权读取，最后独立检查两台残留。此用例与六个既有节点故障用例的同提交实测记录见[版本基线](../references/v1-baseline.json)的 `runtime_b01_acceptance`；基础 CI 的忽略项不计入实机结果。

#10 的隔离 Linux 测试覆盖固定 SDK 网络字段解析、IPv4 网段归一化及规则优先级，并让模拟来宾的数据包穿过真实宿主 veth、INPUT/FORWARD 和 NAT 到达测试专用外部网络空间。它核验准许目标可收到回包、未列目标和宿主本机地址受阻；准备记录已写而闸门未打开时仍禁网，恢复后才放行；意图已写而只安装部分链接时能够精确撤销并留下失败标记。[完整服务网络脚本](../tests/system/sdk_public_network.py)另用固定 E2B SDK 2.51.0 同时创建两台真实 Firecracker：静态允许目标可通、未列目标不可通；省略联网参数允许测试目标但不可访问宿主本机或另一 VM 链路。重启服务后确认原 PID/启动时刻及两套策略不变；销毁一台不影响另一台，最终按本轮身份核对进程、私有 jail、网络空间、根链路及规则均消失。测试使用新建镜像和隔离“外部”网络空间，临时开启宿主 IPv4 转发并在退出后恢复；不经过真实互联网，也尚未覆盖动态宿主地址变化、DNS/IPv6 探测、任意位置重启或全套 S10。

来宾探针现在还临时创建完全隔离的“外部”网络空间：先验证同一沙箱宿主网络空间通过临时链路确能连接测试端点，再开启该沙箱网络空间内的 IPv4 转发、核对来自 TAP 的路由，并让来宾 root 发起相同连接。只有宿主路径可通、来宾仍被禁网规则阻断才通过，避免把没有出口的测试环境误当成防火墙有效。探针结束后恢复该网络空间的转发值并删除临时链路和外部空间；不改宿主全局转发，不代表公网或静态规则已经实现。

[服务恢复测试](../sandbox-api/tests/managed_port.rs)覆盖停止成功但回执未知、准备阶段只有部分资源、IPv4 配置回执丢失、补偿终止围栏回执丢失，以及销毁或失败补偿中清理只完成一部分。重开数据库后的扫描器先匹配当前操作编号、owner、时期和持久资源计划，再要求宿主给出精确结果；重复恢复与迟到的相同回执保持终局不变。这是合成宿主证据测试，不能替代真实服务进程的任意位置强制终止测试。

[常驻服务故障测试](../tests/system/server_process_crash.py)在独立 Linux/KVM 测试机上使用仅调试构建可用的注入点：真实 VM 启动、停止成功之后，服务进程在对应回执写入前直接退出。测试重启同一服务和数据库，核对运行态仍是原 VM 的 PID 与启动时刻、最终销毁后进程、网络空间和私有 jail 均不存在；实测通过。该测试只覆盖这两个确定窗口和一台 VM，不替代任意指令位置的 SIGKILL、并发负载或公网/静态规则验收。运行时须指定独占 UID 范围、可信 Firecracker/jailer、内核、envd 磁盘及 root 独占的临时目录；失败保留精确现场，不能按名称猜测清理其他资源。

这些只是 S07–S10 的部分路径，尚缺公网/静态模式的 DNS/IPv6 与更复杂并发探测、其他位置的 SIGKILL、其他部分副作用下常驻服务跨崩溃自动收尾和旧资源冒名等系统级实验。非空环境变量、元数据、固定 `base` 的任务初始化及完整重启恢复也未验收，不能把 S01–S13 整体标为通过。命令流缺少结束回执时，SDK 抛出异常且本次请求不自动重发；服务端仍须把已开始的命令结果视为未知，不能凭异常断定命令未执行。

- 固定 Harbor、数据集、任务 ID 清单和内容哈希、环境镜像、资源、网络策略、智能体、模型及参数。任务在跑之前按能力选定；不能遇到失败才删除题目。
- 首先用任务提供的标准解答检查环境和评分链，再用同一智能体对比。E2B 自身不支持的任务与我们尚未支持的任务分别记录。
- 固定 E2B SDK 的支持项仍须单独按原调用测试；Harbor 采用薄适配层后，应报告“Harbor 经适配运行”，不能计作原模板链兼容通过。对照 E2B 时固定同一任务输入、标准解答和评分口径，并记录两端环境准备的差异。
- 报告环境构建/启动/执行/传输/清理错误、任务解题结果、耗时和资源残留。不要要求随机模型两次逐字输出或解题率完全一致，也不要把解题失败直接判为控制器 bug。
- 未实现域名策略、动态网络切换、额外服务等能力时，任务预检查须拒绝，不得静默扩大网络权限。若最终要求全量数据集，必须先扩展并验收这些能力。
- 在线 E2B 和模型评测需要单独的凭据、资源和费用预算，不加入普通 PR 的默认检查。

暂停恢复和安全竞争用 S 类专门测试扩展，不能用 Terminal-Bench 通过代替。形式化阶段再证明声明范围内任意历史的性质；V1 测试报告只记录实验结果。

宿主资源验收使用[运行层的显式 cgroup 配置](../sandbox-runtime/README.md)，区分来宾 RAM、VMM 宿主上限与服务/relay 总预算。必须先实测限额被读回、进程属于精确分组，再用受控竞争证明 CPU 被节流、内存超限只终止该组工作负载；空组、含任务组、限额篡改、inode 替代、配置变更、创建记录中断与重复清理分别检查。随后在同配置运行真实 VM/SDK 和启动/停止/清理回执丢失用例，独立观察进程、cgroup、网络空间和私有盘；单独内核探针通过不等于真实 VM 或整个宿主容量已验收。

显式配置下，节点实机回归还须核对运行进程的 cgroup 归属与 inode，临时收紧 CPU 限额后盘点必须拒绝。首个槽位缺失时，未绑定的同名 cgroup 必须阻止失败收尾；清理回执丢失后新建的同名替代组必须让观察与再次清理拒绝，且替代组保持存在。测试只移除自己创建的空组后再继续恢复，不凭控制器终态判断物理资源已消失。已运行的选定用例及资源指纹见[版本基线](../references/v1-baseline.json)，不表示真实磁盘满、完整 SDK 故障矩阵或 #13 任务预算已验收。

固定 base 制备按[运行层配方](../sandbox-runtime/README.md)和[输入清单](../tests/system/base-inputs.json)记录源码、工具链、二进制和镜像指纹。接受新 profile 前须验证错误指纹/已有输出/路径逃逸被拒绝，检查安装内容、登录配置与文件系统，再以新镜像运行两 VM 私有根盘、原 SDK、停止及残留场景；组装成功不能代替 S03、S10、S11 或 #13 任务初始化。历史 CI 镜像的结果不能直接背书新 profile。

## 4. 独立运行宿主预检

[宿主预检工具](../tools/check_kvm_host.py)是 C04 / #14 的独立基础模块，使用 Python 3.11+ 标准库，不依赖公共 API 或控制服务启动。它检查当前身份、Linux x86_64、KVM API、TUN、cgroup v2、宿主工具、可信路径、Firecracker/jailer 版本、四项产物 SHA-256，以及磁盘和内存余量；检查失败仍收集其余结果。

从[配置示例](../tests/system/host.example.json)复制一份到被忽略的 `artifacts/`，按已复核的测试环境填写绝对路径、四个指纹和资源最低余量。示例中的指纹占位符会被拒绝，磁盘/内存数值只是例子，须按本轮 VM 数量、磁盘副本、日志及收尾需求确定。指纹应来自已确认的发布产物或镜像构建记录；不要在不匹配时直接覆盖基线。

在**待测主机**的干净、精确提交上，用运行 jailer 的同一 root 身份执行（先确认该提交及配置适合在该主机运行）：

```sh
mkdir -p artifacts
cp tests/system/host.example.json artifacts/host.json
# 编辑 artifacts/host.json，填入已复核的基线。
sudo python3 tools/check_kvm_host.py --config artifacts/host.json > artifacts/host-preflight.json
```

标准输出始终用于 JSON 报告。有效配置下，报告包含提交、工作区是否有未提交变更、配置摘要、宿主内核、观察指纹和各项检查；有未提交变更时预检失败，不能以 HEAD 代替未提交代码的版本证据。退出码 `0` 仅表示全部前置检查通过，`1` 表示检查失败或不完整，`2` 表示配置错误。每项状态区分 `pass`、`fail`、`unavailable`、`timeout`、`not_run`；二进制未通过可信路径及指纹检查时，不执行它的 `--version`。不要用 `|| true` 或未检查的管道掩盖退出码。

工具只读取环境并执行已核对二进制的版本查询，不创建 VM/TAP/网络空间、不配置资源、不清理残留，也不输出环境变量或凭据。报告中的资源余量是当时快照，不是容量预留；通过不保证 cgroup 创建、网络隔离、来宾启动或 S01–S13 已验收。预检后仍须按本轮身份分配独占资源并运行真实系统测试。该工具尚未接入高权限 KVM CI。
