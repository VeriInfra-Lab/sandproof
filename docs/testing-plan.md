# V1 自动化测试与验收

当前状态：功能检查脚本和 GitHub Actions 已接通，现有 Rust 控制核心有 78 项测试。旧小沙箱原型及其 16 项测试已随模块移除，不再计入当前测试数量；这不是新运行层验收通过。下面的协议、组件、KVM 系统测试及评测用例仍是待实现计划。远端 CI 结果按具体 PR/提交查看，分支保护以仓库设置为准。

## 1. 测试分层与责任

| 层次 | 环境、入口 | 主要内容 | 谁写、何时运行 |
|---|---|---|---|
| 单元 | 无 KVM；当前 `bash scripts/check-function.sh` | 决策、鉴权、身份、容量、重试、TTL、路径及协议边界 | 每位模块开发者；每个 PR |
| 模块合同 | 无 KVM；计划 `tests/contracts/` | A/B/C 共用输入输出样例；接受/拒绝、未知结果、错误映射 | 两端负责人共同维护；接口相关 PR |
| 组件集成 | Linux，无 KVM；计划 `tests/integration/` | 真实事务库 + 假执行器、真实 HTTP + 测试控制服务、进程重启 | A/B/C 各自负责；相关 PR |
| 真实系统 | 专用 Linux/KVM；计划 `tests/system/` | 真实 VM、SDK、命令/文件、网络、恢复及隔离 | C 维护框架，A/B 写对应场景；合并前关键路径与里程碑 |
| E2B 对照 | 固定客户端和配置；计划 `tests/compat/` | 同一组调用对我们的服务和 E2B 记录语义差异 | C，A/B 复核；兼容变更和版本升级 |
| Terminal-Bench | 固定 Harbor、任务、镜像、模型；计划 `benchmarks/` | 标准解答先验证环境，再进行智能体对比 | C 组织；M3 和有必要的性能回归 |
| 现有证明验收 | 固定证明工具链；`scripts/verify-controller.sh` | 当前 Rust 抽取、Lean、依赖审计 | 证明变更及集中证明阶段；不是新增 V1 功能的逐 PR 前置门槛 |

`check-function.sh` 不启动 VM、不访问 E2B、不跑付费模型、不宣称验证安全证明。它检查现有 workspace 的格式、静态检查和测试，使用 `--locked` 固定依赖。测试输出含执行数量；系统测试没有接入时不能用一个空目录或全部 skip 的绿色 job 替代。

## 2. 单元与组件测试设计

- A：所有者错误、错误阶段、同键改参、旧代数/旧尝试、重复回执、容量临界值、整数耗尽；使用伪时钟验证续期和到期竞争。事务库用独立临时目录，验证提交前后进程终止与持久结果。
- B：精确资源选择、路径越界、恶意帧、输出大小限制、部分操作失败、重复停止和清理。Linux 专用路径必须在 Linux 运行，macOS 通过不代替它们。
- C：客户端字段和默认值、错误映射、身份不可伪造、命令和文件网关权限、未实现功能拒绝；覆盖选定 SDK 实际会调用的模板路径。

假执行器允许手动推进成功、明确失败、结果未知、迟到和重复回执。不要靠随机 sleep 控制顺序；并发测试用屏障/明确故障点，超时仅用于防止挂死。随机交错保存 seed 和最小失败历史。没有问题的机械实现不要求逐行镜像测试，优先覆盖合同边界和真实失败原因。

## 3. V1 必须通过的系统用例

以下 ID 用于 issue/PR 验收引用，初始状态全部为待实现。

| ID | 场景 | 通过依据 | 主责 |
|---|---|---|---|
| S01 | 原客户端创建、连接、查询、销毁 | 同一实例；真实停止后才返回销毁完成 | C+A+B |
| S02 | 多次命令、后台进程、输出及非零退出 | PID/句柄、输出和退出码正确，后台任务不会被误重复派发 | B+C |
| S03 | 上传下载、修改系统文件、安装依赖 | 私有系统可写、共享基础镜像不变、宿主文件不被越界修改 | B+C |
| S04 | 两用户、两沙箱交叉访问 | 未授权管理、命令、文件和网络请求拒绝，资源不混绑 | A+C+B |
| S05 | connect、set_timeout 与到期 | 延长/缩短语义正确；旧定时任务不会销毁已续期实例 | A+C |
| S06 | create 与 kill、并发重复 kill | 不发布虚假成功；最终无运行残留，无误杀 | A+B |
| S07 | VM 启动后回执丢失、重复派发 | 恢复认出同一资源，不再启动第二台 VM | A+B |
| S08 | controller/worker 在关键窗口重启 | 提交前无外部动作；提交后能重放/对账；未知结果不丢失 | A+B |
| S09 | 旧资源清理迟到、标识被系统复用 | 只处理绑定身份，不影响其他或新资源 | B+A |
| S10 | 禁网、公网/静态规则与资源限制 | 实际探测不能绕过策略，不能访问宿主管理或其他沙箱 | B |
| S11 | 磁盘/配额不足、恶意大输出或文件 | 新请求合理拒绝，收尾仍有空间，宿主与其他沙箱不受污染 | A+B |
| S12 | 客户端超时及命令通道断开 | 状态未知可观察，不自动重复执行有副作用命令 | B+C+A |
| S13 | 模板制备、查询、创建、失败清理 | 原 SDK/Harbor 所用模板链可运行，失败不留下可执行残留 | B+C |

部分失败测试包括：磁盘已创建但 VM 未启动、网络部分配置、VM 已启动但回执未落盘、停止已生效但记录未提交。程序退出后还要从宿主检查进程/cgroup、TAP/网络空间、磁盘目录和端口，不只读服务自己的“成功”字段。

销毁完成不等于任意存储介质的物理擦除。测试判断资源不可执行、不可被未授权访问，并按约定回收；不声称证明安全擦盘。

## 4. 真实 CI 接入方式

本轮提供 `function-ci.yml` 配置，由 GitHub 托管 Ubuntu 在 PR 上执行现有 Rust 检查和标题格式检查，无需 KVM 或凭据。没有路径过滤，避免作为必需检查时因跳过而永久等待。PR 更新和标题修改触发复核；合并队列也可运行功能检查。合入 main 后，main 推送和手动触发入口生效。实际结果见 [Actions](https://github.com/ningZhang-cs/sandproof/actions)，配置存在不等于已经运行通过。此次不配置 CD。

后续由 C04 增加系统流水线，B 提供运行环境：

1. 受控 Linux/KVM 执行机使用固定镜像与工具；在运行前检查 `/dev/kvm`、jailer、内核/rootfs 指纹和可用资源，缺失时报告环境失败，不能显示通过。
2. 真机需要较高权限，只运行已复核的精确提交。外部 PR 不自动进入有权限的长期运行机；使用隔离、可回收的测试主机或受保护的手动触发流程。不使用 `pull_request_target` 检出并执行外部提交。
3. 每次运行创建自己的资源命名空间和目录；失败时先保存证据，再按登记的资源 ID 清理。不能全局停止所有 Firecracker 或删除宽泛目录。
4. 同一运行机串行执行冲突的系统场景；正常路径与可控故障分别报告。必要集合必须实际执行且通过；缺失、skip、超时和基础设施错误分别统计，不能掩盖成成功。
5. 结果绑定精确提交、版本指纹、配置、用例 ID、seed/failpoint 和关联 ID。PR 后续更新使旧结果失效。日志脱敏，不上传密钥、用户完整文件或含秘密的环境变量。

功能 PR 的合并门槛是基础 CI 通过、相关层测试通过；当前不强制非作者批准，建议重要改动请队友复核。涉及启停、授权、磁盘、网络和恢复的变更，需要对应真机证据；系统流水线尚未可用时可附同一提交的手动实机结果。缺少实机条件的代码可以作为未启用基础模块合入，但该功能不能标为已验收或默认发布。

GitHub 当前规则：要求 `rust` 和 `pr-title` 检查、分支保持最新、讨论已解决，禁止强推和删除 main；管理员同样受约束。按当前决定已取消强制审批，不需要非作者批准。实际是否可合并仍以该提交的检查和仓库设置为准。

## 5. Terminal-Bench 验收

- 固定 Harbor、数据集、任务 ID 清单和内容哈希、环境镜像、资源、网络策略、智能体、模型及参数。任务在跑之前按能力选定；不能遇到失败才删除题目。
- 首先用任务提供的标准解答检查环境和评分链，再用同一智能体对比。E2B 自身不支持的任务与我们尚未支持的任务分别记录。
- 使用原 E2B 接入时，仅改变连接和凭据配置；若暂时使用自定义适配器，报告为功能跑通，不能计作原 SDK/接入兼容通过。
- 报告环境构建/启动/执行/传输/清理错误、任务解题结果、耗时和资源残留。不要要求随机模型两次逐字输出或解题率完全一致，也不要把解题失败直接判为控制器 bug。
- 未实现域名策略、动态网络切换、额外服务等能力时，任务预检查须拒绝，不得静默扩大网络权限。若最终要求全量数据集，必须先扩展并验收这些能力。
- 在线 E2B 和模型评测需要单独的凭据、资源和费用预算，不加入普通 PR 的默认检查。

暂停恢复和安全竞争用 S 类专门测试扩展，不能用 Terminal-Bench 通过代替。形式化阶段再证明声明范围内任意历史的性质；V1 测试报告只记录实验结果。
