## 1. 模块测试重点

#123 正式发布登记使用[组件测试](../sandbox-api/tests/managed_port/publication.rs)覆盖归属、摘要/路径/只读/单链接检查、真实 SQLite 提交前后故障、发布额度、分页、别名比较更新与重启；Ready 须等待临时 VM 精确回收。实机沿用[隔离构建探针](../tests/system/template_build.py)并加 `--registry`：真实多阶段 Dockerfile/离线 OCI 候选 → 正式发布 → 原 SDK 创建/命令/文件 → 别名切换与服务重启 → 销毁；另测正确摘要但不可启动的内核，以及临时检查成功后清理回执未提交时整服务退出。使用新 namespace、root 私有目录、独占 UID 范围和空 CPU/memory 委派父组，不改共享网络或祖先；脚本退出前核对进程/jail/网络/cgroup 和源镜像不变。该实验不是公开 OCI 下载、用户构建服务、89 题或任意位置崩溃验收；实测提交和限制记入[版本基线](../references/v1-baseline.json)。

- A：所有者、阶段、同键改参、旧代数/尝试、重复回执、容量边界；寿命续期与到期竞争；事务提交前后进程退出。
- B：精确资源选择、路径越界、恶意输入、大输出、部分失败、重复停止与清理；真实宿主资源和隔离。
- C：固定客户端字段、默认值、错误映射、身份不可伪造、命令/文件网关权限及未支持功能拒绝；通用模板用户入口与 Harbor 环境适配。

#123 发布故障必须区分两侧：检查已持久确认、清理回执丢失，可在原资源精确回收后 Ready；物理激活成功但检查确认未提交，恢复不能补造 Ready，内部检查会话不可查询/连接，期限回收后失败。两侧均以原身份完成，不重新创建检查 VM。构建服务、公开 OCI 获取和模板垃圾回收仍是独立后续范围，不为本批追加完整矩阵。

#99 第 6 项使用[历史容量组件回归](../sandbox-api/tests/managed_port/history_capacity.rs)：真实 `ManagedPort`、SQLite 和现有控制转换保持两台运行实例，逐步增加完整 create/kill 历史；只有宿主动作使用既有合同测试替身。普通 CI 只运行 0/3 历史的语义回归，检查旧令牌拒绝、原 VM 身份不变、重开与空闲恢复不追加动作，以及一个实例的 StopVm 被屏障阻塞时其他实例的查询、数据准入和第三实例到期能在释放后正确收尾，不设耗时阈值。到期由正式 `set_timeout(0)` 接口确定，不依赖随机等待。

按需定量运行（从仓库根目录执行，产物目录已忽略）：

```sh
SANDPROOF_SOURCE_REVISION="$(git rev-parse HEAD)" \
SANDPROOF_SOURCE_TREE="$(git rev-parse HEAD^{tree})" \
SANDPROOF_HISTORY_POINTS=0,4,16,64 SANDPROOF_HISTORY_SAMPLES=7 \
cargo test --release -p sandproof-api --test managed_port \
  history_capacity::history_capacity_profile --locked -- --ignored --exact --nocapture
```

默认结果为 `artifacts/history-capacity.json`；`SANDPROOF_HISTORY_OUTPUT` 可指定绝对路径。只在干净的已记录提交上运行用于比较的报告；另记实际运行命令与环境。报告逐点保存已完成历史数、输入/操作/动作/回执行数、DB/WAL 字节、宿主调用计数和原始单调时钟纳秒样本；采用 nearest-rank 统计，七个样本的 p95 就是最大值，不能解释为稳定尾延迟。建库/真实创建销毁成本、连接重开校验、首次恢复/命令准入和暖态样本分别计时；暖态每条路径先预热一次。重开仍在同一进程和暖文件系统缓存中，不是主机冷启动。`authorize_data(FileRead)` 与生产网关实际使用的 `data_permit(Exec)` 分开测量；后者只代表命令转发前准入，不是 envd 命令启动或执行时间。另以外部观察者在 StopVm 屏障内保留名义 250 ms 窗口，记录其他实例请求的总耗时；线程报告已开始不证明它已到达互斥锁，结果含调度、锁等待及重放，不能冒称精确锁驻留时间。

历史点须按实际构造成本扩展；外部中止时保留 `in_progress`、已完成点和待测点，不把未测规模算失败或通过。此入口不访问 KVM/E2B 云、不运行题集，不改变准入阈值、缓存或锁范围，也不据组件耗时宣称正式历史上限、无限运行或整体 #99 完成。生产支持边界仍需目标任务、实际宿主预算与相同配置的系统验收。

## 2. 系统场景

## 4. 独立运行宿主预检

自助模板入口用[组件测试](../tools/tests/test_template_build_service.py)核对真实 SQLite 重开、租户/幂等键、上传中断、预算/原期限、丢失构建响应、未知清理保留预留及同编号发布；同一真实 HTTP/SQLite 组件链另检查小客户端读取完整日志页时的 JSON 转义放大、原始字节偏移、跨租户拒绝和响应上限，通用评测回归检查诊断读取失败不改写构建终态或跳过收尾；[私有构建池测试](../sandbox-api/tests/managed_port/build_vm.rs)核对禁用入口、保留 metadata、并发重复准入、墓碑、丢失启动回执，以及已销毁但尚未完成 VM 回收时不释放预算。[实机探针](../tests/system/template_self_service.py)部署两个独占 Rust 池与监督服务，走用户 HTTP 上传、多阶段构建、正式发布、原 SDK 命令/文件、明确构建失败、VM 已启动后 SIGKILL 监督服务并重启，最后独立检查两池进程/jail/netns/cgroup 和构建预留。`--public` 增加公开 OCI 拉取/发布/原 SDK；仅已获准临时修改全局转发时加 `--temporarily-forward`，脚本退出时恢复原值。精确提交/产物/结果记录在 PR，不把未运行模式、macOS 或替身测试算成真实隔离验收。

[宿主预检工具](../tools/check_kvm_host.py)是 C04 / #14 的独立基础模块，使用 Python 3.11+ 标准库，不依赖公共 API 或控制服务启动。它检查当前身份、Linux x86_64、KVM API、TUN、cgroup v2、宿主工具、可信路径、Firecracker/jailer 版本、四项产物 SHA-256，以及磁盘和内存余量；检查失败仍收集其余结果。

构建阶段日志用[定向回归](../tools/tests/test_template_phase_logs.py)核对阶段开始可读、可控单调时钟耗时、失败不记完成、与守护进程共享日志总量，以及诊断失败不替换原异常；[获取链回归](../tools/tests/test_template_worker_acquisition.py)同时核对真实校验到解包失败边界的阶段顺序。[工具退出期限回归](../tools/tests/test_template_command_deadline.py)以真实子进程关闭 stdout/stderr 的屏障推进时钟，检查剩余时间等待、已到期回收、迟到成功拒绝及期限内成功，不依靠随机等待复现。实机日志只提供阶段定位，不能把某个 completed 标记当作整个模板或评测通过。

标准输出始终用于 JSON 报告。有效配置下，报告包含提交、工作区是否有未提交变更、配置摘要、宿主内核、观察指纹和各项检查；有未提交变更时预检失败，不能以 HEAD 代替未提交代码的版本证据。退出码 `0` 仅表示全部前置检查通过，`1` 表示检查失败或不完整，`2` 表示配置错误。每项状态区分 `pass`、`fail`、`unavailable`、`timeout`、`not_run`；二进制未通过可信路径及指纹检查时，不执行它的 `--version`。不要用 `|| true` 或未检查的管道掩盖退出码。

工具只读取环境并执行已核对二进制的版本查询，不创建 VM/TAP/网络空间、不配置资源、不清理残留，也不输出环境变量或凭据。报告中的资源余量是当时快照，不是容量预留；通过不保证 cgroup 创建、网络隔离、来宾启动或 S01–S13 已验收。预检后仍须按本轮身份分配独占资源并运行真实系统测试。该工具尚未接入高权限 KVM CI。
