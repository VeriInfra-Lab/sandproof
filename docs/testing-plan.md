# V1 验收清单

[文档目录](README.md) · [开发与测试规则](../CONTRIBUTING.md) · [产品范围](project-blueprint.md)

本文只定义验收场景，不重复分支规则、合并门槛或 CI 操作流程。S01–S13 在建立清单时均待实现，当前执行状态和证据随对应 issue/PR 维护；不能因清单存在就计为通过。

## 1. 模块测试重点

- A：所有者、阶段、同键改参、旧代数/尝试、重复回执、容量边界；寿命续期与到期竞争；事务提交前后进程退出。
- B：精确资源选择、路径越界、恶意输入、大输出、部分失败、重复停止与清理；真实宿主资源和隔离。
- C：固定客户端字段、默认值、错误映射、身份不可伪造、命令/文件网关权限及未支持功能拒绝；真实模板调用链。

## 2. 系统场景

以下 ID 用于 issue/PR 的验收引用。

| ID | 场景 | 通过依据 | 主责 |
|---|---|---|---|
| S01 | 原客户端创建、连接、查询、销毁 | 同一实例；真实停止后才返回销毁完成 | C+A+B |
| S02 | 多次命令、后台进程、输出及非零退出 | PID/句柄、输出和退出码正确，后台任务不会被误重复派发 | B+C |
| S03 | 上传下载、修改系统文件、安装依赖 | 私有系统可写、共享基础镜像不变、宿主文件不被越界修改 | B+C |
| S04 | 两用户、两沙箱交叉访问 | 未授权管理、命令、文件和网络请求拒绝，资源不混绑 | A+C+B |
| S05 | connect、set_timeout 与到期 | 延长/缩短语义正确；旧定时任务不会销毁已续期实例 | A+C |
| S06 | create 与 kill、并发重复 kill | 不发布虚假成功；最终无运行残留，无误杀 | A+B |
| S07 | VM 启动后回执丢失、重复派发 | 恢复认出同一资源，不再启动第二台 VM | A+B |
| S08 | controller/worker 在关键窗口重启 | 提交前无外部动作；提交后能重放/对账；未知结果不丢失 | A+B |
| S09 | 旧资源清理迟到、标识被系统复用 | 只处理绑定身份，不影响其他或新资源 | B+A |
| S10 | 禁网、公网/静态规则与资源限制 | 实际探测不能绕过策略，不能访问宿主管理或其他沙箱 | B |
| S11 | 磁盘/配额不足、恶意大输出或文件 | 新请求合理拒绝，收尾仍有空间，宿主与其他沙箱不受污染 | A+B |
| S12 | 客户端超时及命令通道断开 | 状态未知可观察，不自动重复执行有副作用命令 | B+C+A |
| S13 | 模板制备、查询、创建、失败清理 | 原 SDK/Harbor 所用模板链可运行，失败不留下可执行残留 | B+C |

部分失败测试包括：磁盘已创建但 VM 未启动、网络部分配置、VM 已启动但回执未落盘、停止已生效但记录未提交。程序退出后还要从宿主检查进程/cgroup、TAP/网络空间、磁盘目录和端口，不只读服务自己的“成功”字段。

S10 还须让来宾 root 改写解析配置，探测未授权的 UDP/TCP 53、IPv6 与其他 DNS 出站路径。若将来启用受控解析器，须用随机子域名、TXT/NS、委托链和携带数据的查询证明不会经解析器访问未授权外部服务；只固定解析器 IP 不算通过。

`controller-service/tests/v1_workflow.rs` 已用确定性回执测试无部分副作用的明确失败：可重试时分配下一尝试；不可重试时撤销、停止、发布失败；补偿停止回执丢失时重启后先观察再完成。真实节点尚不能把任意 I/O 错误证明为无部分副作用，所以这些测试不覆盖部分网络创建、启动进程中断或恶意来宾流量。

销毁完成不等于任意存储介质的物理擦除。测试判断资源不可执行、不可被未授权访问，并按约定回收；不声称证明安全擦盘。


## 3. 兼容与 Terminal-Bench 验收

固定版本的 SDK 调用清单位于[兼容合同](../tests/compat/contract.json)。`bash scripts/check-compat.sh` 使用 E2B Python SDK 2.51.0 和本机回环合成响应；[实机系统测试](../tests/system/sdk_server_smoke.py)则使用同版原 SDK，经真实控制器和网关驱动 Firecracker，覆盖显式禁网的创建、连接、查询、列表、续期、销毁，以及基本命令、文件、超时、终止、断线重连、1 MiB 输出、跨租户与旧令牌、非法文件路径、重复令牌、超限上传拒绝和到期清理。隔离 Linux/KVM 测试已通过，但只覆盖 S01–S05、S11–S12 的部分路径。

[宿主故障测试](../sandbox-node/tests/host_smoke.rs)覆盖 VM 启动或停止后回执丢失，以及独立工作进程恰在真实启停成功、回执提交前退出或被 SIGKILL 杀死。新增测试覆盖首个槽位未写入、网络空间已创建但 inode 记录未提交，以及真实 VM 已停止、私有资源已清理但清理回执尚未提交。重开数据库后只对精确身份做观察或幂等清理，不重复启停；错误 owner 被拒绝，结果未明时 create×kill 被拒绝，迟到的同一回执不改变运行或销毁终局。运行中 VM 的启动盘点核对网络空间 inode 与完整禁网规则；实机测试添加额外限制规则后盘点拒绝，原子恢复规则后仍可正常销毁。[运行层故障注入](../sandbox-runtime/src/linux.rs)验证了未放行门控不能启动子进程、网络空间已创建但 inode 记录未提交、准备回执不确定而精确进程已停止、编号不可复用，以及禁网规则被篡改时不能取得成功观察。[来宾探针](../tests/system/guest_smoke.py)让 root 改写解析器，测试 UDP/TCP DNS、853 和 443 端口及 IPv6 出站被拒绝，同时管理通道可用。

[服务恢复测试](../sandbox-api/tests/managed_port.rs)覆盖停止成功但回执未知、准备阶段只有部分资源，以及销毁或失败补偿中清理只完成一部分。重开数据库后的扫描器先匹配当前操作编号、owner、时期和持久资源计划，再要求宿主给出精确结果；重复恢复与迟到的相同回执保持终局不变。这是合成宿主证据测试，不能替代真实服务进程的任意位置强制终止测试。

这些只是 S07–S10 的部分路径，尚缺公网与静态 IPv4 规则、其他位置的 SIGKILL、完整常驻服务进程跨崩溃自动收尾和旧资源冒名等系统级实验。非空环境变量、元数据、其他模板及完整重启恢复也未验收，不能把 S01–S13 整体标为通过。命令流缺少结束回执时，SDK 抛出异常且本次请求不自动重发；服务端仍须把已开始的命令结果视为未知，不能凭异常断定命令未执行。

- 固定 Harbor、数据集、任务 ID 清单和内容哈希、环境镜像、资源、网络策略、智能体、模型及参数。任务在跑之前按能力选定；不能遇到失败才删除题目。
- 首先用任务提供的标准解答检查环境和评分链，再用同一智能体对比。E2B 自身不支持的任务与我们尚未支持的任务分别记录。
- 使用原 E2B 接入时，仅改变连接和凭据配置；若暂时使用自定义适配器，报告为功能跑通，不能计作原 SDK/接入兼容通过。
- 报告环境构建/启动/执行/传输/清理错误、任务解题结果、耗时和资源残留。不要要求随机模型两次逐字输出或解题率完全一致，也不要把解题失败直接判为控制器 bug。
- 未实现域名策略、动态网络切换、额外服务等能力时，任务预检查须拒绝，不得静默扩大网络权限。若最终要求全量数据集，必须先扩展并验收这些能力。
- 在线 E2B 和模型评测需要单独的凭据、资源和费用预算，不加入普通 PR 的默认检查。

暂停恢复和安全竞争用 S 类专门测试扩展，不能用 Terminal-Bench 通过代替。形式化阶段再证明声明范围内任意历史的性质；V1 测试报告只记录实验结果。

## 4. 独立运行宿主预检

[宿主预检工具](../tools/check_kvm_host.py)是 C04 / #14 的独立基础模块，使用 Python 3.11+ 标准库，不依赖公共 API 或控制服务启动。它检查当前身份、Linux x86_64、KVM API、TUN、cgroup v2、宿主工具、可信路径、Firecracker/jailer 版本、四项产物 SHA-256，以及磁盘和内存余量；检查失败仍收集其余结果。

从[配置示例](../tests/system/host.example.json)复制一份到被忽略的 `artifacts/`，按已复核的测试环境填写绝对路径、四个指纹和资源最低余量。示例中的指纹占位符会被拒绝，磁盘/内存数值只是例子，须按本轮 VM 数量、磁盘副本、日志及收尾需求确定。指纹应来自已确认的发布产物或镜像构建记录；不要在不匹配时直接覆盖基线。

在**待测主机**的干净、精确提交上，用运行 jailer 的同一 root 身份执行（先确认该提交及配置适合在该主机运行）：

```sh
mkdir -p artifacts
cp tests/system/host.example.json artifacts/host.json
# 编辑 artifacts/host.json，填入已复核的基线。
sudo python3 tools/check_kvm_host.py --config artifacts/host.json > artifacts/host-preflight.json
```

标准输出始终用于 JSON 报告。有效配置下，报告包含提交、工作区是否有未提交变更、配置摘要、宿主内核、观察指纹和各项检查；有未提交变更时预检失败，不能以 HEAD 代替未提交代码的版本证据。退出码 `0` 仅表示全部前置检查通过，`1` 表示检查失败或不完整，`2` 表示配置错误。每项状态区分 `pass`、`fail`、`unavailable`、`timeout`、`not_run`；二进制未通过可信路径及指纹检查时，不执行它的 `--version`。不要用 `|| true` 或未检查的管道掩盖退出码。

工具只读取环境并执行已核对二进制的版本查询，不创建 VM/TAP/网络空间、不配置资源、不清理残留，也不输出环境变量或凭据。报告中的资源余量是当时快照，不是容量预留；通过不保证 cgroup 创建、网络隔离、来宾启动或 S01–S13 已验收。预检后仍须按本轮身份分配独占资源并运行真实系统测试。该工具尚未接入高权限 KVM CI。
