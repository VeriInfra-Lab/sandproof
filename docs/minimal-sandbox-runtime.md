# 单节点小沙箱：先实现，再证明

> 历史方案，2026-09-25 起由[项目蓝图](project-blueprint.md)替代。下文的实现状态仍可作代码线索，但“不做暂停恢复”“默认无网络”“只在启动前导入”等不能再用作整个项目的最终范围。现有基础模块将按 E2B 核心兼容路线复核和复用。

## 首版功能边界

目标是一个真正由 Firecracker 隔离的单机沙箱，支持创建、在沙箱里执行命令、取回产物和销毁。首版不做暂停恢复、快照、跨节点迁移、共享卷和实时挂载宿主目录。默认不接入网络；以后若加网络，另行定义允许范围与证明义务。

用户授权的是若干宿主文件夹，而非整个磁盘。启动前将获准文件夹复制为沙箱独有的只读输入磁盘；每个沙箱另有独立可写工作磁盘。命令的输出只能导出到该沙箱的受控结果区，不能直接写回原宿主文件夹。原文件夹后来发生的变化不会自动反映到已启动的沙箱里。

## 当前已写代码和未完成部分

新运行层位于 `sandbox-runtime/`，与旧的纯控制核心隔离，避免把尚未证明的外部操作说成已经被旧定理覆盖。

| 部分 | 当前状态 | 仍需核验 |
|---|---|---|
| 文件夹导入 | 已实现按打开的授权根逐级查找、拒绝相对路径越界、符号链接、硬链接、特殊文件；限制深度、数量和实际复制字节数。Linux 使用 `openat2` 拒绝跨挂载，包括绑定挂载 | 在 Linux 上编译和做并发修改/挂载攻击测试；授权根须由可信注册流程打开，导入期间保持不变 |
| 虚拟磁盘 | 已实现调用固定路径的 `mkfs.ext4` 生成独立输入盘和工作盘；输入盘内容来自前一步 | 在 Linux 上实际格式化、挂载核对内容和只读属性；验证磁盘空间上限与失败清理 |
| Firecracker 配置 | 已实现对已启动的全新 Firecracker API 套接字发送机器、内核、三块磁盘、vsock 和启动请求；不创建网络接口，输入盘标记为只读 | Linux/KVM 真机启动；需要固定内核和基础系统镜像，以及安全启动 Firecracker 的 jailer |
| 命令与结果 | 已实现 Firecracker vsock 主机端握手、限长二进制消息框架，以及只能在私有结果目录内原子发布文件且不覆盖旧结果 | 来宾代理、命令执行与协议字段、总时限和超时后终止、真实结果传输 |
| 生命周期与恢复 | 尚未实现 | 持久记录、启动失败回收、进程终止确认、崩溃后恢复与销毁幂等 |
| 形式化证明 | 尚未开始新范围的证明 | 在真实流程稳定后，建立简化状态机，并逐层对应 Rust 决策和外部适配器 |

当前机器是 macOS，缺少 Linux/KVM 与 `mkfs.ext4`，所以本地通过的只是纯逻辑和接口测试，不能称为“沙箱已经可运行”或“隔离已经实测”。Firecracker 需要用同版本的 jailer 隔离；直接启动未关进 jailer 的 Firecracker 仅可用于实验，不是此项目的生产路径。

## 开发顺序和每批复核

1. 先在 Linux/KVM 主机补齐安全启动器、固定内核及基础系统镜像，完成一次真实启动并检查沙箱看不到未授权文件夹。
2. 加入来宾代理和命令通道，再做只向受控结果区导出的接口；逐项测试超时、重试和恶意路径。
3. 加入持久记录、失败回收和销毁，在崩溃注入下检查没有遗留可执行虚拟机或跨沙箱资源。
4. 最后重构纯决策部分为便于证明的状态机，证明授权、隔离、状态转换和销毁后的不可访问性。外部 `mkfs.ext4`、Linux、KVM 和 Firecracker 仍需清晰列为依赖，不因 Rust/Lean 定理而自动得到证明。

每批完成后分别检查：功能是否真实运行、失败路径是否安全、代码职责是否清楚、哪些性质只是测试而非证明。旧的 `create/pause/resume/kill` 定理不直接作为新 `create/exec/export/destroy` 系统的验证结论。
