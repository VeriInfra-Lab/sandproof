# 控制核心与证明结构复核（2026-09-23）

本次检查范围：Rust 纯控制核心的公开入口、资源与账本存储、各生命周期处理模块；
Lean 规范、完成性证明、Rust 对应证明的导入结构；项目验收与进度文档。
这是针对模块边界和扩展路径的审查，不是逐行重审全部已证明定理。

## 结论与已做调整

职责分离总体合理：Rust 的公开入口按请求、回执、调度、工作执行、发布分派；
纯处理核心不直接调用虚拟机或数据库。Lean 规范与 Rust 对应证明分别在
`SandboxModel/` 和 `SandboxModel/RustRefinement/`，没有把抽取代码当成规范。
新增一种协议动作仍需要明确增加数据类型、处理分支、规范步骤和对应证明；
这种穷尽检查是设计意图，不能为追求“易扩展”改成绕过证明的开放插件入口。
本批完整验收已通过：78 项 Rust 测试、重新抽取一致性、全部项目证明模块、
159 项实际定理依赖审计与占位符扫描；没有修改 Rust 运行行为。

发现并处理的重复：`WorkflowLiveness.lean` 与 `WorkflowReceiptProgress.lean`
曾各自证明一次“清单中有一项严格下降且其他项不增，则总和严格下降”。
现在后者复用前者公开的通用引理，删除重复证明。新增销毁与补偿回执证明
独立放在 `WorkflowCleanupReceipt.lean`；它依赖正常回执的公共部分，不在
原有约 3500 行的完成性文件里继续追加特殊情况。

发现并处理的文档漂移：`progress-overview.md` 曾写 Rust 实现对应证明
“未开始”，与已通过的全输入定理相矛盾。本次改为明确列出已完成的纯核心
对应证明和仍缺少的容量、最终完成性与外部接入，减少后续决策误判。

## 仍需控制的结构风险

| 位置 | 证据 | 对迭代的影响 | 后续处理 |
|---|---|---|---|
| 完成性证明 | `WorkflowLiveness.lean` 约 3500 行，同时含进度量、资源预留、时间合同 | 改一个基础定义易触发大面积重新检查 | 下一次修改该文件时，按进度量、具体动作、时间组合逐层拆模块，保留现有定理名称和审计 |
| Rust 工作流文件 | `scheduler.rs` 约 2000 行、`request.rs` 约 1600 行，分支依次写在同一文件 | 新入口与已有拒绝顺序更易互相干扰 | 待有实际新入口时按命令族拆内部模块；每次拆分必须重新抽取、通过全部对应证明 |
| Rust 公共接口 | `lib.rs` 广泛使用 `pub use ...::*` | 新增同名项时来源不清，也扩大根模块公开面 | 新代码优先使用带模块名的路径；待外部调用者和抽取根清点后再收窄兼容接口 |
| 重复辅助实现 | `effect.rs`、`worker.rs`、`transition.rs` 各有相近的 `insert_unique` | 修复其中一份时容易遗漏其他两份 | 结合容量实现一次性统一，先确认三者完全相同的顺序语义，再重新做抽取与证明 |
| 机器容量 | `Store::put` 可追加向量；当前定理只要求调用时有容量 | 对已接收操作没有长期保留完成空间的机制 | 建立真实状态里的准入预算和持久预留，再证明各步骤不会超支 |

这些风险不应靠一次大范围文件搬迁解决。Rust 函数的分支顺序和辅助函数
都直接进入编译器抽取结果；看似机械的搬迁也可能使已有证明失效。
对上述文件的结构调整以一个实际功能族为单位，并用完整验收确认语义。

## 依据常见设计原则的判断

- **职责单一**：顶层入口与具体处理领域已分开；几个超大文件承担过多职责，
  尤其完成性基础定义与时间证明应进一步分层。本次新增内容使用独立模块。
- **扩展和修改**：封闭枚举让新增协议动作必须通过全部匹配和证明，这是安全边界。
  可扩展性应来自清晰的组件证明接口，而不是绕开穷尽检查。
- **替换与接口隔离**：当前没有底层适配器的生产实现，无法声称可任意替换。
  Rust 公开入口的输入、事件、拒绝类型按领域区分；根模块的通配导出仍过宽。
- **依赖方向**：模型不依赖 Rust 抽取产物；Rust 对应证明单向依赖模型。
  完成性证明会调用具体处理函数与完备性引理，因此它是组合证明层，
  不是可独立复用的纯数学进度量库。后续拆分应先抽出纯进度量定义。

最终完成性接口仍偏强：`WorkflowProtocolClosure.select` 在每个未完成状态
要求一个持续可执行的控制器工作项，但回执和工作执行不是控制器公平调度的
工作项。新增回执证明已把实际回执步骤与进度量相连；下一步仍需将“等待
外部回执”与“控制器可以推进”分别组合，并证明等待期间身份与前置条件保持。
不能把等待时的进展义务改名后交给外部假设。
