# 模块合同 v1：已确认范围与执行边界

[文档目录](README.md) · [项目蓝图](project-blueprint.md) · [开发规则](../CONTRIBUTING.md)

本文件限定接口责任和安全语义；产品范围由 owner 确认，A/B/C 核对各自实现边界。目标合同不等于代码已经实现或完成形式化证明。共享 Rust 消息以 `sandbox-protocol` 为准；固定 SDK 的具体调用、当前支持状态和可执行测试以[兼容合同](../tests/compat/contract.json)为准，不能各写一份独立的业务状态机。

首批跨模块消息类型位于 [sandproof-protocol](../sandbox-protocol/src/lib.rs)：经过鉴权后构造的请求、携带完整身份的动作与回执，以及成功、明确失败、未知三类结果。[共享样例](../sandbox-protocol/tests/contract_examples.rs)覆盖正常、拒绝、冲突重复、迟到、未知、部分完成、资源不匹配与未知协议版本。这里的外部不透明字符串 ID 与既有控制核心的内部数值 ID 不同；持久映射由 A 的 `ControllerJournal` 管理。消息类型本身不执行事务、不确认宿主证据，也不替代已证明的控制状态机；未接入的外部错误映射仍须由 #5/#12 按调用测试。

### 目标与现状的分界

V1 目标由[蓝图](project-blueprint.md)定义；完整服务链已实测固定 `base`、显式禁网、部分 SDK 生命周期/命令/文件调用、选定的创建级环境变量与元数据，以及测试镜像上的公网默认值和静态 IPv4 规则。默认 300 秒、默认续期、非正到期与总寿命截顶已实现，实测范围见验收清单；列表筛选与排序已实现，实测范围见验收清单。公网模式仍须部署方显式开启并满足宿主转发与镜像要求，默认配置拒绝；宿主已有转发链也必须允许对应路径，单独打开 ip_forward 不会覆盖 Docker 等现存 DROP 策略，服务不自动放宽共享防火墙；测试专用网络空间与一条宿主预检可通的真实公网 TCP 路径已测，不等于验证通用互联网、DNS 或全套 V1。C 必须在鉴权和参数校验后才调用 A，不能把未实现参数静默丢弃；B 不能因为目标已定就提前打开宿主出口。

## 请求入口：C → A

- C 从有效凭据得到调用者身份；不能把请求正文中的 tenant/user 字段直接当成可信身份。
- 生命周期输入携带调用者、sandbox ID、操作类型及业务参数；内部操作编号由可信服务分配/映射。没有客户端幂等键时，不能承诺两个独立 create HTTP 请求只创建一次。
- A 根据当前持久状态检查归属、能力、寿命、资源预算及是否正在撤销；接受决定、操作记录和待执行动作在一个事务内提交。
- C 将稳定结果或等待超时映射为固定 E2B 响应。内部 pending/unknown/revoking 等状态可以保留，但不能随意扩展 E2B 公共状态枚举。
- 同一请求重复、操作查询与重新提交是不同动作。相同幂等键改变参数必须拒绝；C 负责记录客户端真实提供了哪些可重放标识。

寿命接口已按固定 v2 SDK 区分：create/connect 省略均为 300 秒，创建不得将过长请求截短；connect 只延长、请求超过部署单次上限返回 400，允许的请求最多续至该实例原始总截止点。set_timeout 按服务端当前时间重设，零/负值立即到期，大正值截顶；成功返回表示期限已提交，不表示宿主停止已经完成。已到期实例不再授权或接受续期；原实例仍处于 Running 但已超过总寿命时更新返回 400，正在撤销时返回 409，外租户/已销毁实例为 404。已撤销令牌的 health 请求仍为 401，固定 SDK 的 is_running 抛认证异常而非返回 False。非正更新立即撤销既有数据传输，停机仍由到期扫描走核心 Kill/宿主精确收尾，不新增第二套状态机。

可信配置 `max_timeout_secs` 限制 create/connect 的单次申请，`max_lifetime_secs` 限制从首次持久发布 Running 起的总可用寿命；后者省略时采用前者。独立的 `startup_timeout_secs` 只限制从准入到发布 Running 的等待，默认 300 秒，由部署方设置，不能由客户端的 `timeout` 改写。准入事务同时保存这条启动期限和获批可用时长；只有在启动期限之前完成真实就绪并原子发布 Running，才以该发布时间重设可用寿命起点、初始截止点和总截止点。到达启动期限即持久记录补偿意图；扫描器尚未运行时，迟到的 Running 发布也必须拒绝。Running 实例不再受启动期限约束。重启或配置放宽均不延长原实例已经持久确定的期限。`default_timeout_secs` 可省略，若仍填写则只能为 300；旧部署的其他默认值须显式改配置，不能静默忽略。创建请求须同时满足单次和总寿命上限，固定 Harbor 的 86400 秒请求必须由实际部署预算支持。存储 V5 升级到 V6 时，旧 Starting 记录沿用其原准入截止点作为启动期限，不擅自延长；旧 Running 记录只使用已授予的可用截止点。更早版本升级时也不猜测未知总预算或重置年龄。旧实例仍可缩短及清理，需要更长寿命时创建新实例。旧二进制不得直接打开升级后的数据库。

查询列表只从调用者当前可见且未到期的实例派生，不另存一份业务状态。`metadata` 按固定 SDK 的分层 URL 编码解码，所有键值同时精确匹配；`state` 接受 `running`、`paused` 及组合，V1 的合法 paused 筛选返回空集。`startedAfter` 是包含边界的启动时间下限，按上游微秒精度比较；`template` 只匹配创建时绑定的不可变模板编号（未配置目录时为 `base`），其他合法名称为空，带标签或非法名称拒绝，不伪造模板别名。默认排序为启动时间降序、相同时间按外部 ID 升序；`order=asc` 同时反转两个键。先筛选、再排序和分页，页大小 1–100；`X-Total-Running` 返回筛选后、游标及页大小之前的运行数，仅在请求包含 running 时提供。游标携带时间、ID 和方向，方向不符或格式非法返回 400；它只定位结果，不授予权限，换用户仍重新检查归属。删除游标所指实例不使游标失效；翻页不冻结整个集合，不承诺并发创建/销毁期间的快照列表。旧数字游标不兼容，应从首页重新查询。

详情查询另返回当前沙箱专属令牌、部署域名、原始联网参数及 `lifecycle={onTimeout:kill,autoResume:false}`；列表不返回令牌或详情专属字段。`allowInternetAccess` 区分创建时省略（null）、显式 true/false，network 保留原始地址顺序、CIDR 写法和空列表/省略区别；这些只用于查询，执行仍使用核心规范化后的策略。参数随创建意图同一事务持久化；旧记录无法还原的原始网络字段省略，不从策略猜测。详情暂不提供别名字段，alias 省略；创建别名不参与列表筛选；V1 无共享卷，get/list 的 volumeMounts 返回空数组。

固定 SDK 的管理 HTTP `request_timeout` 独立于沙箱寿命：类调用省略为 60 秒，实例省略继承其连接配置；类调用、分页覆盖与 `is_running` 的零值关闭该请求期限，但实例管理方法经配置重建后零值实际恢复为 60 秒。负数使用 HTTP 期限错误，不是服务端寿命参数拒绝；大正数也不受 Connect 毫秒头上限约束。管理期限失败可保留原创建或销毁副作用；只能查询原身份并显式收尾，不自动重新创建。这里记录的是固定 SDK 的当前行为，健康请求的错误包装还与管理请求不同，精确观测范围见[验收清单](testing-plan.md)。

## 动作接口：A → B

### 模板服务 → 创建准入（#123/#6）

以下是 2026-09-30 批准的目标合同。当前已实现显式预制模板、正式发布登记与自助构建入口：可信部署目录、受保护候选发布门、持久归属/别名、创建时固定描述和资源准入，以及独立构建池的提交/上传/查询/日志/恢复。自助服务须显式部署；默认未配置目录仍为旧 `base` 路径。测试层级见[验收清单](testing-plan.md)。

预制目录的 `templates` 包含不可变编号、修订、owner（null 为明确共享）、内核及 ext4 的绝对路径/长度/SHA-256、来宾 CPU/内存/磁盘及整个 VMM 的宿主内存上限；`aliases` 只在创建时解析，`compute_limits` 约束全局/租户 CPU 与宿主内存总额度。路径由可信部署方提供，客户端仅给模板名称；不存在逐题特殊入口。同一编号第一次成功准入后不得换描述，即使实例已销毁；变更产物或形状须使用新编号，别名可改指向。创建、连接、详情和列表报告实际不可变编号/形状，筛选也只匹配该编号，不动态解释别名。

实例完整绑定与原创建选项、寿命、资源计划在同一 SQLite 事务提交；未知提交不得重新分配 VM。目录模式的未知与他人模板统一返回 404，避免通过拒绝状态枚举他人模板；旧 base-only 模式仍拒绝其他名称。额度包括尚未确认精确回收的实例，宿主内存额度不是 Linux 物理内存预留。启动前核对受保护产物的类型、长度和摘要；重启后宿主启动记录须与持久绑定相同。观察、停止和精确清理不依赖源镜像仍存在，但新启动必须重新验证它。宿主 cgroup 父目录/UID 范围等仍是稳定部署前提。

节点首次校验稀疏产物时，按文件系统报告的数据/空洞区间计算完整 SHA-256：空洞仍逐字节计入同等长度的零，仅避免通过文件系统读取零区间。摘要及逻辑容量不变；不支持区间查询时从头回退完整流读取，真实 I/O 错误、异常区间和长度变化拒绝。受保护路径、校验前后元数据一致性以及缓存命中条件保持原检查；该优化不免除首次完整摘要校验。

第一次接受预制模板会原子升级数据库到 V8；第一次接受含 `startup` 的模板升至 V9，后续接受旧模板不能降级。旧二进制不可打开对应新库；同库此后拒绝旧式无计算额度准入，关闭配置不能绕过资源账本。启用前须精确清理仍占用资源的旧无绑定实例，不猜测其历史 CPU/内存；它们仍可查询和销毁。模板目录不是构建状态库，不接收用户上传，也不管理镜像回收。

[#123 的候选构建工作器](../tools/template_worker.py)由[自助构建监督服务](../tools/template_build_service.py)在新建、受限、独占且可回收的构建 VM 内运行，复用 BuildKit/umoci/mke2fs，宿主不得执行用户 Dockerfile 或解包用户镜像。boot_id/virtio 磁盘检查只防误操作，不是隔离或远程认证证明；隔离、外部总期限、独立构建额度和最终 VM 清理由监督器负责。每项工作有新目录/缓存、有界输入/展开量/日志，失败保留原身份且不生成成功状态。公开 OCI 由固定 regctl 直接导入；原 OCI tar 工具入口保留。首次层校验在同一读取流核对 blob 大小及 SHA-256、完整展开流 diff_id 与归档成员；仅全部通过后才记录可复用结果。 gzip 层以单个预取线程并行解码和主线程摘要/成员检查，队列至多保留两个 1 MiB 块；预取总量限制为该层剩余展开额度加用于拒绝超限的一字节，不预先解完整层或落盘。成功和异常退出均先停止并等待原线程，再关闭解码源；线程错误传回校验调用，不形成可复用记录。复用已有层检查仍完整重读并校验当前 blob 摘要。检查摘要和展开预算后由 umoci 处理 whiteout；不兼容架构/操作系统、设备节点、容器卷及其他压缩格式明确拒绝。OCI 层的成员名和链接目标使用 Linux/POSIX 语义：反斜杠是普通字符（如 systemd 转义单元名），原样保留，不解码或转成分隔符；成员名和硬链接仍拒绝绝对路径、`..` 分量及 NUL。上下文仍拒绝反斜杠，只接收普通文件、目录和不越界的相对链接，剥离宿主所有权和特殊权限，不跟随链接写出。

转换产物始终为 `candidate`、`ready=false`，构建工作器不能自行登记。它加入静态 BusyBox 启动环境和固定 envd；宿主 cgroup 仍限制整个 VMM，来宾 envd 不启用其可选的进程 cgroup 管理。候选清单保留原始 ENV、WORKDIR、USER、CMD/ENTRYPOINT，并生成 `runtime_defaults`；构建时尚未启动实例，`startup_applied=false`。平台 resolver 来自可信构建配置；这不是对来宾 root 的防修改承诺，目的地址限制仍由宿主 IPv4 规则强制，不新增域名过滤/IPv6。

候选补齐容器运行时通常注入的 IPv4 `localhost` 映射：保留普通 `/etc/hosts` 中的自定义条目和注释，缺少 IPv4 回环映射时追加 `127.0.0.1 localhost`；已有非回环或无效的 `localhost` 地址明确拒绝。输入及生成文件限 64 KiB，拒绝目录/特殊文件；符号链接被替换为平台普通文件，不跟随其目标，硬链接另写新 inode，避免修改其他镜像文件。仅依赖公开 DNS 不能代替本地回环解析；该补齐不改写 NSS 策略、不设置新主机名或承诺 IPv6，也不修改已发布模板/运行实例。新行为须经新构建发布才生效。容器运行时行为参见 [Docker 网络说明](https://docs.docker.com/engine/network/#custom-hosts)。
候选启动时在 `/dev` 就绪后挂载每个实例独立的 `/dev/shm` tmpfs，初始选项为 `nosuid,nodev,noexec,mode=1777,size=64m`；支持普通用户的 POSIX 共享内存和信号量，挂载失败则不写就绪标记。64 MiB 是文件系统容量上限，不是预分配内存或额外宿主预算；实际使用计入既有来宾/VMM 内存边界。来宾 root 可改写自身挂载，该初始上限不代替宿主强制额度。数据不写回模板，不在实例间共享；已发布模板须重新构建才包含该启动行为。默认容量参照 [Docker 运行参数](https://docs.docker.com/engine/containers/run/)，Linux 用途见 [tmpfs 文档](https://docs.kernel.org/filesystems/tmpfs.html)。

候选的本地 envd 启动门只适用于平台制备后的 ext4 冷启动：安装时先验证 `/run` 未被重定向，再删除输入镜像的 `/run/sandproof-boot-ready` 目录项，不跟随符号链接或改写硬链接目标；目录或删除失败使候选构建失败。BusyBox `sysinit` 返回失败仍可能继续 `respawn`，因此不能只依赖启动脚本的退出码。启动在根盘可写后、其余配置前再次删除标记；agent 通过固定 BusyBox 的文件系统 stat 核对 `/run` 的实际 tmpfs 类型，要求 stat 本身成功，并拒绝 `/run` 或标记为符号链接。仅当本轮挂载、网络等配置全部完成后才在新 `/run` 写标记并允许 envd；proc、根盘重挂载或清除失败时，遗留 ext4 文件也不能通过此门。构建前另检查 BusyBox 的 rm/stat applet 与文件系统格式能力。此门不是外部模板 Ready 发布、宿主隔离或远程认证证据，也不防运行中来宾 root 篡改挂载/标记；不承诺成功启动后手工重复执行 boot 的语义。固定 base 的 systemd 启动路径不使用此标记。已有模板须重新构建、检查并发布才包含修复。

公开获取由[固定 regctl 客户端](../tools/template_fetch.py)在同一构建 VM 内执行；工作器的 `kind=oci-reference` 接收仅含 `image` 的 JSON 文件。入口接受公开仓库的标签或 SHA-256 引用，`ubuntu:24.04` 等简写规范化为 Docker Hub 的完整名称。标签只在本次构建开始时解析一次，记录实际原始清单摘要，后续下载按选定摘要固定；用户需要跨构建复现时使用 `@sha256:`。拒绝认证信息、端口、私有 DNS 名或 IP 字面量；地址可达性仍由既有公网 IPv4 隔离策略决定。regctl 固定 v0.11.6/linux-amd64 及 SHA-256，使用空 HOME/Docker/regctl 配置，不携带宿主仓库凭据。摘要输入须匹配原始字节；OCI 清单直接使用，OCI/Docker 索引只允许唯一 linux/amd64 OCI 或 Docker schema2 子清单，不下载其他平台；不支持 schema1 或嵌套索引。Docker schema2 先校验所有 blob、diff_ids、tar 路径与展开限制，再在构建 VM 内由同一固定 regctl 对已校验的单清单私有 layout 绑定本地 `candidate` 标签并执行 `image mod --to-oci --replace`，原地替换清单并复用层文件，不重新获取来源；转换前后配置与各层的摘要、大小、顺序必须一致，转换结果再次通过 OCI 检查。拒绝外部 layer URL 和 foreign layer。导出后校验所选清单、所有 blob、diff_ids 与展开限制。导入不执行 ONBUILD；Dockerfile 构建仍遵循标准构建器的 ONBUILD 语义。

获取清单与 OCI tar 的 stdout 合计受 `max_input_bytes` 限制（不含 HTTP 头、重试等线上字节），监督服务、worker 与验收规划共用 16 GiB 输入硬上限，实际额度由可信配置显式选择；提高输入额度必须同时满足构建盘空闲、传输和预留预算，展开层仍最多 32 GiB。stderr 与其他工具共享 `max_log_bytes`，使用同一总期限和 VM 磁盘/内存限制。候选增加 `public_source` 记录原始引用/实际摘要、所选摘要、平台、下载产物字节及工具指纹；schema2 转换另记 `converted_digest` 和 `conversion=docker-schema2-to-oci`，原始/所选来源摘要保持不变。此能力已接入自助构建 API；私有仓库认证后置。Harbor 的自有构建适配与原模板 API 的差异见[评测入口](../benchmarks/README.md)，不宣称原 E2B 模板 API 全兼容。

可信自助服务配置可选 `docker_hub_mirror`，只接受公开 HTTPS 仓库主机名，不接受 URL、端口、路径、凭据或 IP；客户端不能提交此字段。仅公开 OCI 获取将规范化的 `docker.io` 仓库通过该主机传输，其他仓库及 Dockerfile/BuildKit 不受影响；不修改宿主 Docker、DNS、代理或防火墙。镜像站选择参与持久配置绑定，重启不能隐式切换。`public_source.reference` 仍为原引用，另记 `transport_registry`；标签从镜像站解析一次，所有后续获取按选定摘要固定，摘要引用仍必须与原请求精确匹配，原有输入/日志/期限/网络限制不变。镜像站不是来源真实性证明：需要跨来源复现时应与独立记录的原仓库摘要核对或提交摘要引用，不能仅凭标签相同宣称原镜像相同。没有此配置时仍直连，不自动探测或选择第三方站点。

正式发布门由可信构建监督方确认构建 VM 回收后，用[登记准备工具](../tools/template_stage.py)将候选字节放入 root 独占 `template_registry.root/inbox/<候选编号>`。HTTP 客户端只给随机 32 位十六进制候选编号，不能给宿主路径、owner、修订或 Ready 标志；API key 决定 owner，受保护清单必须匹配。服务检查只读普通文件、单链接、长度/SHA-256、绑定路径、envd 版本，以及 ext4 实际可用空间（扣除保留块），不信任工作器自报空闲值。持久接受发布意图后原子移入同盘 `artifacts/<编号>`；模板编号 `tpl-<候选编号>`、修订 r1 和完整形状不可改，变更须新候选。历史数量与内核+磁盘字节有全局/租户上限；失败和未决记录仍占额。本批不提供模板垃圾回收；可信监督方负责暂存预算，后续公开构建服务须另外限制和清理暂存，发布额度不是完整构建配额。

登记准备为新候选复制独立文件，支持时按文件系统数据区间复制并保留空洞，不支持时回退有界流式稀疏复制。副本同步后完整回读 SHA-256 和长度，匹配工作器候选才写清单并原子暴露；不再额外预读同一源磁盘。源文件不变，同编号已暂存候选的重试仍核对源和副本摘要；复制或校验失败只清理本候选未发布暂存目录，不减弱正式发布门的再次校验。

自助构建监督服务对自己下载并校验的 `builds/<构建编号>/candidate.ext4` 使用内部移交入口：构建 VM 确认回收后，同盘将该单链接 inode 原子移入对应私有暂存目录，省去重复复制；跨盘仍复制。此入口只接受当前宿主用户拥有的普通文件、固定构建槽和独占父目录，不向 HTTP 客户端开放路径或移交选项。文件同步、完整 SHA-256 回读、只读权限及正式发布门检查保持；移交成功后原下载路径消失，不能再由下载目录访问同一 inode。移交中断时按同编号暂存/最终目录恢复，不重新构建；普通检查或 I/O 失败先恢复原槽。原期限已到且已确认发布未接受时，监督服务清理该编号的最终/未完成暂存并释放预算；发布结果未知时保留两者继续观察。通用登记准备工具仍按上一段复制并保留源文件。

临时启动检查复用正常资源准入、真实启动/envd 初始化和精确销毁，VM 身份与创建意图同事务提交，也占运行资源额度，但不暴露为用户沙箱会话。只有完整绑定成功 Running 已持久确认、且原 VM 和网络槽全部回收，才登记 Ready。文件/启动明确失败不发布；提交、启动或收尾未知保留 checking，同编号重提只返回原记录，不另起检查。重启只观察/推进原工作流；未持久确认检查成功的中断不得补造 Ready，原 VM 按既有启动/寿命期限回收。已确认检查成功但丢失清理回执，可在精确回收后登记 Ready。Ready 不保证用户程序持续健康，也不能用来宾 stdout 或清单自报代替管理通道检查。

`template_registry` 为可选可信配置，字段为 `root`（root 独占绝对目录，预建 inbox/artifacts）、`max_templates_global`（1～256）、`max_templates_per_tenant`、`max_artifact_bytes_global`、`max_artifact_bytes_per_tenant` 和 `validation_timeout_secs`（1～300，且不超过运行上限）；租户上限须为正且不超过全局。必须同时配置 `templates` 和 `host_resources`。首次启用升至 V10，并持久绑定唯一根目录，此后生产服务不可关闭登记配置，旧二进制拒绝新库。目录、数据库和私有盘须同文件系统，清理余量观察才能覆盖这些写入。

登记的 imageDigest 是实际使用的 linux/amd64 OCI 清单摘要：Dockerfile 为 BuildKit 导出结果，公开 OCI 为固定的源清单或选定子清单；Docker schema2 为转换后的 OCI 清单摘要，原始来源保存在 `public_source`。可变 tag 不代表跨构建固定来源，需要固定来源时提交 `@sha256:`。服务独立复算内核和根盘摘要，不证明 OCI 软件与转换盘内容等价，也不提供构建供应链认证。明确拒绝私有仓库凭据、任意宿主挂载、特权/GPU、多服务及不兼容镜像，不声称支持任意 Dockerfile。

候选 ext4 在构建 VM 内先格式化，再通过私有 loop 挂载复制完整根目录，使用内核文件系统写入并保留亚秒 mtime、UID/GID、权限、硬链接、符号链接和扩展属性；不跟随镜像符号链接。构建基础镜像须提供 GNU cp、mount/umount，固定内核须支持 loop/ext4，相关工具摘要写入候选清单。正常卸载及原 loop 关联消失的等待使用同一构建剩余期限，允许完成复制后的脏数据落盘；复制或卸载失败不生成成功状态。失败后尚存挂载的卸载和原 loop 回收共用独立的 5 秒宽限，不延长构建期限，也不能将原失败变为成功；剩余资源仍由外部监督器销毁整台 VM。卸载及关联回收完成后才进行 e2fsck、空间检查和完整磁盘摘要。宿主不挂载或解析候选文件系统。

工作器读取工具日志至 EOF 后，等待该工具退出仍受同一构建截止时间约束；输出已关闭不代表进程完成。超时或截止时间之后才观察到退出时按构建超时处理，并继续回收该工具的私有进程组，不能记为成功。

### 自助构建入口、部署与恢复

本批实现的是显式启用的 Sandproof 扩展，不是原 E2B 模板构建 API。运行与构建使用两个 `sandproof-server`、不同数据库/命名空间/状态目录/jail/UID 范围/cgroup 父目录。构建控制器只有独占可信凭据，启用 `internal_build_vms=true`，不可同时启用模板登记。第三个[监督服务](../tools/template_build_service.py)监听回环，由可信 TLS 前端转发构建路径，复用运行服务的 API key/租户；用户不能拿到构建池凭据或 VM 会话。临时模板启动检查仍占运行额度。

| 接口 | 输入与结果 |
|---|---|
| `POST /sandproof/template-builds` | `kind=dockerfile` 或 `kind=oci` 加公开 `image`；可选 `resources={cpuCount,memoryMiB,diskMiB,minFreeMiB}`、`timeoutSeconds`、`allowInternetAccess`；返回 202 与 buildID、state、deadline |
| `PUT /sandproof/template-builds/{id}/context` | tar/tar.gz，根目录有 Dockerfile；须有 Content-Length；超额/不完整拒绝，成功后不能覆盖 |
| `GET /sandproof/template-builds/{id}` | 仅本人；状态、有限失败原因；只有 Ready 返回完整模板编号/修订/摘要/形状 |
| `GET /sandproof/template-builds/{id}/logs?offset=0&limit=65536` | 按字节位置读至多 64 KiB，带 nextOffset；总日志受配置限制；当前在来宾构建结束后获取，不保证实时尾随 |

Ready 返回的模板形状使用 Rust `TemplateView` 的规范字段 `cpuCount`、`memoryMib`、`diskBytes`、`hostMemoryBytes`；构建请求的资源字段仍为 `memoryMiB`。Rust 序列化和 Harbor 适配共用[响应样例](../tests/compat/template-view.json)检查该边界。

不接受 owner、Ready、宿主路径、工具或凭据字段；陌生/他人编号均 404。可选 `Idempotency-Key`（1～64 个字母/数字/下划线/连字符）按租户绑定规范化请求，相同重提返回原编号，不同内容 409；缺省每次是独立工作。公开引用不接受凭据、本地 transport、自定义端口或显式 IP；私网与宿主地址保护仍依赖既有包规则，字符串检查不代表 DNS 安全证明。

日志页的 64 KiB 上限与 offset/nextOffset 按原始日志字节计数；无效 UTF-8 以替换字符展示。JSON 转义可能放大响应，小客户端仅对日志 GET 保留有界的转义与封装余量，其他响应仍限 64 KiB，不增加日志原始总量或单页预算。通用评测报告用 `build_log_error` 单独记录诊断读取/保存失败的异常类型，不覆盖原构建终态，不保存可能含凭据的异常文本，也不为取日志重发构建。

来宾 `build.log` 在获取输入、OCI 校验、rootfs 解包、平台安装、ext4 生成/检查和整盘摘要阶段记录 `[sandproof-phase]` JSON 行，进入阶段先刷新 started，退出记录 completed 或 failed。时间为同一工作器单调时钟的相对秒数；公开 OCI 的获取阶段包含其校验。诊断与工具/守护进程日志共享原总预算，不包含命令参数、路径或异常文本；失败后的诊断写入出错不得替换原异常。缺少结束行只表示诊断不完整，不代表该阶段或构建成功，来宾日志也不能替代外部期限、结果和清理证据。

工作器非零退出时，即使已写出状态文件或工具日志为空，也保存有限的来宾命令输出，不序列化含宿主连接信息的 SDK 异常。优先保留 stderr 尾部的异常原因，其余空间保存 stdout 前缀；与工具日志合并时共用 `max_log_bytes`，必要时截去工具日志尾部。非零退出不能仅凭候选状态继续下载或发布。日志获取仍不是清理完成的证据。

工作器命令等待发生 SDK 超时时，在进入原清理流程前尽力保存 `build.log` / `daemon.log` 的有限前缀，并明确标为不完整日志。两份日志共用 `max_log_bytes` 和 5 秒采集窗口，SDK 请求超时参数设为 1 秒；窗口到期不再发起下一次读取，已在途读取可能稍晚返回。此阶段只读取诊断字节，不读取候选或状态，不重启命令、不延长构建期限；日志缺失、传输失败或落盘失败均不替换原超时结果，SDK 异常文本也不写入用户日志。等待超时和保存日志均不代表来宾命令已终止，仍须独立确认原 VM 清理完成。

正常下载工作器状态、日志和候选盘时，共享原构建截止时间。[固定 SDK 的流读取](https://github.com/e2b-dev/E2B/blob/ccaf9fc0ffe6ac39c7ec786af7608ab1de19467b/packages/python-sdk/e2b/sandbox_sync/filesystem/filesystem.py#L207-L224)已将显式 `request_timeout` 用于整个传输的期限；应用层另在每次读取前后及流结束时核对原工作期限，统一不同下载阶段的剩余预算，不能将 SDK 描述为只有单次空闲超时。到期不再开新流、接受后续块或以迟到 EOF 提交候选，未完成临时文件按原流程删除。SDK 超时参数使用剩余时间，包括不足一秒的余量；正常日志的参数仍至多 30 秒。已在途读取或本地文件同步可能稍晚返回，此检查不承诺强制中断宿主 I/O；超时不代表 VM 已回收，仍保持原身份和清理占额规则。

Dockerfile 构建使用固定 BuildKit 的 `auto` snapshotter，在每项独占构建 VM 的私有工作目录中探测可用实现，避免强制复制完整父快照。固定版本的选择顺序为 OverlayFS、fuse-overlayfs、native，能力探测和回退由 [BuildKit 0.28.0](https://github.com/moby/buildkit/blob/v0.28.0/cmd/buildkitd/main_oci_worker.go#L368) 实现；实际选择保留在受限 `daemon.log`。仍保持 OCI 进程隔离、私有缓存目录与原构建资源/时限，输出照常经过 OCI 校验和独立候选盘转换。内核列出 OverlayFS 只证明驱动可用，不代表本次目录已通过探测或构建已成功。

Dockerfile 的固定 BuildKit 使用不推送、不登记的 image exporter，将 OCI 清单、配置和层留在本次私有内容存储。守护进程停止后，worker 仅按导出描述符将引用的普通文件硬链接到新的 OCI layout，避免在同一构建 VM 内重复复制大层。此路径限定 BuildKit 0.28.0 的单个 `runc-overlayfs`、`runc-fuse-overlayfs` 或 `runc-native` 内容目录；目录/文件符号链接、缺失或歧义的存储、大小/身份变化及不一致的清单/配置摘要均拒绝。硬链接不代表已校验：所有 blob 摘要、diff_ids、tar/gzip 完整性及累计展开/条目限额仍在 umoci 解包前检查，仍由 umoci 处理层删除和权限。固定版本的目录结构变化需要重新适配和实测，不能改用未验证的裸目录作为候选根文件系统。 完整校验成功后，worker 在 `build_cache_cleanup` 阶段删除本项工作已停止的 BuildKit 私有缓存（快照、元数据和原内容链接），再解包并生成候选盘；OCI layout 自己的链接继续保留同一清单、配置和层字节。清理失败即终止转换，由监督器回收原构建 VM，不继续分配候选盘；此清理不操作其他工作或宿主缓存。

候选盘转换使用固定 umoci 0.6.0 的 `raw unpack`，在新建的 0700 私有目录内提取 rootfs。它与普通 `unpack` 使用相同的层解包、ID 映射和 whiteout 处理，省去供 `repack` 使用的全目录 mtree 摘要扫描及未使用的 OCI runtime bundle 配置；不省略输入校验、候选磁盘完整摘要或启动验收。启动参数仍来自已校验的镜像配置，通过平台启动路径应用。此候选根目录不用于 umoci `repack`。

监督服务 root 独占配置包括 `root`、`bind=127.0.0.1:端口`、`runtime_config`、`builder_config`、七项 `tools={名称:{path,sha256}}`（原六项加固定 regctl）、`dns_servers`（1～2 个公开 IPv4 resolver）及 `limits`。Dockerfile 工作只传原六项 profile，公开 OCI 工作另外传 regctl 与获取模块；不能仅更新工作器而漏传工具。limits 为 `max_cpu/max_memory_mib/max_disk_mib`、`timeout_seconds`、`max_jobs/max_jobs_per_tenant`、`max_pending/max_pending_per_tenant`、`workspace_bytes/workspace_bytes_per_tenant`、`max_input_bytes/max_expanded_bytes/max_entries/max_log_bytes`。字段及配置示例见[实机探针](../tests/system/template_self_service.py)的 build 配置；生产需按本机资源填写，不复制实验数值。旧六项自助服务配置须更新，既有构建库的配置绑定变更需显式迁移。私有构建 VM 的同步准备请求使用该工作剩余的原构建期限，避免固定短 RPC 等待将大盘准备提前变为未知；已过期时不发起创建，丢失响应仍只观察原编号。

监督服务启动时还核对跨池必要条件：构建期限加 60 秒同时不超过构建池单次/总寿命；启动检查期限同时满足运行池两个寿命上限；构建池上传覆盖输入/工具及有界 HTTP 开销，下载覆盖完整候选；目标最大形状可被空运行池与发布产物额度接收。构建私有盘预算取私有 API 实际解析的已授权不可变 `base` 描述，不取可能不同的旧 `rootfs` 字段；声明长度须匹配真实文件。盘总量须至少容纳目标盘、展开上限和两份获取输入，实际来宾可用块仍由工作器检查。上述配置检查不是动态资源预留，不能替代运行时配额/真实余量或失败收尾。现有显式部署若不满足这些条件必须调整可信配置后再启用，不能静默缩短已接受请求。普通公网 DNS 仅接收 1–2 个公开单播 IPv4 字符串，拒绝数字、私网、组播、IPv6 与域名；构建与候选复用同一值，仍不承诺域名内容过滤。

独立 SQLite 采用进程锁与 WAL/FULL；材料/候选先同步再记录阶段。历史数量、未决数和保守工作盘预留分别限额；失败/未知清理继续占预留。构建实际 CPU/RAM/VM 私有盘上限由独立 Rust 池执行，不借用运行额度；同盘检查及预留保护运行清理余量。配置/预算指纹持久绑定，变更须显式迁移，重启不能隐式换池。总期限从提交起算，Rust 池另强制 VM 寿命，不因重启续期。

上下文上传沿用提交时的原期限：每次有界 socket 读取、末块/EOF、文件与目录同步、事务提交前都重新核对，不用不断到来的小块延长期限。超时只删除本次持有的精确输入 inode；文件被替换或删除结果未知时进入 `CleanupUnknown` 并保留预留，虚拟机缺席不能授权删除陌生输入。输入已提交为 Queued 而回复丢失时保留原输入，不因 HTTP 失败撤销已接受工作。

阶段为 `Preparing → AwaitingInput/Queued → Building → Cleaning → Publishing → Ready/Failed`；观察不了原 VM 时为 `CleanupUnknown`，不释放预留或再建新 VM。私有 `/sandproof/internal-build-vms/{buildID}` 在准入同一事务保存 buildID/请求，GET 能查未启动和已销毁身份；重复 POST 包括墓碑都不建替代。普通 create 拒绝 `_sandproof_` 保留 metadata。

重启后的 Building 不重执行用户步骤，只观察/精确回收原 VM 并报告 InterruptedBuild；完整候选已同步的 Cleaning 可继续收尾和同编号登记；Publishing 只推进原发布，不重构建。Ready 必须通过既有发布门及临时 VM 的精确回收。只有确认构建 VM、网络槽和相关未决动作全部回收才删除本工作临时输入/候选并释放预留；Destroyed 状态或 DELETE 成功不能替代 cleanupComplete。有限日志/历史保留，正式产物由登记预算管理。窗口模式另执行下述公开结果/日志退休；正式 Ready 模板及产物仍由独立登记额度保留并可继续使用，不随公开构建结果过期删除。未增加模板产物垃圾回收、多构建节点或原 E2B 模板协议。

原构建期限也限制发起新的发布请求：构建 VM 精确回收后已到期的候选不进入新发布；未有发布尝试且查询不存在时，在 staging 前后分别检查期限，POST 的等待使用剩余期限。POST 前必须持久提交发布尝试意图，提交后再次检查剩余期限。staging 跨过期限时，只在没有未决发布尝试且再次查询不存在后清理该候选并报告 BuildDeadlineExceeded。原 POST 明确返回准入前的 400/409/429 拒绝，或本次派发确认尚未调用 POST，才可持久清除该意图；超时、连接错误、控制器 408 和后续 GET 的拒绝均不能替代该证据。

GET 404 不是发布取消或未受理屏障：先前 POST 仍可能排队等待准入。存在未决意图时，即使到期、重启或多次查询 404，也保持 Publishing、候选和预留，只查询原编号，不重新 staging 或 POST。旧库迁移以同一事务增加意图字段并将所有旧 Publishing 记录视为未决；新工作默认未尝试。同一事务升级配置绑定的格式版本，使旧监督器拒绝重新打开升级后的库；原额度与运行池绑定必须完全匹配才允许迁移。提交意图后、发送前崩溃也保守保留，当前没有自动取消/不存在屏障，不能保证这类未知状态自动结束。原发布随后 ready/failed 的回执可完成记录并释放构建预留，但迟到 ready 不能据此声称调用方在原期限内完成。

显式 `bounded_builds` 启用公开窗口/有限结果模式，所有字段必填且无生产默认：`namespace`、`windows={max_open_windows,max_duration_ms}`、`retention_ms`、`max_request_bytes/max_result_bytes/max_record_bytes`、`database_bytes/wal_bytes/recovery_reserve_bytes`、`helper={path,sha256,owner_uid,max_input_bytes,max_output_bytes,timeout_seconds}`。namespace、窗口参数、helper 身份、预算和池绑定写入同一 SQLite 配置，重启不可变更或关闭。旧库只有显式 `migrate_legacy_builds=true`、原配置/池绑定完全匹配且条数/编码可纳入新额度时迁移；旧无窗口键始终在独立空 namespace 域，已接受 tuple 可查询，未见过的旧键永久拒绝，未知旧工作保持占额，绝不映射到当前窗口。不能删除数据库后复用旧 namespace；部署操作者必须保护独占根和永久部署身份。

公开接口 `POST /sandproof/template-build-windows` 接 `{durationMs}`，返回 `{requestWindow:{namespace,sequence},expiresAtMs}`；`POST /sandproof/template-build-windows/close` 接 `{requestWindow}`。窗口模式的 `POST /sandproof/template-builds` 必须同时给出同一 requestWindow 和 `Idempotency-Key`。先按认证 tenant＋namespace＋sequence＋key 查已接受账本，窗口关闭/到期后仍返回原 buildID，规范化参数变化返回冲突。仅不存在 tuple 时，在 `RLock + BEGIN IMMEDIATE` 内调用既有 Rust 窗口转换：先持久推进可信时间下界、再 Admit 和预留工作。过期/满额拒绝须提交已推进下界，不经通用异常路径回滚；系统时钟回退不能重新开放窗口。窗口签发前沿只增不回绕，关闭不撤销已接受工作。 公开 buildID 另由格式 4 的固定 SQLite 单行分配器生成：`namespace 的 16 位十六进制 + 全局作业序号的 16 位十六进制`，仍为原 32 位小写 hex 路径/协议格式。全局 highwater 以固定 16 位 TEXT 保存完整 u64，和作业准入同事务提交；事务回滚不暴露身份，提交结果未知须观察原 tuple，结果 GC 不删除或从幸存行重建前沿，耗尽拒绝而不回绕。因此旧 GET/PUT/私有 buildID 不能命中后来的工作，不以随机碰撞概率代替身份保证。显式旧无退休格式迁移扫描全部保留随机 ID，在同 namespace 前缀下高于最大 suffix 开始，原随机 ID/旧域继续保留；曾允许随机 ID 退休的格式 3 无法从幸存行重建历史，拒绝原 namespace 原地升级。配置或分配器记录丢失、前沿小于已登记身份均失败关闭；固定分配器页属于已有数据库/恢复控制页余量。

[一次性 Rust helper](../controller-service/src/bin/sandproof-window-reducer.rs) 只调用已有 `maintenance::windows::reduce_windows`；stdin 为唯一 `{version:1,state,input}`，成功返回完整 `{version:1,status:"ok",decision:{event,next}}`，核心拒绝返回 `{version:1,status:"rejected",reason}`。显式 argv `--max-input-bytes/--max-output-bytes` 限额读写，超限不得输出截断后继；协议错误码为 `invalid_request/unsupported_version/input_too_large/output_too_large/input_io`，输出至少容纳固定错误 framing（59 字节），不是生产默认。[Python 桥接](../tools/template_build_windows.py) 检查完整响应、受保护 ELF 路径/祖先/owner/摘要，以已打开 FD 执行同一 inode；最小环境、无 shell，有限 selector 读写、超时和精确 child reap。可信 owner、加载器与不可强制中断的宿主 I/O 仍是边界。helper 不读业务时钟、不持久化、不占用第二数据库、不实现另一套生命周期或请求窗口规则；唯一权威仍是 BuildStore 的 SQLite 事务。

接受时同时预留工作盘、未来日志和整条记录的最坏编码字节，`max_jobs` 同时约束活跃与未来保留结果数。candidate、failure、私有窗口/settlement、删除清单均受 `max_record_bytes`，不能只限制请求/最终结果。SQLite 设置 `max_page_count`，数据库额度至少覆盖所有最大记录、索引和迁移/更新余量；WAL 额度至少覆盖两倍数据库页及 framing，另留 recovery reserve。独占单连接所有写事务之前必须成功 TRUNCATE checkpoint，再以 FULL 提交；本服务不允许跨事务流式 SQLite 读游标，外部旧读者阻挡 checkpoint 时拒绝写入/新准入，不能释放清理占额。temp_store 使用内存，有界查询/记录限制其输入；数据库、WAL、恢复/SHM 余量均纳入 workspace 和真实磁盘准入。DELETE 后空闲页可复用，不声称文件立即变小；这不是对绕过独占服务的外部写者、无限未关闭外部读者或整台宿主的配额承诺。

提交文件阶段先提交 Preparing 行/nonce/容量，再创建精确 `.prepare-{buildID}`，同步身份 marker 后原子 rename 到最终目录并同步父目录，最后提交可派发状态。专属 root 租约下该未发布 staging 的空目录或与 nonce 精确匹配的 marker 前缀可恢复；任意最终目录、未知名称、类型、内容或替换 inode 均保留并失败关闭。结果退休须同时满足终态、原窗口已关闭、从终态起 `retention_ms` 已过、构建外部工作已结算、私有 ack 已记录、发布已终结且无未决 staging 删除。先提交 Deleting 与精确设备/inode 清单，再逐文件删除/目录 fsync，最后移除账本；中断仍占记录额度。固定发布 staging 同样使用 nonce marker 和事务内删除清单，不递归接管外来目录；未知 publication_attempted 仍按上文永久保守占额。

私有池须显式配置 `build_retry_windows={window_duration_ms,max_anchors}` 并启用 bounded_host/maintenance。监督器先向 `POST /sandproof/internal-build-windows` 签发窗口，将原字符串窗口持久写入公开作业后才 POST 原 buildID；GET 同样带原 requestWindow。收尾先在 `/sandproof/internal-build-windows/{window}/close` 建立持久准入围栏，再解释 GET404。实际 cleanupComplete 或围栏后确切缺席后，先在公开 SQLite 提交原 `{requestWindow,sandboxID}` 的 builder-settled 证据，再 POST `/sandproof/internal-build-vms/{buildID}/settle`，收到 ack 后持久记录。ack 丢失只重发原身份和已保存证据；没有保存窗口意味着尚未派发 VM POST，旧域未知工作不享受该推断。窗口关闭不消灭已接受的迟到 POST。

普通用户用[小客户端](../tools/template_build_client.py)，凭据从 `SANDBOX_API_KEY` 读取：`--url https://构建服务 --build-mode windowed --intent 原请求.json --context context.tar.gz` 或 `--image public.ecr.aws/docker/library/ubuntu:24.04`。旧部署须显式选择 `--build-mode legacy-unbounded`，不调用窗口接口。两种模式均先同步保存原 key、原请求及上下文摘要，窗口模式另保存 namespace/window；intent 同时绑定服务地址、模式及凭据摘要（不保存凭据），冲突或切换均拒绝。未知回复后重用同一 intent，绝不自动换窗口。通用任务链也先同步相同信息；明确 `legacy-unbounded` 兼容模式不声称满足窗口/退休保证，不允许从窗口请求失败静默降级。两个硬件配置生成器须明确选择 `--legacy-unbounded` 或 `--bounded-policy`；后者仅透传显式 runtime/builder 的 bounded_host/maintenance、私有 build_retry_windows 及 public 的 bounded_builds/独立 workspace 字节预算，并复用配置检查，不生成生产默认。收到模板编号后仍使用原 E2B SDK create，普通沙箱创建合同不添加窗口/键字段。

鉴权扩展接口：`POST /sandproof/template-publications` 接 `{candidateID}`；`GET /sandproof/template-publications/{candidateID}` 返回 checking/ready/failed 与有限原因；`GET /sandproof/templates` 只列本人 Ready，编号升序、limit 1～100、cursor 为上页最后不可变编号；`GET /sandproof/templates/{编号或别名}` 查询本人 Ready。`PUT /sandproof/template-aliases/{别名}` 接 `{templateID, expectedTemplateID?}`，可比较后更新，目标必须本人 Ready 编号；DELETE 只删本人别名，不删产物/实例绑定。静态目录名称保留；未知、未就绪和他人模板均不可创建。别名更新只影响新准入，旧实例/重启始终绑定原字节。响应不含宿主路径、临时 VM 编号或凭据。这是 Sandproof 发布扩展，不宣称原生 E2B 构建协议完全兼容。

发布登记完整计算候选内核和磁盘 SHA-256 后，可向同进程工作器传递不可序列化的校验记录。密封目录移入正式路径后，工作器首次接收该记录时，只有在精确描述符、设备/inode、长度、修改/变更时间、属主/组、权限和硬链接数均未变化且完整路径可信时，才预置摘要缓存。后续节点缓存沿用既有设备/inode、长度、mtime/ctime、期望摘要及可信路径检查，不直接逐次比较属主/组、权限和硬链接数。记录失效或缺失时不预置缓存，仍执行原节点校验；没有有效本地缓存时完整重算，服务重启会清空该缓存。复用延续原节点缓存的部署前提：可信准备方在候选交接前关闭全部可写句柄，暂存和正式产物此后由可信 root 独占且保持不可变。只读权限和 ctime 等文件身份观察不是不可变性证明，不保证发现时间戳粒度内的所有写入，也不防御可任意修改宿主文件的 root。此记录不代表 Ready，不能替代宿主模板校验、资源准入、真实启动及临时 VM 精确清理。校验前后同时核对打开文件和路径身份，可观测身份变化拒绝登记。

模板启动合同：仅 Linux/amd64 的 Debian/Ubuntu 兼容镜像；空 OCI USER/WORKDIR 按 root/根目录处理，不复制固定 E2B Dockerfile 解析器的 user/home 默认值。数字 UID 或 UID:GID 在构建 VM 内按有界账户文件解析为真实用户名；显式组必须是该账户的主组，否则拒绝（固定 envd 不支持替换主组）。目录须已存在，启动参数有数量与字节上限；Env 重复键后者优先。模板默认环境 < 创建环境 < 单次命令环境；显式命令用户/目录优先于模板默认值。无 `startup` 的旧镜像仍使用 root 和 envd 的每用户主目录，不改变旧合同。

节点把默认用户、目录及合并环境写入受鉴权 `/init`，不把镜像环境注入可信 PID 1/envd。启动 argv 是 Entrypoint 后接 Cmd，原样发给 envd，不拼接成 shell 脚本；shell-form 本身由标准构建器转成 argv。空 argv 不启动用户进程。发送前把绑定原 VM/PID/启动时刻、不可变模板与创建环境的意图同步到 root 独占记录；收到完整 Start 事件后才持久确认。确认后的激活恢复不重复发送；未知、损坏或身份不符保持未知并由独立启动期限中止原 VM，不能发布 Running。启动事件只表示进程已启动，不承诺应用健康、持续存活或退出码为零；用户程序可退出而管理通道仍保持可用。正式发布仍需独立检查，不能把此合同说成任意 Docker 容器或原生 E2B 构建接口完全等价。节点启动意图/确认记录随现有不可复用 VM 编号保留作审计，不是存活资源占额。

- 用户构建输入为 Dockerfile+上下文或公开 OCI 镜像；受限构建/转换服务返回构建编号、状态、有限日志和失败原因，只有产物与启动检查完成才发布模板。未知构建不能换成成功或自动重建。
- 模板描述包含 owner、不可变修订、镜像/清单摘要、内核/envd/启动配置和 CPU/内存/磁盘形状。用户名称不是宿主路径；构建输入及镜像层解包均需路径/权限检查。
- 创建先验证归属与就绪、解析别名一次、校验资源并把精确修订/清单与获批形状同创建意图持久提交。别名变化或服务重启不改变旧实例；准备/观察/恢复只使用该绑定，不追踪别名最新值。
- 软件、资源形状和实例分别记录；形状在构建/注册时选择，创建选择模板，不新增固定 SDK 不存在的 CPU 字段。总盘容量、构建后最低空闲空间及管理环境占用分别表达；适配 Harbor 时不能忽略其 storage 要求。
- ENV/WORKDIR/USER、CMD/ENTRYPOINT 与必要服务如何转换逐项说明和测试；未支持输入早拒绝，不忽略后冒称容器等价，不替换可信管理初始化。
- 构建在独立、限额、可回收环境运行，不接触生产管理凭据/数据库、宿主 Docker socket 或特权挂载；构建与运行预算分离，不能占用旧实例收尾预留。失败只清理原身份资源，不误发布 Ready。

此模板子系统（含自有编排和登记/发布）整体在证明边界外；核心使用上述正确授权、不可变产物和准确资源描述作为未证明的外部合同。工程检查和测试仍必须交付，不能借此排除核心执行资格、实例绑定与精确清理的后续证明。边界与状态见[覆盖记录](proof-coverage.md)。未启用预制目录的部署仍只有 `base`；启用后的字段与筛选遵循本节绑定规则，不重开已交付 #12。

节点运行器的首批实现及实机运行方法见 [`sandbox-runtime`](../sandbox-runtime/README.md)。其 `vmm_running` 只代表虚拟机监控器状态，不能当作可用沙箱成功回执。[宿主适配器](../sandbox-node/src/linux.rs)已在隔离 Linux/KVM 测试中补上 envd 健康、鉴权初始化、网络策略和独立磁盘检查，只有这些观察完成才向控制核心回执成功。它还可只读枚举已登记的 VM/网络槽/私有盘，并对丢失的准备和停止回执重新观察；控制器重启时先核对宿主资源与持久计划，再接续可确认的动作。启动盘点对无法归属、身份不符或共享日志损坏的资源仍整体拒绝启动；只有当未写进程记录的 claim 精确对应当前未决 `PrepareVm`、owner、代数、VM 与槽位均吻合时，才交给逐沙箱补偿。该补偿观察失败只阻断所属沙箱，不阻断其他沙箱，但不能因此发布 Running 或释放其配额。

VM 启动前的门控要求先持久化精确进程身份，避免 VM 已运行但无身份记录；网络空间创建前还需同步登记意图。对“准备动作不确定、槽位和持久计划精确匹配、进程记录从未落盘”的情况，启动恢复先核对无 jail、无网络空间内进程，再回收部分网络并留下不可复用的失败标记；若有精确进程记录但进程确已退出，则先核对并清理私有盘和网络，再留下失败标记。仍存活、无法观察或身份不符的进程继续保持未知，不按名称猜测清理。新准入把 VM/槽位编号与创建意图一同持久提交：预留编号本身不代表宿主动作已发出；尚无任何宿主动作被认领且凭证缺失时可补写，动作一旦被认领则不得换发，保持未完成并等待核对。公网与静态 IPv4 出站仅在显式开启的隔离部署完成选定实机测试；受控 DNS 和完整崩溃对账仍未接通。

周期扫描现在也处理准备动作的部分资源：先核对当前操作编号、owner、时期、代数及 VM/槽位计划，再由宿主检查精确进程和网络身份；独立启动期限未到时，存活或不可观察的 VM 不作猜测。首次非终止围栏在动作已登记但尚未写入宿主时中断，只能在原创建仍为当前、未进入终止阶段时补全；宿主围栏仍拒绝从终止态倒退。停止动作中断后，只有当前终止操作与原 VM 停止计划精确匹配，宿主才可对持久进程身份执行幂等停止并重新观察；这不是重派发任意结果未知的动作。清理动作若在虚拟机确已停止后丢失回执，则只在当前终止操作与资源绑定精确匹配时幂等完成清理，再记录回执。启动期限到达后的受限中止路径见下文；它已有组件测试，真实 KVM 测试由[专用脚本](../tests/system/server_unready_abort.py)单独验收。完整服务进程的任意位置强制终止，以及公网与静态 IPv4 模式下的全部故障组合仍未验收。

每项持久动作至少绑定：协议版本、sandbox、owner、operation、epoch/generation、逻辑动作 ID、attempt ID、精确资源 ID、动作参数。只有已提交动作可派发；B 的控制入口不向沙箱或公网开放。宿主槽位登记同时持久记录 owner、sandbox、generation、VM 和槽位；后续动作（包括停止和清理）与只读回执均核对 owner。重启回收在删除任何物理资源前也核对槽位 owner 与控制器持久沙箱 owner。旧版缺少 owner 的槽位记录会被拒绝，不能悄悄按新格式解释；升级前须先让旧沙箱安全销毁并清理。

B 检查动作身份、当前执行资格、终止围栏和真实资源归属，返回以下结果之一：已观察成功、明确失败、尚未知。超时不是失败证据。只有明确可重试失败、没有待核对的部分资源，且 A 的持久状态和预算检查也允许时，才能创建新的尝试；重发同一未知动作不能凭空分配第二个 VM。

回执包含完整动作身份、观察对象及结构化结果，不能仅有 `success=true`。A 决定是否接收当前回执及是否推进阶段；旧动作的回执不授予新代数权限。

### Harbor 逐试验产物保留边界

[SDK 适配](../benchmarks/sdk_environment.py)使用同一逐试验预算累计原 Oracle/Verifier 下载、递归目录/文件尝试、命令事件与另存的包清单/环境诊断。字节、条目、深度和单文件上限由运行器显式配置，单文件仅可在既有 96 MiB 硬上限内调低；失败、重试、覆盖同一路径和诊断回退均不返还已记账额度。空文件也占条目，目录遍历和新建本地父目录另占条目；命令在派发前预留事件/命令文本额度，返回输出按实际 JSON 转义长度计费，超量必须失败而不能静默截断后通过。固定 SDK/网关仍可能先缓冲一次有界命令结果，本预算只界定保留量，不是进程内存上限。

文件使用固定 SDK 的异步流接口，逐块先记账后写同目录独占 `.partial`，完整结束并关闭流后才原子替换目标；读取/关闭由独立任务持有，取消后最多等待同一 5 秒清理期限，避免中断固定 SDK/HTTPX 的 EOF 内部关闭。关闭失败或期限耗尽在 `stream_close_failure` 独立记录失败/未确认（不被较早预算错误覆盖），不声称连接已释放，也不无限阻断 VM kill；原取消/读取错误仍传播。取消/失败只删除本次精确临时 inode，既有目标与其他临时文件不动。不接受宿主路径越界、符号链接、重复/非规范目录项或超过深度的树；目标根须为当前用户独占目录。来宾文件元数据中的符号链接明确拒绝，元数据与读取之间的来宾修改仍不是一致快照保证。过滤下载入口明确拒绝，不回退到上游宿主临时 tar 解包。字节限制是接收后、写入前的有效载荷记账，拒绝时至多已收到当前 SDK 块；不包含 HTTP/TLS 头或底层缓冲，不能称为精确线上传输配额。

失败证据单独记录 `artifact_budget` 与 `evidence_complete=false`；即使原 Oracle 吞下下载异常，运行器也不能报告完整通过。原阶段结果及已经取得的原奖励保留，不伪造/改写评分。预算违规后后续产物与诊断请求拒绝，但精确 SDK kill 始终独立尝试，未知收尾仍保持未知。输入 context、构建日志/检查点、原奖励字典与 result/full-set/report 元数据不在本有效载荷上限内；它不是整个试验目录或宿主全局写入限额。批次容量集成须另加“每试验上限 × 选定题数 × 重复次数”，同时为这些排除项、服务日志/数据库及收尾留额，不能用该乘积或配置默认值声称硬件容量已验收。

## 数据通道：C → A/B → 来宾

命令和文件请求先经过身份、所属沙箱、阶段和能力检查，实际执行时再确认仍指向同一有效实例。请求通过检查到实际发生副作用之间必须有明确的执行资格/撤销规则，不能只依赖入口处的一次检查。

当前复用固定版本的 E2B envd 来兼容命令和文件协议；B 负责部署与传输，C 负责 SDK 接入和网关，A 负责执行资格。M0 记录实际选用版本和必需改动，不能仅因传输层可通就宣称 E2B 兼容。

来宾可运行不可信代码，甚至获得来宾 root。来宾回复不作为宿主 VM 已停止、宿主网络已隔离或资源归属的唯一证据。控制凭据与宿主管理入口不得因复用 envd 暴露给来宾。

普通用户命令可能有任意副作用；不承诺任意命令恰好执行一次。命令发送后连接中断时保留结果未知，通过已知句柄查询/终止；不得自动再运行一次同样的 shell 命令。命令执行超时、等待回复超时和沙箱寿命到期分别处理。

固定 SDK/envd 的命令期限必须按接口解释：`commands.run(timeout=...)` 同时限定 Start 流和进程执行，envd 在执行期限到期时终止进程；`commands.connect(timeout=...)` 只限定本次连接流，不重置原命令执行期限。`wait()` 沿用所在流的期限，没有单独超时参数。同步 run/connect 忽略 `request_timeout`，异步调用用它限制首事件等待。负数流期限由 SDK 转为 1 ms，零关闭该期限；超过十位毫秒头范围的期限由 Connect 明确拒绝。客户端收到超时仍须查询/连接已知 PID 核对实际结果，不能直接推断进程已停止或再次启动 shell；执行期限、连接期限及沙箱寿命的实测范围见[验收清单](testing-plan.md)。

命令启动、等待、重连与终止是不同操作：连接断开不能解释为来宾进程已终止，命令超时不能解释为沙箱寿命到期。文件写入或传输中断可以已产生部分来宾侧内容；只有完整成功回执才可作为完成，失败不得宣称原子覆盖或自动回滚。HTTP/1.1 是现有传输要求，不是单文件 8 MiB 上限的协议来源；总量限额、流式内存界限归 #8/#12 验收。

## 状态与持久化：A

V1 采用单节点 SQLite 事务存储路线。Redis、多节点共识和存储引擎内部证明不在 V1。

[#4 的首批持久化代码](../controller-service/src/lib.rs)使用固定的 `rusqlite 0.40.2`（启用内置 SQLite，具体依赖以 `Cargo.lock` 为准），在本地可信文件系统上使用 `WAL`、`synchronous=FULL`、外键检查、`trusted_schema=OFF` 和 5 秒忙等待；写入及派发领取使用 `BEGIN IMMEDIATE`。这些配置可由 `storage_settings` 读取以记录测试指纹。[SQLite 官方说明](https://www.sqlite.org/pragma.html)解释了 WAL 中同步设置的区别，但目前只测试进程中断与重启，不声称已经验证宿主掉电、磁盘损坏或网络文件系统。部署方还须提供仅控制器可访问的数据库目录，并连同 WAL 辅助文件一起管理与备份。

底层 `Journal` 将同一控制决定给出的 sandbox、operation 状态字节与待执行动作原子写入。其上的 `ControllerJournal` 已接入既有 `controller-core`：旧模式从初始状态重放已接受输入；显式格式 4 从经过验证的版本化当前状态检查点和连续输入尾恢复，不反序列化任意 `World`，也不另写生命周期规则。输入历史、查询投影、后续动作在同一事务提交；成功回执所对应的资源状态更新也在该事务内。恢复需使用兼容的控制核心和输入格式；升级改变重放语义时必须迁移，不能直接复用旧库。

#99 身份分配基础层将控制器数据库的基础 `PRAGMA user_version` 原子升级为 2；通用 `Journal` 仍使用基础格式 1，旧二进制拒绝控制器的新库。`controller_meta.version` 的 V7/V8/V9/V10 功能门保持原义，不因基础格式升级启用模板或登记。迁移在同一 IMMEDIATE 事务中完成完整重放、从既有核心身份与 SQL 行播种高水位及格式切换；格式 2 缺失/非法计数器失败关闭，重开不得从当前最大行号重新播种。服务生成的 sandbox、每沙箱 operation、逻辑动作映射、输入序号、outbox 和回执历史序号使用持久高水位；原有公共字符串格式不变。sandbox/operation 保存规范十进制 u64，SQL 身份使用检查后的正 i64；输入序号最多为 `i64::MAX-1`，给现有连续重放的下一序号检查保留哨兵。VM/槽位/快照/manifest 仍使用核心已有分配器，不增加第二份真值。

高水位只随实际接受的工作在原事务中推进；只读编号提议不消费身份，拒绝或确认回滚不消费，提交不确定时须依现有缓存失效边界重新读取持久状态。新操作准入前拒绝任一已耗尽的 SQL 身份家族；批量分配先检查整个批次，不能环绕或退回 SQLite 随机 ROWID。创建已经持久接受后遇到后续耗尽仍返回结果未知并保留原身份，不伪装为无副作用拒绝。本层没有预留整个未来工作流的重试、停止、回执和清理编号；完整工作流容量预留仍待实现，不能据此宣称持续服务或所有已接受操作必然完成。

身份高水位基础层本身不删除历史、宿主 claim/fence 或旧幂等键；未启用下述格式 4 维护时，每沙箱 operation 高水位仍随历史沙箱数增加。格式 4 只在纯核心退休、精确 SQL 闭包删除和永久身份前沿保留的同一事务内删除该沙箱 operation 高水位。可信底层显式身份输入仍由原核心检查，不增加“低于高水位一律拒绝”的新合同；因此当前高水位只保证服务生成路径不因保留行减少而倒退，不是完整的 GC 后旧身份拒绝证明。

`ControllerJournal` 的旧模式在打开时从完整输入历史重建 `World`；格式 4 使用下述检查点与输入尾。两种模式在单写者租约期间共用仅驻内存的已提交 `World` 缓存，其不变量是等于同一打开身份下最新持久恢复映像的核心状态。每个写事务持有私有候选；唯一输入追加入口逐项推进候选，覆盖创建与预留、Worker 与 Receipt、批量启动补偿等多输入事务。只有 SQLite 确认提交后才以所有权移动发布候选，且先于 AfterCommit/AfterDispatchClaim 故障点；派发时的 Worker 资格预演不得发布。确认回滚保留旧缓存，提交不确定或回滚无法确认则整体失效；同一对象后续读取必须先确认连接不在事务中，再在同一 SQLite 读取快照内从持久恢复映像重新建立状态，否则失败关闭。缓存没有独立序号真值来源，也不以最大序号检查代替逐输入推进与单写者合同。

缓存只保存核心 `World`，不保存 SQL 寿命、模板状态或授权结果。SQL-only 写入同样经过提交/失效边界；每次授权仍核对当前服务时钟、持久期限与核心权限，授权和撤销订阅仍在原管理锁内原子完成。kill、到期及 set_timeout 的不确定提交继续撤销已有数据通道。全局管理互斥锁及宿主 I/O 期间持锁保持不变；不引入并行宿主派发或另一套生命周期状态机；缓存本身不充当持久检查点。

底层公开 `Journal` 拒绝打开已由控制器标记的数据库，其每个写事务还在 `BEGIN IMMEDIATE` 后重查标记，阻止在控制器打开之前取得的旧句柄绕过缓存。缓存绑定同一 SQLite 连接的 `data_version`，打开时在重放事务内取值，写入时在 IMMEDIATE 事务内复核；其他连接的提交（包括旧历史或 SQL 投影修改）使本对象失败关闭，须停下、核对原库后重新打开，不能仅重放核心便自动认可外部投影变化。这是对可信单写者合同的保守检测，不是恶意宿主/直接磁盘修改的完整防护或多写者支持。普通读取连接不改变此版本，自己的提交不刷新外部版本基线。

控制服务持有数据库进程锁，派发期间独占控制服务写入口；生产调用方不得绕过它用底层 `Journal` 另行写入。动作先在库中标记已派发，再调用工作执行器。标记后尚无最终回执的动作在重启时保留为“结果不明”，不能自动再次执行；一般情况下，同一沙箱后续生命周期写入拒绝，直到可信宿主观察解决未知结果。终止调度的受限例外是当前创建的 `PrepareVm` 结果未知而独立启动期限已到：控制器先在同一数据库事务中提交失败补偿意图，再安装终止围栏；仅当前密封计划的原 VM 和槽位可以安排 `AbortPrepare`。宿主核对 owner、沙箱、时期、代数、槽位和持久进程身份，用 pidfd 停止并观察精确退出，完成私有资源清理与失败标记后才返回成功。原准备命令绝不重派发；晚到的启动成功不能撤销终止决定。失败发布必须覆盖计划中每一个预留 VM 和槽位，不能用空资源索引当作“已清理”。中止动作回执再次丢失时，重启只核对并幂等完成同一动作。此例外依赖 V1 的单控制器进程锁与串行宿主派发；若改成独立并发 worker，必须先增加宿主级启动闸门与终止围栏的原子协调，不得直接沿用该安全结论。除下述同一初始化的重复完成外，其他未知动作仍保持拒绝，不因定时器重做。旧动作必须仍通过核心工作入口的资格检查，才可送往宿主。

`ActivateVm` 的重复完成只针对固定 envd 0.9.0 的受限初始化请求（同一访问令牌、绑定模板默认值和创建时持久化的环境变量），不是重放任意工作命令。控制器先检查动作仍为当前创建的未完成尝试，owner、操作编号、时期、代数、密封 VM/槽位计划与已配置网络完全匹配；宿主再核对非终止围栏、工作区绑定和原 VM 进程身份，按原持久凭证发送相同 `/init`，并在前后观察同一进程及鉴权文件接口。含模板启动程序时，还须符合上文一次性启动合同：只复用已确认的启动，不重发未知命令。凭证、默认值或环境变量不一致、VM 身份变化、envd 不可观察都不得生成成功回执。恢复在宿主调用前检查持久启动期限，调用后再检查一次；到期先持久提交终止意图，不再初始化或探测旧初始化的来宾结果，迟到成功不得发布 Running。

未知初始化的终止例外仅允许当前创建、原密封 VM/槽位计划内的终止围栏及精确 `StopVm`。停止成功回执和终止围栏均已确认后，核心 `RetireActivation` 将旧动作标为 `RetiredByStop`，保存原操作、停止时期/尝试及结果摘要；不伪造初始化成功或明确失败。服务在同一事务中提交这一输入与查询投影，从重放后的核心状态派生剩余工作；outbox 的派发/回执列保留历史事实，退休不会填补缺失回执，不能只统计 `dispatch_state='dispatched'` 判断尚未完成。V7 存储标记拒绝旧控制器打开；V6 及更早输入继续按原顺序重放，不重置寿命或改写历史回执。失败发布仍要求真实停止及访问撤销，资源配额仍待清理回执后释放。初始化的迟到新回执被拒绝，已确认回执的相同重放仍是无状态变化；停止未知或身份不符继续保持未完成。此规则不覆盖任意未知网络动作、不引入并行 worker，也不依赖来宾恢复响应。

启动和周期恢复按沙箱身份处理宿主结果：某个沙箱的精确资源检查失败、宿主观察不能完成、单条回执身份/证据被拒绝，或本沙箱的工作流程仍无可信结果时，本轮不再推进该沙箱，也不报告它销毁成功或释放其资源占额；其余沙箱可以继续恢复。对于尚未终止的 `ActivateVm`，来宾不可观察同样保持原动作未知；只有启动期限已持久到期并进入终止流程后，才跳过来宾请求、核对原 VM 的停止。恢复报告区分未完成总数与本轮出错数，常驻扫描器记录出错数量。到期销毁也逐台接收和收尾，第一台停止不明不会推迟已到期的其他沙箱。共享 SQLite 故障、重放损坏或提交结果不确定无法限定到单个沙箱，立即停止本轮扫描并上报；任何一种局部隔离都不把未确认的宿主动作解释为成功。

宿主适配器通过 `HostEvidence` 提供具体命令与资源的成功观察；来宾回复或外部 API 不得直接构造它。部分完成视为未知，不直接重试。明确失败映射到核心的失败类别，并要求回执的可重试标志与该类别一致；不一致时拒绝回执并保留待核对状态，不擅自授予重试。创建流程对“无部分副作用的明确失败”现在通过核心的重试预算分配新尝试；预算耗尽或不可重试时提交失败证据、关闭围栏、精确停止已登记 VM、发布失败并清理。真实 Linux 工作执行器目前把无法确认无副作用的错误都返回未知，不能把合成故障测试等同于真实部分失败已自动补偿。未知观察允许被后续最终观察解决，历史回执保留；最终回执冲突被拒绝。

外部资源编号由部署方提供的唯一 16 位小写十六进制命名空间与核心编号组成；该命名空间持久保存，跨部署唯一性是部署合同。数据库所在目录仅允许可信控制器访问，进程锁不防范恶意宿主或绕过服务的数据库写入。未启用格式 4 时，打开及缓存失效仍重放完整历史；格式 4 按下面的单库检查点协议恢复。正常读写复用已提交缓存，仍有当前状态复制/扫描成本；不宣称固定复杂度、吞吐 SLA 或已经完成整体容量保证。

SQLite 提交本身若报告结果不确定，调用方必须按操作编号重新查询，不能把它当成未提交并直接重试。创建与销毁的编排已通过环回 HTTP 服务接上真实宿主适配器。创建级环境变量与元数据在接受创建的同一事务落盘；前者随 root 独占的来宾凭证记录传给 envd 初始化，重启时与已接受值逐项比较，不匹配则拒绝继续；后者由管理查询返回，不授予权限。创建级环境变量作为该来宾的命令默认值，root/ubuntu 均可读取；单次命令的同名 envs 覆盖只影响该命令，不修改后续默认值或其他 VM。metadata 仅为管理数据，不自动注入环境；查询与分页筛选在服务重启后保持相同值，并重新核对调用者归属。重复 kill 若仍处于撤销中，只观察并接续原持久操作，不分配第二个操作编号；观察不明继续返回未知。两个独立 create 在没有客户端幂等键时仍不合并；真实宿主完整恢复属于 A04/#11。

只有 A 更新业务状态；B 的本地资源登记是观察依据，不能成为另一个可独立改写业务状态的控制器。提交、派发、回执记录及状态发布必须有可注入崩溃的位置。恢复扫描先核对身份和实际状态，再安排重放或清理。

允许 controller/worker 进程被终止后重启；宿主持续运行、可信存储按合同工作。宿主掉电、存储损坏及恶意宿主不在首版故障保证内。后续若扩大故障域，须新增合同和实验。

### #99 有界维护与物理位置复用（显式启用，未实机验收）

宿主目录身份（#223）：启动闸门放行之前，运行层独占创建 jail/root，并将资源名、UID/GID、物理位置、parent/jail/root 的设备、inode 与 Linux `statx` 创建时间持久写入 `jail.json`；文件系统不提供创建时间时拒绝新启动，不退回仅凭名称删除。停止仍按原 PID/开始时间执行；清理只处理原登记目录，使用已打开目录描述符遍历、不跟随链接，并在最后删除目录项前重新核对身份。目录消失后保留原登记直到既有精确退休协议完成；同名替换、上下文改变、登记损坏及缺登记的旧目录保持未知，禁止在清理现场补认领。旧记录且目录已不存在可继续收尾。恢复观察须核对同一登记，不能将陌生目录里的磁盘视作原资源。`jail.json` 及固定 staging 都纳入宿主登记/退休清单和清理空间推导，旧额度不足则拒绝准入。目录修改在原宿主串行边界与 claim 锁内进行；额外的特权写者、任意并发挂载或伪造文件系统身份不属于部署边界。实现中的登记、比较、闸门和退休衔接仍是本项目待证明代码，不因依赖系统调用而整体排除。

纯核心基础之上，服务、管理适配器和 Linux 宿主已接通显式 `bounded_host` 物理位置复用；只通过云端组件/事务/合成传输测试，未执行本版 KVM、root 网络或长期宿主容量验收。未配置时维持原模式。公开原始维护入口仍拒绝。另显式配置顶层 `maintenance` 后，格式 4 的受限无 outbox 路径已接通退休、结果过期、检查点与覆盖输入删除；请求窗口迁移另见自助构建合同。增加明确的 `maintenance.capacity`、`console_policy=discard` 和下述物理部署 profile 后才属于完整容量模式；生产入口拒绝缺少 capacity 的顶层维护配置；库级无预留模式只保留作组件/迁移测试，不获得未来收尾或物理空间保证，组件检查也不代替实机验收。

- 显式启用维护时从已重放的 sandbox/workspace 记录固定身份前沿；此前的乱序显式编号仍按原语义重放。此后新创建必须同时高于两个前沿，只有接受才推进，删除历史不降低它们。零是合法编号；最大整数不回绕。老的活跃对象可以继续服务，不阻止更大编号的终止对象独立退休。

显式 `bounded_host` 必须同时提供完整 `data_transfer`；固定逐位置 route cell 额度、全局额度与控制预留分别从既有 `max_transfers_per_vm`、`max_transfers`、`control_reserve` 派生并持久绑定，不接受重复填写派生字段，也不使用隐含默认值。`bounded_host` 的 `uid_base`、`uplink_base` 与 `maintenance` 均必填；`maintenance` 包含 `max_host_slots`、`max_retained_results`、`windows.max_open_windows` 与 `windows.max_duration_ms`，不接受拼错字段。`uid_base` 必须与节点配置一致，完整 UID 范围不得包含 root/保留 UID；`uplink_base + max_host_slots - 1` 必须在有限 /30 池内。旧 `max_vm_id` 在显式模式下不再限制永久 VM 身份，只保留其旧模式意义；新模式仍在 u64 身份耗尽时拒绝，不回绕。构建/运行池任一启用该模式时，无论当前公网开关如何，两池保留 UID 和地址范围都须互不重叠；namespace 只区分名字，不能区分地址。全旧模式配置行为保持原样，不能据此断言其跨池地址已隔离。

首次启用仅支持空控制器日志与独立核对为空的旧宿主目录/资源；非空旧部署须另行迁移，本批不自动采用旧 residue。服务先只读预检数据库，再启用宿主，最后在 IMMEDIATE 事务重检并将基础 `user_version` 升为 3；`controller_meta` 既有功能门不变。关闭或改动已持久 UID/地址/位置配置均拒绝，旧二进制不能打开新库。格式 3 的 SQL 逐位置上下文在打开时与原 Bind 输入逐项核对；格式 4 从检查点中已覆盖的精确上下文见证加连续 Bind 输入尾核对，不能重扫已删除前缀或只相信一个更小的前驱编号。

释放先提交核心 Releasing，再调用宿主。管理器持锁核对旧工作、构建/发布引用和已撤销数据通道；响应 body 与 relay 都持有 RAII pin，发送撤销信号不代表已排空。每个同步宿主 helper 有独立固定 marker，每个并行 relay 占用一个固定 route cell；子进程在 stdin 启动门后阻塞，精确 PID、启动 ticks、boot 身份、位置 incarnation 与命令摘要同步落盘后才准许同 PID exec。控制器或监督进程退出、子进程关闭继承 FD 都不能抹除未决证据；匹配的 zombie 仍占位，只有确切 reaping/进程消失才可重用。原动作执行资格在 relay 真正派发前再次核对。relay 取消与早期错误由预先建立的精确子进程 reaper 接管，不能丢弃 std Child 并累积 zombie；迟到完成不得按 cell 编号清除后来者。route marker 持久记录可信网关现有 RPC 分类给出的 control/ordinary；新普通请求按全部 live/unknown cells 的全局/逐位置数量检查 max-minus-reserve，control 请求受完整额度限制。重启不会把旧未决连接从这些计数中抹去；确切持久额度满返回 429，身份/观察异常仍保持未知而不是伪装成满额。宿主还须独立观察精确旧物理资源、持久 helper/route marker 与进程/namespace 持有者，不能靠服务重启把内存 pin 清空就放行。helper gate 的永久 inode 在初始化时登记；已知仍活着的旧 helper 只阻塞所属位置，身份/配置损坏才拒绝整个启动。位置表、启动数据及凭证使用精确的有界 staging，Initializing 可恢复本部署的合法中断；Ready 后不得重造缺失位置。有界 inventory 可核对/回收精确完成的 helper 记账，但不凭盘点执行生命周期资源清理。宿主根的持久独占租约在任何初始化/恢复写入前取得，第二个控制器不得先碰 staged 数据再等待数据库锁。宿主在删除旧 claim、secret、fence、startup 或日志之前，先持久化精确 inode/内容绑定的清理清单与所需运行配置，删除中断可按同一清单恢复；任何外来 inode 或未知观察保留 Releasing。公网地址复用还需精确旧连接跟踪清除/缺席核对，不能只删 veth/nft 表。宿主确认 Free 后服务才记录 ConfirmRelease；丢失确认保持 Releasing，空闲记录保留最后永久 VM 身份。未结算的私有 buildID 锚点或模板验证引用继续阻止释放；仅按下述窗口结算/验证证据迁移解除逻辑引用后，才允许独立的更强物理释放检查。

生产维护协调入口为 `ManagedPort::maintain`，只由可信服务启动/周期扫描调用，不接收 HTTP 证书或客户端四项布尔值。它与创建、宿主派发、启动凭证写入和撤销共用原管理互斥锁；仅接受精确 `ConfirmRelease` 的持久见证及已排空的本地 body/relay 记录，并让纯核心再次核对终态、回收回执、未决动作和依赖。旧位置已被后来实例复用时，核对原见证而不对后来绑定执行旧资源观察或清理。一个老的活跃/未知实例不形成按历史编号清理的屏障，其他已满足条件的对象可以独立退休。未迁移/未结算的私有 buildID 与活动模板验证引用继续保留阻塞语义，不能因检查点或服务重启解除。成功退休后删除该对象的进程内撤销/排空登记；任何仍有持有者或未知 relay 的记录都不得靠清空内存变成成功证据。

顶层 `maintenance` 必须与 `bounded_host` 同时启用，全部字段显式必填且为可表示正整数：`retention_ms`、`max_checkpoint_bytes`、`max_records`、`max_references`、`max_tail_inputs`、`max_tail_bytes`、`max_input_bytes`、`prune_batch_rows`；单输入字节额度不得超过尾日志字节额度。它与 `bounded_host.maintenance` 的纯核心位置/结果/窗口参数是不同层次，均无生产默认。首次格式 3→4 升级在同一 IMMEDIATE 事务里完整重放旧历史、核对配置/SQL/原 Bind 与 ConfirmRelease、生成有效检查点并切换格式；失败不留下部分升级。非空格式 1/2 仍不自动改成 bounded host。格式 4 不允许关闭或修改持久配置，旧模式读写器拒绝新库。

格式 4 的恢复映像由同一个 SQLite 读取快照内的版本化核心检查点、严格连续输入尾、当前权威 SQL 表组成，并非可脱离该库的独立备份。检查点保存精简后的活跃/未决核心状态、保留结果、全部四类资源游标、永久身份前沿、窗口与时钟、逐位置完整上下文和释放见证、SQL 身份游标、命名空间/配置及输入截点。先核对 blob 长度/摘要，再通过私有 DTO 的限额、重复键、跨对象引用与状态检查恢复，未给 World/Store 增加任意反序列化。V1 明确拒绝 Pause/Resume、Pausing/Paused 以及所有快照引用，不能静默丢弃。已回收资源上的历史 Prepare 成功仍保留原义。

宿主释放成功后，服务在 ConfirmRelease 同一事务保存每个尚未退休对象的精确位置上下文和该确认输入序号；这份有界待退休见证跨重开和位置再次复用保留，只随该对象 Retire 一起删除，不形成永久逐对象宿主墓碑。升级只从确实存在的已接受 ConfirmRelease 输入构造，不能由 Destroyed/Free 推断。Retire 原子保留查询结果，并删除该对象的回执历史、outbox、逻辑动作映射、操作/沙箱投影、寿命、创建选项、释放见证和每沙箱 operation 高水位；全局游标与 Free 最后绑定继续保留。旧无窗口 buildID 元数据、仍存在的窗口锚点和活动模板验证引用阻塞删除；已确认结算的窗口锚点和持久验证证据采用下面的显式解除规则，不改写原创建选项。

检查点发布只原子替换根记录，不删输入；确认提交后另用最多 `prune_batch_rows` 行的独立事务删除已覆盖前缀并推进删除下界。中断或未知提交恢复后先核对实际持久根，再继续删除；损坏/缺失的格式 4 根一律失败关闭，不因仍有旧行而回退。输入高水位必须等于检查点截点加连续尾，不得用剩余 MAX(sequence) 重新播种。尾可包含早于其他对象的未知工作当前状态，不让旧未决操作钉住全部输入前缀。当前寿命/登记等 SQL-only 更新始终从当前 SQL 表读取，绝不被旧检查点侧数据覆盖；单写者、data_version 和不确定提交缓存失效边界保持。

单输入与尾日志的条数/字节在追加前检查，序列化使用有界 writer；每个格式 4 提交也须确认候选能编码为配置内的检查点。它们是失败关闭的存储拒绝边界，不是未来工作流的预留证明：过小的参数仍可能使已接受工作等待收尾容量。WAL、临时文件、长期 reader、SQL-only 大小、检查点替换峰值及未来重试/停止/结果承诺的准入预留仍属后续批次；删除行不会自行缩小 DB 文件，不能据此宣称完整字节上界或无条件持续接单。连续 churn 容量与实机验收及证明状态仍分别见[验收清单](testing-plan.md)和[覆盖记录](proof-coverage.md)。

### 完整容量、请求结算与物理部署前提

`maintenance.capacity` 是显式收尾预留策略；生产服务启用顶层 `maintenance` 时必须提供，在缺少预留时拒绝打开数据库或接单。库级无预留维护模式仅保留为检查点组件/迁移测试接口，不作为可接单的生产配置。它的正整数参数为 `max_live_sandboxes`、`max_sql_rows`、`max_sql_bytes`、`max_sql_value_bytes`、`max_receipt_bytes`、`max_transaction_inputs`、`max_transaction_bytes`、`max_database_bytes`、`max_wal_bytes`、`max_shm_bytes`、`checkpoint_scratch_bytes`、`max_online_storage_bytes`。`max_transaction_bytes` 限制一次事务新增的控制输入批次，不冒充所有 SQL 修改的字节数；SQL、页与 WAL 另有整体上限。最大原子批次必须能放入尾部，单条输入、未来命令/回执包装、完整标量宽度和检查点替换空间也必须可表示；配置不足或溢出明确拒绝。新完整模式只在受支持的空控制状态启用，不自动为旧的无预留在途工作补造额度。

每个接受的 V1 创建在同一事务拥有后续行、引用、编码字节、实际 SQL 编号和两个结果的额度；固定重试上界来自核心常量，并保守涵盖成功创建、文件策略、失败准备/初始化、终止抢占及合法终止重试。未知对象保留自身额度，不钉住无关历史。结果、开放窗口及发布验证证据的未来增长/到期转换也必须计入；最后一次清理可以消费其已预留编号，不能用永远不释放的“加一”假预留阻止最后一步。编号只在实际插入时前进，不预先跳过输入序号。静态界与现行 V1 图对应，不表示已经新增自动终止失败重试器或任意将来操作；新状态/命令须重新核对界限。

写入前在原单写者/缓存边界检查剩余输入空间，必要时先确认检查点，再逐批删除覆盖前缀；每个内部事务也在 IMMEDIATE 内核对身份并在提交前使缓存失效。未知提交先恢复实际根后才能继续。相同截点的完整模式检查点不递增代数，无可观察变化的维护/重复请求不消耗输入；仍返回原核心事件并保留必要 SQL 决定。管理器完整模式依赖这个受限写入前调度，空闲轮询不不断发布根；裁剪统计从持久删除前沿计算。

控制器文件额度组合数据库页上限、单事务 WAL 帧及同步扇区填充、SHM 索引和检查点替换空间；设置后读回实际页上限。关闭 cache spill、使用有界当前状态及内存临时表，并在写入前完成受管 WAL checkpoint。持久外部读者阻挡或磁盘 I/O 失败时拒绝继续写入/派发，保留未知结果；这些额度不创造物理磁盘或内存，也不容许不受管写者。SQL-only 更新、模板发布的未来证据和最大宽度计数器不能偷偷使用已承诺的收尾字节。接受物理 VM 前的 `cleanup_reserve_bytes` 至少覆盖控制器文件峰值；下述 profile 还要求它覆盖推导的宿主登记空间。

完整模式显式选择 `bounded_host.console_policy: "discard"`，VMM stdout/stderr 进入空设备，不创建无限 console.log。这个选择会失去 VMM 控制台诊断，命令流和构建日志合同不变；不自动替部署方选择，旧未配置的文件日志模式不属于完整有界承诺。宿主登记上界由真实固定位置/route cell 全集、每种记录的写入上限及固定 staging 推导；空闲后残留的死 route marker 仍计数，不能拿并发 route 数代替所有物理 cell。未来最大身份、配置和退休清单的编码须在写入/接受工作之前能放入原有上限。

完整生产入口还必须显式提供同一个 `bounded_host.physical_storage`（version 1）。profile 列出唯一运行池及可选独立构建池的 role/namespace、数据库/node/jail 根、根盘逻辑预算、位置数、每 jail 的 kernel/Firecracker 复制品上限、控制器＋宿主清理空间；有自助构建时还列出公开工作区和注册库的字节/inode 额度及 `max_jobs`、`max_templates`；注册库预算包含产物额度及每模板最大 64 KiB manifest 和 87 字节 owner marker，工作区在任何 SQLite 写入前须容纳数据库、WAL 和恢复余量。保护的 `coordination_file` 由部署方预置在同一已核对文件系统，不要求写挂载根、不创建新文件系统。所有列出的配置、宿主租约与 profile 必须相符；每个入口核对自身角色和子预算，未表示的 registry/构建池不得写入。候选/模板文件、旧稀疏盘未来增长和每 jail 复制品不能只按当下 statvfs 已用量计费。

首次激活只由列出的 Rust 服务在所有列出数据库不存在、受管根处于允许的空初始化状态时执行；独占核对并持久保存 profile 与协调文件设备/inode，随后持有共享租约。Python 服务只加入已经激活的匹配 profile，必须在创建 BuildStore 前拒绝缺失/不完整 marker。部分初始化仅在独占锁及原 quiescent 条件成立时截断、同步精确未发布前缀，再重新观察空闲空间；不把任意旧文件当成本次 profile。完整匹配记录重开也须确认记录和父目录持久同步。首次空部署需要至少两倍共同峰值的可用字节和 inode；新准入要求一倍峰值。已有分配不做有竞争的 du 抵扣，这是有意的保守空间成本：受管增长达到一倍峰值后仍留下另一份余量，重复 churn 不因自身热身耗尽准入/收尾空间。匹配 profile 的重启、查询和原工作清理不重新要求初始/新准入余量。

`filesystem_overhead_bytes`、`filesystem_overhead_inodes` 及固定 jailer 的 inode 上界是显式、经部署验证的文件系统分配/目录/extent 前提，不是跨任意文件系统的定理；必须覆盖已推导文件全集、全量 inode 的分配粒度取整、另加协调记录编码，以及额外开销。配置值不能代替实际空闲字节/inode 观察。全部受管池必须使用这个协调路径和 profile，不承诺排除另选路径的不合作控制器、未列出的 bind/submount 别名、外部写者、系统日志收集器、宿主掉电或存储损坏。CPU、RAM、FD、inode 和物理盘的实际部署仍须覆盖配置峰值并通过固定版本实机验收；有界不是任意参数下都能运行的保证。

私有构建池的 `build_retry_windows:{window_duration_ms,max_anchors}` 显式必填于完整模式并持久绑定，关闭旧无窗口新准入。先核对原已接受 tuple，再判断是否允许新工作；实际准入时刻的到期观察必须先持久化，不能因随后拒绝而回滚。窗口 Admit、原创建和锚点同事务；关闭与创建共用原串行边界。公开构建库先保存原 builder 的结算证据，再确认私有锚点移除；闭窗后无记录才能拒绝迟到 POST 而不制造替代 VM。原无窗口未知锚点保持阻塞。构建锚点与模板验证证据只在精确终态逻辑清理成立后解除，不能要求先 Free 造成循环 pin；随后仍由原宿主/数据排空协议确认物理释放。

验证证据绑定候选、owner、完整模板/产物/启动/资源身份、实际激活和精确逻辑清理，与终局结果及活动引用解除原子保存。重开不依赖已退休创建选项；旧终态记录只在原证据完整时迁移，Checking/unknown 不解除。内部验证身份的隐私过滤独立于活动 pin，退休前不得短暂出现在普通列表；模板及证据仍占原登记额度，不随公开结果到期退款或删除。控制器 schema 11 阻止旧读写器误读这些新语义；模板实现仍属工程测试边界。

## 生命周期和撤销

`sandbox-api` 的管理路径已经由 `ManagedPort` 接入 `ControllerJournal`；`sandbox-server` 只监听环回地址，使用 root 独占的配置、数据库、宿主状态和二进制。公开 API 从 API key 取得租户，不接受请求体指定租户；envd 网关从沙箱专属令牌反查当前实例，并在每次命令、文件请求转发前调用控制核心的权限判断。未配置 `data_transfer` 时保留旧限制：文件请求整包缓冲，上限 8 MiB，命令输入流上限 1 MiB、响应流上限 32 MiB。显式配置后的流式行为见下表；两种配置下，超限流都必须由客户端观察为失败，输出不会整块缓存在宿主。数据通道只接受固定 SDK 使用的 HTTP/1.1；其他请求版本在转发前返回 505，防止 HTTP/1.0 把未知长度流的截断当作正常结束。上游响应版本不改变客户端连接版本。固定 SDK 的 create 默认省略 `allow_internet_access`，现已支持受平台限制的公网 IPv4 默认值、显式禁网和静态 IPv4 规则；公网能力须由可信部署配置开启，未开启时创建请求明确拒绝。创建级 `envVars`/`metadata` 已进入持久创建数据与来宾初始化；未启用预制目录时其他模板仍拒绝，启用后的行为见本页模板合同；暂停仍明确拒绝。默认 E2B create 只在选定隔离网络测试中通过，不宣称 Harbor 已跑通。服务端时间、TLS 前端与系统磁盘余量属于明确的外部前提；物理余量检查会为新磁盘和收尾保留空间，但不能约束其他宿主进程事后占满磁盘。部分工作关联 A02/#7、A03/#9、B03/#8、C02/#12；E2B 字段差异见[兼容合同](../tests/compat/contract.json)。

`data_transfer` 是可信服务配置中的可选对象，存在时下列字段均必填，不从客户端接收。流式模块已实现并通过组件、固定 SDK 组合及选定真实 KVM 边界验收；完整资源与故障矩阵仍待验收，保持显式启用。最终默认值和部署最大值仍须结合 #13 固定任务、宿主配额和实测确定；测试夹具的 64/96 MiB 不是生产推荐值。

| 字段 | 单位与约束 | 行为 |
|---|---|---|
| `file_upload_bytes` | 正整数字节 | `POST /files` 的 HTTP body 总量，含 multipart 边界；已知长度和分块都逐块转发 |
| `file_download_bytes` | 正整数字节 | `GET /files` 的响应 body 总量 |
| `command_input_bytes`、`command_output_bytes` | 正整数字节 | Process RPC 输入/输出总量，含 Connect 编码；独立于文件预算 |
| `rpc_request_bytes`、`rpc_response_bytes` | 正整数字节；请求不超过 8 MiB | 其他文件请求及元数据 RPC 的输入/输出；输入仍有界缓冲以检查非法路径，其他非文件响应也使用该输出预算 |
| `max_transfers`、`max_transfers_per_vm` | 全局上限 ≥ 每实例上限 > `control_reserve` | 鉴权后按 `(vm, generation)` 计数，涵盖读取请求至响应结束和上游连接退出；超额返回 429，不排无限队列 |
| `control_reserve` | 正整数，包含在上述上限内 | 普通文件/Start 请求不能占用这部分名额；health、SendSignal、SendInput、CloseStdin 可使用，仍受总上限约束 |
| `request_idle_seconds` | 正整数秒，可由系统时钟表示 | 请求体生产者停顿超时；可返回响应时为 408 |
| `file_idle_seconds` | 正整数秒，可由系统时钟表示 | 文件响应头等待按上传进度续计，超时为 504；响应体中途停顿则中断流 |
| `write_idle_seconds` | 正整数秒，可由系统时钟表示 | relay 写入和前端套接字写入/flush 阻塞超时；断开相应连接 |

零、负数、字段缺失/拼错和无效并发关系均拒绝配置。上传已知长度超限在读取前返回 413；未知长度累计超限会停止转发并返回 413，但可能已截断或部分写入来宾文件，不能自动重传或承诺原子覆盖/批量回滚。上游在上传体尚未完整交给 HTTP 传输层时提前返回成功，网关改为 502；完整传输也不等于持久化提交证明。下载在响应头后超限/断流必须以不完整 HTTP 消息结束，SDK 不能收到完整成功。

该配置暂不支持压缩请求：非 identity 的 HTTP/Connect/gRPC 编码返回 415；向上游协商 identity，仍收到压缩响应则返回 502。因而不会仅按压缩后大小放行更大的解压内容。上传/下载不整包缓存，relay 的 HTTP 读缓冲限制为 64 KiB；namespace 中继在两个方向各使用固定 64 KiB 读缓冲，读取到数据即转发，不等待缓冲填满，请求写半关闭后仍可接收响应。元数据缓冲、每连接 HTTP/内核缓冲和并发仍占内存，不能把这些缓冲或文件总量预算说成整个进程的内存限额。慢写超时也作用于同一监听器上的管理响应，但管理请求不占数据传输名额。传输超时独立于 SDK 请求/等待期限、命令执行超时及沙箱寿命；安静但仍在运行的命令不会因没有 stdout 而触发文件空闲超时。真实磁盘满、到期/kill 中断、授权撤销及宿主资源残留仍须按[验收清单](testing-plan.md)验证。

固定 envd 的文件 `user` 决定相对路径/`~` 的用户主目录，以及上传文件和新建目录的归属；文件处理仍由来宾 root 执行，不构成来宾用户之间的 DAC 权限边界。原 SDK 指定 ubuntu 时仍能读取 root 私有目录，并覆盖其中的文件、把该文件归属改为 ubuntu；同一 ubuntu 命令仍受 Linux 目录权限限制。未知用户明确拒绝，不回退默认用户。沙箱令牌代表整个实例的访问资格，隔离边界是宿主与不同 VM，不能向不受信任的来宾用户发放令牌后依赖 `user` 限权。

固定 SDK 的批量上传不提供整体事务：multipart 顺序处理文件，某项失败前已写的内容保留，后项不处理；同步 octet-stream 同样顺序发送并在错误后停止。异步 octet-stream 使用并发请求，某项报错时其他项可能已经写入或仍在完成。调用者应查询原路径确认结果，不因异常自动重发整批；选定路径错误、用户归属及跨 VM/宿主路径实测见[验收清单](testing-plan.md)。

固定 SDK 文件 HTTP 的 `request_timeout` 与 Connect RPC 头限制不同：大正数可用于 HTTP，不能按 Connect 的十位毫秒头规则拒绝。普通读取和缓冲上传使用请求期限，流读取仅在显式提供时设置总传输期限；实际流式 IO 上传的两个客户端都省略该期限。multipart 的文本 IO 会先缓冲，因此仍受请求期限约束，不能仅凭对象是 IO 就推断不受限。负数 HTTP 期限在固定传输适配器中变为立即到期，而非参数验证错误。同步流读取忽略 `stream_idle_timeout`；异步对首个响应和后续各次读取应用该参数，零关闭显式空闲期限。所有这些期限都不代表写入回滚，具体实测范围见[验收清单](testing-plan.md)。

固定 SDK 的常用文件/命令一元 RPC 将 `request_timeout` 写入 Connect 毫秒期限：省略用连接配置，零关闭，负数量化为 1 ms，超过十位毫秒头范围明确拒绝。1 ms 不保证必定失败，完整响应可能先到；期限错误不证明副作用未发生。文件变更或输入/终止结果不明时只核对已有路径、PID 和结果，不通过自动重发把未知变成成功；详见[验收清单](testing-plan.md)的一元 RPC 探针。

- create：在资源及策略就绪后才发布运行成功；部分配置失败要有明确收尾路径。
- connect：V1 只连接运行中的同一实例并按约定延长寿命；暂停对象恢复尚未实现时明确报告不支持。
- set_timeout：以服务端时钟计算新截止时间；与到期处理原子协调。单元测试使用伪时钟；进程重启后的时钟/截止时间合同由 A03 固定。
- kill：接受后进入撤销，停止授予新的执行资格；此前在途操作可能需要核对和收尾。只有确认相关 VM 停止、访问撤销，才能发布销毁完成。失败或未知不得冒充完成。
- cleanup：仅处理动作绑定的资源，核验资源的所有者、sandbox 和代数；不能只凭可复用的 PID、IP、文件名或目录名删除资源。
- 失败：准入拒绝无副作用；接受后的不可安全继续可以失败关闭。不是每个 RPC 超时都销毁沙箱；公开差异写入兼容清单。

数据请求的授权与本地撤销订阅在同一管理锁内完成，避免 kill 落在检查与登记之间。kill 或到期撤销持久提交后，通知该沙箱的全部在途连接：尚未转发的请求停止准备，等待响应或已流式返回的连接终止，所属 relay 进程退出；无需等待来宾 TCP 自己发现 VM 消失。通知只撤回既有访问，不授予权限，也不替代宿主停止回执。提交结果不确定时保守关闭连接，管理结果仍为未知；错误 owner 或被拒绝的操作不撤销其他实例。关闭可能留下部分文件或结果未知的命令，不自动重传；流已开始后通过不完整 HTTP 消息报告失败。通知是本进程状态，服务重启后按持久状态重新鉴权，不恢复旧连接。

V1 寿命合同：创建与连接省略寿命时按固定 SDK v2 的 300 秒处理；连接现有运行实例只延长，不新建 VM；`set_timeout` 自服务端当前时刻重设，可以缩短，零/负值走到期处理。创建/连接超过单次上限应拒绝，`set_timeout` 到总寿命上限时应截顶，不能把两者合并成同一种结果。准入先持久预留时长与资源；物理 VM 就绪后，在同一事务内发布 Running 并重设可见的启动时间、初始截止与总截止，避免把启动耗时算作可用寿命。发布前崩溃仍保持 Starting，恢复只接续原操作，不重做已确认的宿主动作。旧库已运行实例只保留其原有截止，不因这项修改自动补长。

创建意图已持久提交后，启动凭证写入、后续执行或返回会话失败都可能留下已接收操作，必须返回结果未知（HTTP 500），不能以固定 SDK 视为未改变状态的 503 引导重试；明确终结的创建失败保留失败语义。创建没有通用客户端幂等键时，两个独立 HTTP 请求不保证只创建一次；`session_id` 等元数据不是重放键。创建结果不明的沙箱继续占用配额，并须可由已提交身份发现和收尾。`kill` 的服务端回复等待上限是 25 秒，更短的客户端期限可能先到；期限到达只表示本次回复不确定，后台已接受操作继续持锁完成物理停止与回执，不能把撤销中的实例回滚成 Running 或报已销毁。重复调用在撤销中只核对并接续同一持久 kill，仍不确定就继续返回未知；完成后再次 kill 按固定 SDK 的不存在语义返回 404/false，查询也不把它伪装成 Running。真实停止和访问撤销后才可发布完成。具体 HTTP 状态、SDK 返回值和异常按 #5 的逐调用合同验收。

已接受的 `kill` 在恢复观察、持久状态读取或宿主停止后续步骤失败时返回结果未知（HTTP 500），不能以表示可安全重试的 503 掩盖可能已发生的副作用；后续调用只核对原操作，不派发第二次停止。

网络合同目标：省略联网参数默认允许受平台禁区约束的公网出站；显式禁网和原 SDK 的 `network.allow_out`/`deny_out` 静态 IPv4 地址或网段规则由 #10/#12 实现。平台禁区始终优先；用户允许高于用户拒绝，`false` 与显式允许项可以共存。高级 DNS/域名授权、IPv6 放行后置；静态 IPv4 规则不得被解释为自动授权任意 DNS 查询。公网模式要求部署配置显式开启、宿主 IPv4 转发已启用、固定 `base` 镜像包含默认路由；任何安装或观察失败不得发布可用。隔离 Linux 流量、固定 SDK→真实 VM→测试专用外部网络空间以及一条真实公网 TCP 握手路径的选定场景已通过；通用互联网、DNS 查询内容控制和完整 S10 尚未验收。

`controller-service` 的寿命准入层已把创建意图、截止时间和逻辑磁盘预算放入同一 SQLite 事务；连接只延长，`set_timeout` 可缩短或延长，到期处理在接受 kill 前重新核对截止时间，防止旧定时事件误杀。它使用调用方提供的服务端时钟和部署配额；`ManagedPort` 与 `sandbox-server` 已接入真实时钟、外部接口和周期到期执行，固定 SDK 实机测试覆盖部分到期清理路径。完整竞争和跨崩溃场景仍须按[验收清单](testing-plan.md)完成，不以局部测试替代整套验收。

## 容量与资源：A/B

A 控制租户配额、操作预算、有限重试与收尾预留；B 设置实际 CPU/内存/磁盘等限制并报告观察。现有准入层限制同时活跃数量、每租户和全局的逻辑磁盘预算，保留固定清理余量；销毁后只有资源清理回执完成才释放预算。宿主可用的最大 VM 编号由可信配置给出；准入在同一事务里预留 VM/网络槽位编号并检查边界，编号即使资源清理也不回绕复用。编号耗尽时拒绝新创建，不留下已接受但宿主无法启动的记录。宿主准备动作还会独立核对编号与 UID 映射，防止部署配置漂移。服务启动要求数据库父目录（含 SQLite WAL 辅助文件）、节点状态目录与私有 VM 磁盘目录的文件系统设备相同，任一异盘都在打开数据库和初始化节点前拒绝，确保磁盘余量观察覆盖这些写入。管理接入已在创建前检查真实可用磁盘是否覆盖实例盘与清理预留，但这只是当时观察，不是对所有外部磁盘写入的原子预留，也不等于宿主物理内存保障或长期容量证明。容量不足可以拒绝新请求，但已接收操作的清理预算不能被其他请求消耗。

## M0 必须产出的可执行合同

1. Rust 模块接口和结构化错误以 `sandbox-protocol` 为准；C 的 E2B 请求/响应映射以[兼容合同](../tests/compat/contract.json)为准。外部错误与内部错误不可直接等同。
2. 能力矩阵逐项标明目标、现状、支持/差异/拒绝/未测及测试层级；不以合成服务通过宣称真实 VM 通过。
3. 正常、拒绝、重复、迟到、未知和部分完成的共享测试样例见 `sandbox-protocol/tests/`；A 在持久状态中决定冲突回执，B 的观察不能自行发布业务状态。
4. 资源身份包含 owner、sandbox、operation、epoch/generation、logical action、attempt 和精确资源。仅调试构建的服务级崩溃点 `prepare_vm`、`stop_vm` 位于真实宿主动作成功与回执落库之间；其他窗口不得按这两个测试推断已覆盖。日志和实验报告至少关联上述字段、执行提交、宿主资源与观察结果，脱敏后保存。
5. [版本基线](../references/v1-baseline.json)区分固定源码、当前宿主只读观察与既有实机测试提交；未复现实验不得升级为整套验收。

A/B/C 核对影响各自模块的合同；范围变更由 owner 决定。后续合同修改必须更新调用方、执行方、样例及影响说明，不能靠宽松解析悄悄吞掉新增字段。Harbor 固定任务预检和评分链归 #13/#14，不是本 M0 合同的关闭前提。
