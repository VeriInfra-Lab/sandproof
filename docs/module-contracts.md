# 模块合同 v1 草案

[文档目录](README.md) · [项目蓝图](project-blueprint.md) · [开发规则](../CONTRIBUTING.md)

本文件供 M0 联合复核，限定接口的责任和安全语义；不是已经实现的 Rust API 或已经验证的规范。具体字段类型、错误码和客户端路径由 G01/C01 固定后，以同一份接口定义生成/测试，避免三个人各写一份。

首批跨模块消息类型位于 [sandproof-protocol](../sandbox-protocol/src/lib.rs)：经过鉴权后构造的请求、携带完整身份的动作与回执，以及成功、明确失败、未知三类结果。样例和校验见 `sandbox-protocol/tests/`。这里的外部不透明字符串 ID 与既有控制核心的内部数值 ID 不同；A 后续必须建立持久、无歧义的映射。消息类型本身不执行事务、不确认宿主证据，也不替代已证明的控制状态机；当前仍为待三方复核的合同草案。

## 请求入口：C → A

- C 从有效凭据得到调用者身份；不能把请求正文中的 tenant/user 字段直接当成可信身份。
- 生命周期输入携带调用者、sandbox ID、操作类型及业务参数；内部操作编号由可信服务分配/映射。没有客户端幂等键时，不能承诺两个独立 create HTTP 请求只创建一次。
- A 根据当前持久状态检查归属、能力、寿命、资源预算及是否正在撤销；接受决定、操作记录和待执行动作在一个事务内提交。
- C 将稳定结果或等待超时映射为固定 E2B 响应。内部 pending/unknown/revoking 等状态可以保留，但不能随意扩展 E2B 公共状态枚举。
- 同一请求重复、操作查询与重新提交是不同动作。相同幂等键改变参数必须拒绝；C 负责记录客户端真实提供了哪些可重放标识。

## 动作接口：A → B

节点运行器的首批实现及实机运行方法见 [`sandbox-runtime`](../sandbox-runtime/README.md)。其 `vmm_running` 只代表虚拟机监控器状态，不能当作可用沙箱成功回执。[宿主适配器](../sandbox-node/src/linux.rs)已在隔离 Linux/KVM 测试中补上 envd 健康、鉴权初始化、禁网和独立磁盘检查，只有这些观察完成才向控制核心回执成功；公网出站、外部 API 鉴权和完整崩溃对账仍未接通。

每项持久动作至少绑定：协议版本、sandbox、owner、operation、epoch/generation、逻辑动作 ID、attempt ID、精确资源 ID、动作参数。只有已提交动作可派发；B 的控制入口不向沙箱或公网开放。

B 检查动作身份、当前执行资格、终止围栏和真实资源归属，返回以下结果之一：已观察成功、明确失败、尚未知。超时不是失败证据。只有明确可重试失败、没有待核对的部分资源，且 A 的持久状态和预算检查也允许时，才能创建新的尝试；重发同一未知动作不能凭空分配第二个 VM。

回执包含完整动作身份、观察对象及结构化结果，不能仅有 `success=true`。A 决定是否接收当前回执及是否推进阶段；旧动作的回执不授予新代数权限。

## 数据通道：C → A/B → 来宾

命令和文件请求先经过身份、所属沙箱、阶段和能力检查，实际执行时再确认仍指向同一有效实例。请求通过检查到实际发生副作用之间必须有明确的执行资格/撤销规则，不能只依赖入口处的一次检查。

优先评估复用固定版本的 E2B envd 来兼容命令和文件协议；B 负责部署与传输，C 负责 SDK 接入和网关，A 负责执行资格。M0 记录实际选用版本和必需改动，不能仅因传输层可通就宣称 E2B 兼容。

来宾可运行不可信代码，甚至获得来宾 root。来宾回复不作为宿主 VM 已停止、宿主网络已隔离或资源归属的唯一证据。控制凭据与宿主管理入口不得因复用 envd 暴露给来宾。

普通用户命令可能有任意副作用；不承诺任意命令恰好执行一次。命令发送后连接中断时保留结果未知，通过已知句柄查询/终止；不得自动再运行一次同样的 shell 命令。命令执行超时、等待回复超时和沙箱寿命到期分别处理。

## 状态与持久化：A

V1 采用单节点 SQLite 事务存储路线。Redis、多节点共识和存储引擎内部证明不在 V1。

[#4 的首批持久化代码](../controller-service/src/lib.rs)使用固定的 `rusqlite 0.40.2`（启用内置 SQLite，具体依赖以 `Cargo.lock` 为准），在本地可信文件系统上使用 `WAL`、`synchronous=FULL`、外键检查、`trusted_schema=OFF` 和 5 秒忙等待；写入及派发领取使用 `BEGIN IMMEDIATE`。这些配置可由 `storage_settings` 读取以记录测试指纹。[SQLite 官方说明](https://www.sqlite.org/pragma.html)解释了 WAL 中同步设置的区别，但目前只测试进程中断与重启，不声称已经验证宿主掉电、磁盘损坏或网络文件系统。部署方还须提供仅控制器可访问的数据库目录，并连同 WAL 辅助文件一起管理与备份。

底层 `Journal` 将同一控制决定给出的 sandbox、operation 状态字节与待执行动作原子写入。其上的 `ControllerJournal` 已接入既有 `controller-core`：从初始状态重放已接受输入来恢复状态，不反序列化任意 `World`，也不另写生命周期规则。输入历史、查询投影、后续动作在同一事务提交；成功回执所对应的资源状态更新也在该事务内。恢复需使用兼容的控制核心和输入格式；升级改变重放语义时必须迁移，不能直接复用旧库。

控制服务持有数据库进程锁，派发期间独占控制服务写入口；生产调用方不得绕过它用底层 `Journal` 另行写入。动作先在库中标记已派发，再调用工作执行器。标记后尚无最终回执的动作在重启时保留为“结果不明”，不能自动再次执行；同一沙箱后续生命周期写入暂时拒绝，直到可信宿主观察解决未知结果。该首版串行策略优先避免在途启动与销毁竞争，不承诺未知结果下及时销毁或高吞吐。旧动作必须仍通过核心工作入口的资格检查，才可送往宿主。

宿主适配器通过 `HostEvidence` 提供具体命令与资源的成功观察；来宾回复或外部 API 不得直接构造它。部分完成视为未知，不直接重试。明确失败映射到核心的失败类别，并要求回执的可重试标志与该类别一致；不一致时拒绝回执并保留待核对状态，不擅自授予重试。未知观察允许被后续最终观察解决，历史回执保留；最终回执冲突被拒绝。

外部资源编号由部署方提供的唯一 16 位小写十六进制命名空间与核心编号组成；该命名空间持久保存，跨部署唯一性是部署合同。数据库所在目录仅允许可信控制器访问，进程锁不防范恶意宿主或绕过服务的数据库写入。当前恢复与写入会重放完整历史，尚无日志压缩和规模性能保证。

SQLite 提交本身若报告结果不确定，调用方必须按操作编号重新查询，不能把它当成未提交并直接重试。创建与销毁的编排已在隔离 Linux/KVM 测试中接上真实宿主适配器，但尚无外部 HTTP 服务、重复请求处理和 A04 自动对账；不能将这次实机闭环等同于完整 A02/C02 验收。

只有 A 更新业务状态；B 的本地资源登记是观察依据，不能成为另一个可独立改写业务状态的控制器。提交、派发、回执记录及状态发布必须有可注入崩溃的位置。恢复扫描先核对身份和实际状态，再安排重放或清理。

允许 controller/worker 进程被终止后重启；宿主持续运行、可信存储按合同工作。宿主掉电、存储损坏及恶意宿主不在首版故障保证内。后续若扩大故障域，须新增合同和实验。

## 生命周期和撤销

当前 `sandbox-api` 只提供可测试的 E2B 管理路径、字段映射、租户 API key 与 `ControllerPort` 合同；它尚未绑定真实 `ControllerJournal`、宿主执行器或 envd 网关，不能启动真实服务。公开 API 不接受请求体指定租户；端口实现仍须逐次通过控制核心核对归属和当前执行资格。固定 SDK 的 create 默认省略 `allow_internet_access`，而当前宿主只实现禁网，所以此接口暂时只接受显式 `false`，省略或 `true` 均明确拒绝；这是有意的兼容缺口，不宣称默认 E2B create 已跑通。部分工作关联 C02 / #12；E2B 字段差异见[兼容合同](../tests/compat/contract.json)。

- create：在资源及策略就绪后才发布运行成功；部分配置失败要有明确收尾路径。
- connect：V1 只连接运行中的同一实例并按约定延长寿命；暂停对象恢复尚未实现时明确报告不支持。
- set_timeout：以服务端时钟计算新截止时间；与到期处理原子协调。单元测试使用伪时钟；进程重启后的时钟/截止时间合同由 A03 固定。
- kill：接受后进入撤销，停止授予新的执行资格；此前在途操作可能需要核对和收尾。只有确认相关 VM 停止、访问撤销，才能发布销毁完成。失败或未知不得冒充完成。
- cleanup：仅处理动作绑定的资源，核验资源的所有者、sandbox 和代数；不能只凭可复用的 PID、IP、文件名或目录名删除资源。
- 失败：准入拒绝无副作用；接受后的不可安全继续可以失败关闭。不是每个 RPC 超时都销毁沙箱；公开差异写入兼容清单。

`controller-service` 的寿命准入层已把创建意图、截止时间和逻辑磁盘预算放入同一 SQLite 事务；连接只延长，`set_timeout` 可缩短或延长，到期处理在接受 kill 前重新核对截止时间，防止旧定时事件误杀。它使用调用方提供的服务端时钟和部署配额；生产时钟驱动、真实到期执行器及外部接口仍需接入，不把这些局部测试视为到期销毁端到端通过。

## 容量与资源：A/B

A 控制租户配额、操作预算、有限重试与收尾预留；B 设置实际 CPU/内存/磁盘等限制并报告观察。现有准入层限制同时活跃数量、每租户和全局的逻辑磁盘预算，保留固定清理余量；销毁后只有资源清理回执完成才释放预算。逻辑条目余量不等于宿主物理内存或剩余磁盘保障，真实宿主物理准入检查尚需接入。容量不足可以拒绝新请求，但已接收操作的清理预算不能被其他请求消耗。

## M0 必须产出的可执行合同

1. Rust 模块接口和结构化错误；C 的 E2B 请求/响应映射。
2. 支持能力矩阵，包含默认值、身份/状态/超时错误和未实现功能。
3. 正常、拒绝、重复、迟到、未知和部分完成的共享测试样例。
4. 资源身份与观察格式、崩溃点名称、日志关联字段。
5. 版本清单和测试基线。上游源码参考不等于这些合同已完成。

A/B/C 都复核这五项。后续合同修改必须更新调用方、执行方、样例及影响说明，不能靠宽松解析悄悄吞掉新增字段。
