# 模块合同：中心、宿主与执行边界

[文档目录](README.md) · [项目蓝图](project-blueprint.md) · [开发规则](../CONTRIBUTING.md)

本文件限定接口责任和安全语义；产品范围由 owner 确认，A/B/C 核对各自实现边界。目标合同不等于代码已经实现或完成形式化证明。共享 Rust 消息以 `sandbox-protocol` 为准；固定 SDK 的具体调用、当前支持状态和可执行测试以[兼容合同](../tests/compat/contract.json)为准，不能各写一份独立的业务状态机。系统验证目标和状态/故障模型见[验证设计](formal-verification-design.md)，不将尚未实现的合同当作已证事实。

首批跨模块消息类型位于 [sandproof-protocol](../sandbox-protocol/src/lib.rs)：经过鉴权后构造的请求、携带完整身份的动作与回执，以及成功、明确失败、未知三类结果。[共享样例](../sandbox-protocol/tests/contract_examples.rs)覆盖正常、拒绝、冲突重复、迟到、未知、部分完成、资源不匹配与未知协议版本。这里的外部不透明字符串 ID 与既有控制核心的内部数值 ID 不同；持久映射由 A 的 `ControllerJournal` 管理。消息类型本身不执行事务、不确认宿主证据，也不替代已证明的控制状态机；消息对应的外部错误映射以固定兼容测试判断；共享类型不代表中心/节点网络协议已经交付。

本页的M0等编号表示工程里程碑，不是证明模块。证明责任采用[验证总览](formal-verification-design.md#2-按真实模块划分证明责任)中的V0–V9；同一事务/入口的不同证明责任仍使用本页唯一业务合同，不复制算法。

### 目标与现状的分界

目标架构与交付范围由[蓝图](project-blueprint.md)定义。下述合同适用于唯一的中心/宿主链路；原 SQLite、控制核心和宿主执行仍复用，但旧单宿主公开入口的实测不自动覆盖新组装。默认寿命、续期、总寿命截顶和列表合同保持，验收按候选记录。公网模式仍须部署方显式开启并满足宿主转发与镜像要求，默认配置拒绝；已有转发链也必须允许对应路径，单独打开 ip_forward 不会覆盖 Docker 等 DROP 策略，服务不自动放宽共享防火墙。C 在鉴权和参数校验后才调用 A，不能静默丢弃参数；B 不能因为架构已定就提前打开宿主出口。

## 中心与宿主的高级操作合同

**工程实现与验收分开记录。** 中心决策、Redis 提交、宿主持久收件、原应用生命周期、结果确认及有限窗口已有实现；#292 仍须在同一候选验收产品入口、模板、故障组及两级晋升。本节限定两端责任、提交与恢复语义，不以组件通过宣称全部交付。使用同一共享类型、测试样例和依赖锁，不另建协议专用本地算法。

### 内部通信与受保护产品入口

[共享类型](../sandbox-protocol/src/internal.rs)固定协议版本 2：`NodeIdentity` 绑定部署、节点及正数代际；`ControlIdentity` 另含认证租户、全局沙箱/操作、正数意图版本、固定保留位置 `retention_slot` 及该位置的正数代次 `request_window`，计数器耗尽拒绝而不回绕。高级意图另携带原创建选项、模板/资源/期限及节点观察事实，但不产生本地执行许可。只读 `POST /internal/v2/probe` 使用节点身份与本次请求编号，响应必须匹配原请求；未知字段、版本及身份错配拒绝。成功不表示准入、存储耐久、VM 就绪或模板可用。

[通信库](../sandbox-internal/src/lib.rs)使用固定 Rustls 0.23.45 / tokio-rustls 0.26.6，仅 TLS 1.3 和 HTTP/1.1，禁用会话恢复与提前数据。两端验证私有 CA 链、证书有效期及用途，并核对受保护登记的叶证书 SHA-256；至多两个不同摘要用于显式轮换，不只凭同 CA 接受任意身份。客户端只连接可信登记的固定 `SocketAddr`，另验证登记的 DNS 证书名，不从请求解析 URL、重定向或 DNS 路由。中心使用独立非 root 账号和私有配置，宿主使用 root 私有配置；同一叶证书不得映射多个不同节点身份。命令统一为各自的 `initialize`、`serve`、`audit --config /绝对路径` 与 `contract-versions`，初始化不属于恢复路径，当前格式不匹配就拒绝，不自动导入或升级。

连接/在途调用数显式限制为 1～8192，超额立即拒绝，不建立信号量等待队列。握手期限须为正且不超过管理调用期限，管理完整期限至多 24 小时，覆盖连接、握手、请求头/正文和完整响应，不能收头即退还许可；两端共用 HTTP 头至多 16 项、读取缓冲至多 8192 字节的边界，错误响应也不能绕过正文限制。探测仅接受 JSON，无压缩，请求与响应正文各限 4096 字节，包括分块传输。客户端不自动重试，无后台连接池或响应关联表；传输故障不是高级操作的无副作用失败证据。高级 `POST /internal/v2/lifecycle` 复用同一 TLS/HTTP 实现，正文限为 270336 字节，含原 64 KiB 字节数组的 JSON 编码包络；全节点绑定核对后调用接收端口，返回前再次核对全响应身份/种类。客户端取消先关闭原连接再退还连接额度；停机只取消并等待连接，不接管已经提交的宿主工作。HTTP 拒绝、超时、断线都不是无副作用失败证据。当前组件检查见[验收清单](testing-plan.md#已实现的通信基础检查)；未实现的高级操作继续遵守下面的唯一持久化和本地算法合同。

内部 `/internal/v2/data/…` 复用同一登记端点与双向认证，带有界完整控制身份而不是用户 API key；宿主在原应用锁内重新核对映射、当前 VM、归属、寿命、围栏和原权限。中心签发的 SDK 访问令牌与来宾 envd 凭据不同：中心不读取来宾秘密，宿主在同次原资格检查后仅向原中继覆写来宾凭据。路由/请求分类和字节处理分别由唯一的 [共享传输库](../sandbox-data-transport/src/lib.rs) 提供，宿主中继仍使用原持久子进程与排空协议，不再保留两套流算法。长命令不套短管理期限或累计输出上限；连接、请求头、待写数据及文件/一元回复仍有原边界。中心从同次确认权威视图带出原固定最大寿命，以绝对界限取消网络黑洞，截断必须报告错误而非成功 EOF；这不取代宿主到期和撤销。正文与实际连接各自持有额度，实际结束前不能提前退还。

### 状态权威与模块责任

宿主内部收件与执行组件使用唯一 [HostLifecycle](../sandbox-host-service/src/lib.rs) 和原 `ControllerApplication`，不再保留只包裹独立 journal 锁的旧收件组装。HTTPS 接收只提交原意图；受信工作器用已登记不可变模板调用原应用的准入/执行/恢复，创建后恢复只读取原持久模板、凭据和编号。执行前保留原物理包络、真实可用磁盘、网络开启条件与模板校验；模板或空间不可用不退回 base。销毁收件与本地终止同提交，并在同一应用锁中撤销原数据许可；共享提交未知时保守撤销已有许可，不授予新许可。实际停止、逻辑清理、通道排空和物理 ConfirmRelease 仍分别成立，只有全部要求满足才发布 Cleaned。

接收、执行和周期恢复共用一个无等待的阻塞工作许可，许可由实际工作持有，HTTP/调用者取消不提前退还；原应用串行锁与 #284 的后续并行范围不变。周期恢复沿用本地独立启动期限和到期处理，中心断线不延长寿命。结果确认保留原创建映射、当前意图和终止前的寿命依据；单位置退休另要求该实例原责任终局、精确确认与无未结算引用，不要求无关实例终止。生产组合须至少四个操作槽，保留重复续期和必要销毁空间。`contract-versions` 从共享常量报告内部协议、中心权威格式及宿主收件格式，不能由测试脚本手填另一个版本。真实组件启停不代替公开 SDK、DK 故障组或两题验收。

`POST /internal/v2/node-status` 是已登记宿主的只读资源观察，受同一 mTLS、固定端点和有限管理调用预算约束。初始配置只允许零健康期限、零物理空闲和空模板可用表；中心不能把配置值当现场事实。有效回应须匹配原节点、受保护的 `retention_slots`（等于原收件配置 `max_sandboxes`）、显式时钟偏差和全部资源上限；健康期限从请求前的中心时间起算，不能用迟到回应延长。忙碌/丢回复不延长原有限期限；成功但越界的观察否决该节点。物理空闲和近期健康只用于否决准入/新路由，不释放预留、不改绑，也不证明已有 VM 已停止。

运行池与构建池通过受保护的节点 `role` 固定隔离。普通 create 仅选 runtime，内部构建仅选 builder，二者复用同一个全局编号、准入及生命周期算法；客户端不能选择池。中心模板可用表只接受匹配 GLOBAL 描述、原修订及摘要的宿主校验事实。宿主缓存提供 GLOBAL 原描述与仅改本机路径的 LOCAL 描述；本地 owner 投影只在原映射/准入事务中进行，不能把本地路径或本地租户摘要当 GLOBAL 摘要。

| 对象 | 唯一决定或记录者 | 另一层责任 |
|---|---|---|
| 用户公开凭据、认证租户、全局准入/节点选择 | 中心 | 节点验证中心身份和完整租户/绑定，不持有全量用户 API 密钥 |
| 全局身份、固定宿主/代际、意图、预留及待发送责任 | 中心 Redis 权威状态 | 节点持久映射原本地身份，同键异参数拒绝 |
| 本机阶段、执行、资源、观察与实际停止/清理 | 节点本地控制器、SQLite 和宿主证据 | 中心接受匹配身份/版本的事实，不推演本地 VM 子步骤 |
| 本机到期、围栏与当前执行资格 | 节点 | 中心也拒绝过期新入口，不能代替节点实际执行检查 |
| get/list、公开结果与数据路由 | 中心，从已提交绑定及确认事实派生 | 旧观察不覆盖新决定，失联不伪造健康或停止 |
| 模板归属、别名与不可变描述 | 中心模板入口 | 节点校验绑定产物，不重新解释别名 |

中心保存获准意图，节点保存本机责任与事实；缓存只派生视图。两端不合并为一个阶段枚举，也不要求时刻进度相等。一节点可多租户，同一用户的不同沙箱可跨节点；已接受的同一沙箱只绑定一个原节点/代际，不自动改绑。

只保留“用户 → 中心 → 宿主 → 虚拟机”的生产链路，即使只有一台宿主也不提供独立公开宿主模式。`sandproof-center` 是唯一用户入口，`sandproof-host` 不解析全量用户 API key、不连接 Redis、不监听公开管理/构建接口。模板构建也必须经过中心授权；构建池隔离和原本地控制/SQLite/执行/恢复算法继续复用。禁止旧模式别名、旧库升级工具，以及中心或 Redis 故障时回退公开宿主。测试可直接调用本地组件，但不把这种调用作为另一种产品部署；退出检查见[验收清单](testing-plan.md#53-旧公开入口退出验收)。

### 身份、认证与参数保真

- 可信管理初始化持久 `deployment_id`；既有 Redis 为空/损坏不能自动当新部署接单。静态登记 `node_id`、节点实例代际、证书、端点、兼容版本与容量；地址不是身份，重装不能沿用旧代际认领资源。
- 版本化 HTTPS 使用双向证书验证，同机也不省略。可信根、证书和端点来自受保护配置，用户/模板/PR 不指定路由或信任材料。
- 高级请求带协议版本、部署、节点/代际、认证租户、全局沙箱/操作、单调意图版本、种类与全部规范化参数，以及原模板、资源和期限绑定；响应另带节点观察版本和结构化结果。
- 中心修订、意图版本、节点观察版本、本地 epoch/generation/attempt 不混用。全局身份在准入提交中分配且永不复用；本地编号规则保留，耗尽拒绝、不回绕。
- 节点核验对端后仍检查全身份、归属、窗口、资格、寿命与终止；持久建立原本地映射。同操作同完整参数复用原进度/结果，同编号异参数拒绝且无新副作用。规范化正文与摘要均持久绑定，不只比较用户摘要。
- 接口仅有高级创建/续期/销毁/查询、心跳/盘点和受鉴权中继，无任意宿主命令/路径。中心不得远程逐个调用 PrepareVm/网络/Activate；节点保留唯一的本地算法。

### 中心状态与节点责任

中心状态包括部署/格式/修订、高水位、有限节点登记、平台/租户/节点预留、owner、固定节点/代际、不可变模板/资源形状、原创建选项、意图/版本、启动/运行期限、未决操作及待发送集合、已确认事实、有限结果/窗口和退休责任。节点持久保存原本地映射、高级操作完整参数/结果、终止记忆、事实版本和接收确认。

中心不复制本地动作日志，不存命令/文件正文或磁盘；凭据配置仅在中心读取。查询/路由缓存绑定权威修订，重启可重建，不是授权真值。Pub/Sub 可唤醒，不是唯一可靠队列。

| 语义事件 | 成立依据 | 不可据此推出 |
|---|---|---|
| 中心接受 | 身份、参数、固定绑定、额度/收尾及待发送责任确认耐久提交 | 节点接受或 VM 就绪 |
| 节点接受 | 检查通过，原映射及本地责任持久保存 | VM 已启动或用户程序正常 |
| 节点就绪/停止/清理事实 | 原身份下该类真实证据持久保存 | 各类事实互相替代 |
| 中心应用事实 | 来源/全身份/操作/观察版本匹配，结果耐久保存 | 确认已被节点收到 |
| 中心确认、节点退休 | 中心保存后确认，节点满足责任/窗口/保留/引用条件 | 发出回执或心跳过期即可遗忘 |

中心先持久意图再派发；节点先持久责任再产生宿主效果。存储、消息、宿主动作和确认是独立步骤，不假设 Redis/SQLite 跨库原子化。接收确认也可丢失；有界摘要/高水位可替代细节，但不能遗失未知责任、终止记忆及旧请求拒绝依据。

### 中心持久化与恢复

首版使用有界 Redis 权威控制块，把必须共同提交的准入、额度、绑定、未决操作、结果窗口与 outbox 放入同一 hash。配置块字节/对象条数上限，并预留已接受工作的回执、终止、清理和退休空间；大文件、日志、模板正文不入块。

- 自有 Lua/CAS 写前校验键类型、部署/格式和预期 revision；成功以**单条 HSET**替换 revision 与规范化状态，写后不执行影响提交正确性的第二次写操作。Lua 原子执行不表示多条写入出错会回滚。
- 首版不另设权威二级索引；内存视图从块派生。CAS 冲突从最新状态重新计算，中心决定锁不跨远程 I/O、流或模板下载。
- 回复未知先核对原 operation_id/参数/修订，未确认不派发或分配替代身份。持久化错误后内存读到记录不足以确认耐久；恢复存储健康，再以新修订耐久提交包含原责任的状态，随后推进。
- 固定 Redis 版本在依赖/部署锁登记并实测。必需 `appendonly yes`、`appendfsync always`、`maxmemory-policy noeviction`、`no-appendfsync-on-rewrite no`、`aof-load-truncated no`；启动核对全部，未知配置不忽略，截断/损坏不静默修复后接单。
- 权威实例与可淘汰缓存分离，使用受保护网络/ACL、远程加密，配置内存、AOF/重写/备份磁盘和日志预算。新请求不侵占收尾预留。
- 一个有效中心写入者持有固定中心机器的部署独占进程锁，第二个同部署进程拒绝。这不是跨机租约；禁止另一机器同时运行同部署中心，不启用 Redis 自动切换来宣称无丢失。
- 正常进程重启使用原可靠存储。整盘丢失、备份回滚和管理员改写不在保证内；旧备份恢复须关闭接单、受控对账，不能以同库标记检测任意回滚。

中心、节点、Redis 独立重启；重启不清空别层。中心查询原节点/重发原高级请求；节点运行原本机盘点、未知处理和精确清理。格式/配置/有效写者/原记录不满足则失败关闭，不先执行再补账。

中心使用 `sandbox-center-store`：固定 Redis 引擎/客户端和官方归档指纹见[输入锁](../references/v1-baseline.json)。首版只接受同机 IPv4 回环字面地址、ACL 与固定独占目录，不支持远程 Redis、自动初始化或回退；回环连接使用客户端实际支持的期限。可信中心机器及受保护配置是前提，不向用户/来宾开放 Redis。恢复读取得到 `Observed`，成功 CAS 与持久化健康确认才得到 `Committed`；写入结果未知后，读取或重连不会解除围栏，必须以新修订重新耐久提交原责任。GLOBAL 生命周期与模板/内部构建引用保存在同一 `BusinessEnvelope`，只通过原 CAS 更新，不增加第二个权威块、索引或队列。字节额度在接受前覆盖未来回执、终止、清理、验证证据和构建结算；磁盘、重写及日志实际部署仍须按候选验收。

### 调度、寿命与终止

[中心核心](../sandbox-center-core/src/lib.rs)只决定全局创建、固定绑定、已归一化续期、销毁及窗口意图；[持久组装](../sandbox-center-store/src/authority.rs)负责决定后 CAS、当前状态耐久重确认和可脱离决定锁发送的派发包。[中心应用](../sandbox-center-service/src/application.rs)与 SDK 适配复用原输入、列表筛选/排序/分页和错误合同；connect 只延长原寿命，set_timeout 可缩短，零或负值接受终止。派发不跨决定锁；回复错配或通信失败不释放资源，停止与精确清理分开，真实就绪时间不能改为中心收件时间。查询/新路由每次耐久确认权威视图，不使用 Redis 故障前缓存授权；部署密钥产生实例绑定令牌，续期不更换。公开等待使用同一绝对截止点，内部重发和可选确认不得反复重置期限。

[宿主持久收件](../controller-service/src/controller/internal_inbox.rs)使用原控制器连接、进程租约和事务守卫；规范化全文、摘要、观察编号与终止记忆一起提交。`Recorded` **只代表持久收件**，不是创建准入或 VM 成功；已映射实例的销毁收件同时提交原核心 Kill，禁止恢复继续启动。[宿主服务](../sandbox-host-service/src/lib.rs)与[后台推进](../sandbox-host-service/src/driver.rs)复用原维护、恢复、到期和生命周期执行，不建第二队列/算法。所有接收、执行、确认及扫描共享同一非等待工作名额，取消后直到实际任务退出才归还；不能按请求另建接收句柄。有效局部失败停放该实例，共享权威故障中止扫描。该服务不连接 Redis、不安装用户 API key。

`admit_internal_create` 复用原创建准入事务：GLOBAL 租户到本地租户的稳定单射、全局实例到本地实例/创建操作，与额度、完整选项、原寿命、物理位置和 outbox 同事务提交。拒绝不消耗本地编号/映射；提交未知先恢复原记录，同请求不分配第二实例。已有映射或更新意图先于新时钟/模板检查，重放不重新定时或解释别名；映射是责任而非绕过执行检查的许可。宿主缓存提供 GLOBAL 原描述及 LOCAL 路径投影，准入核对原摘要、资源和 owner；远端选项不能携带宿主路径，网络规则复用原判定。启动使用原绝对截止点，重试不延后，获批时长为完整秒且不超过本机上限；可信时钟偏差观察不代替宿主独立到期。

`capture_internal_progress` 只从原本地权威状态提取并持久保存匹配事实，不接受调用者传入成功标志、不执行宿主动作。首次 Ready 使用原 Running 发布时刻与寿命；停止事实要求原 Destroyed 发布，Cleaned 还要求全部逻辑回收及精确 ConfirmRelease 持久见证。无本地映射的销毁可确认空清理，因为原子准入不会产生无映射责任且终止记忆阻止迟到创建。结果写入丢失可从原状态重建，重复已保存结果保持原观察版本，旧意图不在更新意图之后补写事实。内部续期复用原寿命检查，固定绝对期限与 Renewed 事实同事务保存，重复/迟到请求不重新计时。绑定的本地细节在两端确认/窗口退休完成前持续 pin 住，不由原维护单方面删除。当前收件格式仅由 `contract-versions` 报告，旧格式明确拒绝，不提供升级或自动修复。HTTP 接收只负责持久收件/重放已保存事实，真实动作由原应用推进；完整双服务生产链路尚待交付。

两层创建前预留完整对象/操作/回执编码包络，普通操作不能吃掉销毁槽；宿主收件及有限租户/本地映射进入原 SQLite 总预算。本地模板由原准入计费，不重复复制进收件块。选项保持原 64 KiB 上限，较小组件预算不是 SDK 默认。`/internal/v2/result-confirmation` 发送完整原事实：中心耐久保存后，宿主精确匹配已保存终态并压缩旧续期，中心收到精确确认才压缩自身历史；丢确认保留原责任，迟到确认不删更新意图。每个已登记保留位置独立经过 Open→ClosePending→后继代次/耗尽；节点排空只控制新准入，不是历史退休前置条件。关闭只针对同一沙箱的最新精确 Cleaned/NotAccepted 及其确认，原物理资源、数据/构建/发布引用均已结算；完整回执随关闭意图提交，丢回复重发同一回执。宿主在原 SQLite 事务只移除该实例细节并保存此位置单调前沿与最近完整终局回执；中心收到相同确认后才释放该位置。长寿命同伴不阻塞已销毁实例退休。不同位置、异参数或更老回执不能触及后继实例；不以缺席记录推断清理。永久全局/本地编号前沿仍不复用，单位置代次耗尽只禁用该位置。共享格式只以上述 `contract-versions` 为准，旧格式拒绝，无自动升级；至少四个槽保留重复续期和销毁。永久未知可安全阻塞新准入，不承诺无限接单或无条件完成。

节点为可接单、排空、暂不可达或禁用；排空只阻止新创建，已有命令/到期/收尾保持。候选同时满足兼容、模板、容量与近期健康；中心平台/租户预算准入后节点仍检查本机额度和收尾能力。

负载取已预留并发、CPU、宿主内存、磁盘各自除以正上限的最大比例，升序选择，同负载按 node_id 升序；检查溢出的整数比较，不使用浮点。物理空闲可否决，不替代预留。不可表达配置启动拒绝；无候选明确暂不可用，不替换模板。

仅明确“未接受且无副作用”的节点拒绝可解除原预留并记录失败，同次创建不自动换宿主。当前 `NotAccepted` 只由原应用明确的准入前容量拒绝产生：仍持有同一工作许可和应用锁，在原 SQLite 事务复核完整当前 Create、未准入且无本地映射，才保存终局事实。中心将该唯一原因映射为 429；模板、I/O、忙碌及提交未知不得转换成这种事实。模板验证和私有构建另按原创建身份、宿主无准入证据及完整终局确认结算引用，不能伪造 Cleaned。超时、丢回执、心跳过期和失联保持未知、固定绑定及占用，不迁移、不释额、不标销毁。

运行起点来自节点首次持久就绪，中心晚收不重算。中心保存固定续期意图，节点按原参数合法应用并持久保存后才确认；重放不从新的 now 反复加时。各机使用可信时钟与误差/安全裕量，具体数值在合同实现批次冻结；超偏差停止相关新准入/续期，回退不延长已持久期限，节点独立执行到期。

销毁单调：中心提交后拒绝新中心资格，节点持久落实后撤销本地资格、安装围栏，销毁先到仍阻止迟到创建。未知对象终止记忆按窗口安全退休。公开 kill 成功至少有原 VM 停止证据，精确清理前保留额度；停止、通道排空、目录/网络回收不同。分区不承诺中心接受即瞬间停止来宾。

等待本应用已持久接受的原销毁时，后台可能已将它退休；此时只能从本次新鲜耐久状态中读取同一完整操作身份的 `Cleaned` 终局回执，在原回复期限内返回成功。不以活动记录缺席、窗口前沿增大或不同操作的回执推断成功；存储读取故障仍为未知。该等待不开放历史查询或重新执行旧请求的入口。

### 查询与两端数据路径

成功 get/list 对应本次调用期间合法的中心已提交视图。已确认续期之后才发起的查询，不返回续期前期限，除非后续合法决定改变结果；旧节点观察不覆盖新期限/终止。单次 list 同一视图筛选、排序、分页，不拼各节点第一页；跨页无快照。心跳/历史 Ready 不证明当前健康，需要实时确认而无法取得时按固定错误处理。

单次 get/list 的生命周期、可见性及不可变模板绑定来自同一已耐久确认的业务包络；逐实例构造字段不再调用模板提供者重新读库，也不回退别名或另一份缓存。确认次数不随页大小或匹配实例数量增加。每次调用的原持久重确认及共享存储故障围栏仍保留，不以本项优化改变 Redis 持久性合同。

中心按权威固定绑定路由，节点重查全身份与本地许可、VM、围栏、寿命，再连原 envd。两端各自有限请求/流/缓冲/并发与撤销排空，不暴露未批准的宿主/envd 控制端口，不用用户 URL 决定目标。公开路径、字段与错误合同不增加自定义必填项。

Start/Connect 不设累计输出上限，顺序、单消息/在途边界保持；文件/一元回复/辅助工具预算分别适用。许可覆盖实际执行、完整正文或排空，不以响应头、发送取消或 HTTP 成功退还。

### 模板分发、退休与公开重复请求

中心统一模板归属/别名；创建一次解析并绑定授权、不可变描述/修订/摘要/启动配置/形状。构建/产物服务提供受保护 HTTPS 只读接口，不接受任意宿主路径；Redis 只存描述。节点在有界临时空间下载并验证类型/长度/摘要/配置，再登记可用；中心收到匹配可用事实才列为该模板候选。中断/损坏/无空间不发布就绪或退回 base；缓存可回收，实例盘私有可写，预装 CI 模板也遵守登记/查询。

单个模板的缓存尝试仍按原总期限串行执行。每个受管修订/摘要独立轮转宿主起点，前置超时不能使后续健康宿主在连续扫描中一直得不到尝试；多个模板不互相重置起点。轮转位置只是非持久调度提示，按当前有界目录/登记清除失效键，不新增权威记录或任务队列。重启可重置提示，但不能重置缓存事实、身份或未决责任；只有原校验回执提交成功才登记可用。

模板整个子系统用工程测试、不形式化证明；核心绑定、准入、执行资格及精确清理不能随之排除。两层分别配置活跃/在途/未知、结果/窗口、传输、模板缓存、存储/日志和收尾预算。归属/未决/预留不用 TTL 删除；原资源、引用、保留及中心耐久接收条件满足才退休，高水位/窗口不倒退。结果过期后的旧请求拒绝，不当新请求执行。

内部 operation_id 只保护同一已接受操作，不合并无幂等键的两次公开 create；丢回复后再次 create 可产生第二个沙箱，metadata/list 不能原子找回唯一原请求。可选公开幂等键/授权操作查询为需另行确认的候选，不是当前必做接口。任意有副作用命令/文件写也不承诺恰好执行一次。

## 请求入口：C → A

本节规定固定 SDK 的公共语义和已实现的本地检查；目标公开入口由中心承担，本地节点保留独立执行前检查。提到同事务时指该层自己的事务，不表示跨 Redis/SQLite 原子化。

- C 从有效凭据得到调用者身份；不能把请求正文中的 tenant/user 字段直接当成可信身份。
- 生命周期输入携带调用者、sandbox ID、操作类型及业务参数；内部操作编号由可信服务分配/映射。没有客户端幂等键时，不能承诺两个独立 create HTTP 请求只创建一次。
- A 根据当前持久状态检查归属、能力、寿命、资源预算及是否正在撤销；接受决定、操作记录和待执行动作在一个事务内提交。
- C 将稳定结果或等待超时映射为固定 E2B 响应。内部 pending/unknown/revoking 等状态可以保留，但不能随意扩展 E2B 公共状态枚举。
- 同一请求重复、操作查询与重新提交是不同动作。相同幂等键改变参数必须拒绝；C 负责记录客户端真实提供了哪些可重放标识。

寿命接口已按固定 v2 SDK 区分：create/connect 省略均为 300 秒，创建不得将过长请求截短；connect 只延长、请求超过部署单次上限返回 400，允许的请求最多续至该实例原始总截止点。set_timeout 按服务端当前时间重设，零/负值立即到期，大正值截顶；成功返回表示期限已提交，不表示宿主停止已经完成。已到期实例不再授权或接受续期；原实例仍处于 Running 但已超过总寿命时更新返回 400，正在撤销时返回 409，外租户/已销毁实例为 404。已撤销令牌的 health 请求仍为 401，固定 SDK 的 is_running 抛认证异常而非返回 False。非正更新立即撤销既有数据传输，停机仍由到期扫描走核心 Kill/宿主精确收尾，不新增第二套状态机。

可信配置 `max_timeout_secs` 限制 create/connect 的单次申请，`max_lifetime_secs` 限制从首次持久发布 Running 起的总可用寿命；后者省略时采用前者。独立的 `startup_timeout_secs` 只限制从准入到发布 Running 的等待，默认 300 秒，由部署方设置，不能由客户端的 `timeout` 改写。准入事务同时保存这条启动期限和获批可用时长；只有在启动期限之前完成真实就绪并原子发布 Running，才以该发布时间重设可用寿命起点、初始截止点和总截止点。到达启动期限即持久记录补偿意图；扫描器尚未运行时，迟到的 Running 发布也必须拒绝。Running 实例不再受启动期限约束。重启或配置放宽均不延长原实例已经持久确定的期限。`default_timeout_secs` 可省略，若仍填写则只能为 300；旧部署的其他默认值须显式改配置，不能静默忽略。创建请求须同时满足单次和总寿命上限，固定 Harbor 的 86400 秒请求必须由实际部署预算支持。当前完整库只支持同配置重启；旧数据库或不完整配置明确拒绝，不提供旧部署升级或寿命补造。

查询列表只从调用者当前可见且未到期的实例派生，不另存一份业务状态。`metadata` 按固定 SDK 的分层 URL 编码解码，所有键值同时精确匹配；`state` 接受 `running`、`paused` 及组合，V1 的合法 paused 筛选返回空集。`startedAfter` 是包含边界的启动时间下限，按上游微秒精度比较；`template` 只匹配创建时绑定的不可变模板编号（未配置目录时为 `base`），其他合法名称为空，带标签或非法名称拒绝，不伪造模板别名。默认排序为启动时间降序、相同时间按外部 ID 升序；`order=asc` 同时反转两个键。先筛选、再排序和分页，页大小 1–100；`X-Total-Running` 返回筛选后、游标及页大小之前的运行数，仅在请求包含 running 时提供。游标携带时间、ID 和方向，方向不符或格式非法返回 400；它只定位结果，不授予权限，换用户仍重新检查归属。删除游标所指实例不使游标失效；翻页不冻结整个集合，不承诺并发创建/销毁期间的快照列表。旧数字游标不兼容，应从首页重新查询。

详情查询另返回当前沙箱专属令牌、部署域名、原始联网参数及 `lifecycle={onTimeout:kill,autoResume:false}`；列表不返回令牌或详情专属字段。`allowInternetAccess` 区分创建时省略（null）、显式 true/false，network 保留原始地址顺序、CIDR 写法和空列表/省略区别；这些只用于查询，执行仍使用核心规范化后的策略。参数随创建意图同一事务持久化；旧记录无法还原的原始网络字段省略，不从策略猜测。详情暂不提供别名字段，alias 省略；创建别名不参与列表筛选；V1 无共享卷，get/list 的 volumeMounts 返回空数组。

固定 SDK 的管理 HTTP `request_timeout` 独立于沙箱寿命：类调用省略为 60 秒，实例省略继承其连接配置；类调用、分页覆盖与 `is_running` 的零值关闭该请求期限，但实例管理方法经配置重建后零值实际恢复为 60 秒。负数使用 HTTP 期限错误，不是服务端寿命参数拒绝；大正数也不受 Connect 毫秒头上限约束。管理期限失败可保留原创建或销毁副作用；只能查询原身份并显式收尾，不自动重新创建。这里记录的是固定 SDK 的当前行为，健康请求的错误包装还与管理请求不同，精确观测范围见[验收清单](testing-plan.md)。

## 动作接口：A → B

### 模板服务 → 创建准入（#123/#6）

模板目录、归属、别名、候选发布门与自助构建入口属于中心。构建能力由受保护配置显式启用；未部署时明确拒绝构建，不切换旧模式。静态目录始终是明确登记的不可变描述，`base` 只是其中一个名称，不能替代不可用的其他模板。测试层级见[验收清单](testing-plan.md)。

预制目录的 `templates` 包含不可变编号、修订、owner（null 为明确共享）、内核及 ext4 的绝对路径/长度/SHA-256、来宾 CPU/内存/磁盘及整个 VMM 的宿主内存上限；`aliases` 只在创建时解析，`compute_limits` 约束全局/租户 CPU 与宿主内存总额度。路径由可信部署方提供，客户端仅给模板名称；不存在逐题特殊入口。同一编号第一次成功准入后不得换描述，即使实例已销毁；变更产物或形状须使用新编号，别名可改指向。创建、连接、详情和列表报告实际不可变编号/形状，筛选也只匹配该编号，不动态解释别名。

中心先在同一 Redis 权威块持久绑定 GLOBAL 模板、原创建选项、寿命、资源及固定宿主；宿主在原 SQLite 准入事务保存 LOCAL 产物、租户映射、资源计划和 outbox。二者没有跨库原子事务；任一提交未知都不重新分配替代 VM。未知与他人模板统一返回 404，避免枚举；已授权模板暂无校验可用节点返回暂不可用，不换 base。尚未确认精确回收的实例继续占额，逻辑宿主内存额度不是 Linux 物理预留。启动前核对本机受保护产物的类型、长度和摘要，重启核对原绑定；观察、停止和精确清理不依赖源镜像存在。cgroup 父目录/UID 范围仍是稳定部署前提。

节点首次校验稀疏产物时，按文件系统报告的数据/空洞区间计算完整 SHA-256：空洞仍逐字节计入同等长度的零，仅避免通过文件系统读取零区间。摘要及逻辑容量不变；不支持区间查询时从头回退完整流读取，真实 I/O 错误、异常区间和长度变化拒绝。受保护路径、校验前后元数据一致性以及缓存命中条件保持原检查；该优化不免除首次完整摘要校验。

预制模板、启动描述及验证证据按已启用功能提高当前库的功能门；这不是旧部署导入路径。模板一旦进入资源账本，关闭目录配置不能绕过计算额度或改写绑定。模板目录不是构建状态库，不接收用户上传，也不管理镜像回收。

[#123 的候选构建工作器](../tools/template_worker.py)由[自助构建监督服务](../tools/template_build_service.py)在新建、受限、独占且可回收的构建 VM 内运行，复用 BuildKit/umoci/mke2fs，宿主不得执行用户 Dockerfile 或解包用户镜像。boot_id/virtio 磁盘检查只防误操作，不是隔离或远程认证证明；隔离、外部总期限、独立构建额度和最终 VM 清理由监督器负责。每项工作有新目录/缓存、有界输入/展开量/日志，失败保留原身份且不生成成功状态。公开 OCI 由固定 regctl 直接导入；原 OCI tar 工具入口保留。首次层校验在同一读取流核对 blob 大小及 SHA-256、完整展开流 diff_id 与归档成员；仅全部通过后才记录可复用结果。 gzip 层以单个预取线程并行解码和主线程摘要/成员检查，队列至多保留两个 1 MiB 块；预取总量限制为该层剩余展开额度加用于拒绝超限的一字节，不预先解完整层或落盘。成功和异常退出均先停止并等待原线程，再关闭解码源；线程错误传回校验调用，不形成可复用记录。复用已有层检查仍完整重读并校验当前 blob 摘要。检查摘要和展开预算后由 umoci 处理 whiteout；不兼容架构/操作系统、设备节点、容器卷及其他压缩格式明确拒绝。OCI 层的成员名和链接目标使用 Linux/POSIX 语义：反斜杠是普通字符（如 systemd 转义单元名），原样保留，不解码或转成分隔符；成员名和硬链接仍拒绝绝对路径、`..` 分量及 NUL。上下文仍拒绝反斜杠，只接收普通文件、目录和不越界的相对链接，剥离宿主所有权和特殊权限，不跟随链接写出。

转换产物始终为 `candidate`、`ready=false`，构建工作器不能自行登记。它加入静态 BusyBox 启动环境和固定 envd；宿主 cgroup 仍限制整个 VMM，来宾 envd 不启用其可选的进程 cgroup 管理。候选清单保留原始 ENV、WORKDIR、USER、CMD/ENTRYPOINT，并生成 `runtime_defaults`；构建时尚未启动实例，`startup_applied=false`。平台 resolver 来自可信构建配置；这不是对来宾 root 的防修改承诺，目的地址限制仍由宿主 IPv4 规则强制，不新增域名过滤/IPv6。

候选补齐容器运行时通常注入的 IPv4 `localhost` 映射：保留普通 `/etc/hosts` 中的自定义条目和注释，缺少 IPv4 回环映射时追加 `127.0.0.1 localhost`；已有非回环或无效的 `localhost` 地址明确拒绝。输入及生成文件限 64 KiB，拒绝目录/特殊文件；符号链接被替换为平台普通文件，不跟随其目标，硬链接另写新 inode，避免修改其他镜像文件。仅依赖公开 DNS 不能代替本地回环解析；该补齐不改写 NSS 策略、不设置新主机名或承诺 IPv6，也不修改已发布模板/运行实例。新行为须经新构建发布才生效。容器运行时行为参见 [Docker 网络说明](https://docs.docker.com/engine/network/#custom-hosts)。
候选启动时在 `/dev` 就绪后挂载每个实例独立的 `/dev/shm` tmpfs，初始选项为 `nosuid,nodev,noexec,mode=1777,size=64m`；支持普通用户的 POSIX 共享内存和信号量，挂载失败则不写就绪标记。64 MiB 是文件系统容量上限，不是预分配内存或额外宿主预算；实际使用计入既有来宾/VMM 内存边界。来宾 root 可改写自身挂载，该初始上限不代替宿主强制额度。数据不写回模板，不在实例间共享；已发布模板须重新构建才包含该启动行为。默认容量参照 [Docker 运行参数](https://docs.docker.com/engine/containers/run/)，Linux 用途见 [tmpfs 文档](https://docs.kernel.org/filesystems/tmpfs.html)。

候选的本地 envd 启动门只适用于平台制备后的 ext4 冷启动：安装时先验证 `/run` 未被重定向，再删除输入镜像的 `/run/sandproof-boot-ready` 目录项，不跟随符号链接或改写硬链接目标；目录或删除失败使候选构建失败。BusyBox `sysinit` 返回失败仍可能继续 `respawn`，因此不能只依赖启动脚本的退出码。启动在根盘可写后、其余配置前再次删除标记；agent 通过固定 BusyBox 的文件系统 stat 核对 `/run` 的实际 tmpfs 类型，要求 stat 本身成功，并拒绝 `/run` 或标记为符号链接。仅当本轮挂载、网络等配置全部完成后才在新 `/run` 写标记并允许 envd；proc、根盘重挂载或清除失败时，遗留 ext4 文件也不能通过此门。构建前另检查 BusyBox 的 rm/stat applet 与文件系统格式能力。此门不是外部模板 Ready 发布、宿主隔离或远程认证证据，也不防运行中来宾 root 篡改挂载/标记；不承诺成功启动后手工重复执行 boot 的语义。固定 base 的 systemd 启动路径不使用此标记。已有模板须重新构建、检查并发布才包含修复。

公开获取由[固定 regctl 客户端](../tools/template_fetch.py)在同一构建 VM 内执行；工作器的 `kind=oci-reference` 接收仅含 `image` 的 JSON 文件。入口接受公开仓库的标签或 SHA-256 引用，`ubuntu:24.04` 等简写规范化为 Docker Hub 的完整名称。标签只在本次构建开始时解析一次，记录实际原始清单摘要，后续下载按选定摘要固定；用户需要跨构建复现时使用 `@sha256:`。拒绝认证信息、端口、私有 DNS 名或 IP 字面量；地址可达性仍由既有公网 IPv4 隔离策略决定。regctl 固定 v0.11.6/linux-amd64 及 SHA-256，使用空 HOME/Docker/regctl 配置，不携带宿主仓库凭据。摘要输入须匹配原始字节；OCI 清单直接使用，OCI/Docker 索引只允许唯一 linux/amd64 OCI 或 Docker schema2 子清单，不下载其他平台；不支持 schema1 或嵌套索引。Docker schema2 先校验所有 blob、diff_ids、tar 路径与展开限制，再在构建 VM 内由同一固定 regctl 对已校验的单清单私有 layout 绑定本地 `candidate` 标签并执行 `image mod --to-oci --replace`，原地替换清单并复用层文件，不重新获取来源；转换前后配置与各层的摘要、大小、顺序必须一致，转换结果再次通过 OCI 检查。拒绝外部 layer URL 和 foreign layer。导出后校验所选清单、所有 blob、diff_ids 与展开限制。导入不执行 ONBUILD；Dockerfile 构建仍遵循标准构建器的 ONBUILD 语义。

获取清单与 OCI tar 的 stdout 合计受 `max_input_bytes` 限制（不含 HTTP 头、重试等线上字节），监督服务、worker 与验收规划共用 16 GiB 输入硬上限，实际额度由可信配置显式选择；提高输入额度必须同时满足构建盘空闲、传输和预留预算，展开层仍最多 32 GiB。stderr 与其他工具共享 `max_log_bytes`，使用同一总期限和 VM 磁盘/内存限制。候选增加 `public_source` 记录原始引用/实际摘要、所选摘要、平台、下载产物字节及工具指纹；schema2 转换另记 `converted_digest` 和 `conversion=docker-schema2-to-oci`，原始/所选来源摘要保持不变。此能力已接入自助构建 API；私有仓库认证后置。Harbor 的自有构建适配与原模板 API 的差异见[评测入口](../benchmarks/README.md)，不宣称原 E2B 模板 API 全兼容。

可信自助服务配置可选 `docker_hub_mirror`，只接受公开 HTTPS 仓库主机名，不接受 URL、端口、路径、凭据或 IP；客户端不能提交此字段。仅公开 OCI 获取将规范化的 `docker.io` 仓库通过该主机传输，其他仓库及 Dockerfile/BuildKit 不受影响；不修改宿主 Docker、DNS、代理或防火墙。镜像站选择参与持久配置绑定，重启不能隐式切换。`public_source.reference` 仍为原引用，另记 `transport_registry`；标签从镜像站解析一次，所有后续获取按选定摘要固定，摘要引用仍必须与原请求精确匹配，原有输入/日志/期限/网络限制不变。镜像站不是来源真实性证明：需要跨来源复现时应与独立记录的原仓库摘要核对或提交摘要引用，不能仅凭标签相同宣称原镜像相同。没有此配置时仍直连，不自动探测或选择第三方站点。

正式发布门由可信构建监督方确认构建 VM 回收、旧写者退出后，用[登记准备工具](../tools/template_stage.py)移交候选至中心服务账号独占的 `template_registry.root/inbox/<候选编号>`。HTTP 客户端只给随机 32 位十六进制候选编号，不能给宿主路径、owner、修订或 Ready 标志；中心认证决定 owner。中心复用原候选校验/密封算法，检查只读普通文件、单链接、长度/SHA-256、绑定路径、envd 版本和 ext4 实际可用空间，不信任工作器自报。持久接受发布意图后密封同盘 `artifacts/<编号>`；编号 `tpl-<候选编号>`、修订 r1 和形状不可改。历史数量及产物字节有全局/租户额度；失败和未决记录仍占额，模板不随构建结果到期删除。移交是可信部署动作，不给中心读取宿主 root 私有目录的权限。

登记准备为新候选复制独立文件，支持时按文件系统数据区间复制并保留空洞，不支持时回退有界流式稀疏复制。副本同步后完整回读 SHA-256 和长度，匹配工作器候选才写清单并原子暴露；不再额外预读同一源磁盘。源文件不变，同编号已暂存候选的重试仍核对源和副本摘要；复制或校验失败只清理本候选未发布暂存目录，不减弱正式发布门的再次校验。

自助构建监督服务对自己下载并校验的 `builds/<构建编号>/candidate.ext4` 使用内部移交入口：构建 VM 确认回收后，同盘将该单链接 inode 原子移入对应私有暂存目录，省去重复复制；跨盘仍复制。此入口只接受当前宿主用户拥有的普通文件、固定构建槽和独占父目录，不向 HTTP 客户端开放路径或移交选项。文件同步、完整 SHA-256 回读、只读权限及正式发布门检查保持；移交成功后原下载路径消失，不能再由下载目录访问同一 inode。移交中断时按同编号暂存/最终目录恢复，不重新构建；普通检查或 I/O 失败先恢复原槽。原期限已到且已确认发布未接受时，监督服务清理该编号的最终/未完成暂存并释放预算；发布结果未知时保留两者继续观察。通用登记准备工具仍按上一段复制并保留源文件。

临时启动检查复用正常资源准入、真实启动/envd 初始化和精确销毁，VM 身份与创建意图同事务提交，也占运行资源额度，但不暴露为用户沙箱会话。只有完整绑定成功 Running 已持久确认、且原 VM 和网络槽全部回收，才登记 Ready。文件/启动明确失败不发布；提交、启动或收尾未知保留 checking，同编号重提只返回原记录，不另起检查。重启只观察/推进原工作流；未持久确认检查成功的中断不得补造 Ready，原 VM 按既有启动/寿命期限回收。已确认检查成功但丢失清理回执，可在精确回收后登记 Ready。Ready 不保证用户程序持续健康，也不能用来宾 stdout 或清单自报代替管理通道检查。

中心的 `template_registry` 是完整可信配置，字段为 `root`（中心账号独占绝对目录，预建 inbox/artifacts）、`max_templates_global`（1～256）、`max_templates_per_tenant`、`max_artifact_bytes_global`、`max_artifact_bytes_per_tenant` 和 `validation_timeout_secs`（1～300 且不超过运行上限）；个人额度为正且不超过全局。`metadata_budget` 在接受前保留完整描述、验证请求、终局响应与原验证证书。该配置和静态描述持久绑定；重启不改根、不关闭功能、不补造证据，也不自动升级旧账本。

受保护只读产物接口只接受 `{node, revision, digest, part}`；part 仅 kernel/rootfs，不接受 URL、路径或重定向。双向证书须匹配请求中的唯一已登记节点；描述来自同一新鲜权威视图。宿主有界下载到原缓存目录，逐段核对完整长度和摘要，再用原模板/ext4 检查登记可用。每个池独立缓存、独占写者及显式下载/文件/inode 预算，共同计入原物理 profile；取消 HTTP 不提前归还尚未退出的工作许可。未知、损坏、无空间、目录替换或错误证书都不发布可用事实，也不自动宽泛删除临时目录。

在线模板就绪观察使用同一双向认证通道的 `/internal/v2/template-readiness`，仅接受匹配证书的 `{node}`。返回同一已确认权威快照中的该节点及其保护的预置目录修订/摘要，响应最多 256 KiB；不返回文件路径、用户凭据或沙箱记录，不读取镜像正文、不设置健康/缓存状态、不派发工作。宿主受保护 `observe-center --config` 命令复用固定源和证书，既不打开本地账本/VM 租约，也不初始化或恢复。该观察不替代创建时原准入检查或离线 audit；测试轮询不得停启服务，每次须等到本次检查开始后的一次成功宿主状态观察，不能复用重启前尚未过期的健康租约。判据使用原健康策略的发送时刻加固定窗口，不另设等待时长或健康缓存。模板观察的绝对期限使用原下载预算，单次查询保留短期限，轮询不重置期限；VM 启动、寿命、评分和监督总期限不变。

中断下载只有在全部缓存声明、目录设备/inode、owner、文件类型及预算核对通过后，才清理该原目录内的 kernel/rootfs 残片；原声明和目录保留。同全文请求复用原身份重新下载，不新建替代目录；空闲待恢复项仍占完整条目和产物预留，清理未知仍占临时预留。缺失/不完整声明、身份冲突或无法确认的库存使模板缓存明确不可用：不下载、不登记模板、不宣称缓存空间可用，保留原目录及排他租约。该缓存故障不关闭唯一宿主内部入口和原生命周期驱动，已有实例仍按原 SQLite 绑定执行到期、终止和精确清理；配置、共享权威、受管根或租约检查失败则仍拒绝启动。不可用缓存不是备用模式，也不回退 base 或认领陌生资源。

登记的 imageDigest 是实际使用的 linux/amd64 OCI 清单摘要：Dockerfile 为 BuildKit 导出结果，公开 OCI 为固定的源清单或选定子清单；Docker schema2 为转换后的 OCI 清单摘要，原始来源保存在 `public_source`。可变 tag 不代表跨构建固定来源，需要固定来源时提交 `@sha256:`。服务独立复算内核和根盘摘要，不证明 OCI 软件与转换盘内容等价，也不提供构建供应链认证。明确拒绝私有仓库凭据、任意宿主挂载、特权/GPU、多服务及不兼容镜像，不声称支持任意 Dockerfile。

候选 ext4 在构建 VM 内先格式化，再通过私有 loop 挂载复制完整根目录，使用内核文件系统写入并保留亚秒 mtime、UID/GID、权限、硬链接、符号链接和扩展属性；不跟随镜像符号链接。构建基础镜像须提供 GNU cp、mount/umount，固定内核须支持 loop/ext4，相关工具摘要写入候选清单。正常卸载及原 loop 关联消失的等待使用同一构建剩余期限，允许完成复制后的脏数据落盘；复制或卸载失败不生成成功状态。失败后尚存挂载的卸载和原 loop 回收共用独立的 5 秒宽限，不延长构建期限，也不能将原失败变为成功；剩余资源仍由外部监督器销毁整台 VM。卸载及关联回收完成后才进行 e2fsck、空间检查和完整磁盘摘要。宿主不挂载或解析候选文件系统。

工作器读取工具日志至 EOF 后，等待该工具退出仍受同一构建截止时间约束；输出已关闭不代表进程完成。超时或截止时间之后才观察到退出时按构建超时处理，并继续回收该工具的私有进程组，不能记为成功。

### 自助构建入口、部署与恢复

这是显式部署的 Sandproof 扩展，不是原 E2B 模板构建 API。用户构建请求由中心认证并转交受保护的[监督服务](../tools/template_build_service.py)；该私有辅助角色不持有全量用户 API key、不作为另一个公开入口。运行与构建使用同一个 `sandproof-host` 产物、独立数据库/命名空间/状态/jail/UID/cgroup/缓存根，受同一物理 profile 管理。中心原权威块内保存原窗口及构建锚点，窗口准入＋固定 builder 创建一次 CAS 接受；同 tuple 重试不创建替代 VM，参数变更拒绝。私有数据访问只授权同一新鲜视图中的原构建锚点，不允许普通用户访问隐藏 VM；临时模板验证同样沿原生命周期并持续隐藏，成功及精确收尾证据齐全才 Ready。监督服务的原 BuildStore 仍是唯一构建工作队列，不增加第二套构建日志库。

| 接口 | 输入与结果 |
|---|---|
| `POST /sandproof/template-builds` | `kind=dockerfile` 或 `kind=oci` 加公开 `image`；可选 `resources={cpuCount,memoryMiB,diskMiB,minFreeMiB}`、`timeoutSeconds`、`allowInternetAccess`；返回 202 与 buildID、state、deadline |
| `PUT /sandproof/template-builds/{id}/context` | tar/tar.gz，根目录有 Dockerfile；须有 Content-Length；超额/不完整拒绝，成功后不能覆盖 |
| `GET /sandproof/template-builds/{id}` | 仅本人；状态、有限失败原因；只有 Ready 返回完整模板编号/修订/摘要/形状 |
| `GET /sandproof/template-builds/{id}/logs?offset=0&limit=65536` | 按字节位置读至多 64 KiB，带 nextOffset；总日志受配置限制；当前在来宾构建结束后获取，不保证实时尾随 |

Ready 返回的模板形状使用 Rust `TemplateView` 的规范字段 `cpuCount`、`memoryMib`、`diskBytes`、`hostMemoryBytes`；构建请求的资源字段仍为 `memoryMiB`。Rust 序列化和 Harbor 适配共用[响应样例](../tests/compat/template-view.json)检查该边界。

不接受 owner、Ready、宿主路径、工具或凭据字段；陌生/他人编号均 404。可选 `Idempotency-Key`（1～64 个字母/数字/下划线/连字符）按租户绑定规范化请求，相同重提返回原编号，不同内容 409；缺省每次是独立工作。公开引用不接受凭据、本地 transport、自定义端口或显式 IP；私网与宿主地址保护仍依赖既有包规则，字符串检查不代表 DNS 安全证明。

日志页的 64 KiB 上限与 offset/nextOffset 按原始日志字节计数；无效 UTF-8 以替换字符展示。JSON 转义可能放大响应，小客户端仅对日志 GET 保留有界的转义与封装余量，其他响应仍限 64 KiB，不增加日志原始总量或单页预算。通用评测报告用 `build_log_error` 单独记录诊断读取/保存失败的异常类型，不覆盖原构建终态，不保存可能含凭据的异常文本，也不为取日志重发构建。

来宾 `build.log` 在获取输入、OCI 校验、rootfs 解包、平台安装、ext4 生成/检查和整盘摘要阶段记录 `[sandproof-phase]` JSON 行，进入阶段先刷新 started，退出记录 completed 或 failed。时间为同一工作器单调时钟的相对秒数；公开 OCI 的获取阶段包含其校验。诊断与工具/守护进程日志共享原总预算，不包含命令参数、路径或异常文本；失败后的诊断写入出错不得替换原异常。缺少结束行只表示诊断不完整，不代表该阶段或构建成功，来宾日志也不能替代外部期限、结果和清理证据。

工作器非零退出时，即使已写出状态文件或工具日志为空，也保存有限的来宾命令输出，不序列化含宿主连接信息的 SDK 异常。优先保留 stderr 尾部的异常原因，其余空间保存 stdout 前缀；与工具日志合并时共用 `max_log_bytes`，必要时截去工具日志尾部。非零退出不能仅凭候选状态继续下载或发布。日志获取仍不是清理完成的证据。

工作器命令等待发生 SDK 超时时，在进入原清理流程前尽力保存 `build.log` / `daemon.log` 的有限前缀，并明确标为不完整日志。两份日志共用 `max_log_bytes` 和 5 秒采集窗口，SDK 请求超时参数设为 1 秒；窗口到期不再发起下一次读取，已在途读取可能稍晚返回。此阶段只读取诊断字节，不读取候选或状态，不重启命令、不延长构建期限；日志缺失、传输失败或落盘失败均不替换原超时结果，SDK 异常文本也不写入用户日志。等待超时和保存日志均不代表来宾命令已终止，仍须独立确认原 VM 清理完成。

正常下载工作器状态、日志和候选盘时，共享原构建截止时间。[固定 SDK 的流读取](https://github.com/e2b-dev/E2B/blob/ccaf9fc0ffe6ac39c7ec786af7608ab1de19467b/packages/python-sdk/e2b/sandbox_sync/filesystem/filesystem.py#L207-L224)已将显式 `request_timeout` 用于整个传输的期限；应用层另在每次读取前后及流结束时核对原工作期限，统一不同下载阶段的剩余预算，不能将 SDK 描述为只有单次空闲超时。到期不再开新流、接受后续块或以迟到 EOF 提交候选，未完成临时文件按原流程删除。SDK 超时参数使用剩余时间，包括不足一秒的余量；正常日志的参数仍至多 30 秒。已在途读取或本地文件同步可能稍晚返回，此检查不承诺强制中断宿主 I/O；超时不代表 VM 已回收，仍保持原身份和清理占额规则。

Dockerfile 构建使用固定 BuildKit 的 `auto` snapshotter，在每项独占构建 VM 的私有工作目录中探测可用实现，避免强制复制完整父快照。固定版本的选择顺序为 OverlayFS、fuse-overlayfs、native，能力探测和回退由 [BuildKit 0.28.0](https://github.com/moby/buildkit/blob/v0.28.0/cmd/buildkitd/main_oci_worker.go#L368) 实现；实际选择保留在受限 `daemon.log`。仍保持 OCI 进程隔离、私有缓存目录与原构建资源/时限，输出照常经过 OCI 校验和独立候选盘转换。内核列出 OverlayFS 只证明驱动可用，不代表本次目录已通过探测或构建已成功。

Dockerfile 构建默认明确禁用外部 gzip 解压器。运维可在可信 `tools` 配置中同时添加 `igzip` 和 `libisal.so.2`，两项均须提供绝对普通文件路径及 SHA-256；缺一项或含其他工具名会被拒绝。监督服务上传这对产物，工作器重新核对指纹，在本项构建私有目录中建立标准名称的硬链接，仅向 BuildKit 守护进程提供该目录的 PATH / LD_LIBRARY_PATH，并禁用 unpigz 回退。固定 [containerd 2.2.1](https://github.com/containerd/containerd/blob/v2.2.1/pkg/archive/compression/compression.go#L270) 选择 igzip 后会传播启动及非零退出错误；后续完整 OCI 校验和原构建期限仍生效。运行库须兼容固定构建来宾；工具安装或组件提速不代表完整任务已通过。用户构建请求不能选择工具或修改这些环境变量。

Dockerfile 的固定 BuildKit 使用不推送、不登记的 image exporter，将 OCI 清单、配置和层留在本次私有内容存储。守护进程停止后，worker 仅按导出描述符将引用的普通文件硬链接到新的 OCI layout，避免在同一构建 VM 内重复复制大层。此路径限定 BuildKit 0.28.0 的单个 `runc-overlayfs`、`runc-fuse-overlayfs` 或 `runc-native` 内容目录；目录/文件符号链接、缺失或歧义的存储、大小/身份变化及不一致的清单/配置摘要均拒绝。硬链接不代表已校验：所有 blob 摘要、diff_ids、tar/gzip 完整性及累计展开/条目限额仍在 umoci 解包前检查，仍由 umoci 处理层删除和权限。固定版本的目录结构变化需要重新适配和实测，不能改用未验证的裸目录作为候选根文件系统。 完整校验成功后，worker 在 `build_cache_cleanup` 阶段删除本项工作已停止的 BuildKit 私有缓存（快照、元数据和原内容链接），再解包并生成候选盘；OCI layout 自己的链接继续保留同一清单、配置和层字节。清理失败即终止转换，由监督器回收原构建 VM，不继续分配候选盘；此清理不操作其他工作或宿主缓存。

候选盘转换使用固定 umoci 0.6.0 的 `raw unpack`，在新建的 0700 私有目录内提取 rootfs。它与普通 `unpack` 使用相同的层解包、ID 映射和 whiteout 处理，省去供 `repack` 使用的全目录 mtree 摘要扫描及未使用的 OCI runtime bundle 配置；不省略输入校验、候选磁盘完整摘要或启动验收。启动参数仍来自已校验的镜像配置，通过平台启动路径应用。此候选根目录不用于 umoci `repack`。

监督服务仍以 root 运行并独占原工作库、窗口 helper 和物理租约。配置包括 `root`、固定回环 `bind`、仅供必要物理检查的 `runtime_config/builder_config`（唯一宿主格式，业务字段位于 `native`）、显式 `registry/registry_owner_uid`、`builder_template` 的可信必要形状、`center` 受保护边界、七项必需的 `tools={名称:{path,sha256}}`（可另加完整 igzip / libisal.so.2 对）、`dns_servers` 及 `limits`。`center` 明确给出固定私有地址、domain、仅此服务使用的 opaque 凭据文件、私有窗口时长/锚点上限及寿命上限；不保存整套用户密钥，不从旧宿主字段推导公开入口。用户只能通过中心的原鉴权构建接口进入，中心派生租户，固定凭据与 canonical owner 一起提交；此凭据不直接授权来宾动作，中心仍逐请求核对同一 Redis 信封的窗口及锚点。Dockerfile 工作传六项必需工具及已配置的可选解压器对，公开 OCI 另外传 regctl 与获取模块。limits 仍为原 CPU/内存/盘、工作期限、作业/未决数、工作盘、输入/展开/条目和日志预算；生产须按本机资源明确填写。旧格式或配置绑定变更拒绝，不自动迁移。私有 VM 同步准备使用工作剩余期限；过期不创建，丢失回复只观察原编号。

监督服务启动时核对跨池必要条件：构建期限加 60 秒不超过构建池及中心的单次/总寿命；启动检查期限满足运行池寿命上限；上传覆盖输入/工具及有界 HTTP 开销，下载覆盖完整候选；目标最大形状可被空运行池与发布额度接收。中心从同一受保护登记中的唯一 `builder_revision` 选择基底并规范化派生摘要，Python 不提交基底或摘要作为准入授权；其显式 `builder_template` 只做原必要形状检查，真实文件仍由原宿主缓存验证。私有盘至少容纳目标盘、展开上限和两份获取输入，实际来宾可用块仍由工作器检查。这些检查不是动态预留，不能替代真实配额或失败收尾，也不能静默缩短已接受请求。公网 DNS 仍只接收 1–2 个公开单播 IPv4 resolver，不承诺域名内容过滤。

构建产物先按原 nonce、完整摘要及 inode 身份封存。root 监督器关闭所有写入句柄并同步后，仅将精确已登记的 kernel、rootfs、manifest 和 owner marker 移交给中心账户；交接中断不发布，保留原身份重试，不能接管陌生目录。中心只读取自己独占登记根，经受保护只读 HTTPS 服务提供产物；宿主重新限额下载、核摘要及原 ext4 检查后才登记可用事实。中心不读取宿主 jail、缓存或私有配置，原工作库仍由 root 监督器唯一持有。

独立 SQLite 采用进程锁与 WAL/FULL；材料/候选先同步再记录阶段。历史数量、未决数和保守工作盘预留分别限额；失败/未知清理继续占预留。构建实际 CPU/RAM/VM 私有盘上限由独立 Rust 池执行，不借用运行额度；同盘检查及预留保护运行清理余量。配置/预算指纹持久绑定，变更明确拒绝，重启不能隐式换池。总期限从提交起算，Rust 池另强制 VM 寿命，不因重启续期。

上下文上传沿用提交时的原期限：每次有界 socket 读取、末块/EOF、文件与目录同步、事务提交前都重新核对，不用不断到来的小块延长期限。超时只删除本次持有的精确输入 inode；文件被替换或删除结果未知时进入 `CleanupUnknown` 并保留预留，虚拟机缺席不能授权删除陌生输入。输入已提交为 Queued 而回复丢失时保留原输入，不因 HTTP 失败撤销已接受工作。

阶段为 `Preparing → AwaitingInput/Queued → Building → Cleaning → Publishing → Ready/Failed`；观察不了原 VM 时为 `CleanupUnknown`，不释放预留或再建新 VM。私有构建准入必须携带原服务端窗口与用户键，按租户、窗口、键和原参数保存锚点；窗口关闭后仍可查询已接受身份，缺窗口拒绝。普通 create 拒绝 `_sandproof_` 保留 metadata。

重启后的 Building 不重执行用户步骤，只观察/精确回收原 VM 并报告 InterruptedBuild；完整候选已同步的 Cleaning 可继续收尾和同编号登记；Publishing 只推进原发布，不重构建。Ready 必须通过既有发布门及临时 VM 的精确回收。只有确认构建 VM、网络槽和相关未决动作全部回收才删除本工作临时输入/候选并释放预留；Destroyed 状态或 DELETE 成功不能替代 cleanupComplete。有限日志/历史保留，正式产物由登记预算管理。窗口模式另执行下述公开结果/日志退休；正式 Ready 模板及产物仍由独立登记额度保留并可继续使用，不随公开构建结果过期删除。未增加模板产物垃圾回收、多构建节点或原 E2B 模板协议。

原构建期限也限制发起新的发布请求：构建 VM 精确回收后已到期的候选不进入新发布；未有发布尝试且查询不存在时，在 staging 前后分别检查期限，POST 的等待使用剩余期限。POST 前必须持久提交发布尝试意图，提交后再次检查剩余期限。staging 跨过期限时，只在没有未决发布尝试且再次查询不存在后清理该候选并报告 BuildDeadlineExceeded。原 POST 明确返回准入前的 400/409/429 拒绝，或本次派发确认尚未调用 POST，才可持久清除该意图；超时、连接错误、控制器 408 和后续 GET 的拒绝均不能替代该证据。

GET 404 不是发布取消或未受理屏障：先前 POST 仍可能排队等待准入。存在未决意图时，即使到期、重启或多次查询 404，也保持 Publishing、候选和预留，只查询原编号，不重新 staging 或 POST。发布意图和配置绑定从当前新库初始化时就存在；旧库不导入，损坏记录不补造。提交意图后、发送前崩溃也保守保留，当前没有自动取消/不存在屏障，不能保证这类未知状态自动结束。原发布随后 ready/failed 的回执可完成记录并释放构建预留，但迟到 ready 不能据此声称调用方在原期限内完成。

公开构建必须提供 `bounded_builds` 的窗口与有限结果配置，所有字段必填且无生产默认：`namespace`、`windows={max_open_windows,max_duration_ms}`、`retention_ms`、`max_request_bytes/max_result_bytes/max_record_bytes`、`database_bytes/wal_bytes/recovery_reserve_bytes`、`helper={path,sha256,owner_uid,max_input_bytes,max_output_bytes,timeout_seconds}`。namespace、窗口参数、helper 身份、预算和池绑定写入同一 SQLite 配置，重启不可变更或关闭。旧格式、缺失配置、旧无窗口提交和迁移开关均明确拒绝；所有成功路径都使用当前窗口协议。不能删除数据库后复用旧 namespace；部署操作者必须保护独占根和永久部署身份。

公开接口 `POST /sandproof/template-build-windows` 接 `{durationMs}`，返回 `{requestWindow:{namespace,sequence},expiresAtMs}`；`POST /sandproof/template-build-windows/close` 接 `{requestWindow}`。窗口模式的 `POST /sandproof/template-builds` 必须同时给出同一 requestWindow 和 `Idempotency-Key`。先按认证 tenant＋namespace＋sequence＋key 查已接受账本，窗口关闭/到期后仍返回原 buildID，规范化参数变化返回冲突。仅不存在 tuple 时，在 `RLock + BEGIN IMMEDIATE` 内调用既有 Rust 窗口转换：先持久推进可信时间下界、再 Admit 和预留工作。过期/满额拒绝须提交已推进下界，不经通用异常路径回滚；系统时钟回退不能重新开放窗口。窗口签发前沿只增不回绕，关闭不撤销已接受工作。 公开 buildID 另由格式 4 的固定 SQLite 单行分配器生成：`namespace 的 16 位十六进制 + 全局作业序号的 16 位十六进制`，仍为原 32 位小写 hex 路径/协议格式。全局 highwater 以固定 16 位 TEXT 保存完整 u64，和作业准入同事务提交；事务回滚不暴露身份，提交结果未知须观察原 tuple，结果 GC 不删除或从幸存行重建前沿，耗尽拒绝而不回绕。因此旧 GET/PUT/私有 buildID 不能命中后来的工作，不以随机碰撞概率代替身份保证。不从旧随机编号或幸存行导入身份前沿，不提供原地升级。配置或分配器记录丢失、前沿小于已登记身份均失败关闭；固定分配器页属于已有数据库/恢复控制页余量。

[一次性 Rust helper](../controller-service/src/bin/sandproof-window-reducer.rs) 只调用已有 `maintenance::windows::reduce_windows`；stdin 为唯一 `{version:1,state,input}`，成功返回完整 `{version:1,status:"ok",decision:{event,next}}`，核心拒绝返回 `{version:1,status:"rejected",reason}`。显式 argv `--max-input-bytes/--max-output-bytes` 限额读写，超限不得输出截断后继；协议错误码为 `invalid_request/unsupported_version/input_too_large/output_too_large/input_io`，输出至少容纳固定错误 framing（59 字节），不是生产默认。[Python 桥接](../tools/template_build_windows.py) 检查完整响应、受保护 ELF 路径/祖先/owner/摘要，以已打开 FD 执行同一 inode；最小环境、无 shell，有限 selector 读写、超时和精确 child reap。可信 owner、加载器与不可强制中断的宿主 I/O 仍是边界。helper 不读业务时钟、不持久化、不占用第二数据库、不实现另一套生命周期或请求窗口规则；唯一权威仍是 BuildStore 的 SQLite 事务。

接受时同时预留工作盘、未来日志和整条记录的最坏编码字节，`max_jobs` 同时约束活跃与未来保留结果数。candidate、failure、私有窗口/settlement、删除清单均受 `max_record_bytes`，不能只限制请求/最终结果。SQLite 设置 `max_page_count`，数据库额度至少覆盖所有最大记录、索引和迁移/更新余量；WAL 额度至少覆盖两倍数据库页及 framing，另留 recovery reserve。独占单连接所有写事务之前必须成功 TRUNCATE checkpoint，再以 FULL 提交；本服务不允许跨事务流式 SQLite 读游标，外部旧读者阻挡 checkpoint 时拒绝写入/新准入，不能释放清理占额。temp_store 使用内存，有界查询/记录限制其输入；数据库、WAL、恢复/SHM 余量均纳入 workspace 和真实磁盘准入。DELETE 后空闲页可复用，不声称文件立即变小；这不是对绕过独占服务的外部写者、无限未关闭外部读者或整台宿主的配额承诺。

提交文件阶段先提交 Preparing 行/nonce/容量，再创建精确 `.prepare-{buildID}`，同步身份 marker 后原子 rename 到最终目录并同步父目录，最后提交可派发状态。专属 root 租约下该未发布 staging 的空目录或与 nonce 精确匹配的 marker 前缀可恢复；任意最终目录、未知名称、类型、内容或替换 inode 均保留并失败关闭。结果退休须同时满足终态、原窗口已关闭、从终态起 `retention_ms` 已过、构建外部工作已结算、私有 ack 已记录、发布已终结且无未决 staging 删除。先提交 Deleting 与精确设备/inode 清单，再逐文件删除/目录 fsync，最后移除账本；中断仍占记录额度。固定发布 staging 同样使用 nonce marker 和事务内删除清单，不递归接管外来目录；未知 publication_attempted 仍按上文永久保守占额。

中心须显式配置 `private_builds={windows,window_duration_ms,max_anchors,builder_revision,policy}`，以及完整 `private_build_boundary`；两者同时为 null 或同时启用。`policy` 必填 `public_ipv4_enabled/max_timeout_secs/max_lifetime_secs/startup_timeout_secs`，保留构建池原有、独立且持久绑定的网络与寿命策略。运行池禁止联网时，构建池可在其原授权内联网安装依赖；不能因此开放运行池。两者复用同一个窄创建参数校验，不复制生命周期算法或整份公开配置。原描述符摘要由 Rust 从同一个受保护目录的唯一构建修订派生，不从 Python 或用户请求接受另一份摘要。构建窗口、原全局 Create 和锚点在同一 Redis CAS 接受；宿主只接原高级意图，不再安装 `internal_build_vms/build_retry_windows` 开关或另一套构建窗口。监督器先在中心私有接口签发窗口，将原窗口写入唯一公开作业库，再 POST 原 buildID；GET 同样带原 requestWindow。收尾先关闭原窗口，再持久保存精确 `{requestWindow,sandboxID}` 结算证据并请求同编号 settle。GET404 本身不是清理证明：只有原围栏及确切未准入事实，或匹配的原 Destroy/Cleaned 才允许结算。ack 丢失只观察/重发原身份，不重建 VM。锚点还须等待原本地窗口退休后才能移除。

普通用户用[小客户端](../tools/template_build_client.py)，凭据从 `SANDBOX_API_KEY` 读取：`--url https://中心入口 --intent 原请求.json --context context.tar.gz` 或 `--image public.ecr.aws/docker/library/ubuntu:24.04`。客户端只使用请求窗口，不接受构建模式参数；窗口不可用不提交无窗口工作。派发前同步保存原 key、请求、上下文摘要及 namespace/window，intent 绑定服务地址和凭据摘要而不保存凭据；`build_mode=windowed` 只是保存格式。窗口须恰含两个 u64 字段，旧/畸形 intent 或来源/参数冲突拒绝并保留，不自动升级或换身份。未知回复后重用原 intent。唯一完整服务装配将显式 `--bounded-policy` 的宿主 bounded_host/maintenance、公开 bounded_builds 和中心 private_builds 分别交给所属角色；不把旧私有开关注入宿主，也不生成隐式生产额度。收到模板编号后仍用原 E2B SDK create，普通创建合同不增加窗口/键字段。

鉴权扩展接口：`POST /sandproof/template-publications` 接 `{candidateID}`；`GET /sandproof/template-publications/{candidateID}` 返回 checking/ready/failed 与有限原因；`GET /sandproof/templates` 只列本人 Ready，编号升序、limit 1～100、cursor 为上页最后不可变编号；`GET /sandproof/templates/{编号或别名}` 查询本人 Ready。`PUT /sandproof/template-aliases/{别名}` 接 `{templateID, expectedTemplateID?}`，可比较后更新，目标必须本人 Ready 编号；DELETE 只删本人别名，不删产物/实例绑定。静态目录名称保留；未知、未就绪和他人模板均不可创建。别名更新只影响新准入，旧实例/重启始终绑定原字节。响应不含宿主路径、临时 VM 编号或凭据。这是 Sandproof 发布扩展，不宣称原生 E2B 构建协议完全兼容。

发布登记完整计算候选内核和磁盘 SHA-256 后，可向同进程工作器传递不可序列化的校验记录。密封目录移入正式路径后，工作器首次接收该记录时，只有在精确描述符、设备/inode、长度、修改/变更时间、属主/组、权限和硬链接数均未变化且完整路径可信时，才预置摘要缓存。后续节点缓存沿用既有设备/inode、长度、mtime/ctime、期望摘要及可信路径检查，不直接逐次比较属主/组、权限和硬链接数。记录失效或缺失时不预置缓存，仍执行原节点校验；没有有效本地缓存时完整重算，服务重启会清空该缓存。复用延续原节点缓存的部署前提：可信准备方在候选交接前关闭全部可写句柄，暂存和正式产物此后由可信 root 独占且保持不可变。只读权限和 ctime 等文件身份观察不是不可变性证明，不保证发现时间戳粒度内的所有写入，也不防御可任意修改宿主文件的 root。此记录不代表 Ready，不能替代宿主模板校验、资源准入、真实启动及临时 VM 精确清理。校验前后同时核对打开文件和路径身份，可观测身份变化拒绝登记。

模板启动合同：仅 Linux/amd64 的 Debian/Ubuntu 兼容镜像；空 OCI USER/WORKDIR 按 root/根目录处理，不复制固定 E2B Dockerfile 解析器的 user/home 默认值。数字 UID 或 UID:GID 在构建 VM 内按有界账户文件解析为真实用户名；显式组必须是该账户的主组，否则拒绝（固定 envd 不支持替换主组）。目录须已存在，启动参数有数量与字节上限；Env 重复键后者优先。模板默认环境 < 创建环境 < 单次命令环境；显式命令用户/目录优先于模板默认值。无 `startup` 的旧镜像仍使用 root 和 envd 的每用户主目录，不改变旧合同。

节点把默认用户、目录及合并环境写入受鉴权 `/init`，不把镜像环境注入可信 PID 1/envd。启动 argv 是 Entrypoint 后接 Cmd，原样发给 envd，不拼接成 shell 脚本；shell-form 本身由标准构建器转成 argv。空 argv 不启动用户进程。发送前把绑定原 VM/PID/启动时刻、不可变模板与创建环境的意图同步到 root 独占记录；收到完整 Start 事件后才持久确认。确认后的激活恢复不重复发送；未知、损坏或身份不符保持未知并由独立启动期限中止原 VM，不能发布 Running。启动事件只表示进程已启动，不承诺应用健康、持续存活或退出码为零；用户程序可退出而管理通道仍保持可用。正式发布仍需独立检查，不能把此合同说成任意 Docker 容器或原生 E2B 构建接口完全等价。节点启动意图/确认记录随现有不可复用 VM 编号保留作审计，不是存活资源占额。

- 用户构建输入为 Dockerfile+上下文或公开 OCI 镜像；受限构建/转换服务返回构建编号、状态、有限日志和失败原因，只有产物与启动检查完成才发布模板。未知构建不能换成成功或自动重建。
- 模板描述包含 owner、不可变修订、镜像/清单摘要、内核/envd/启动配置和 CPU/内存/磁盘形状。用户名称不是宿主路径；构建输入及镜像层解包均需路径/权限检查。
- 创建先验证归属与就绪、解析别名一次、校验资源并把精确修订/清单与获批形状同创建意图持久提交。别名变化或服务重启不改变旧实例；准备/观察/恢复只使用该绑定，不追踪别名最新值。
- 软件、资源形状和实例分别记录；形状在构建/注册时选择，创建选择模板，不新增固定 SDK 不存在的 CPU 字段。总盘容量、构建后最低空闲空间及管理环境占用分别表达；适配 Harbor 时不能忽略其 storage 要求。
- ENV/WORKDIR/USER、CMD/ENTRYPOINT 与必要服务如何转换逐项说明和测试；未支持输入早拒绝，不忽略后冒称容器等价，不替换可信管理初始化。
- 构建在独立、限额、可回收环境运行，不接触生产管理凭据/数据库、宿主 Docker socket 或特权挂载；构建与运行预算分离，不能占用旧实例收尾预留。失败只清理原身份资源，不误发布 Ready。

此模板子系统（含自有编排和登记/发布）整体在证明边界外；核心使用上述正确授权、不可变产物和准确资源描述作为未证明的外部合同。工程检查和测试仍必须交付，不能借此排除核心执行资格、实例绑定与精确清理的后续证明。边界与状态见[覆盖记录](proof-coverage.md)。未启用预制目录的部署仍只有 `base`；启用后的字段与筛选遵循本节绑定规则，不重开已交付 #12。

节点运行器的首批实现及实机运行方法见 [`sandbox-runtime`](../sandbox-runtime/README.md)。其 `vmm_running` 只代表虚拟机监控器状态，不能当作可用沙箱成功回执。[宿主适配器](../sandbox-node/src/linux.rs)已在隔离 Linux/KVM 测试中补上 envd 健康、鉴权初始化、网络策略和独立磁盘检查，只有这些观察完成才向控制核心回执成功。它还可只读枚举已登记的 VM/网络槽/私有盘，并对丢失的准备和停止回执重新观察；控制器重启时先核对宿主资源与持久计划，再接续可确认的动作。启动盘点对无法归属、身份不符或共享日志损坏的资源仍整体拒绝启动；只有当未写进程记录的 claim 精确对应当前未决 `PrepareVm`、owner、代数、VM 与槽位均吻合时，才交给逐沙箱补偿。该补偿观察失败只阻断所属沙箱，不阻断其他沙箱，但不能因此发布 Running 或释放其配额。

VM 启动前的门控要求先持久化精确进程身份，避免 VM 已运行但无身份记录；网络空间创建前还需同步登记意图。对“准备动作不确定、槽位和持久计划精确匹配、进程记录从未落盘”的情况，启动恢复先核对无 jail、无网络空间内进程，再回收部分网络并留下不可复用的失败标记；若有精确进程记录但进程确已退出，则先核对并清理私有盘和网络，再留下失败标记。仍存活、无法观察或身份不符的进程继续保持未知，不按名称猜测清理。新准入把 VM/槽位编号与创建意图一同持久提交：预留编号本身不代表宿主动作已发出；尚无任何宿主动作被认领且凭证缺失时可补写，动作一旦被认领则不得换发，保持未完成并等待核对。公网与静态 IPv4 出站仅在显式开启的隔离部署完成选定实机测试；受控 DNS 和完整崩溃对账仍未接通。

周期扫描现在也处理准备动作的部分资源：先核对当前操作编号、owner、时期、代数及 VM/槽位计划，再由宿主检查精确进程和网络身份；独立启动期限未到时，存活或不可观察的 VM 不作猜测。首次非终止围栏在动作已登记但尚未写入宿主时中断，只能在原创建仍为当前、未进入终止阶段时补全；宿主围栏仍拒绝从终止态倒退。停止动作中断后，只有当前终止操作与原 VM 停止计划精确匹配，宿主才可对持久进程身份执行幂等停止并重新观察；这不是重派发任意结果未知的动作。清理动作若在虚拟机确已停止后丢失回执，则只在当前终止操作与资源绑定精确匹配时幂等完成清理，再记录回执。启动期限到达后的受限中止路径见下文；它已有组件测试，真实 KVM 测试由[专用脚本](../tests/system/server_unready_abort.py)单独验收。完整服务进程的任意位置强制终止，以及公网与静态 IPv4 模式下的全部故障组合仍未验收。

每项持久动作至少绑定：协议版本、sandbox、owner、operation、epoch/generation、逻辑动作 ID、attempt ID、精确资源 ID、动作参数。只有已提交动作可派发；B 的控制入口不向沙箱或公网开放。宿主槽位登记同时持久记录 owner、sandbox、generation、VM 和槽位；后续动作（包括停止和清理）与只读回执均核对 owner。重启回收在删除任何物理资源前也核对槽位 owner 与控制器持久沙箱 owner。缺少 owner 的槽位记录会被拒绝，不能猜测归属、自动升级或认领未知资源。

B 检查动作身份、当前执行资格、终止围栏和真实资源归属，返回以下结果之一：已观察成功、明确失败、尚未知。超时不是失败证据。只有明确可重试失败、没有待核对的部分资源，且 A 的持久状态和预算检查也允许时，才能创建新的尝试；重发同一未知动作不能凭空分配第二个 VM。

回执包含完整动作身份、观察对象及结构化结果，不能仅有 `success=true`。A 决定是否接收当前回执及是否推进阶段；旧动作的回执不授予新代数权限。

### Harbor 逐试验产物保留边界

[SDK 适配](../benchmarks/sdk_environment.py)使用同一逐试验预算累计原 Oracle/Verifier 下载、递归目录/文件尝试、命令事件与另存的包清单/环境诊断。字节、条目、深度和单文件上限由运行器显式配置，单文件仅可在既有 96 MiB 硬上限内调低；失败、重试、覆盖同一路径和诊断回退均不返还已记账额度。空文件也占条目，目录遍历和新建本地父目录另占条目；命令在派发前预留事件/命令文本额度，返回输出按实际 JSON 转义长度计费，超量必须失败而不能静默截断后通过。固定 SDK 可能先在客户端累计完整命令结果，网关不再设置累计命令输出上限；本预算只界定评测产物保留量，不能限制 SDK 先行分配，也不是客户端或服务进程内存上限。

文件使用固定 SDK 的异步流接口，逐块先记账后写同目录独占 `.partial`，完整结束并关闭流后才原子替换目标；读取/关闭由独立任务持有，取消后最多等待同一 5 秒清理期限，避免中断固定 SDK/HTTPX 的 EOF 内部关闭。关闭失败或期限耗尽在 `stream_close_failure` 独立记录失败/未确认（不被较早预算错误覆盖），不声称连接已释放，也不无限阻断 VM kill；原取消/读取错误仍传播。取消/失败只删除本次精确临时 inode，既有目标与其他临时文件不动。不接受宿主路径越界、符号链接、重复/非规范目录项或超过深度的树；目标根须为当前用户独占目录。来宾文件元数据中的符号链接明确拒绝，元数据与读取之间的来宾修改仍不是一致快照保证。过滤下载入口明确拒绝，不回退到上游宿主临时 tar 解包。字节限制是接收后、写入前的有效载荷记账，拒绝时至多已收到当前 SDK 块；不包含 HTTP/TLS 头或底层缓冲，不能称为精确线上传输配额。

失败证据单独记录 `artifact_budget` 与 `evidence_complete=false`；即使原 Oracle 吞下下载异常，运行器也不能报告完整通过。原阶段结果及已经取得的原奖励保留，不伪造/改写评分。预算违规后后续产物与诊断请求拒绝，但精确 SDK kill 始终独立尝试，未知收尾仍保持未知。输入 context、构建日志/检查点、原奖励字典与 result/full-set/report 元数据不在本有效载荷上限内；它不是整个试验目录或宿主全局写入限额。批次容量集成须另加“每试验上限 × 选定题数 × 重复次数”，同时为这些排除项、服务日志/数据库及收尾留额，不能用该乘积或配置默认值声称硬件容量已验收。

## 数据通道：C → A/B → 来宾

命令和文件请求先经过身份、所属沙箱、阶段和能力检查，实际执行时再确认仍指向同一有效实例。请求通过检查到实际发生副作用之间必须有明确的执行资格/撤销规则，不能只依赖入口处的一次检查。

沙箱令牌的 SHA-256 摘要、原实例编号与代数保存在控制器同一 SQLite 库的唯一索引中；该索引只定位目标，不授予权限。创建先持久保存原宿主启动凭据，再登记摘要，登记确认后才派发首个动作。登记回复未知时保留原身份；Starting 恢复只复用原凭据，Running 缺索引不自动补造或换令牌。数据请求先查共享索引，再读取目标实例的宿主凭据并恒定时间核对，之后检查当前阶段、代数、寿命和核心能力；一个目标凭据读取失败不扫描或阻断其他健康目标。详情回传令牌及真正中继派发也核对原登记。重复摘要或同对象改换摘要会持久标记整个数据索引不可授权，重启不解除，但原生命周期与精确清理仍可进行；共享结构损坏或缺少 Running 映射整体拒绝数据访问。索引行计入准入预留，只在精确退休事务中删除。可信宿主凭据生产者和受保护存储仍是前提，不承诺识别恶意特权写者任意伪造的有效文件。

完整服务重启先从原持久创建参数和物理位置构造无凭据的只读观察器，核验全体资源及孤儿资源，不能从损坏凭据猜配置或跳过进程、目录、cgroup、网络身份。全部物理核验通过后，只有具备可信原摘要及代数绑定的单对象凭据故障可局部停用；保持原资源、未知动作和额度，不补凭据、不重启 VM、不推断回收成功。父路径不可信、启动参数变更、资源身份或共享索引损坏仍整体拒绝。只读原身份接口允许观察正常持久封锁下的资源，但不是数据授权、启动或清理许可。

当前复用固定版本的 E2B envd 来兼容命令和文件协议；B 负责部署与传输，C 负责 SDK 接入和网关，A 负责执行资格。M0 记录实际选用版本和必需改动，不能仅因传输层可通就宣称 E2B 兼容。

来宾可运行不可信代码，甚至获得来宾 root。来宾回复不作为宿主 VM 已停止、宿主网络已隔离或资源归属的唯一证据。控制凭据与宿主管理入口不得因复用 envd 暴露给来宾。

普通用户命令可能有任意副作用；不承诺任意命令恰好执行一次。命令发送后连接中断时保留结果未知，通过已知句柄查询/终止；不得自动再运行一次同样的 shell 命令。命令执行超时、等待回复超时和沙箱寿命到期分别处理。

固定 SDK/envd 的命令期限必须按接口解释：`commands.run(timeout=...)` 同时限定 Start 流和进程执行，envd 在执行期限到期时终止进程；`commands.connect(timeout=...)` 只限定本次连接流，不重置原命令执行期限。`wait()` 沿用所在流的期限，没有单独超时参数。同步 run/connect 忽略 `request_timeout`，异步调用用它限制首事件等待。负数流期限由 SDK 转为 1 ms，零关闭该期限；超过十位毫秒头范围的期限由 Connect 明确拒绝。客户端收到超时仍须查询/连接已知 PID 核对实际结果，不能直接推断进程已停止或再次启动 shell；执行期限、连接期限及沙箱寿命的实测范围见[验收清单](testing-plan.md)。

命令启动、等待、重连与终止是不同操作：连接断开不能解释为来宾进程已终止，命令超时不能解释为沙箱寿命到期。文件写入或传输中断可以已产生部分来宾侧内容；只有完整成功回执才可作为完成，失败不得宣称原子覆盖或自动回滚。HTTP/1.1 是现有传输要求，不是单文件 8 MiB 上限的协议来源；总量限额、流式内存界限归 #8/#12 验收。

### 命令句柄与来宾服务故障

固定 SDK/envd 的主进程退出/被终止、后代或进程组停止、整 VM 停止分别确认，不用单命令超时/kill 证明全部后代停止，也不新增更强的进程组终止承诺。Start/Connect 句柄绑定原实例及有效 envd 会话；PID 不是永久身份。重连的历史/新增输出及结束语义按固定端点协议验收，等待/重连期限不重置原执行期限。

envd 重启可丢失登记而原来宾进程仍在：按固定协议返回不可重连/未知，不仅凭 PID 接管或重执行。空命令列表不等于来宾全部进程停止；原 VM 绑定、占用及宿主停止/清理责任保持，清理不依赖 envd 正常响应。自有路由、转发、撤销和失败处理需证明；端点输出、完成和回调排空为外部功能合同并测试，不证明整个 envd/SDK。

### Rust 来宾替换的合同入口（#311，未启用）

现役模板继续使用固定 envd。#311 在同仓库实现来宾命令/文件服务，公开路径仍经中心和私有宿主网关；中心/宿主链冻结并完成对应实机验收后才切换新不可变模板。下面区分现有合同、待实现端口和当前纯函数模块，不将合同样例当成已运行服务。

固定依据为 SDK 2.51.0 / `ccaf9fc0ffe6ac39c7ec786af7608ab1de19467b` 和 runtime `f455fd58fa3f289e78ce1de690c35968d8d29322` 的 [process.proto](https://github.com/e2b-dev/runtime/blob/f455fd58fa3f289e78ce1de690c35968d8d29322/packages/envd/spec/process/process.proto)、[filesystem.proto](https://github.com/e2b-dev/runtime/blob/f455fd58fa3f289e78ce1de690c35968d8d29322/packages/envd/spec/filesystem/filesystem.proto)。[共享协议样例](../tests/compat/guest-service-contract.json)由固定 SDK 的生成类型读取并往返编码；它是后续 Rust 适配器共用输入，不是另一份能力矩阵，也不代表已完成协议对照。

| 入口 | 保留的行为与当前边界 |
|---|---|
| `process.Process/Start`、`Connect` | Connect JSON 流；保留 cmd/argv/cwd/env/user、stdin 的缺省/显式值、Start→原字节 Data→真实 End；非零退出原样返回。Connect 不重新执行命令、不重新计执行期限；无订阅期间完整输出重放不在既有承诺中 |
| `List`、`SendInput`、`CloseStdin`、`SendSignal` | 固定选择器和错误映射；输入是 bytes，空输入与关闭 stdin 不同；信号请求成功不等于主进程或后代全部退出。结束记录先保存再从活跃表移除；短期保留需有条数/字节/期限界 |
| PTY `Start` / `Update` / 输入 | 当前进程路由及固定 SDK 已有该协议，不因首批实现只覆盖管道而删除；PTY 输出使用单独通道，关闭 stdin 的适用性按固定端点合同 |
| `GET/POST /files`，`Stat/MakeDir/ListDir/Move/Remove` | 保留普通/流式与批量组合、文件属性、相对路径/home、归属和部分失败。文件 `user` 不是来宾用户间 DAC 边界；原固定行为见本页文件合同 |
| `GET /health`、`POST /init` | 健康不等于已鉴权或模板就绪；初始化由宿主管理通道执行，重复的同一受限初始化须符合既有恢复合同，公开网关不新增初始化入口 |
| 文件 watcher | 固定 SDK/端点具有 WatchDir/CreateWatcher/GetWatcherEvents/RemoveWatcher，但[当前两端路由](../sandbox-data-transport/src/request.rs)拒绝这些调用。保留现状并显式记录；扩大公开范围需先复核，不以 proto 中存在接口当成已经支持 |

**身份尚待冻结的决策：**内部事件必须绑定来宾服务会话、命令编号及真实 PID/创建证据，控制操作使用稳定进程句柄或等效的原进程绑定。固定 SDK 公开选择器只有 PID 或 tag；内部增加会话字段无法区分一个迟到的旧 PID 请求与同号新进程请求。PID 复用拒绝、跨重启保留及耗尽策略须以具体方案复核后才能启用；不得声称当前纯核心已解决公开句柄歧义。envd 重启后旧命令可按既定合同不可重连/未知，但不能认领同号新进程或重执行旧命令。

拟复核的方案保留真实 PID：在同一 VM 内记录已发布 PID，启动子进程先停在可信执行闸门，取得稳定句柄和创建证据，确认该 PID 从未发布并保存记录后才执行用户命令。拒绝复用发生在用户代码执行前，不自动重试另一个 Start。记录跨服务重启保留，并与原 VM/启动身份绑定；记录缺失、损坏、写入不确定、容量耗尽或 PID 超出可表示范围时拒绝新启动。PID 集可用固定范围位图限制空间，原进程结束不能清除此位；原登记表丢失后不接管进程。该方案会引入复用/耗尽拒绝，精确范围、错误及 tag 的重复绑定政策仍待技术复核和 owner 确认，尚未实现或启用。

已加入的 [sandproof-guest-core](../sandbox-guest-core/src/lib.rs) 只承担两个有限局部决定，不依赖 HTTP、Tokio、文件系统或宿主控制器：

| 类型 / 入口 | 输入及决定 | 适配器仍须履行的责任 |
|---|---|---|
| `CommandStream` | 每订阅的完整内部身份、输出模式、驻留字节预算、实际管道/PTY EOF、主进程退出与输出消耗；仅退出及输出完整排空才给出可发送的 End，非零码保留 | 在同一登记会话匹配原进程及管道；真实 wait/读写不能伪造。订阅数量、消息编码、实际分配/内核缓冲另有预算；慢消费者不能无限阻塞其他订阅 |
| `Transfer` | 单文件总预算、驻留预算、可选长度、实际接收/短写与 EOF；完整输入/写入及必要 close/metadata 成功后显式 `finish`；断流/磁盘错误保留已写字节 | 有界读取和实际文件 I/O、路径/账户处理、元数据与错误映射；不能将写入计数当作 fsync、整体事务或回滚证据 |

命令驻留计数在消费后归还，不累计全部输出；文件总量预算与驻留预算分开。取消/超时只结束相应订阅/传输，不推断进程已停止或文件未改变；失败对象不会自动退还尚未确认释放的底层资源。实际服务的进程、连接、订阅、请求、终局保留和日志预算仍须在后续实现中逐项接通并验收，不能用数值边界测试冒充整机资源测量。

新增的 [sandproof-guest-runtime](../sandbox-guest-runtime/src/lib.rs) 是未接入公开服务的 Linux 执行端口。`CommandProcess::prepare` 只启动受信任安装路径的私有 worker：创建独占临时 Unix socket，核对内核 peer PID/UID、pidfd 与 `/proc` 创建时钟，传入有界执行上下文，再停在放行闸门。调用者须在 prepare 前预留进程容量、在 `release` 前保存公开选择器归属；该端口尚未实现持久登记或解决公开 PID 复用。

[可保留的准备对象](../sandbox-guest-runtime/src/process/preparation.rs)在同步 `spawn` 返回前持有原 child；借用式 `finish` 握手只能尝试一次，取消或失败保留原对象供 `abort` 实际 wait。已取得 pidfd 后只信号原内核身份；取得前的 child 停止至多尝试一次，不在未知 wait 后反复按数值 PID 发信号。Drop 只请求停止，不能作为容量归还依据；低层便利方法 `CommandProcess::prepare` 被整体取消时仍只有这一 Drop 保证，需要取消后收尾的调用方使用准备对象或下面的管理入口。

`release` 第一次进入即记录“已尝试、未知”，取消、超时或诊断丢失不会恢复为可再次放行。闸门的 EOF 只记为 `NoExecErrorObserved`，不是抵抗 worker 崩溃的完整执行证明；明确 exec 错误走私有诊断，不混入用户 stderr，也不冒充用户退出码。主动中止未放行 worker 后禁止再次放行。对象丢弃会请求停止未放行 worker，但丢弃本身不是已观察回收；`abort_prepared` 才等待实际退出。已放行/未知进程不因对象丢弃主动发送 kill，生产编排仍须让进程所有者独立于 HTTP 请求存活；管道关闭或最后一个终端 master 关闭导致的 hangup 可能影响用户程序，不能承诺它必定继续存活。

该端口执行管道及 PTY 命令，显式 cwd/完整环境替换父进程环境；可信解析器可提供数值身份，在私有单线程 worker 内、用户 exec 前设置附加组及真实/有效/保存的 GID、UID。任何一步失败只返回私有诊断并退出，不回退服务账号。未给数值身份的模式仍仅供原当前账号组件使用，鉴权上下文解析总是给出完整身份。stdin 独立于 wait 保存，`take_input` 可移交唯一的 `CommandInput`，使大块写入与输出读取/等待/信号并行推进；移交后由该句柄检查原身份及关闭输入，原进程端口拒绝输入/关闭调用，不伪报管道已关闭。服务登记持有句柄，请求只借用，避免断线销毁句柄而隐式关闭 stdin。空输入、关闭输入和取消写入分别处理；失败/取消的写入可能已送入前缀。信号只作用于保留的 pidfd，先核对完整内部身份。输出适配调用原 `CommandStream`，一个未确认消费的块会阻止继续读取；每次读取使用两个有界 scratch 块，已交给消费方的块及其传输分配另归消费方预算，不设累计输出限额。只有真实 wait、双管道或终端 EOF 和消费确认齐备才产生 End；主进程退出不等于后代退出。

独立的[命令协议编解码](../sandbox-guest-runtime/src/protocol.rs)已覆盖固定 SDK 的 Start/Connect、List、SendInput、CloseStdin、SendSignal、Update 请求，以及 Start/Data/End/keepalive 和 Connect 流终结帧。保留 stdin 缺省为 true、显式 false、空输入、PTY 通道、PID/tag 及未选择的区别；解码不授予 PID 控制资格。Start/Connect 请求须有单个完整未压缩 JSON 帧，拒绝不符长度、额外帧、非法 flags、重复消息字段和数组式消息；未知方法不伪报成功。编码按原字节使用 base64，非零码、信号退出的 `exited=false` 和错误字段分别保留。进程 End 与 Connect 传输终结不同，EOF 不能替代它们。消息字节预算在 JSON 解码前和编码写入中检查；HTTP 层仍须在收集正文前限额，输出传输及实际分配另有预算，不设置流累计上限。

独立的[文件协议编解码](../sandbox-guest-runtime/src/file_protocol.rs)覆盖 Stat/MakeDir/ListDir/Move/Remove 的一元 JSON 请求与属性/列表/空回复。缺省或 null 路径保留为空，ListDir 的零深度留给实际操作应用原默认值；Move 的两个路径分别保留。拒绝重复字段、数组消息、流帧及未知方法，未开放 watcher 不伪造成功。属性 size 用 int64 十进制字符串，时间戳限制 protobuf 年份范围并保留纳秒，以 UTC 和 0/3/6/9 位小数编码；symlinkTarget 的未给出与空值保持区别，元数据按原字符串编码。解码前与编码过程中限制消息字节，不先复制整份属性列表；列表驻留、真实文件属性与部分失败仍归后续 I/O 端口。编解码成功不能代表文件存在、修改已完成或输入来源已授权。

[PTY 端口](../sandbox-guest-runtime/src/pty.rs)通过原 master FD 打开对应 slave，不按可替换的 `/dev/pts` 路径重新查找。worker 的三个标准描述符均接到同一 slave，PTY 模式不使用管道的 stdin 开关；只有放行后，原单线程 worker 才建立独立 session/controlling terminal，再设置数值身份并 exec，同一主 PID 不变。stdout/stderr 合并为 `Pty` 通道，终端 line discipline 可能转换字节；需要原字节模式的用户程序自行配置 raw，服务不擅自改变默认终端模式。

初始及 resize 的行列按固定 Go 端点将 wire uint32 取低 16 位，零与缺省尺寸保留为零；这只用于终端尺寸，不适用于身份或资源预算。`write_pty` 与管道 `write_input` 互斥，错误通道明确拒绝；PTY 拒绝 CloseStdin，Ctrl+D 是普通终端输入，实际 EOF 仍由终端模式决定。独立控制句柄执行 resize，检查原完整身份和实际 ioctl 结果，不等待正在写入的输入锁；内核可向前台进程组发送 SIGWINCH，显式 kill/term 仍只使用原主进程 pidfd。Linux PTY read 的 EIO 按该端口的 EOF 处理，其他错误仍为失败；EOF 不能替代实际 wait/消费确认。写就绪若已挂断/出错立即失败，不在满缓冲的 EAGAIN 上忙转阻塞收尾。终端 FD 随原管理记录/输入/控制引用保留，结束记录及 TTL 仍按下述待接入规则处理。

`ProcessLimits` 的块大小、上下文字节和闸门握手期限是显式组件参数，没有生产默认值；握手期限不是命令执行期限。账户/默认上下文与真实 worker 已有组合入口；正式命令路由及鉴权接入、终局保留期限、跨重启登记和完整资源收尾仍待接入；命令管理组件见下文。编解码和测试路由不能当作可安装的 Rust envd 或模板切换证据；一元操作执行/回复及正式协议对照仍未完成。

[sandproof-guest-service](../sandbox-guest-service/src/lib.rs) 已实现独立的初始化 HTTP 路由和会话组件，尚无生产监听器、命令/文件路由或模板安装。`GET /health` 返回 204 及自身 `X-Sandproof-Guest-Version`，不借用 Go envd 版本，也不代表认证或模板就绪。`POST /init` 只接受原宿主实际发送的 JSON 字段 `accessToken`、`defaultUser`、`defaultWorkdir`、`envVars`；其他上游可选初始化功能明确拒绝，不静默忽略。公开网关未增加初始化入口。

初次初始化或新令牌必须核对本 VM 的 MMDS 哈希与身份；固定 [MMDS 客户端](../sandbox-guest-service/src/metadata.rs) 仅访问 `169.254.169.254:80`，先取得短期元数据令牌，再读取实例、模板和访问令牌 SHA-512。正文、接收缓冲、请求头数量及两次交换共用的期限有明确限制；不使用环境代理、DNS、重定向或请求提供的地址。失败、缺字段、坏哈希、身份变化均不授权；这比固定 Go envd 的无 MMDS 匿名回退更严格，属于尚未启用的 Sandproof 受保护初始化配置，真实模板启用前仍须按 E01 复核。取消/失败直接丢弃原连接，无脱离请求存活的连接驱动任务。

会话从未初始化状态开始，接受完整 token/defaults 替换才原子提交；失败不部分轮换，提交后响应丢失仍是宿主未知结果。同令牌重试沿用已绑定身份，不要求 MMDS 再次可用；服务重启须重新核验，不恢复旧授权或接管旧进程。鉴权拒绝缺失、重复、非文本、超长或过期的 `X-Access-Token`，对固定长度摘要作常量时间比较。`AuthPermit` 持有同一默认上下文快照，调用方须保留到操作准入/副作用派发完成；初始化等待这些派发结束，后续请求重新核对令牌。该约束已有上下文到 worker 的定向组合测试，尚未接到正式命令/文件路由，不能据组件通过宣称完整执行路径已经受保护。

默认用户初始为 root；用户/工作目录缺省、null 或空字符串保留原值。`envVars` 给出时替换用户环境，空对象清除用户项；MMDS 的 `E2B_SANDBOX_ID`、`E2B_TEMPLATE_ID` 随后加入，初始化不得覆盖。宿主原有模板/创建环境合并保持不变；初始化本身不解析账户或执行命令，也不写上游元数据文件；账户与逐命令上下文由下面的独立组件处理。令牌不加入默认环境或公开错误，解析后的令牌副本在释放时清零；不声称传输库及原始正文的全部副本被清零。

初始化的正文/令牌字节、保留默认值字节、环境项数、在途正文数和期限均为显式参数，没有生产默认值。正文额度由同一会话的所有路由共享，收集正文前占额；重叠状态更新不排队，超额、超时和畸形请求显式失败，取消释放原槽位。保留字节计数包括两个元数据环境项，但不等于分配器、连接、库缓冲或整机 RAM 上界；正式监听器仍须接入连接/请求头/任务及收尾预算。健康路由不占初始化正文槽位。

[账户与执行上下文](../sandbox-guest-service/src/execution.rs)从原 `AuthPermit` 解析用户名和默认值：Basic 用户名存在时选该账号，否则沿用初始化用户；按固定 Go 行为，非 Basic 或畸形 Basic 选择默认用户，显式空用户名拒绝。重复 Authorization 头、超长用户名/头、无效命令和预算超额明确拒绝；用户名不是数值 UID，HOME/USER 环境覆盖不改变内核身份。环境顺序为受信任 daemon PATH、账号 HOME/USER/LOGNAME → 初始化环境 → 单次 envs；不继承其余 daemon 环境。相对路径按账号 home 连接并作词法清理，`~` 只展开自身 home，已有绝对路径保留；不把词法清理当作符号链接或目录访问证明，实际 chdir/exec 仍须成功。

[文件账户/路径上下文](../sandbox-guest-service/src/files.rs)从同一 `AuthPermit` 快照解析：RPC 沿用 Basic 用户规则，HTTP 文件操作仅从解码后的 `username` 查询选择账号，缺省才使用初始化用户；不把 `user` 别名或 Basic 头当作 HTTP 选择器。显式空/未知账号失败，环境 HOME/USER 不参与账号或 home 选择。Move 的两个路径共用一次账户查询，完整解析后才能交给后续派发；本组件不创建目录、重命名或打开文件。返回的 UID/GID 是创建对象的目标归属，不是文件 worker 的降权凭据，保持既有 daemon/root 文件 I/O 边界。

文件空路径先取初始化工作目录，再按账号 home 展开；已有绝对路径保留原拼写，相对路径只做原词法整理，不提前解析链接或断言权限。NUL 在路径解析阶段保留，由后续实际 I/O 产生该操作的错误，不能冒充已通过路径检查。用户名、Authorization 和输入/展开后每条路径有显式组件预算，Move 至多两条路径；不把这些参数当成正式用户上限或全内存预算。原账户池继续约束取消/超时后仍在运行的查询；正式 HTTP `/files` 路由尚未接通，流式端口的当前边界见下文。

[一元文件端口](../sandbox-guest-runtime/src/filesystem/mod.rs)执行已解析绝对路径的 Stat、MakeDir、ListDir、Move、Remove。属性保留固定 Go 的 lstat 大小/归属/权限字符串与链接目标类型/权限数值；断链保留原路径目标和未知类型，epoch 零时间不生成时间戳。纯本地 UID/GID 显示查询失败退回数值，不参与授权。`user.e2b.*` xattr 跟随原路径，忽略非 UTF-8 键/值，普通读取错误按原 best-effort 行为放弃元数据；显式预算耗尽必须报 ResourceExhausted。RPC 无法表示的文件名/目标字符串报 Internal，不有损替换。

目录创建沿固定词法父路径逐级检查，新建或观察到创建竞争后设置目标归属，不修改原有目录权限。Move 先建立目的父目录，再 rename 并读取属性；失败可能已留下父目录或已完成重命名。ListDir 按固定 Go 的最多 255 次链接解析、零深度默认 1、词法深度优先顺序工作，不遍历子链接，返回路径保留请求别名；边界深度目录的读取失败仍可使调用失败。Remove 使用父目录句柄和不跟随最终链接的逐层打开/删除，删除链接本身；不把并发路径替换下的局部效果称作目录约束、快照或事务。缺失删除成功，其他失败/预算耗尽可留下部分删除；不得重放以消除丢失回复的不确定性。

[文件工作池](../sandbox-guest-service/src/file_io.rs)在提交阻塞工作前占额；调用者交入同一原授权与上下文，原许可持有至实际 I/O 结束，包括请求取消、等待超时和失败。已返回的属性/列表继续占据原槽位，直到结果丢弃。等待期限不打断系统调用，不回滚已执行操作；文件仍使用 daemon 凭据，UID/GID 只控制创建目录的归属。路径、遍历工作数、结果条数/字符串、xattr 和账户源有独立组件上限，超额不返回截断成功。遍历暂存路径受 `visited × path_bytes` 约束，目录 FD 数受遍历数约束；库/内核分配、全线程池、序列化副本、网络在途字节及请求入口另有义务。参数无生产默认值，E01 正式预算、完整服务停止/重启、磁盘满和流式部分传输仍待验收。

[流式文件端口](../sandbox-guest-runtime/src/filesystem/transfer.rs)已实现单文件正文的阻塞读写组件，已有 Linux 组件及固定 SDK 测试路由检查。上传先校验已知长度和元数据，再沿固定 envd 的父目录、已有文件 chown、truncate 和必要 fchown 顺序打开；跟随来宾链接，使用 daemon 凭据。按实际短写量推进原 `Transfer`；中断、超额、提前 EOF 或写入错误可留下已创建目录、归属变化和文件前缀，不重试、不回滚，不产生完整成功。完整输入后才通过原 FD 替换 `user.e2b.*`：清除未指定键，保留其他命名空间，元数据键/值遵守固定 printable ASCII 与 4096 字节合同；不支持 xattr 时沿用原忽略行为。回执元数据仍经原路径读取，路径并发替换不构成快照或 inode 身份保证；完成不表示 fsync 耐久提交。

identity 下载持有原 FD 与打开后 seek 得到的初始长度，按块读取；后续增长不附加，提前 EOF 报不完整，文件并发修改不保证内容快照。[流式工作池](../sandbox-guest-service/src/file_transfer.rs)准入后才提交阻塞工作，授权保留至实际工作结束；等待超时或调用取消不提前归还原工作槽位。每个传输最多拥有一个正文块，上传需确认实际写入并释放该块后才接收下一块，下载需已交付块实际丢弃后才继续读。句柄、在途块和成功结果仍保留原槽位；取消中的读写使原句柄不可复用，工作者消失不能冒充正常 EOF。绝对期限覆盖打开、正文与收尾，过期的已就绪回复也不能返回成功；期限不强制中断内核阻塞调用，授权及容量可继续占用到它实际返回。

[顺序批量上传组件](../sandbox-guest-service/src/file_transfer/batch.rs)为整个请求保留同一授权、一次账户/defaults 快照、一个池槽位及原绝对期限；每个文件共享原预留，不因文件数量耗尽工作槽位或重置期限。完整文件名保留路径，存在的查询 `path`（包括空串）覆盖各文件名；按既有词法规则解析后，以结果路径原字符串判重，不声称识别硬链接/符号链接指向同一 inode。重复目标在再次打开前拒绝，先前成功文件保留。正在处理的文件独占借用批次，取消、丢弃、写入或结果预算失败后整批不可继续/成功；完整输入才允许相应 part/request finish，合法空批次返回空结果。调用方仍负责从原 HTTP 正文验证这些结束事实。

批次另有文件数、文件正文总量和累计结果路径/元数据字节预算；结果保留至批次回执释放，单个待追加结果仍受原单文件预算约束。未知字段、MIME 头、边界与传输帧不计入文件正文预算，必须由后续解码入口另行约束。该组件及账号快照重构已有 Linux 批量回归，仍只接收已解码文件名/正文。该池及批次的并发、块大小、总量及文件预算均须显式配置，没有生产默认值。调用者输入、序列化副本及内核/库分配另行计费，不能用组件的一块内存约束替代 E01 全服务预算。当前 HTTP 测试适配支持原始字节/multipart 上传及 identity 下载，multipart 组合已有原提交 Linux 组件证据，后续候选仍须重跑；gzip 上传/下载组件已增加但待 Linux 实跑；正式头部/错误映射、range/conditional、磁盘满与故障文件系统、服务重启和模板切换仍待实现或独立验收。

[增量 multipart 解码器](../sandbox-guest-runtime/src/multipart/mod.rs)已有可移植组件实现和固定 Go 1.26.8 MIME reader 对照，现由下述上传连接交付给上述批次。按消费事件后再输入的顺序处理，不累计完整文件；边界跨块、近似边界正文、CRLF/LF、前导/尾随内容、折叠和重复头遵循固定 Go 行为。文件名保留完整路径，缺少参数与显式空串分开；支持 RFC 2231 编码/续段和 quoted-printable。无法表示为 UTF-8 的参数明确拒绝，不有损替换。quoted-printable 错误可同时交出已解码前缀；上游失败通过 abort 交付剩余可解码前缀，不能调用成功 finish。

解码预算显式覆盖输入块、边界、每个 part 的全部原始 MIME 头/字段数、前导/分隔符行、全部 part 数以及整个输入字节（含未知字段、framing 和尾随内容），没有生产默认值。解析缓冲容量由配置预先确定且不增长，数据事件至多一个输入块；quoted-printable 另留固定 4096 字节物理行和至多输入块加一行的解码结果。调用者必须及时释放事件/头部/结果副本，HTTP 帧、请求准入和实际写入仍由后续组合另行占额。显式 PartEnd 仅说明原文件正文已结束，之后的边界行仍可能无效；只有显式 End 才允许 multipart 请求完成，实际 HTTP EOF/传输错误还须分别处理。为维持完整输入合同，MIME 头中截断一律失败；这是比 Go 某些 io.EOF 成功路径更严格的已记录差异。组件预算、UTF-8 拒绝和该差异不等于固定 Go 全协议兼容。

[multipart 上传连接](../sandbox-guest-service/src/file_transfer/batch/multipart.rs)消费一个新批次和 identity 编码的 HTTP Body，保持原授权、账号快照、容量与绝对期限。接受固定 Go MultipartReader 所用的 multipart/form-data 或 multipart/mixed；仅 name=file 的字段打开文件，查询 path 存在时覆盖文件名，缺少文件名在无查询覆盖时拒绝。未知字段按原始正文排空，没有文件/QP 解码效果，但仍消耗 MIME part、头、总量和期限预算；不声明畸形未知字段的 Go 全协议等价。文件字段的 quoted-printable 前缀按实际文件块大小顺序写入，错误不清除先前效果。

HTTP 数据帧先检查单帧/整请求字节及帧数（包括空帧），再切入固定解码块；声明 Content-Length 超额在当前文件打开前拒绝，观测长度不符也不能成功。尾随内容仍计入总量，HTTP trailers 另有字段/字节预算，重复 trailers 或其后的数据拒绝。必须同时取得 MIME End、实际 HTTP EOF 和声明长度一致才允许批次回执；仅看到结束标记仍持有原批次，随后断流、超额或原期限到达使整批失败。取消持有中的 future 不使已经派发的 I/O 提前归还授权/容量。该连接不新增监听器、不解析原请求认证/metadata 头、不处理 gzip，也不把已接受帧的长度上限当作 HTTP 库之前分配的内存证明；传输库、响应序列化/发送仍另行计费。实现和真实文件/SDK 组合入口已有原提交 Linux 组件证据，后续候选仍须重跑，完整基础和系统验收分别报告。

[gzip 编解码组件](../sandbox-guest-runtime/src/gzip/mod.rs)提供阻塞 `BufRead` 到有界正文块的独立连接，现由下述上传及下载适配连接 HTTP/文件。解码构造先检查首个头部，调用者须在成功之后才打开或截断目标；逐段核对 DEFLATE 结束、CRC32 与模 2³² 长度，再检查下一段或真实源 EOF。空输入不能初始化，尾随非 gzip、截断、校验失败和源错误均不能成功；错误前已交出字节不回滚，错误后不可复用。头部只以固定栈缓冲检查并丢弃，不按额外字段长度分配；名称/注释的 512 字节含 NUL 上限、保留 flag 行为和多段语义遵循固定 Go reader。显式预算另限单次输入/输出块、全部编码/展开字节、每段头部字节及段数，无生产默认值；精确总量上限仍核对真实 EOF，最多一个私有探测字节不向调用者交付。

编码单段 gzip，固定压缩级别、零时间戳及无名称/注释，按源真实 EOF 结束；源错误和预算超限不产生完成回执。不同 DEFLATE 实现的压缩字节不要求等同，解码结果须一致。只由 `Ok(None)` 表示完整成功，drop 仅为取消。调用者持有的源缓冲/未释放结果、固定压缩库工作区及 HTTP 分配须另计入服务预算；授权/容量仍须保留至实际阻塞工作结束，源读取须检查原绝对期限。固定 `flate2`/`zlib-rs`/`crc32fast` 的版本及摘要在 Cargo 锁内，库实现不在已证明范围；完整 HTTP 内容编码选择和生产启用仍待后续实现/验收。

[HTTP gzip 输入](../sandbox-guest-service/src/upload_body/mod.rs)与[批次连接](../sandbox-guest-service/src/file_transfer/batch/gzip.rs)支持 gzip raw/multipart 上传组件。每个原已准入批次至多增加一个阻塞解压任务，与当前文件 worker 共用原授权/容量和绝对期限，没有第二次准入或重起期限。首个头部检查完成后才允许文件打开；压缩的 Content-Length 只核对压缩 HTTP 字节，不传作展开后的文件长度。HTTP 帧/空帧/尾部的原预算检查已抽为 identity 与 gzip 共用入口，解压后的 MIME/file/result 预算仍独立计算。

压缩输入最多保留一个已接受帧；每次消费请求才解下一块，前一块的全部 `Bytes` 副本释放前不预读。块持有原责任守卫，释放数据之后才确认消费；取消唤醒待处理 HTTP 读取和通道等待，已经进入的同步源轮询或系统调用仍持有守卫直到实际退出。预检失败与正文中途失败分开返回，错误不被 Body 包装成 EOF。raw 只有全部 gzip 段、校验、声明长度及真实 HTTP EOF 完成后才应用 metadata；multipart 已完成文件的 metadata 保留，之后 gzip/HTTP 失败仍使整批失败。缺少查询 path 的 raw 拒绝，显式空串仍按原路径规则处理。

上述底层连接消费已授权、已解析账号/metadata 的批次；下述请求组件已连接内容编码、账户与 metadata 的拒绝顺序，完整鉴权/签名和正式 HTTP 入口仍待接通，不声明固定 Go 端点全等价。可移植传输所有权测试已有本地运行；实际 Linux 文件及扩展 SDK 回读组合待此候选实跑。库分配、调用方持有的源帧、MIME 缓冲及文件写入副本仍另计费；同一请求的两个阻塞任务不表示整个服务任务预算已经冻结。

[上传请求组件](../sandbox-guest-service/src/file_transfer/upload.rs)接受原 AuthPermit、已解码的可选 username/path、HTTP HeaderMap 与带原始声明长度的 Body。完整头字段/字节预算包含重复和忽略字段，在复制前检查；随后一次准入，在同一原绝对期限内依次执行第一 Content-Encoding 选择、gzip 首头预检、账户查询、metadata 验证、Content-Type 选择和原上传批次。初始化已保证默认用户名非空；显式空用户名在 gzip 预检后拒绝。阻塞账户查询另占自身工作槽位，并持有原上传授权/容量直到实际退出；取消或等待超时不能提前归还，后续批次不二次准入、不重置期限。

[上传头决策](../sandbox-guest-runtime/src/file_upload.rs)保留固定 Go ParseMediaType 的返回类型：普通畸形可选参数可保留 raw/multipart 类型，冲突的重复参数使类型无效。metadata 取规范化同名头的首值，忽略空后缀，复用真实写入的可打印 ASCII、键长和总量验证；原始头预算与保存后的 metadata 预算分开计算。raw 需要查询 path，multipart 继续用原边界解析器及完整文件名规则；非 UTF-8 multipart 参数仍明确拒绝。identity raw 也使用共用 HTTP 帧/长度/EOF 校验，失败保留已写前缀且不完成 metadata。固定 Go 有限头部对照已本地运行；实际 Linux 四种正文组合和账户阻塞取消待实跑。组件不承担查询解码、请求签名、完整上传错误 JSON 或响应序列化/发送，SDK 夹具的通用拒绝响应不代表正式错误合同。

[gzip 下载连接](../sandbox-guest-service/src/file_transfer/gzip_download.rs)在原文件池单次准入后，把授权、容量和原绝对期限交给同一个打开/编码阻塞任务。[实际 EOF 文件源](../sandbox-guest-runtime/src/filesystem/transfer.rs)共用原路径/stat/open 错误检查，跟随来宾链接并保留原 FD，但不 seek、不以 stat 大小截断或预检总量。这对应固定 Go gzip 路径的 `io.Copy`：读取前发生的增长可以进入响应，缩短成为实际 EOF，替换路径不切换到新文件；不承诺并发内容快照。identity 仍保留初始 seek 长度行为。

[阻塞编码连接](../sandbox-guest-service/src/upload_body/encode.rs)与上传共用按需消费、Bytes 最后副本释放和取消通道。打开成功不预读正文；每个请求只有一个编码 worker、一个显式块大小的源缓冲和一个交付块，压缩库工作区及 HTTP 分配另计。原始/压缩字节预算独立，缓冲可预读至一个源块，超出累计消费预算不能成功。每次源填充前后及缓冲消费时均检查原期限/取消；已进入的 open/read/destructor 不能被超时强制终止，其原守卫保留至真正返回。句柄、worker 与已交出块分别保留原容量，Bytes 副本还保留原授权；没有 Content-Length 或重新准入。

只有实际 EOF、编码尾部及预算检查全部完成才返回成功。源错误、超额、取消或过期传播为正文错误，不补成功尾部；这比固定 Go 下载在 `io.Copy` 失败后仍 defer `gzip.Close` 更严格，须在 E01 全端点对照保留差异。SDK 测试路由经下述单 worker 下载连接按固定头部规则选择 gzip/identity，gzip 响应无压缩长度；该测试路由已按原查询扩展名使用受控 MIME 表，未知类型回退 application/octet-stream，并在成功 open 后格式化解析路径的 Content-Disposition；gzip 不嗅探正文。编码、range/conditional 与 stat/open 顺序已有组件连接，完整正式路由/错误映射仍未接通。可移植编码所有权检查已有本地运行；Linux 实际 FD/授权和固定 SDK `gzip=True` 组合仍待验证，未启用到模板。

[文件内容编码选择](../sandbox-guest-runtime/src/file_encoding/mod.rs)和[HTTP 头连接](../sandbox-guest-service/src/file_encoding.rs)已实现固定 Go 的 Content-Encoding / Accept-Encoding 局部规则，尚未接正式文件入口。只取每个字段的第一值（即使它为空），不合并重复值；保留非 UTF-8 字节，按 Go Unicode 空白及大小写识别编码名。Content-Encoding 缺失/精确空值为 identity，否则去掉分号参数后只接受 identity/gzip，不把逗号编码链拆开或按 q=0 拒绝 gzip。

Accept-Encoding 默认 q=1，重复 q 参数取最后一个可解析值，非法参数保留此前值；沿固定 `strconv.ParseFloat` 接受十六进制/下划线、NaN/Inf、负值及大于 1 的值，溢出参数作为无效值忽略。只跳过精确零；identity 显式拒绝、wildcard 与重复项仍各按固定算法处理。长列表同权重选择会受 Go 不稳定排序影响，已移植固定 Go 1.26.8 排序及十六进制舍入辅助，并用原函数显式对照，不能擅自改成稳定排序或新的严格 RFC q 校验器。

下载先选可接受编码，随后仅当第一值非空的 Range / If-Modified-Since / If-None-Match / If-Range 存在时强制 identity；仅空白或畸形条件值也进入此分支。If-Match / If-Unmodified-Since 不参与这个预选。若 identity 被拒绝则返回 NotAcceptable；HTTP 连接保留 Vary 的阶段区别：初次编码选择失败前还未设置 Vary，之后的条件回退失败保留 Vary。原端点相应错误为 406，上传不支持编码为 400；预算错误的正式映射另须冻结。

参数显式限制首字段原始字节和逗号项数，先计数后分配固定容量的项数组；q 临时规范化至多一个原字段大小，排序只保留有界递归，不保留整个 HTTP 请求。所有重复字段/其他请求头、传输库先行分配、全请求授权/期限仍由调用者约束。上传编码/首 gzip 头先于账号/metadata 的完整顺序仍待正式路由连接。下载在 stat/目录拒绝之后、open 之前选编码，已由下述单 worker 组件连接实际文件与响应；独立选择函数本身不执行这些 I/O，也不把局部选择一致当作 E01/E03 全端点验收。

[下载条件/范围决策](../sandbox-guest-runtime/src/file_download/mod.rs)及[分阶段响应计划](../sandbox-guest-service/src/file_download.rs)另实现固定 Go 1.26.8 `http.ServeContent` 的局部 identity 行为。`prepare` 的调用前提是原 stat/编码选择/open 已成功；它按 If-Match → If-Unmodified-Since → If-None-Match → If-Modified-Since 顺序决定 304/412，非空 If-Match/If-None-Match 各自抑制对应日期检查。标签保留弱/强比较、畸形值、逗号及通配符的原语义。只有返回 Continue 才允许调用者嗅探/回绕和探测长度；随后 `finish` 才解析 Range。计划不执行文件 I/O，也不证明调用方已保持该顺序。

HTTP 日期接受固定 Go 的三种布局、小数秒、大小写和旧两位年份规则。Last-Modified 使用 UTC，精确 year-1 零值和 Unix epoch 零纳秒不设置该头；带纳秒的 epoch 仍设置。旧格式的命名时区依赖显式可信 `LocalZone` 快照，未知名字沿 Go 保留 nominal UTC 秒值，不能直接当作固定数字偏移；正式 daemon 本地时区解析尚待连接，不得默认以 UTC 冒充部署环境。日期转换限现有 `time` 库的 -9999..9999 年，超出范围明确组件错误；该限制须列入 E01 差异。

Range 保留区间顺序、重叠、重复、后缀零长度、空列表、空文件的无交集例外和超过文件大小的区间总量回退。If-Range 只在 GET/HEAD 的非空 Range 下检查，失败忽略 Range；单段 206 在发送任何头之前仍要求成功 seek（HEAD 也一样）。多段使用调用者提供的 Go 形状、60 字节小写十六进制随机边界，逐段计划 MIME 头/文件区间及结尾，线长包含全部 MIME 字节；边界必须由可信熵产生，不接收用户字段。正文执行者必须在 seek/read 失败或短读时立即结束错误，不能继续生成后续段或成功结尾；该执行连接见下项，Linux 组合尚待实跑。

响应计划保留 200/206/304/412/416 头的差异，以及 416 对 Cache-Control、Content-Encoding、ETag、Last-Modified 的默认清除，保留 Vary/Disposition。这里只实现 `httpservecontentkeepheaders=0` 的固定默认行为；不声称支持 Go 环境开关。错误正文计划仍包含 HEAD 时原 writer 尝试写入的字节，传输层的 HEAD 正文抑制尚由 HTTP 连接承担。显式预算覆盖选中请求字段总字节、扫描项数、响应头及含 MIME 的线长（HEAD 也检查所声明长度）；超额或 int64 长度溢出明确拒绝，不复现 Go 整数回绕。全头解析分配、响应库自动头、原授权/期限/容量、MIME 查表/嗅探、Content-Disposition 及 seek 错误映射仍需正式连接；这些局部预算拒绝尚未冻结为端点状态码。

[identity 范围执行](../sandbox-guest-service/src/file_download/stream.rs)与 gzip 复用[受所有权约束的阻塞正文任务](../sandbox-guest-service/src/owned_body.rs)。每个请求一个 worker，准备、同一 FD 的 seek/read 和销毁都在其中完成；304/412 不探测长度、不读正文。长度探测和回绕、单段范围初始 seek 在返回响应头之前完成，多段每一段在发完该段 MIME 头后 seek。只在消费者请求时生成一个输出块，最后一个 Bytes 副本释放前不继续读；保留一个有界 MIME 头、范围列表和一个输出块，不缓存整文件。原期限及取消在每次系统调用前后检查，取消不能中断已派发调用，原授权/容量保留到实际调用与 FD 销毁结束；保留的下载句柄和在途字节也持有原守卫。

该执行器把增长限制在计划长度内，提前 EOF、读取或后续 seek 失败成为正文错误，不补后续 MIME 段/结尾。HEAD 在执行必需的单段初始 seek 后抑制全部正文，含 416 错误正文；保留声明线长和所选文件字节的预算检查。原单独 identity 入口在响应开始前仍返回长度 seek / range seek 组件错误；下述协商入口负责已知的 Go 500/416 错误响应。正式路由与完整故障验收仍未接通。

[Linux 文件池连接](../sandbox-guest-service/src/file_transfer/identity_download.rs)复用单次准入、原 AuthPermit、绝对期限与解析路径；保留原 pre-open stat 的 mtime，不在打开后重新 stat 替换其时间。路径替换后仍读原 FD，这不是一致快照。池总量限制所选文件字节，MIME 线长另有限额，完整文件过大时合格小范围仍可执行。当前入口接受预先已知类型或原查询路径与不可变 MIME 表，以及可信边界/时区参数。成功 open 后格式化解析路径的 Content-Disposition，再执行条件判断；304/412 不查表或嗅探。继续响应时，已有 Content-Type（含显式空值）跳过查表/嗅探，否则先查原查询路径最后扩展名，未知/空类型才在原 worker 读取至多 512 字节并回绕，再探测长度。读取错误按固定 Go 使用已有嗅探前缀，回绕失败保留 SniffSeek 错误；后续正文读取错误仍不能成功结束。嗅探每次 read/seek 前后检查原期限/取消，且始终持有原授权/容量，调用方不得提前在守卫外嗅探。固定 SDK 测试路由已使用该连接，并有合成 range/conditional/HEAD 请求；可移植故障/所有权测试已有本地运行，Linux 文件/HTTP 扩展待实跑，模板未启用。

[下载 MIME 组件](../sandbox-guest-runtime/src/file_mime/mod.rs)对齐固定 Go 1.26.8 的扩展名查表、DetectContentType 和 inline filename 格式。查表先精确大小写再 Unicode 小写；内建表之后按固定 Linux 路径顺序取首个成功打开的 globs2（空文件也停止），没有 globs2 才顺序应用全部可打开的 mime.types。globs2 不覆盖已有精确扩展名，mime.types 后项覆盖；文本默认 charset、无效条目和原 Go 格式化边界由显式原函数对照检查。加载结果不可变，不随请求重读或自动刷新；生产须在有准入的阻塞启动任务中加载实际来宾文件，并把来源/指纹绑定模板验收，不能用开发宿主或仅内建表代替。Linux 固定路径加载入口已有实现及交叉检查，实际运行待补。

配置显式限制全部源字节、原始行字节、扩展名/值、两张表的合计条目与键值字节，内建条目也计费。原始行限额至多 65535 字节（含换行），比 Go Scanner 缓冲边界保守；超额、非 UTF-8 数据库/解码参数或打开后的读取失败拒绝加载，不发布部分表。路径和格式化头长度也在分配前检查。filename 取 Linux basename，保留点、反斜线及原始字节，非 ASCII/控制字节按 RFC 2231 编码，不做有损 UTF-8 转换。嗅探无堆分配，只看前 512 字节并保持原签名顺序；这些有限对照与严格预算差异不表示全协议等价。下载 stat→编码选择→open 顺序与通用嗅探/长度 seek 错误已由下述组件连接；初始 range seek 的已知 Linux errno 文本也已由下述协商组件连接；真实本地时区及全服务预算仍待连接。

[协商下载](../sandbox-guest-service/src/file_download/stream/negotiated.rs)在同一个原已准入 worker 中执行 stat/目录拒绝→编码选择→open→Disposition→identity/gzip 准备与正文；[Linux 文件池](../sandbox-guest-service/src/file_transfer/download.rs)只取得一次 AuthPermit/容量/绝对期限。stat 返回的原 mtime 与延迟打开的同一路径分别保留，选择失败不 open，open 后不 restat；路径在两阶段间被替换时仍按固定 Go 打开新对象而保留旧 stat 信息，不宣称 inode 固定或一致快照。stat/open 的阻塞取消仍持有原守卫到调用与源销毁结束。

编码解析失败与四类条件字段强制 identity 失败保留不同的 Vary 阶段；If-Match/If-Unmodified-Since 本身不强制回退。identity 复用原条件/嗅探/范围执行，gzip 复用原有界编码器而不再准入或重新计时。准备期 SniffSeek/LengthSeek 变为固定 `500 seeker can't seek`，清除原实体缓存头、保留 Vary/Disposition 并抑制 HEAD 正文；原单独 identity 入口仍返回组件错误。初始单段 range seek 的已知 Linux errno 变为 `416 seek <解析路径>: <errno 文本>`，不带成功范围计划尚未应设置的 Content-Range/Accept-Ranges/Content-Length；默认清除实体缓存头，保留此前已有头。未知 I/O 错误仍返回组件失败；多段正文开始后的 seek/read 失败仍为正文错误，不能改写已经发送的状态。gzip HEAD 仍消费/压缩至实际 EOF，在同一 worker 丢弃输出后返回空正文，避免 HTTP 不轮询 HEAD body 时完全省略读取；本组件延后交出 HEAD 响应头，编码/源失败仍显式失败，这一发送时机及原 gzip 失败差异须保留在端点验收中，不能称已与 Go 故障路径等价。

协商连接的 identity 响应计划、原文件字节、压缩字节/线长、MIME 表及路径预算分别生效；成功选择后的响应头及一份 identity 准备错误所需头副本受显式头预算约束。完整请求解析前分配、认证/签名、账户默认值及其错误、上传错误、自动 HTTP 头、本地时区及监听器仍为正式入口义务。可移植顺序/取消/seek 错误检查与固定 Go 有限对照已有本地运行，Linux 实际文件和 SDK 扩展待实跑；没有更换模板。

[下载错误响应](../sandbox-guest-service/src/file_download/stream/errors.rs)在原 worker 内构造有界正文并通过同一 OwnedBody 交付，响应和在途 Bytes 副本继续持有授权/容量/绝对期限。stat 的 ENOENT 映射 404，已确认目录映射 400，其他已知 stat errno（含 ENOTDIR）及 open errno 映射 500；编码不可接受映射 406，保留编码解析失败前无新增 Vary、条件回退和 open 失败有 Vary 的阶段区别。上述 JSON 使用固定 envd 的 code/message 顺序、UTF-8 Content-Type、nosniff 和末尾换行，沿 Go 默认转义控制字节、HTML 字符、U+2028/U+2029 及非法 UTF-8；HEAD 仍核对预算后抑制正文。stat/编码/open 失败不提前生成 Disposition。

Linux 文件端口只携带已知操作的结构化 errno；文本来自固定 Go 1.26.8 Linux amd64 表及未知编号的 `errno N`，不用开发宿主 locale/strerror 或任意 I/O 异常字符串。文件路径取原已解析、限额路径，不从异常文本提取；Rust 在 syscall 前拒绝的 NUL 路径按 Go 的 EINVAL 处理。错误格式化先用同一编码器计算精确线长并检查原 wire_bytes，随后才分配正文；执行阶段至多另有一份受同预算限制的错误段副本和一个输出块，不能将 wire_bytes 称为整个进程的内存上界。路径、响应头、原期限和组件预算仍分别生效，超额/未知错误的正式端点映射尚待冻结。可移植对照使用固定 Linux errno 表的受控错误，不代表 Linux 内核故障已实测。

[本地账户端口](../sandbox-guest-runtime/src/accounts.rs)读取固定 `/etc/passwd`、`/etc/group`，对应固定 envd 的无 CGO 构建，不新增 NSS/网络查询或数字用户名回退。普通文件按打开的 inode 核对，符号链接至普通文件保留；非阻塞打开后拒绝 FIFO/设备等类型。未知账号和选中记录的坏 UID/GID 拒绝，`u32::MAX` 不得成为“保留原身份”。组文件不可读时按固定端点只保留已解析的主组，不继承 daemon 附加组；成功组查询保留固定实现的重复主组项，超过 Go 组扫描行界限则丢弃附加结果。文件字节和组数量另有显式预算，超额拒绝而非截断。非 UTF-8 home 无法进入当前 JSON 执行上下文，明确失败；不是完整 NSS/POSIX 账号数据库的兼容声明。

账户查询池在提交阻塞工作前占额；请求取消或回复期限耗尽后，实际查询仍占原槽位直至返回/异常退出，不无限新建阻塞工作。查询只读，不在背景任务执行命令；调用者仍须持有原授权许可到真正派发，并先保留进程和公开选择器容量。上下文字节、环境项、参数数、用户名/头部长度与查询并发/期限没有生产默认值。这些组件未安装到模板，也未补齐公开 PID/tag 归属、完整请求期限、进程优先级/全部 envd 行为或 KVM 验收。

[命令管理组件](../sandbox-guest-service/src/command.rs)的 `CommandOwners::prepare_command` 先预留记录，再建立独立的[准备管理任务](../sandbox-guest-service/src/command/preparation.rs)。`PendingCommand::prepared` 只返回仍被闸门阻挡的完整内部身份；调用者完成所需登记后，以同一身份 `commit`，原额度和授权许可随原 worker 移交执行任务。该确认接口不自行登记公开 PID/tag，也不冻结其复用政策。底层 `reserve` / `start_registered` 保留；直接使用它们的调用方仍须负责准备取消后的实际收尾。初始输出订阅先于执行任务启动登记，避免多线程下快命令抢先产生输出。授权持有到实际放行结束，不贯穿整段用户执行；后续公开请求仍须重新鉴权，内部句柄不是新的公开凭据。

准备及等待登记共用一个绝对期限，并受原执行期限约束；零或不可表示的准备/收尾/重试时间拒绝。确认接受前丢弃 ticket、取消 commit 或期限耗尽会中止原 worker；接受后回复丢失保持执行结果未知，不取消或重做用户命令。准备失败/中止只有确认未 spawn 或原 child 实际 wait 成功才归还记录额度；wait 失败或观察超时报告 `CleanupUnknown`，同一管理任务以有限频率继续收尾，保留原 child/句柄及额度，不创建替代 worker。任务意外丢失时，已可能 spawn 的额度在该池内保守隔离；首次轮询前确定未 spawn 才能归还。不得重建池抹去未知责任。组件的 `Stopped` 只表示未创建或主 child 的实际退出，私有目录释放不构成故障文件系统清理保证；目录回收失败、阻塞系统调用、服务重启及整机预算仍需单独验收，最终停止责任归原 VM 生命周期。

执行期限按原起点保存为绝对时刻，零/未设置不设执行期限，准备耗时和重连不重置。到期前未放行则中止原 worker；放行中/后到期只通过保留的 pidfd 尝试 KILL，记录信号成功/失败，真实 wait 和管道排空另行观察。信号与输入/输出压力独立；断线、等待者取消和丢弃全部客户端句柄不取消命令任务，也不隐式关闭 stdin。执行期限不代替 HTTP 流期限，主进程终止不证明后代或 VM 停止。明确 exec 失败和放行诊断未知保持原错误；未知情况下可丢弃排空原管道并等待原进程，不能重执行或生成完整成功。真实 wait 持续失败时保留责任并有界频率重试，不凭错误释放容量。

订阅仅接收登记后的输出和结束结果，无完整历史重放。每订阅有独立条数/字节预算，慢订阅在已排队前缀后得到明确 `Lagged`，不会阻塞其他订阅、管道排空或期限；后续协议映射仍须 E01/E03 复核。输出块被消费方取走后，字节、订阅和记录额度仍保留到块实际释放，不能通过反复重连积累游离缓冲。Data 排在终局之前；已截断的订阅不能因后来 wait 成功而改成正常 End。记录额度覆盖管理任务、保留句柄/订阅/在途块，只有任务完成且这些引用全部释放才归还；终局登记的 TTL 及公开请求/编码/传输额度仍待接入，不把该计数当整机 RAM 上界，也不新增累计输出上限。

唯一管道/终端输入由管理记录持有，两种通道共用 `stdin_bytes` 单次字节预算，重叠写入/关闭明确拒绝且不排队；失败或取消可能已写前缀，不自动重放。终局到达时关闭空闲输入，正在写入的调用观察终局后中断并关闭，控制信号不等待输入锁。管理任务异常消失（包括首次轮询前被运行时丢弃）报告 `owner_lost`，该池原槽位永久保守占用；不把它当完成回执或任意重建池来清除未决责任。进程仍可能存活，最终停止责任继续归原 VM 生命周期。这些新增自有并发和资源逻辑仅有组件测试，尚无生产登记/监听器、KVM 或证明验收。

## 状态与持久化：A

本节是已实现的宿主本地 SQLite 合同；每个节点保持独占本地写入及自主恢复。中心 Redis 协调合同见[中心持久化与恢复](#中心持久化与恢复)，不是用 Redis 替换本地 SQLite。两个引擎内部证明和多活共识不在范围内；自有事务顺序、未知结果及适配连接仍须证明。

[#4 的首批持久化代码](../controller-service/src/lib.rs)使用固定的 `rusqlite 0.40.2`（启用内置 SQLite，具体依赖以 `Cargo.lock` 为准），在本地可信文件系统上使用 `WAL`、`synchronous=FULL`、外键检查、`trusted_schema=OFF` 和 5 秒忙等待；写入及派发领取使用 `BEGIN IMMEDIATE`。这些配置可由 `storage_settings` 读取以记录测试指纹。[SQLite 官方说明](https://www.sqlite.org/pragma.html)解释了 WAL 中同步设置的区别，但目前只测试进程中断与重启，不声称已经验证宿主掉电、磁盘损坏或网络文件系统。部署方还须提供仅控制器可访问的数据库目录，并连同 WAL 辅助文件一起管理与备份。

底层 `Journal` 将同一控制决定给出的 sandbox、operation 状态字节与待执行动作原子写入。其上的 `ControllerJournal` 接入同一 `controller-core`，仅从经过验证的版本化当前状态检查点和连续输入尾恢复，不反序列化任意 `World`，也不另写生命周期规则。输入、查询投影、后续动作在同一事务提交；成功回执所对应的资源状态更新也在该事务内。当前控制库只接受完整格式 5，不提供旧库升级或全历史恢复备用入口。

控制器基础 `PRAGMA user_version` 为 5；通用 `Journal` 的基础格式 1 不属于正式控制器入口，且拒绝打开控制器数据库。`controller_meta.version` 的 7–11 功能门仍用于核对实际启用能力，不是可选存储模式。全新控制库在同一 IMMEDIATE 事务初始化身份前沿、配置、容量、凭据索引和检查点；重开时缺失或非法计数器失败关闭，不从当前最大行号重新播种。服务生成的 sandbox、每沙箱 operation、逻辑动作映射、输入序号、outbox 和回执历史序号使用持久高水位；公共字符串格式不变。sandbox/operation 保存规范十进制 u64，SQL 身份使用检查后的正 i64；输入序号最多为 `i64::MAX-1`，给连续尾恢复保留哨兵。VM/槽位/快照/manifest 仍使用核心已有分配器，不增加第二份真值。

高水位只随实际接受的工作在原事务中推进；只读编号提议不消费身份，拒绝或确认回滚不消费，提交不确定时须依现有缓存失效边界重新读取持久状态。新操作准入前拒绝任一已耗尽的 SQL 身份家族；批量分配先检查整个批次，不能环绕或退回 SQLite 随机 ROWID。创建已经持久接受后遇到后续耗尽仍返回结果未知并保留原身份，不伪装为无副作用拒绝。完整容量层在准入时为固定 V1 工作图预留后续输入、动作、派发和回执身份额度，以及有限退休结果；未知工作继续占用原预留。该预留不证明宿主动作必然成功，也不承诺越过永久编号耗尽后仍能无限运行。

完整模式只在纯核心退休、精确 SQL 闭包删除和永久身份前沿保留的同一事务内删除该沙箱 operation 高水位。可信底层显式身份输入仍由原核心检查，不增加“低于高水位一律拒绝”的新合同；高水位保证服务生成路径不因保留行减少而倒退，不单独构成完整的回收后旧身份拒绝证明。

`ControllerJournal` 在单写者租约期间使用仅驻内存的已提交 `World` 缓存，其不变量是等于同一打开身份下最新持久检查点与输入尾恢复的核心状态。每个写事务持有私有候选；唯一输入追加入口逐项推进候选，覆盖创建与预留、Worker 与 Receipt、批量启动补偿等多输入事务。只有 SQLite 确认提交后才以所有权移动发布候选，且先于 AfterCommit/AfterDispatchClaim 故障点；派发时的 Worker 资格预演不得发布。确认回滚保留旧缓存，提交不确定或回滚无法确认则整体失效；同一对象后续读取必须先确认连接不在事务中，再在同一 SQLite 读取快照内从持久恢复映像重新建立状态，否则失败关闭。缓存没有独立序号真值来源，也不以最大序号检查代替逐输入推进与单写者合同。

缓存只保存核心 `World`，不保存 SQL 寿命、模板状态或授权结果。SQL-only 写入同样经过提交/失效边界；每次授权仍核对当前服务时钟、持久期限与核心权限，授权和撤销订阅仍在原管理锁内原子完成。kill、到期及 set_timeout 的不确定提交继续撤销已有数据通道。全局管理互斥锁及宿主 I/O 期间持锁保持不变；不引入并行宿主派发或另一套生命周期状态机；缓存本身不充当持久检查点。

底层公开 `Journal` 拒绝打开已由控制器标记的数据库，其每个写事务还在 `BEGIN IMMEDIATE` 后重查标记，阻止在控制器打开之前取得的旧句柄绕过缓存。缓存绑定同一 SQLite 连接的 `data_version`，打开时在重放事务内取值，写入时在 IMMEDIATE 事务内复核；其他连接的提交（包括旧历史或 SQL 投影修改）使本对象失败关闭，须停下、核对原库后重新打开，不能仅重放核心便自动认可外部投影变化。这是对可信单写者合同的保守检测，不是恶意宿主/直接磁盘修改的完整防护或多写者支持。普通读取连接不改变此版本，自己的提交不刷新外部版本基线。

数据库租约只属于控制器，不向子进程转移控制权。成功加锁后立即由私有守卫持有；正常关闭时先关闭 SQLite 连接，再显式解锁，打开失败也由同一守卫释放。这样，启动子进程期间短暂继承的旧文件描述符不会延长已结束控制器的租约；关闭旧描述符也不能释放后来控制器的新租约。运行中的控制器仍拒绝第二写者，不删除或替换锁文件；此释放策略不适用于承载子进程资源所有权的宿主守卫。

控制服务持有数据库进程锁，派发期间独占控制服务写入口；生产调用方不得绕过它用底层 `Journal` 另行写入。动作先在库中标记已派发，再调用工作执行器。标记后尚无最终回执的动作在重启时保留为“结果不明”，不能自动再次执行；一般情况下，同一沙箱后续生命周期写入拒绝，直到可信宿主观察解决未知结果。终止调度的受限例外是当前创建的 `PrepareVm` 结果未知而独立启动期限已到：控制器先在同一数据库事务中提交失败补偿意图，再安装终止围栏；仅当前密封计划的原 VM 和槽位可以安排 `AbortPrepare`。宿主核对 owner、沙箱、时期、代数、槽位和持久进程身份，用 pidfd 停止并观察精确退出，完成私有资源清理与失败标记后才返回成功。原准备命令绝不重派发；晚到的启动成功不能撤销终止决定。失败发布必须覆盖计划中每一个预留 VM 和槽位，不能用空资源索引当作“已清理”。中止动作回执再次丢失时，重启只核对并幂等完成同一动作。此例外依赖 V1 的单控制器进程锁与串行宿主派发；若改成独立并发 worker，必须先增加宿主级启动闸门与终止围栏的原子协调，不得直接沿用该安全结论。除下述同一初始化的重复完成外，其他未知动作仍保持拒绝，不因定时器重做。旧动作必须仍通过核心工作入口的资格检查，才可送往宿主。

`ActivateVm` 的重复完成只针对固定 envd 0.9.0 的受限初始化请求（同一访问令牌、绑定模板默认值和创建时持久化的环境变量），不是重放任意工作命令。控制器先检查动作仍为当前创建的未完成尝试，owner、操作编号、时期、代数、密封 VM/槽位计划与已配置网络完全匹配；宿主再核对非终止围栏、工作区绑定和原 VM 进程身份，按原持久凭证发送相同 `/init`，并在前后观察同一进程及鉴权文件接口。含模板启动程序时，还须符合上文一次性启动合同：只复用已确认的启动，不重发未知命令。凭证、默认值或环境变量不一致、VM 身份变化、envd 不可观察都不得生成成功回执。恢复在宿主调用前检查持久启动期限，调用后再检查一次；到期先持久提交终止意图，不再初始化或探测旧初始化的来宾结果，迟到成功不得发布 Running。

未知初始化的终止例外仅允许当前创建、原密封 VM/槽位计划内的终止围栏及精确 `StopVm`。停止成功回执和终止围栏均已确认后，核心 `RetireActivation` 将旧动作标为 `RetiredByStop`，保存原操作、停止时期/尝试及结果摘要；不伪造初始化成功或明确失败。服务在同一事务中提交这一输入与查询投影，从重放后的核心状态派生剩余工作；outbox 的派发/回执列保留历史事实，退休不会填补缺失回执，不能只统计 `dispatch_state='dispatched'` 判断尚未完成。生命周期功能门要求至少为 7，完整存储格式固定为 5；重开不重置寿命或改写历史回执，不接收旧格式库。失败发布仍要求真实停止及访问撤销，资源配额仍待清理回执后释放。初始化的迟到新回执被拒绝，已确认回执的相同重放仍是无状态变化；停止未知或身份不符继续保持未完成。此规则不覆盖任意未知网络动作、不引入并行 worker，也不依赖来宾恢复响应。

启动和周期恢复按沙箱身份处理宿主结果：某个沙箱的精确资源检查失败、宿主观察不能完成、单条回执身份/证据被拒绝，或本沙箱的工作流程仍无可信结果时，本轮不再推进该沙箱，也不报告它销毁成功或释放其资源占额；其余沙箱可以继续恢复。对于尚未终止的 `ActivateVm`，来宾不可观察同样保持原动作未知；只有启动期限已持久到期并进入终止流程后，才跳过来宾请求、核对原 VM 的停止。恢复报告区分未完成总数与本轮出错数，常驻扫描器记录出错数量。到期销毁也逐台接收和收尾，第一台停止不明不会推迟已到期的其他沙箱。共享 SQLite 故障、重放损坏或提交结果不确定无法限定到单个沙箱，立即停止本轮扫描并上报；任何一种局部隔离都不把未确认的宿主动作解释为成功。

宿主适配器通过 `HostEvidence` 提供具体命令与资源的成功观察；来宾回复或外部 API 不得直接构造它。部分完成视为未知，不直接重试。明确失败映射到核心的失败类别，并要求回执的可重试标志与该类别一致；不一致时拒绝回执并保留待核对状态，不擅自授予重试。创建流程对“无部分副作用的明确失败”现在通过核心的重试预算分配新尝试；预算耗尽或不可重试时提交失败证据、关闭围栏、精确停止已登记 VM、发布失败并清理。真实 Linux 工作执行器目前把无法确认无副作用的错误都返回未知，不能把合成故障测试等同于真实部分失败已自动补偿。未知观察允许被后续最终观察解决，历史回执保留；最终回执冲突被拒绝。

外部资源编号由部署方提供的唯一 16 位小写十六进制命名空间与核心编号组成；该命名空间持久保存，跨部署唯一性是部署合同。数据库所在目录仅允许可信控制器访问，进程锁不防范恶意宿主或绕过服务的数据库写入。打开及缓存失效按下面的单库检查点协议恢复。正常读写复用已提交缓存，仍有当前状态复制/扫描成本；不宣称固定复杂度、吞吐 SLA 或已经完成整体容量保证。

SQLite 提交本身若报告结果不确定，调用方必须按操作编号重新查询，不能把它当成未提交并直接重试。创建与销毁的编排已通过环回 HTTP 服务接上真实宿主适配器。创建级环境变量与元数据在接受创建的同一事务落盘；前者随 root 独占的来宾凭证记录传给 envd 初始化，重启时与已接受值逐项比较，不匹配则拒绝继续；后者由管理查询返回，不授予权限。创建级环境变量作为该来宾的命令默认值，root/ubuntu 均可读取；单次命令的同名 envs 覆盖只影响该命令，不修改后续默认值或其他 VM。metadata 仅为管理数据，不自动注入环境；查询与分页筛选在服务重启后保持相同值，并重新核对调用者归属。重复 kill 若仍处于撤销中，只观察并接续原持久操作，不分配第二个操作编号；观察不明继续返回未知。两个独立 create 在没有客户端幂等键时仍不合并；真实宿主完整恢复属于 A04/#11。

只有 A 更新业务状态；B 的本地资源登记是观察依据，不能成为另一个可独立改写业务状态的控制器。提交、派发、回执记录及状态发布必须有可注入崩溃的位置。恢复扫描先核对身份和实际状态，再安排重放或清理。

允许 controller/worker 进程被终止后重启；宿主持续运行、可信存储按合同工作。宿主掉电、存储损坏及恶意宿主不在首版故障保证内。后续若扩大故障域，须新增合同和实验。

### #99 有界维护与物理位置复用

宿主目录身份（#223）：启动闸门放行之前，运行层独占创建 jail/root，并将资源名、UID/GID、物理位置、parent/jail/root 的设备、inode 与 Linux `statx` 创建时间持久写入 `jail.json`；文件系统不提供创建时间时拒绝新启动，不退回仅凭名称删除。停止仍按原 PID/开始时间执行；清理只处理原登记目录，使用已打开目录描述符遍历、不跟随链接，并在最后删除目录项前重新核对身份。目录消失后保留原登记直到既有精确退休协议完成；同名替换、上下文改变、登记损坏及缺登记的旧目录保持未知，禁止在清理现场补认领。旧记录且目录已不存在可继续收尾。恢复观察须核对同一登记，不能将陌生目录里的磁盘视作原资源。`jail.json` 及固定 staging 都纳入宿主登记/退休清单和清理空间推导，旧额度不足则拒绝准入。目录修改在原宿主串行边界与 claim 锁内进行；额外的特权写者、任意并发挂载或伪造文件系统身份不属于部署边界。实现中的登记、比较、闸门和退休衔接仍是本项目待证明代码，不因依赖系统调用而整体排除。

本地维护使用现有状态机内的操作，不另建清理控制器或更换 SQLite。目标是在活跃对象、未决工作、保留结果和模板的条数/字节都有显式额度时，反复创建销毁不使在线记录及宿主登记按累计次数增长；重启从有限当前状态和有限输入尾恢复。容量不足拒绝新工作，但不能侵占已接受工作的收尾预留。宿主永远不可观察时仍保留未知工作，不承诺无条件继续接单；有限整数身份耗尽仍明确拒绝，不能据此声称数学意义的无限新身份。

服务、管理适配器和 Linux 节点只使用完整物理位置配置、容量预留、有限退休结果及检查点＋输入尾。不存在无维护、无物理配置或无窗口构建的备用运行模式；缺配置在开库和准入前拒绝。组件测试与相关实机验收分别绑定准确提交记录，不能从旧版本验收推断新版通过。

- 新完整库初始化永久 sandbox/workspace 身份前沿；新创建必须同时高于两个前沿，只有接受才推进，退休或裁剪历史不降低它们。零是合法编号；最大整数不回绕。老的活跃对象可以继续服务，不阻止更大编号的终止对象独立退休。
- 退休必须核对终止状态、关闭权限、精确资源回收回执、全部操作终局和没有未决派发/未知动作。已有 `RetiredByStop` 保留其停止覆盖含义；未派发且已被终止取代的动作只能按既有工作资格判断为不可执行，不能伪造成功回执。扫描实际资源/账本并核对跨对象引用，不能只相信可能不完整的索引。含快照的历史在该 V1 基础中拒绝退休。
- 物理资源、旧数据连接/relay、宿主工作及外部构建/发布引用的静止确认由可信执行/服务层提供，证书绑定原 owner、sandbox、epoch、operation 和 workspace；纯函数不能观察物理世界。生产连接必须从实际记录与观察构造证书，不能仅凭 Destroyed 或调用者布尔值放行。私有 buildID 重试锚点及模板验证引用在显式迁移前都是退休阻塞条件。
- 退休先在纯后继状态中保存逐操作的最小 owner、原参数、终态与结果及明确到期点，再删除该对象的详细账本、动作、资源元数据和历史队列成员。查询/重放在保留期内仍核对 owner 与原参数；显式到期转换之后返回已过期，旧创建/命令/回执不能重建原身份。保留记录条数满时整个退休拒绝，不提前驱逐承诺内结果。格式 5 使用显式 `retention_ms`，从可信单调时间下界加该时长计算保留截止点；检查点编码有字节上限；完整容量模式在准入时另保留全部受支持 V1 后续转换、结果及到期清理额度。时间下界到达截止后 Query/Replay 即拒绝，行可继续计入额度直到 `ExpireResults` 实际删除；窗口推进时间不要求同时裁剪结果。
- 物理位置使用独立 `HostSlotId`；占用、待释放、空闲三态均保留当前或最后一次永久 `VmId` 绑定。复用只允许更大的新 VM 身份，并比较预期旧绑定。释放确认丢失保持待释放；空闲也拒绝旧准备/开放围栏，所有宿主入口须在同一串行边界核对绑定再执行。显式模式在创建的同一 IMMEDIATE 事务中预留位置并保存完整绑定与预期旧 VM；首次围栏之前宿主须先持久绑定。恢复通常只在从未认领任何动作时安装缺失的首个绑定。唯一附加情况是已接受终止、当前无 VM，且所有曾认领动作均为终止围栏；这仅补全原实例的未启动取消，不生成凭据或启动 VM。任何曾认领的开放围栏、准备或其他动作仍要求既有绑定。服务启动库存与管理恢复使用同一安装条件。取消在认领终止围栏前先核对原位置；绑定未知则保留原取消意图。宿主先完整初始化有限 NeverUsed 位置表，再提交配置标记；已初始化表的任一缺失记录均失败关闭，不能用空文件重置旧身份。UID 和 /30 地址从位置及显式基址派生，进程、jail 与 netns 名仍含永久 VmId。
- 进入持久 `Free` 之前，退休仍须核对原网络空间的所有线程与 FD 持有者，未知则不可释放。完整退休已确认并持久为 `Free` 后，旧 namespace 的设备/inode 只作为历史记录；Linux 可把该数值分给无关新 namespace，不能再以当前全局持有者推翻已确认的释放。复用和重开仍检查原 PID/启动时刻、原 jail/netns/cgroup/claim 名、helper gate、节点登记及专用地址的连接跟踪均无残留；只有读取原持久 Free 见证的节点路径能使用此观察，未完成释放仍走严格检查。
- 自助构建已接通租户＋服务端窗口＋用户键、同 SQLite 事务的 Rust 窗口桥接、有限公开结果和私有结算握手；接口、不可变配置、文件恢复约束只以上文自助构建合同为准。普通 E2B SDK create 不添加这些字段；云端组件通过不等于本版 KVM 或宿主长期容量已验收。

正式服务的 `bounded_host` 必须同时提供完整 `data_transfer`；逐位置 route cell、全局额度和控制预留分别从 `max_transfers_per_vm`、`max_transfers`、`control_reserve` 派生并持久绑定，不重复填写派生字段，不使用隐含默认值。`uid_base`、`uplink_base`、位置/结果/窗口参数均必填，拒绝拼错字段、root/保留 UID 和越界 /30 地址。正式配置不再接收旧 `max_vm_id`；永久身份在 u64 耗尽时拒绝，不回绕。构建/运行池无论公网开关如何，保留的 UID 和地址范围均须互不重叠，namespace 不能替代地址隔离。

正式宿主仅有 `sandproof-host initialize|serve|audit --config 绝对路径`。受保护 `HostConfig` 包含原 `native`、已登记节点的 `inbox/internal`、`template_cache/artifact_source`；不接旧公共 bind、用户密钥、注册库或私有构建开关。原 native 的 `bounded_host`、顶层 `maintenance.capacity`、`data_transfer`、完整 `physical_storage` 与 `console_policy: "discard"` 必须显式提供。首次初始化才激活空受管根、原 SQLite 和内部收件箱；serve 先检查当前格式及不可变配置，再取得原租约、核对资源、恢复工作和安装私有监听，不补建丢失权威。audit 离线取得原宿主租约，读取已校验原事务视图并检查原目录，不恢复、不派发；运行期间拒绝审计不能靠取消租约修成通过。`preflight_complete/open_complete` 保留原有界检查点与连续尾恢复，不升级旧库、补身份或认领未知资源。当前内部协议及宿主格式从两个实际产物的 `contract-versions` 核对，不复制硬编码版本表。

释放先提交核心 Releasing，再调用宿主。管理器持锁核对旧工作、构建/发布引用和已撤销数据通道；响应 body 与 relay 都持有 RAII pin，发送撤销信号不代表已排空。每个同步宿主 helper 有独立固定 marker，每个并行 relay 占用一个固定 route cell；子进程在 stdin 启动门后阻塞，精确 PID、启动 ticks、boot 身份、位置 incarnation 与命令摘要同步落盘后才准许同 PID exec。控制器或监督进程退出、子进程关闭继承 FD 都不能抹除未决证据；匹配的 zombie 仍占位，只有确切 reaping/进程消失才可重用。原动作执行资格在 relay 真正派发前再次核对。relay 取消与早期错误由预先建立的精确子进程 reaper 接管，不能丢弃 std Child 并累积 zombie；迟到完成不得按 cell 编号清除后来者。route marker 持久记录可信网关现有 RPC 分类给出的 control/ordinary；新普通请求按全部 live/unknown cells 的全局/逐位置数量检查 max-minus-reserve，control 请求受完整额度限制。重启不会把旧未决连接从这些计数中抹去；确切持久额度满返回 429，身份/观察异常仍保持未知而不是伪装成满额。宿主还须独立观察精确旧物理资源、持久 helper/route marker 与进程/namespace 持有者，不能靠服务重启把内存 pin 清空就放行。helper gate 的永久 inode 在初始化时登记；已知仍活着的旧 helper 只阻塞所属位置，身份/配置损坏才拒绝整个启动。位置表、启动数据及凭证使用精确的有界 staging，Initializing 可恢复本部署的合法中断；Ready 后不得重造缺失位置。有界 inventory 可核对/回收精确完成的 helper 记账，但不凭盘点执行生命周期资源清理。宿主根的持久独占租约在任何初始化/恢复写入前取得，第二个控制器不得先碰 staged 数据再等待数据库锁。宿主在删除旧 claim、secret、fence、startup 或日志之前，先持久化精确 inode/内容绑定的清理清单与所需运行配置，删除中断可按同一清单恢复；任何外来 inode 或未知观察保留 Releasing。公网地址复用还需精确旧连接跟踪清除/缺席核对，不能只删 veth/nft 表。宿主确认 Free 后服务才记录 ConfirmRelease；丢失确认保持 Releasing，空闲记录保留最后永久 VM 身份。未结算的私有 buildID 锚点或模板验证引用继续阻止释放；仅按下述窗口结算/验证证据迁移解除逻辑引用后，才允许独立的更强物理释放检查。

生产维护协调入口位于控制服务的应用模块，为 `ControllerApplication::maintain`，只由可信服务启动/周期扫描调用，不接收 HTTP 证书或客户端四项布尔值。它与创建、宿主派发、启动凭证写入和撤销共用原管理互斥锁；仅接受精确 `ConfirmRelease` 的持久见证及已排空的本地 body/relay 记录，并让纯核心再次核对终态、回收回执、未决动作和依赖。旧位置已被后来实例复用时，核对原见证而不对后来绑定执行旧资源观察或清理。一个老的活跃/未知实例不形成按历史编号清理的屏障，其他已满足条件的对象可以独立退休。未迁移/未结算的私有 buildID 与活动模板验证引用继续保留阻塞语义，不能因检查点或服务重启解除。成功退休后删除该对象的进程内撤销/排空登记；任何仍有持有者或未知 relay 的记录都不得靠清空内存变成成功证据。

顶层 `maintenance` 与 `bounded_host` 均为正式部署必需字段，全部字段显式必填且为可表示正整数：`retention_ms`、`max_checkpoint_bytes`、`max_records`、`max_references`、`max_tail_inputs`、`max_tail_bytes`、`max_input_bytes`、`prune_batch_rows`；单输入字节额度不得超过尾日志字节额度。它与 `bounded_host.maintenance` 的纯核心位置/结果/窗口参数是不同层次，均无生产默认。控制库只提供 `open_complete` 和只读 `preflight_complete`；旧开库、升级及全历史恢复接口已删除。

格式 5 的恢复映像由同一个 SQLite 读取快照内的版本化核心检查点、严格连续输入尾、当前权威 SQL 表组成，并非可脱离该库的独立备份。检查点保存精简后的活跃/未决核心状态、保留结果、全部四类资源游标、永久身份前沿、窗口与时钟、逐位置完整上下文和释放见证、SQL 身份游标、命名空间/配置及输入截点。先核对 blob 长度/摘要，再通过私有 DTO 的限额、重复键、跨对象引用与状态检查恢复，未给 World/Store 增加任意反序列化。V1 明确拒绝 Pause/Resume、Pausing/Paused 以及所有快照引用，不能静默丢弃。已回收资源上的历史 Prepare 成功仍保留原义。

宿主释放成功后，服务在 ConfirmRelease 同一事务保存每个尚未退休对象的精确位置上下文和该确认输入序号；这份有界待退休见证跨重开和位置再次复用保留，只随该对象 Retire 一起删除，不形成永久逐对象宿主墓碑。见证只能由已接受的精确 ConfirmRelease 输入构造，不能由 Destroyed/Free 推断。Retire 原子保留查询结果，并删除该对象的回执历史、outbox、逻辑动作映射、操作/沙箱投影、寿命、创建选项、凭据索引、释放见证和每沙箱 operation 高水位；全局游标与 Free 最后绑定继续保留。仍存在的窗口锚点和活动模板验证引用阻塞删除；已确认结算的窗口锚点和持久验证证据采用下面的显式解除规则，不改写原创建选项。

写事务准备阶段自动检查尾额度，必要时原子发布新检查点，再以最多 `prune_batch_rows` 行的独立事务删除已覆盖前缀并推进删除下界；不另公开重复的手动历史裁剪入口。中断或未知提交恢复后先核对实际持久根，再继续删除；损坏/缺失的格式 5 根一律失败关闭，不因仍有旧行而回退。输入高水位必须等于检查点截点加连续尾，不得用剩余 MAX(sequence) 重新播种。尾可包含早于其他对象的未知工作当前状态，不让旧未决操作钉住全部输入前缀。当前寿命/登记等 SQL-only 更新始终从当前 SQL 表读取，绝不被旧检查点侧数据覆盖；单写者、data_version 和不确定提交缓存失效边界保持。

单输入、尾日志、检查点、SQL 行与字节、文件页及后续收尾额度均在完整模式下检查；详细组合和部署前提以下节为准，不再维护无预留检查点路径。删除行不会自行缩小 DB 文件，也不表示不受管外部写者的磁盘占用已受约束。

### 完整容量、请求结算与物理部署前提

`maintenance.capacity` 是显式收尾预留策略；生产服务启用顶层 `maintenance` 时必须提供，在缺少预留时拒绝打开数据库或接单。库级无预留维护接口已删除，组件测试同样使用完整配置。它的正整数参数为 `max_live_sandboxes`、`max_sql_rows`、`max_sql_bytes`、`max_sql_value_bytes`、`max_receipt_bytes`、`max_transaction_inputs`、`max_transaction_bytes`、`max_database_bytes`、`max_wal_bytes`、`max_shm_bytes`、`checkpoint_scratch_bytes`、`max_online_storage_bytes`。`max_transaction_bytes` 限制一次事务新增的控制输入批次，不冒充所有 SQL 修改的字节数；SQL、页与 WAL 另有整体上限。最大原子批次必须能放入尾部，单条输入、未来命令/回执包装、完整标量宽度和检查点替换空间也必须可表示；配置不足或溢出明确拒绝。新完整模式只在受支持的空控制状态启用，不自动为旧的无预留在途工作补造额度。

每个接受的 V1 创建在同一事务拥有后续行、引用、编码字节、实际 SQL 编号和两个结果的额度；固定重试上界来自核心常量，并保守涵盖成功创建、文件策略、失败准备/初始化、终止抢占及合法终止重试。未知对象保留自身额度，不钉住无关历史。结果、开放窗口及发布验证证据的未来增长/到期转换也必须计入；最后一次清理可以消费其已预留编号，不能用永远不释放的“加一”假预留阻止最后一步。编号只在实际插入时前进，不预先跳过输入序号。静态界与现行 V1 图对应，不表示已经新增自动终止失败重试器或任意将来操作；新状态/命令须重新核对界限。

写入前在原单写者/缓存边界检查剩余输入空间，必要时先确认检查点，再逐批删除覆盖前缀；每个内部事务也在 IMMEDIATE 内核对身份并在提交前使缓存失效。未知提交先恢复实际根后才能继续。相同截点的完整模式检查点不递增代数，无可观察变化的维护/重复请求不消耗输入；仍返回原核心事件并保留必要 SQL 决定。管理器完整模式依赖这个受限写入前调度，空闲轮询不不断发布根；裁剪统计从持久删除前沿计算。

控制器文件额度组合数据库页上限、单事务 WAL 帧及同步扇区填充、SHM 索引和检查点替换空间；设置后读回实际页上限。关闭 cache spill、使用有界当前状态及内存临时表，并在写入前完成受管 WAL checkpoint。持久外部读者阻挡或磁盘 I/O 失败时拒绝继续写入/派发，保留未知结果；这些额度不创造物理磁盘或内存，也不容许不受管写者。SQL-only 更新、模板发布的未来证据和最大宽度计数器不能偷偷使用已承诺的收尾字节。接受物理 VM 前的 `cleanup_reserve_bytes` 至少覆盖控制器文件峰值；下述 profile 还要求它覆盖推导的宿主登记空间。

完整模式显式选择 `bounded_host.console_policy: "discard"`，VMM stdout/stderr 进入空设备，不创建无限 console.log。这个选择会失去 VMM 控制台诊断，命令流和构建日志合同不变；不自动替部署方选择，旧未配置的文件日志模式不属于完整有界承诺。宿主登记上界由真实固定位置/route cell 全集、每种记录的写入上限及固定 staging 推导；空闲后残留的死 route marker 仍计数，不能拿并发 route 数代替所有物理 cell。未来最大身份、配置和退休清单的编码须在写入/接受工作之前能放入原有上限。

完整生产入口还必须显式提供同一个 `bounded_host.physical_storage`（version 1）。profile 列出唯一运行池及可选独立构建池的 role/namespace、数据库/node/jail 根、根盘逻辑预算、位置数、每 jail 的 kernel/Firecracker 复制品上限、控制器＋宿主清理空间；有自助构建时还列出公开工作区和注册库的字节/inode 额度及 `max_jobs`、`max_templates`；注册库预算包含产物额度及每模板最大 64 KiB manifest 和 87 字节 owner marker，工作区在任何 SQLite 写入前须容纳数据库、WAL 和恢复余量。保护的 `coordination_file` 由部署方预置在同一已核对文件系统，不要求写挂载根、不创建新文件系统。所有列出的配置、宿主租约与 profile 必须相符；每个入口核对自身角色和子预算，未表示的 registry/构建池不得写入。候选/模板文件、旧稀疏盘未来增长和每 jail 复制品不能只按当下 statvfs 已用量计费。

首次激活只由列出的 Rust 服务在所有列出数据库不存在、受管根处于允许的空初始化状态时执行；独占核对并持久保存 profile 与协调文件设备/inode，随后持有共享租约。Python 服务只加入已经激活的匹配 profile，必须在创建 BuildStore 前拒绝缺失/不完整 marker。部分初始化仅在独占锁及原 quiescent 条件成立时截断、同步精确未发布前缀，再重新观察空闲空间；不把任意旧文件当成本次 profile。完整匹配记录重开也须确认记录和父目录持久同步。首次空部署需要至少两倍共同峰值的可用字节和 inode；新准入要求一倍峰值。已有分配不做有竞争的 du 抵扣，这是有意的保守空间成本：受管增长达到一倍峰值后仍留下另一份余量，重复 churn 不因自身热身耗尽准入/收尾空间。匹配 profile 的重启、查询和原工作清理不重新要求初始/新准入余量。

`filesystem_overhead_bytes`、`filesystem_overhead_inodes` 及固定 jailer 的 inode 上界是显式、经部署验证的文件系统分配/目录/extent 前提，不是跨任意文件系统的定理；必须覆盖已推导文件全集、全量 inode 的分配粒度取整、另加协调记录编码，以及额外开销。配置值不能代替实际空闲字节/inode 观察。全部受管池必须使用这个协调路径和 profile，不承诺排除另选路径的不合作控制器、未列出的 bind/submount 别名、外部写者、系统日志收集器、宿主掉电或存储损坏。CPU、RAM、FD、inode 和物理盘的实际部署仍须覆盖配置峰值并通过固定版本实机验收；有界不是任意参数下都能运行的保证。

私有构建的唯一准入/结算合同见本页自助构建部分；中心复用原纯窗口转换并在同一业务控制块提交，不在宿主另设窗口账本。先匹配原 tuple，再检查新准入；推进到期观察后发生拒绝也不能回滚可信时间。模板验证引用只在原精确终态证据成立后解除，不以 Free 作为循环前提；物理资源仍须独立核对排空及释放。

验证证据绑定候选、owner、完整模板/产物/启动/资源身份、实际激活和精确逻辑清理，与终局结果及活动引用解除原子保存。重开不依赖已退休创建选项；Ready 记录缺失原验证证据时拒绝，Checking/unknown 不解除；不在重启时补造旧证书。内部验证身份的隐私过滤独立于活动 pin，退休前不得短暂出现在普通列表；模板及证据仍占原登记额度，不随公开结果到期退款或删除。原本地组件的 schema 11 曾为这些验证语义设置功能门，仅用于相应组件合同，不是当前生产宿主格式；唯一宿主入口要求共享合同中的当前格式 16，不导入旧库。模板实现仍属工程测试边界。

## 生命周期和撤销

### 内部故障诊断（#290 R6）

应用层的七类业务错误及公开 HTTP 状态/脱敏消息保持原合同。节点在映射错误前，只投影固定故障类别、OS errno/I/O 类别、SQLite 数值错误码或 Firecracker HTTP 状态；不保存或输出底层消息、命令/策略内容、令牌、环境变量、宿主路径和任意 panic 文本。关联字段只包含已有的数值沙箱/操作/代数/尝试/VM 编号；未知字段省略，不用诊断解析结果授予权限。尚未类型化的宿主错误归为 `HostInvariant`，不伪称已保留完整原文或因果链。

恢复继续使用原 `is_local_recovery_failure` 判断，不使用诊断故障域决定能否恢复。单实例失败仍只停放该实例，共享存储损坏仍中止恢复，共享凭据索引故障仍保持原拒绝与清理语义；`CommitUncertain` 和已接受工作的 `OutcomeUnknown` 不改成可安全重试或成功。后台维护前、恢复、到期和维护后的次序不变，日志指出具体失败阶段。每轮恢复报告最多保存一个固定大小的故障样本，节点最后错误也只有一个脱敏样本；其余通过原 stderr 运维出口记录，不建立数据库、消息队列或可观测存储平台。诊断输出失败不改变业务返回值；诊断不提供无条件墙钟期限或持久交付保证。

### 请求派发预算（#290 R1）

前置入口可从[独立 Nginx 示例](../tests/system/tls-front.example.conf)制备：替换域名、证书、监听和固定环回目标后，运行 `nginx -t -c /绝对路径/配置.conf`，部署验收再检查慢请求头、连接上限及固定 SDK 流式调用。该示例未自动部署；实际部署必须记录配置与结果。`limit_conn` 只统计已读完请求头的请求，所以还需要固定 worker 数及 `worker_connections` 约束前期连接（也计入上游连接），不能只按 IP 限流或只依赖 TLS。语义见 [Nginx 连接限制](https://nginx.org/en/docs/http/ngx_http_limit_conn_module.html)及 [worker_connections](https://nginx.org/en/docs/ngx_core_module.html#worker_connections)。

管理 API 与数据网关共用 `request_admission`，在 `spawn_blocking` 前无等待地申请名额；满额直接返回 429，不调用后端、不产生新意图，也不建立信号量等待队列。数据请求在令牌反查前申请，格式正确的未知令牌也受限；取得资格后仍须通过原有全局/逐实例传输预算及派发时资格重检，名额不授予权限。

中心部署显式提供完整 `request_admission`，满足 `0 < control_reserve < max_pending_requests <= 8192`；缺失、拼错字段及 null 均拒绝。组件测试的有限初始值不是生产回退，也不是 SDK 创建参数或持久资源配额。公共管理、数据及构建代理共用这一个预算；私有辅助接口不另建队列或传输预算。普通请求只能使用总额扣除预留后的名额；kill、connect、set_timeout、私有窗口关闭/结算及网关 health/SendSignal/SendInput/CloseStdin 可用控制预留。非法凭据不会因此取得访问权。

单个数据请求在鉴权、请求体准备及中继派发期间共用一个名额，随后由原传输预算管辖响应与中继退出。阻塞闭包持有名额直到真正结束；HTTP 取消或 kill 回应期限耗尽不提前释放，不把未知结果变成成功。宿主后台扫描保留一个不可由公开请求占用的名额。中心生命周期协调与模板材料/发布协调分别保留一个名额，每条工作链内部仍串行、无无限等待队列；中心与公开请求合计最多 `max_pending_requests + 2` 个在途派发名额，宿主仍最多 `max_pending_requests + 1`。模板大文件检查和下载不排在中心生命周期扫描之前，不持决定锁；工作仍来自原目录和 Checking 记录，完成后通过原身份/摘要及 CAS 确认。中继停止/等待受原传输持有者及退出流程约束。

预留只保证准入，不保证抢占慢宿主操作或在固定期限内完成清理；同一管理锁仍串行执行，跨实例并行留给 P2 #284。预算不覆盖套接字建立、请求头读取或管理 JSON 提取阶段，因此远程部署的可信 TLS 前置入口还必须设置有限连接数、请求头大小及读取期限、请求体大小及读取期限；直连内部监听不构成完整防耗尽承诺。生命周期安全和请求资源有界是两层不同的检查。

控制服务 `application` 模块拥有宿主接口、数据连接端口、业务错误和中继持有者类型；HTTP 状态及 SDK 字段仍由 API/网关映射。网关的 `DataAccessPort` 只提供原身份许可和受管连接，不提供网络空间名称、命令字符串或任意目的地址。派发继续在原管理锁内重检原实例、代数、有效寿命和撤销，持久登记子进程后才开放启动闸门。成功必须返回可确切回收的 `TrackedRelayChild`；缺少后端能力或未知启动是错误，不存在空子进程成功及网关自行启动后备路径。许可、响应和中继的排空 pin、未知退出阻塞及精确宿主释放前置条件不因接口搬迁改变。

`sandbox-api` 复用原 SDK 解析，生产由 `CenterPort` 调用当前 Redis 权威；旧 `ManagedPort` 只保留在组件测试夹具，不是生产适配或另一启动模式。中心网关按当前令牌、租户、可见性和寿命路由到固定 mTLS 宿主；宿主再核对完整 GLOBAL→LOCAL 映射并调用原 `ControllerApplication` 的本地权限/撤销/中继流程。原宿主接口按执行、恢复、位置、容量、来宾配置及校验职责划分，不拆原管理锁、不另造控制器。宿主与辅助工具不持全量用户密钥，客户端不能选择宿主地址或中继命令。公共与私有中心监听共用一个传输预算，并分别拒绝另一角色的凭据；请求头不能切换接口权限。流式行为见下表，超限或中断须可见为失败，输出不整块缓存在宿主；数据只支持 HTTP/1.1，其他版本转发前返回 505。公网默认值、显式禁网、静态 IPv4、创建级环境/元数据与原兼容合同保持一致；暂停拒绝，未知模板不回退。时间、前置 TLS、存储引擎和实际宿主资源属于明确部署前提；真实链路和 Harbor 验收绑定精确候选，不从组件通过推断已部署。字段差异见[兼容合同](../tests/compat/contract.json)。

`data_transfer` 是可信正式服务配置中的必需对象，下列字段均必填，不从客户端接收。流式模块已实现并通过组件、固定 SDK 组合及选定真实 KVM 边界验收；完整资源与故障矩阵仍待验收，保持显式启用。最终默认值和部署最大值仍须结合 #13 固定任务、宿主配额和实测确定；测试夹具的 64/96 MiB 不是生产推荐值。

| 字段 | 单位与约束 | 行为 |
|---|---|---|
| `file_upload_bytes` | 正整数字节 | `POST /files` 的 HTTP body 总量，含 multipart 边界；已知长度和分块都逐块转发 |
| `file_download_bytes` | 正整数字节 | `GET /files` 的响应 body 总量 |
| `command_input_bytes` | 正整数字节 | 每次 Process RPC 请求总量，含 Connect 编码；独立于文件预算 |
| `rpc_request_bytes`、`rpc_response_bytes` | 正整数字节；请求不超过 8 MiB | 其他文件请求及一元 RPC 的输入/输出；输入仍有界缓冲以检查非法路径。Process Start/Connect 的持续输出不使用累计响应预算 |
| `max_transfers`、`max_transfers_per_vm` | 全局上限 ≥ 每实例上限 > `control_reserve` | 鉴权后按 `(vm, generation)` 计数，涵盖读取请求至响应结束和上游连接退出；超额返回 429，不排无限队列 |
| `control_reserve` | 正整数，包含在上述上限内 | 普通文件/Start 请求不能占用这部分名额；health、SendSignal、SendInput、CloseStdin 可使用，仍受总上限约束 |
| `request_idle_seconds` | 正整数秒，可由系统时钟表示 | 请求体生产者停顿超时；可返回响应时为 408 |
| `file_idle_seconds` | 正整数秒，可由系统时钟表示 | 文件响应头等待按上传进度续计，超时为 504；响应体中途停顿则中断流 |
| `write_idle_seconds` | 正整数秒，可由系统时钟表示 | relay 写入和前端套接字写入/flush 阻塞超时；断开相应连接 |

零、负数、字段缺失/拼错和无效并发关系均拒绝配置。`command_output_bytes` 已移除，开发阶段的部署配置删除该字段，不能继续把它当成有效限制。上传已知长度超限在读取前返回 413；未知长度累计超限会停止转发并返回 413，但可能已截断或部分写入来宾文件，不能自动重传或承诺原子覆盖/批量回滚。上游在上传体尚未完整交给 HTTP 传输层时提前返回成功，网关改为 502；完整传输也不等于持久化提交证明。下载在响应头后超限/断流必须以不完整 HTTP 消息结束，SDK 不能收到完整成功。

命令 Start/Connect 输出按背压持续转发，不累计整份输出，不设总字节上限，也不增加用户可选的输出额度或带宽限制。一元查询/信号/输入回复、请求体、文件传输和宿主辅助命令仍保留各自边界。命令执行期限不是字节上限：输出速度不受其保证；后台命令、客户端等待期限、断开连接和沙箱寿命是不同事实。慢消费者由写入空闲期限、并发预算与撤销机制约束，安静的命令不因缺少输出被判失败。固定 envd 的消息块和队列、HTTP/内核缓冲须在后续证明中分别建模或声明可信前提；固定 SDK 可能在客户端累计全部输出，本合同不保证客户端内存有界。


该配置暂不支持压缩请求：非 identity 的 HTTP/Connect/gRPC 编码返回 415；向上游协商 identity，仍收到压缩响应则返回 502。因而不会仅按压缩后大小放行更大的解压内容。上传/下载不整包缓存，relay 的 HTTP 读缓冲限制为 64 KiB；namespace 中继在两个方向各使用固定 64 KiB 读缓冲，读取到数据即转发，不等待缓冲填满，请求写半关闭后仍可接收响应。元数据缓冲、每连接 HTTP/内核缓冲和并发仍占内存，不能把这些缓冲或文件总量预算说成整个进程的内存限额。慢写超时也作用于同一监听器上的管理响应，但管理请求不占数据传输名额。传输超时独立于 SDK 请求/等待期限、命令执行超时及沙箱寿命；安静但仍在运行的命令不会因没有 stdout 而触发文件空闲超时。真实磁盘满、到期/kill 中断、授权撤销及宿主资源残留仍须按[验收清单](testing-plan.md)验证。

固定 envd 的文件 `user` 决定相对路径/`~` 的用户主目录，以及上传文件和新建目录的归属；文件处理仍由来宾 root 执行，不构成来宾用户之间的 DAC 权限边界。原 SDK 指定 ubuntu 时仍能读取 root 私有目录，并覆盖其中的文件、把该文件归属改为 ubuntu；同一 ubuntu 命令仍受 Linux 目录权限限制。未知用户明确拒绝，不回退默认用户。沙箱令牌代表整个实例的访问资格，隔离边界是宿主与不同 VM，不能向不受信任的来宾用户发放令牌后依赖 `user` 限权。

固定 SDK 的批量上传不提供整体事务：multipart 顺序处理文件，某项失败前已写的内容保留，后项不处理；同步 octet-stream 同样顺序发送并在错误后停止。异步 octet-stream 使用并发请求，某项报错时其他项可能已经写入或仍在完成。调用者应查询原路径确认结果，不因异常自动重发整批；选定路径错误、用户归属及跨 VM/宿主路径实测见[验收清单](testing-plan.md)。

固定 SDK 文件 HTTP 的 `request_timeout` 与 Connect RPC 头限制不同：大正数可用于 HTTP，不能按 Connect 的十位毫秒头规则拒绝。普通读取和缓冲上传使用请求期限，流读取仅在显式提供时设置总传输期限；实际流式 IO 上传的两个客户端都省略该期限。multipart 的文本 IO 会先缓冲，因此仍受请求期限约束，不能仅凭对象是 IO 就推断不受限。负数 HTTP 期限在固定传输适配器中变为立即到期，而非参数验证错误。同步流读取忽略 `stream_idle_timeout`；异步对首个响应和后续各次读取应用该参数，零关闭显式空闲期限。所有这些期限都不代表写入回滚，具体实测范围见[验收清单](testing-plan.md)。

固定 SDK 的常用文件/命令一元 RPC 将 `request_timeout` 写入 Connect 毫秒期限：省略用连接配置，零关闭，负数量化为 1 ms，超过十位毫秒头范围明确拒绝。1 ms 不保证必定失败，完整响应可能先到；期限错误不证明副作用未发生。文件变更或输入/终止结果不明时只核对已有路径、PID 和结果，不通过自动重发把未知变成成功；详见[验收清单](testing-plan.md)的一元 RPC 探针。

- create：在资源及策略就绪后才发布运行成功；部分配置失败要有明确收尾路径。
- connect：V1 只连接运行中的同一实例并按约定延长寿命；暂停对象恢复尚未实现时明确报告不支持。
- set_timeout：以服务端时钟计算新截止时间；与到期处理原子协调。单元测试使用伪时钟；进程重启后的时钟/截止时间合同由 A03 固定。
- kill：接受后进入撤销，停止授予新的执行资格；此前在途操作可能需要核对和收尾。只有确认相关 VM 停止、访问撤销，才能发布销毁完成。失败或未知不得冒充完成。
- cleanup：仅处理动作绑定的资源，核验资源的所有者、sandbox 和代数；不能只凭可复用的 PID、IP、文件名或目录名删除资源。
- 失败：准入拒绝无副作用；接受后的不可安全继续可以失败关闭。不是每个 RPC 超时都销毁沙箱；公开差异写入兼容清单。

数据请求的授权与本地撤销订阅在同一管理锁内完成，避免 kill 落在检查与登记之间。kill 或到期撤销持久提交后，通知该沙箱的全部在途连接：尚未转发的请求停止准备，等待响应或已流式返回的连接终止，所属 relay 进程退出；无需等待来宾 TCP 自己发现 VM 消失。通知只撤回既有访问，不授予权限，也不替代宿主停止回执。提交结果不确定时保守关闭连接，管理结果仍为未知；错误 owner 或被拒绝的操作不撤销其他实例。关闭可能留下部分文件或结果未知的命令，不自动重传；流已开始后通过不完整 HTTP 消息报告失败。通知是本进程状态，服务重启后按持久状态重新鉴权，不恢复旧连接。

V1 寿命合同：创建与连接省略寿命时按固定 SDK v2 的 300 秒处理；连接现有运行实例只延长，不新建 VM；`set_timeout` 自服务端当前时刻重设，可以缩短，零/负值走到期处理。创建/连接超过单次上限应拒绝，`set_timeout` 到总寿命上限时应截顶，不能把两者合并成同一种结果。准入先持久预留时长与资源；物理 VM 就绪后，在同一事务内发布 Running 并重设可见的启动时间、初始截止与总截止，避免把启动耗时算作可用寿命。发布前崩溃仍保持 Starting，恢复只接续原操作，不重做已确认的宿主动作。当前完整库的 Running 实例重启后保留已提交的原有截止，不自动补长。

创建意图已持久提交后，启动凭证写入、后续执行或返回会话失败都可能留下已接收操作，必须返回结果未知（HTTP 500），不能以固定 SDK 视为未改变状态的 503 引导重试；明确终结的创建失败保留失败语义。创建没有通用客户端幂等键时，两个独立 HTTP 请求不保证只创建一次；`session_id` 等元数据不是重放键。创建结果不明的沙箱继续占用配额，并须可由已提交身份发现和收尾。`kill` 的服务端回复等待上限是 25 秒，更短的客户端期限可能先到；期限到达只表示本次回复不确定，后台已接受操作继续持锁完成物理停止与回执，不能把撤销中的实例回滚成 Running 或报已销毁。重复调用在撤销中只核对并接续同一持久 kill，仍不确定就继续返回未知；完成后再次 kill 按固定 SDK 的不存在语义返回 404/false，查询也不把它伪装成 Running。真实停止和访问撤销后才可发布完成。具体 HTTP 状态、SDK 返回值和异常按 #5 的逐调用合同验收。

已接受的 `kill` 在恢复观察、持久状态读取或宿主停止后续步骤失败时返回结果未知（HTTP 500），不能以表示可安全重试的 503 掩盖可能已发生的副作用；后续调用只核对原操作，不派发第二次停止。

网络合同目标：省略联网参数默认允许受平台禁区约束的公网出站；显式禁网和原 SDK 的 `network.allow_out`/`deny_out` 静态 IPv4 地址或网段规则由 #10/#12 实现。平台禁区始终优先；用户允许高于用户拒绝，`false` 与显式允许项可以共存。高级 DNS/域名授权、IPv6 放行后置；静态 IPv4 规则不得被解释为自动授权任意 DNS 查询。公网模式要求部署配置显式开启、宿主 IPv4 转发已启用、固定 `base` 镜像包含默认路由；任何安装或观察失败不得发布可用。隔离 Linux 流量、固定 SDK→真实 VM→测试专用外部网络空间以及一条真实公网 TCP 握手路径的选定场景已通过；通用互联网、DNS 查询内容控制和完整 S10 尚未验收。

`controller-service` 的寿命准入层已把创建意图、截止时间和逻辑磁盘预算放入同一 SQLite 事务；连接只延长，`set_timeout` 可缩短或延长，到期处理在接受 kill 前重新核对截止时间，防止旧定时事件误杀。它使用调用方提供的服务端时钟和部署配额；应用时钟是可信部署依赖，不接受用户请求指定时间，每个原寿命检查、恢复观察后的复核及稳定发布均重新取值，读不到合法时间时拒绝，已准入工作保持未知；`ControllerApplication` 与 `sandbox-server` 已接入真实时钟、外部接口和周期到期执行，固定 SDK 实机测试覆盖部分到期清理路径。完整竞争和跨崩溃场景仍须按[验收清单](testing-plan.md)完成，不以局部测试替代整套验收。

### 宿主同步辅助命令

`sandbox-runtime::OwnedChild` 统一承接可信宿主工具，而非用户的持续输出流。启动前获取最多 64 个进程额度；非阻塞轮询同时写 stdin、读 stdout/stderr，每次最多处理 8 KiB，防止三条管道互相等待。控制操作的交换期限为 10 秒，输入 1 MiB、stdout 2 MiB、stderr 16 KiB；小格式摘要操作为 3 秒、64 KiB、1 KiB、4 KiB。envd 模板启动只观察首个有界 Start 帧（帧载荷最多 8 KiB，传输观察缓冲最多 64 KiB），随后停止宿主 curl，不终止来宾程序。curl 自身已有的 5 秒期限仍保留，启动确认不能用截断或 EOF 代替。

超时、管道故障或超量均返回错误，不把截断结果当作成功；副作用可能已发生，持久节点意图保持未知，不自动重发。只对自有未回收 Child 停止并观察退出，另给最多 2 秒回收等待；仍未确认退出则交给唯一固定回收线程并继续占额。持久闸门的原身份记录也不由错误路径清除，恢复沿用原身份核验。已确认退出不代表外部资源已清理。可信辅助程序必须同 PID exec、不能自行派生常驻子进程；异步中继使用其独立的有界额度和持久身份协议，不能用同步工具预算代替。

这些期限约束可返回的管道交换与退出观察，不保证操作系统调度、进程创建、文件同步或不可中断内核调用一定按时返回；永久故障时只保证保守占额，不承诺最终完成。64 个额度是当前固定宿主策略，不是 SDK 参数，也不是整机进程/内存配额。

### 故障域与驻留预算

区分请求/流局部、实例局部和真正共享依赖故障。坏请求、失效订阅或单实例恢复错误按原身份保留/收尾，不经自有错误传播、扫描、队列、引用或锁无限阻断可独立处理的健康实例；共享 Redis/SQLite 权威损坏可按范围失败关闭。中心决定锁不跨远程 I/O；本地串行路径在声明期限/调度条件下释放等待，跨实例并行优化仍归 #284，不新增固定 SLA。外部持续不返回的影响须明示，不能把自身工作启用/出队/引用释放/无环等待假定正确。

受管驻留计费包括零计数键、已结束订阅、请求/响应关联、连接池、取消监听、排队/重试任务与库内在途队列。每类按活跃＋在途＋显式保留＋固定开销列条数/字节界，连接实际分配、引用和回收；unknown 继续占有限预算并限制新准入。并发驱逐与引用/计费一致，不分裂使用中的计数器或遗失未知责任。

许可覆盖完整正文、流或实际执行退出/排空，不以响应头或发送取消退还。自有计费到实际驻留是待证明义务；分配器、运行库、内核、envd 剩余开销列版本/配置和外部界并工程核对。用户命令累计输出与 SDK 客户端积累内存不属于宿主累计字节/内存保障，有限键数不等于整个进程内存已证明有界。

## 容量与资源：A/B

A 控制租户配额、操作预算、有限重试与收尾预留；B 设置实际 CPU/内存/磁盘等限制并报告观察。现有准入层限制同时活跃数量、每租户和全局的逻辑磁盘预算，保留固定清理余量；销毁后只有资源清理回执完成才释放预算。宿主可用的最大 VM 编号由可信配置给出；准入在同一事务里预留 VM/网络槽位编号并检查边界，编号即使资源清理也不回绕复用。编号耗尽时拒绝新创建，不留下已接受但宿主无法启动的记录。宿主准备动作还会独立核对编号与 UID 映射，防止部署配置漂移。服务启动要求数据库父目录（含 SQLite WAL 辅助文件）、节点状态目录与私有 VM 磁盘目录的文件系统设备相同，任一异盘都在打开数据库和初始化节点前拒绝，确保磁盘余量观察覆盖这些写入。管理接入已在创建前检查真实可用磁盘是否覆盖实例盘与清理预留，但这只是当时观察，不是对所有外部磁盘写入的原子预留，也不等于宿主物理内存保障或长期容量证明。容量不足可以拒绝新请求，但已接收操作的清理预算不能被其他请求消耗。

## M0 必须产出的可执行合同

1. Rust 模块接口和结构化错误以 `sandbox-protocol` 为准；C 的 E2B 请求/响应映射以[兼容合同](../tests/compat/contract.json)为准。外部错误与内部错误不可直接等同。
2. 能力矩阵逐项标明目标、现状、支持/差异/拒绝/未测及测试层级；不以合成服务通过宣称真实 VM 通过。
3. 正常、拒绝、重复、迟到、未知和部分完成的共享测试样例见 `sandbox-protocol/tests/`；A 在持久状态中决定冲突回执，B 的观察不能自行发布业务状态。
4. 资源身份包含 owner、sandbox、operation、epoch/generation、logical action、attempt 和精确资源。仅调试构建的服务级崩溃点 `prepare_vm`、`stop_vm` 位于真实宿主动作成功与回执落库之间；其他窗口不得按这两个测试推断已覆盖。日志和实验报告至少关联上述字段、执行提交、宿主资源与观察结果，脱敏后保存。
5. [输入锁](../references/v1-baseline.json)只记录固定依赖与源码依据；实机证据在 PR 绑定精确提交与配置，未复现实验不得升级为整套验收。

A/B/C 核对影响各自模块的合同；范围变更由 owner 决定。后续合同修改必须更新调用方、执行方、样例及影响说明，不能靠宽松解析悄悄吞掉新增字段。Harbor 固定任务预检和评分链归 #13/#14，不是本 M0 合同的关闭前提。
