## 1 目标与边界

证明“在声明边界内，真实控制系统的每一种允许执行符合规约”，不只检查一个静态切面或一条测试轨迹。分别交付：

- 安全：不越权、不重复分配原操作、不误删、不把未知/截断当成功。
- 功能正确：完整合法请求得到合同规定结果，不能靠拒绝全部请求满足安全。
- 有条件最终完成性：外部通信/存储/停止清理最终提供所需结果、声明调度成立时，内部流程确实能达到规定终局与收尾。

当前范围为单有效中心写者、单权威Redis、预算内任意有限静态登记宿主；每个沙箱固定节点/代际，不迁移或失联后异地重建。覆盖创建、连接、get/list、续期、销毁、命令/文件网关、受控IPv4和两端独立恢复。宿主可多租户，同一租户的不同实例可跨节点。

中心不远程重复本地PrepareVm等算法。中心模型管理全局意图/绑定/预留；节点模型管理本地计划/工作/事实/恢复；真实资源和数据连接另建状态，通过系统不变量连接。

暂停恢复、快照/fork/warmup、共享卷、多中心多活、自动迁移、Redis自动切换、IPv6放行及域名/DNS内容过滤不包含。**模板构建与管理整个子系统（含自有编排/别名/登记/发布/产物服务）不证明**，核心使用其授权/不可变/准确描述合同仍须证明。非启用历史类型要证明当前初态/允许输入不可达，不直接删掉历史证明。

恶意请求/来宾、并发、重复/迟到/丢消息、断线、超时、资源不足、部分效果、独立崩溃都在模型内。宿主内核被攻破、管理员恶意改控制数据、硬件静默损坏、任意旧备份回滚和未约定断电持久性不承诺。详细前提和失效处理只见[依赖登记](formal/dependencies.md)。

## 2 按真实模块划分证明责任

采用 V0–V9，避免与工程里程碑 M0–M5 混淆。模块是**证明所有权边界**，不是要求增加服务或crate；共享crate按状态/函数归属，允许复用公共引理。

|---|---|---|
| V0 公共基础 | sandbox-protocol、公共类型/工具链接口 | [身份、数值、合同及精化](formal/00-foundations.md) |
| V1 中心纯决策 | sandbox-center-core | [固定节点、预留、意图和退休](formal/01-center-core.md) |
| V2 中心持久协调 | sandbox-center-store、中心编排提交部分 | [Redis/Lua、耐久派发和恢复](formal/02-center-store.md) |
| V3 内部协议与持久收件 | sandbox-internal、controller-service/internal_inbox | [认证全身份、原本地映射、确认/窗口](formal/03-protocol-inbox.md) |
| V4 本地纯控制 | controller-core | [生命周期、工作账本、调度/发布和维护](formal/04-local-core.md) |

## 3 系统状态和动作

完整状态及初态定义只在 [V9 B1/B8](formal/09-system-composition.md#b1-不能只建模纯核心)：

```text
Σ = (Cfg, Cc, Jc, {Ni=(Ki,Ji,Hi,Gi)}i∈N, Gc, M, E)
```

中心意图、节点逻辑状态、物理状态与一次观察可以不同。中心不知道启动结果但VM已经运行，是允许且必须处理的状态。每一步都要证明守卫正确、后继保持不变量和修改范围；网络、数据库、宿主和崩溃也是动作。

纯函数一个步骤对应，服务函数可能对应多个微步骤。接受创建、VM启动、envd就绪、运行发布、节点结果保存、中心确认分别有证据与提交点；销毁意图、两端撤销、围栏、停止、清理、排空、释放也不能合并。

## 4 性质索引与完备性检查

性质精确公式及成立条件的唯一位置为 [V9 G](formal/09-system-composition.md#g-目标性质和成立条件)。下表只索引责任，不重复维护公式。

| 性质 | 局部提供方 → 系统闭合 |
|---|---|
| S1身份 / S5结果不可改写 / S7修改范围 | V0/V1/V3/V4/V5/V6/V8 → V9 |
| S2授权 / S12查询与错误 | V3/V5/V7/V8 → V9；保密另做双执行 |
| S3终止 / S4真实证据 | V1/V3/V4/V5/V6/V8 → V9，各生效阶段分开 |
| S6持久责任 / S13恢复 | V2/V3/V5/V6 → V9，两库无共同提交点 |
| S8准入边界 / S14安全退休 | V1–V6/V8 → V9，所有未知与收尾继续计费 |
| S9流完整性 / S10时间 / S11策略 | V5/V6/V7/V8 → V9，所需端点/时钟/内核合同显式列出 |
| F1接受完备 / F2正常功能 | 每模块合法输入不额外拒绝 → V9功能端点合同下闭合 |
| L1/DL1最终结果 / L2/DL2最终清理 | 各模块内部启用/出队/预算/无环等待 → V9，外部最终可用与公平单列 |
| DS1–DS8分布式性质 | V1–V8邻接及共同不变量 → V9，任意预算内有限节点 |

完整性按“产品条款→真实入口/字段/错误→状态与故障→局部义务→邻接/系统目标”检查。必须包含 get/list调用期间视图、命令句柄/envd故障、局部故障域、零计数键/订阅/池/关联与真实退出计费；详见V7/V8/V9，不靠含糊的“成功、公平、有界”略过。

## 5 外部合同与输入输出

TLS/Redis/SQLite等引擎不重证，但要声明成功、失败、未知与恢复的最小合同；实际证书角色映射、Lua/SQL、缓存、持久责任、许可和回调是自有义务。版本/配置/模型/使用点统一见[依赖登记](formal/dependencies.md)，官方文档和预检不是全部合同成立的证明。

输入需保留认证租户、原参数、单位、默认/拒绝/截顶及语义；没有公开幂等键的重试create不承诺唯一创建，内部去重不能冒充用户exactly-once。

数据正确性分网关写出、接收方交付和来宾业务完成。HTTP200不能单独证明流/命令成功；Start/Connect持续输出无累计上限，但有单消息/在途缓冲、并发、适用期限和撤销约束。时间不能替代内存界限。完整字节定义、半关闭、部分失败、端点合同及实际异步对应只见 [V8](formal/08-data-gateway.md)。

## 6 实现精化与组合

Rust经固定Charon/Aeneas生成Lean实现语义，手写Lean模型独立规定允许行为；以逐字段表示关系连接初始化、成功、拒绝、完备性、未知和恢复。抽取成功不等于async/I/O/Lua等都已覆盖，不宣称任意Rust翻译无条件无损。

翻译结构限制优先通过保持行为的生产代码局部重构处理；工具变更单独审查其正确性与信任条件，详见[V0责任](formal/00-foundations.md#h22-翻译障碍与工具变更责任)及[处理流程](proof-workflow.md#翻译障碍的识别与处理)。

各模块提供模型性质与实际精化，V9证明上游保证满足下游前提、共同不变量和真实组装精化；自有未解条件最终必须实例化，不能偷换成外部假设。保密是双执行关系，条件推进还需内部进展证明，不从单步安全自动得到。[精化接口](formal/00-foundations.md#h2-rust-与-lean-模型的对应)、[组合接口](formal/09-system-composition.md#h3-系统组合的证明接口)

## 7 推进顺序与三人分工

```text
V0公共定义 + 依赖登记 + V9最小系统模型/共同不变量
                 ↓
#292工程验收 + 少量抽取/桥接可行性试验 → 冻结首批真实提交
                 ↓
中心线 V1→V2 ───────────┐
本地线 V3＋V4→V5↔V6 ────┼→ V9首条跨层闭环
入口/数据线 V7＋V8最小子集 ┘
                 ↓
扩展各线全部入口/拒绝/恢复/流与退休
                 ↓
V9容量闭合 + 双执行保密 + 条件最终完成性
```

箭头是证明前提依赖，不要求串行等待整个模块完成。V5↔V6的交互按联合不变量归纳，不循环假设。V9负责人从第一阶段协调，可由三人之一兼任；建议中心线、本地线、入口/数据线各一主责，公共合同由三人核对。实际认领和任务状态仅放issue。

首条链路固定“中心耐久创建→原节点就绪→丢回执→中心重启→原身份恢复→销毁/精确清理”，证明声明子集所有允许分支/交错，含最小鉴权和撤销/排空，不是只证明示例一次成功。完整查询/网关/保密/长期容量仍为后续交付。

每批：详细骨架/表示关系→目标/前提审查→局部证明→模型/实际实现/邻接组合→完整验收。正式库不使用占位证明或自定义公理。新增抽取根/审计接线是对应证明批次任务；本次仅拆分计划，不调整工具版本、产品代码或CI门槛。[完整操作与闭合判据](proof-workflow.md)
